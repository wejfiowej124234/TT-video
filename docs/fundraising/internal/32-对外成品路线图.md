## 先说结论

当前最该做的，不是继续扩写解释型文档，而是把现有内容收束成 5 类对外成品：

1. 对外介绍成品
2. 融资沟通成品
3. 高频问答成品
4. 平台与社区承接成品
5. 资料管理与签核成品

**与当前仓库对齐**：**One Pager / FAQ / Pitch Deck 初稿**与 **资料室索引** 已在 **[项目-One-Pager](../external/01-OnePager.md)**、**[项目-FAQ](../external/03-FAQ.md)**、**[Pitch-Deck-页序初稿](../external/04-PitchDeck-Storyboard.md)**、**[资料室总索引](10-资料室索引.md)**；后续重心宜放在 **签核版、双语终版、视觉终版、owner/版本号**。

## 建设原则

1. 对外成品必须回链到 `docs/spec/` 的原始单源，不能自由发挥。
2. 每份成品都要区分“当前事实”和“未来路线图”。
3. 每份成品都要先过合规与法务边界，再进入外部使用。
4. 先做通用版，再做渠道定制版，不要一开始就分散精力。
5. 每份成品都要有负责人、验收标准和最新版本记录。

## 推荐推进顺序

若 **`docs/fundraising/external/`** 与 **资料室总索引** 已有初稿或骨架，可将下列「第 1～2 周」理解为 **收口与签核排期**，而非从零新建。

### 第 1 周

1. 固化 One Pager 目录。
2. 固化 Pitch Deck 页序。
3. 梳理 FAQ 问题池。
4. 建账号矩阵表。
5. 建资料室总索引页骨架。

### 第 2 周

1. 完成 One Pager 第一版。
2. 完成 Pitch Deck 第一版。
3. 完成 FAQ 第一版。
4. 补齐账号矩阵与社区入口。
5. 把已有对外资料全部挂到资料室索引页。

### 第 3 周

1. 做中英文项目介绍。
2. 做 Token / 治理边界外部版。
3. 做动画视频脚本第一版。
4. 做渠道推进状态表。

### 第 4 周

1. 做法务与合规复核。
2. 修正所有外部资料口径。
3. 开始针对头部渠道做定制版整理。

## 每份对外成品的统一验收标准

1. 能回答“我们是什么，不是什么”。
2. 没有把支付币、治理币、股权、分红混着讲。
3. 没有把未来规划写成当前事实上线能力。
4. 所有数字、参数、边界都能回溯到原始单源。
5. 有明确版本号、更新时间和负责人。
6. 已经过法务或合规确认后，才能进入对外投递。
7. **叙事分轨**：不把 **`IdentityStakingPool` 系** 身份质押与 **TTG / `/governance`** 治理叙事混写进同一段「质押」话术（见 **[07-产品经理术语表](../../product-manager/07-产品经理术语表.md)**、**[README 快照](../../product-manager/README.md)**）。

## 最后一句话

对内工作包与 spec 已具备基础；外部推进阶段应把内容 **收束为可投递、可签核、可持续维护的成品**，而非继续扩写解释型文档。
