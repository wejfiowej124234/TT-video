## 1. 文档控制头（对内 / 运维稿）

### 1.1 `internal/`、`board/`、`data-room/`、`legal/`（及根 `README.md`）

须在首个 `#` 标题后包含 **Owner / Version / Status / Classification / Last Updated / SSOT** 六键表（见下），供机读闸校验。

| 键 | 取值示例 | 说明 |
|----|----------|------|
| **Owner** | IR / PM / Legal | 单一主 Owner；联署在正文注明 |
| **Version** | `1.0.0-ir` | 维护层版本；与内部台账对拍 |
| **Status** | `draft` / `active` / `frozen` / `archived` | 生命周期 |
| **Classification** | `internal` / `confidential` 等 | 外发前不得升格 |
| **Last Updated** | `YYYY-MM-DD` | 实质性修改须 bump |
| **SSOT** | 反引号路径 | 数字与协议以 `docs/spec/` 为准 |

**批量注入（仅当缺表且非 external）**：`python3 scripts/tools/apply-fundraising-ir-dc-headers.py`（**跳过** `docs/fundraising/external/**`）。

### 1.2 `external/`（投资人终稿 · 不含仓库与内规痕迹）

**与 `internal/` 分层冻结**：单向纪律与禁止重复正文见 [34-融资分层冻结与单向流转](34-融资分层冻结与单向流转.md)。

**不得**出现六键 IR 表、`docs/spec/` 路径、`registry/`、`scripts/`、`internal/` 跳转等（机读闸硬拦）。文首约 **55** 行内须出现统一 banner：

- 中文稿：`版本 **X.Y**`（与 `registry/fundraising-external-numeric-anchors.v1.json` 的 `release` 同号）。
- 英文稿：`Release **X.Y**`（与上同号）。

**CN/EN 成对**：`registry/fundraising-external-cn-en-pairs.v1.json`；**对外百分比**：仅允许出现在 `registry/fundraising-external-numeric-anchors.v1.json` 白名单内（当前为白皮书 `06` / `en/06` 中的 **45% / 55% / 100%** 与协议经济 SSOT 对拍，**不**写入投资人正文 footnote）。

## 2. 生命周期状态

| Status | 含义 | 允许动作 |
|--------|------|----------|
| `draft` | 起草中 | 内部编辑；**不**对外群发 |
| `active` | 现行有效 | 可按签核结果外发 |
| `frozen` | 已签核冻结 | 仅允许勘误 + 版本线递增；重大改写新开文件 |
| `archived` | 归档 | 只读；新读者跳转 `active` 继任篇 |

**归档**：重大结构变更时，将旧版 `Status` 改为 `archived`，在 `00-融资文档地图` 或本文件「归档索引」登记继任路径（可选 `internal/archive/` 子目录，另立项时启用）。
