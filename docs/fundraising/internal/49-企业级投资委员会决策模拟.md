## 0. 模拟设定

| 角色 | IC 中典型关切 |
|------|----------------|
| **Partner（投委会主席）** | 组合定位、回报倍数、声誉风险、能否写进 LP letter |
| **Principal** | 轮次结构、估值、权利条款、跟投与信息权 |
| **Research** | 赛道 TAM、竞争地图、技术可行性、链上可验证性 |
| **Product** | 履约闭环、UX、B 端嵌入路径、与 OTA/PSP 现实摩擦 |
| **Legal** | 证券/VA 监管、推广边界、数据与隐私、合同可执行性 |
| **Token** | TTG 可选性、效用边界、流动性与解锁、与 Escrow 分轨 |
| **Venture Partner** | 引荐渠道 credibility、portfolio conflict |

**输入材料（本轮假定已读）**：`external/01–06`、Deck、IC Memo、FAQ、Whitepaper、Demo 包、Data Room 索引、内部 **39–48**、工程侧 **Evidence** 链（以 **[44](44-企业级证据架构审计.md)** 与仓库 **`evidence/`** 约定为准）、**[TT-GATE](../../runbook/TT-GATE-COVERAGE-vs-96-15-GAP-REGISTRY-001.md)**（**① 机读绿 ≠ 深度多维**）、**[TT-NEXT-BATCH](../../runbook/TT-NEXT-BATCH-BACKLOG-001.md)**（未完成批量）。

**阶次纪律**：本模拟对 **② 测试网 / ③ 生产** 的举证 **单独设闸**；**禁止**用 **①** 冒充 **②③**（与 **AGENTS.md**、**CONTRIBUTING#no-false-completion** 同源）。

## 3. 最大争议点（IC 桌上会吵的）

1. **这是「旅行 Crypto 基础设施」还是「重产品公司」？** — Partner 要一个标签写 memo；团队答案是 **双栖**，但 **双栖 = 两边资源分配** 会被挑战。  
2. **TTG「可能永不发行」 vs Crypto fund mandate** — Token seat 问：若无 token，基金回报是否只靠股权；条款如何对齐。  
3. **FeeRouter 第一层公开口径** — 研究/会计问：对外 **100/45/55** 与仲裁/本金分母关系是否在 **所有对外切片**（含短视频/路演口播）**零误读**；一次口误 = 信任破产。  
4. **① 绿能证明什么** — Research 引用 **TT-GATE**：本地机读 **不**等价 **96-15 Tier C / 93 全文**；团队若辩护过弱，Partner 标记 **execution risk**。  
5. **② 时间表** — 何时有 **staging 可签字的验收包**（非 Markdown）；无日期则 **Defer** 成默认选项。

## 5. 最可能被 **Defer** 的原因（排序）

1. **② 证据包未齐**（Partner：「六个月后再看」）。  
2. **Token 效用与基金 mandate 不完全对齐**（Token seat 弃权或强条件）。  
3. **估值与轮次**：缺少 **NDA 内** 增长/毛利锚，Principal 无法过会。  
4. **Legal 未给书面路径**（多辖区 + 可选发行）。  
5. **TT-GATE 所代表的长尾产品面** 使 Product seat 认为 **12–18 个月内 FOMO 窗口与交付不匹配**（见 **[43](43-FOMO与投资时机-审计.md)** 张力）。

## 7. 会议结论（模拟投票与理由摘要）

| 席位 | 倾向 | 一句话理由 |
|------|------|-------------|
| Partner | **Defer → 条件满足后 Invest** | 叙事与分轨成熟，但 **② + 书面监管 + pilot** 未齐前不上 LP letter |
| Principal | **Defer** | 缺 NDA 内财务与 cap table 对齐 |
| Research | **Defer** | **TT-GATE** 诚实；需 **②** 可验证闭环 |
| Product | **Defer / 弱 Invest** | 多域执行面大，需 staging 验收包减认知负载 |
| Legal | **Defer** | 缺签字边界包 |
| Token | **Defer** | TTG 可选性与 fund thesis 需条款对齐 |
| Venture Partner | **Pass / Defer** | 无强引荐背书时偏 Pass；有渠道背书则随大流 Defer |

**合成**：全票 **硬 Invest** 概率低；**硬 Pass** 概率中等（因问题真实且材料前置）；**条件 Defer** 概率最高。

## 8. 最终输出：概率 + Top 10 阻碍 + 最小修复

### 8.1 Invest / Defer / Pass 概率（0–100）

| 结局 | 概率 | 说明 |
|------|------|------|
| **Invest**（本轮 IC 即授权 TS） | **15** | 需现场出现 **强 pilot + ② 录像 + Legal memo** 小概率同时齐 |
| **Defer**（6–12 个月复盘或条件 TS） | **60** | 与上节 **§5–§6** 一致，为 **Tier1 Crypto** 基线 |
| **Pass**（本轮不做） | **25** | 多因 **mandate / 估值 / 无引荐** 叠加；非「项目假」为主因 |

> 以上为本仓库 **①** 文档与门禁语境下的 **情景模拟**，**不是**真实基金预测；**不**构成投资建议。

### 8.2 Top 10 阻碍（合并 Bear + TT-GATE + 48）

| # | 阻碍 |
|---|------|
| 1 | **② 测试网** 可重复订单/托管/争议证据不足 |
| 2 | **TT-GATE** 登记的深度多维长尾 vs 叙事野心张力 |
| 3 | **Legal 书面包**（多辖区 + TTG 可选）未进 IC |
| 4 | **财务/cap table** 未在 Data Room 与叙事对齐 |
| 5 | **TTG 与 fund mandate** 条款未澄清 |
| 6 | **Demo 环境** 与生产标签一致性（**48 C8**） |
| 7 | **FeeRouter 分母** 在口播/短视频中的误读风险 |
| 8 | **Pilot 数量** 不足以支撑估值（定性 Moat 过多） |
| 9 | **团队带宽** vs **TT-NEXT-BATCH** A/B 域并行 |
| 10 | **Principal 信息权**：NDA 前材料深度不足 |

### 8.3 最小修复方案（**不新增 SKU**）

| 优先级 | 动作 | 负责 | 真源 |

| P0 | **Legal 一页纸**进 Data Room 索引（推广禁区 + TTG 可选三句） | Legal | **internal 04**、**06** |
| P1 | **IR 口播卡**（FeeRouter 三句脚注 + TrustLayer 双名）全员培训 | IR | **48 C1/C3**、**46** |
