## 0. 方法与评分键（① 本地）

- **方法**：按给定角色**主动找投反对票理由**；材料范围以 **`docs/fundraising/external/`**、`export-ready/` 说明、**`build-investor-pitch-deck.py` 主 Deck 15p**、**`ir_ic_appendix` IC 附录** 为主；**未**重审链上字节码、**未**替代法务签核。  
- **修复优先级评分（每条）**：**影响分 1–5**（5 = 直接导致「不推进」或合规雷）× **材料可控性 1–5**（5 = 纯改稿即可缓解）→ 文中记为 **「修复分」= 影响×可控**（20–25 倾向 **P0**，12–19 **P1**，≤11 **P2**）。  
- **阶段**：结论仅落在 **①**；**不**将本审计当作 **②③** 已验。

## 1. 红队总判（一句话）

材料在 **「合规 + 分轨 + 反代币叙事」** 上防守很强，但在 **「可证伪的采用证据、单位经济、TTG 价值捕获闭环、合约与升级的具体缓解」** 上给怀疑型投资人的**弹药偏多**——若不靠 **NDA 包 + 现场演示 + 工程/审计附录**，常见结局是 **「尊重叙事，搁置 IC」**。

## 2. 分角色攻击面（每人 Top 5）

### 2.1 VC Partner（节奏与仓位）

| 攻击点 | 材料弱点 |
|--------|----------|
| 「So what 的**规模曲线**在哪？」 | 公开层**刻意无** GMV/订单/留存；Partner 会问「这是不是永远定性故事」。 |
| 「**为什么你们会赢**而不是 Stripe + 某链托管？」 | 双栖叙事有，**可嵌入 API 的已签伙伴证据**在公开包内弱。 |
| 「**18 个月**后我检查什么指标？」 | 路线图定性强，**可验收里程碑**指向 NDA，冷接触易失焦。 |
| 「团队**执行密度**？」 | 材料几乎不承载组织与交付节奏（有意省略则口述必须补）。 |
| 「**退出/流动性**想象？」 | 非材料义务，但沉默会被脑补为「协议股+币」混乱——需 **IR 一页** 澄清公司/协议边界（NDA）。 |

### 2.2 投委会（IC）

| 攻击点 | 材料弱点 |
|--------|----------|
| 「**反事实**：若不发行 TTG，协议还值钱吗？」 | 06 有分轨，**非 TTG 路径的价值捕获**（纯费 / 嵌入）可再压缩成 **02 首屏三句**。 |
| 「**监管最坏情形**下业务形态是什么？」 | 11.1 有，缺 **情景化**「禁币但可托管」「禁某链但可换链」的**分支叙述**（仍定性）。 |
| 「**资本效率**：要烧多久买到什么证据？」 | 公开层无；CFO/IC 会并联攻击。 |

### 2.3 法务

| 攻击点 | 材料弱点 |
|--------|----------|
| 「**演示环境**表述是否与销售材料一致？」 | 多处正确提示；风险在 **销售口头** 与 PDF **不同步**——需在 **31** 签核勾「口头脚本」。 |
| 「KOL/渠道披露」与 **证券推广** 边界 | 06 有原则句；**活动模板**是否进 data-room 决定防守厚度。 |
| 「白皮书」一词与 **TTG** 并列 | 敏感辖区可能挑战命名——已有治理代币白皮书定位，**封面副标题**可考虑更中性（P2，法审）。 |

### 2.4 Web3 研究员

| 攻击点 | 材料弱点 |
|--------|----------|
| 「**链、账户模型、最终性**是哪条？」 | 协议栈口述有，**对外单页「技术锚」**不足（测试网名、合约族谱占位可放 NDA）。 |
| 「**去中心化**程度：谁升级？谁暂停？」 | Timelock/Governor 在文中有，**运维密钥与多签实践**未在公开层展开。 |
| 「**与其他 travel-crypto** 差异」 | 矩阵定性有；研究员要 **repo/地址/审计 PDF** — 属 NDA/Data Room。 |

### 2.5 协议工程师

| 攻击点 | 材料弱点 |
|--------|----------|
| 「**状态机**与链上事件如何一一对应？」 | 06 分层有，**接口与失败回滚**未公开细写（合理），但工程师会记 **「文档/实现 gap 风险」**。 |
| 「**升级路径**：代理？迁移？」 | 11.2 一笔带过；**红队结论**：公开层可接受，DD 必须给 **架构图 + 升级治理**。 |
| 「**预言机/桥**若存在谁背锅？」 | 06 已点风险；若产品**实际未用**，应在 **03** 明确 **「当前未用」** 减攻击面（若属实）。 |

### 2.6 Token 研究员

| 攻击点 | 材料弱点 |
|--------|----------|
| 「**价值捕获 = 费**，TTG **捕获什么增量**？」 | 若 TTG 仅投票，**边际买家叙事弱**；06 已写「可能永不发行」，**研究员默认打折扣**。 |
| 「**流通供给、解锁、委托集中度**？」 | 公开层 **未定稿** 正确，但会触发 **「那现在讨论 TTG 干什么」** ——需 **IC 附录** 或口述明确 **「期权性 / 路线图挂钩」**。 |
| 「**45/55 内层**与团队/投资人关系？」 | 指向签署附录 — **未签前** Red Team 会猜 **利益冲突**；需 NDA **cap table 与 token 侧关系表**（非本仓公开）。 |

### 2.7 CFO

| 攻击点 | 材料弱点 |
|--------|----------|
| 「**收入确认**与协议费关系？」 | 费路由叙事有，**会计准则口径**（公司 vs 协议）不在公开包 — 必须 **NDA 财务备忘录**。 |
| 「**Burn vs 里程碑**？」 | 无；正常，但 CFO 会 **因信息不足降权**。 |
| 「**对赌/业绩**是否隐含在路线图？」 | 06/03 已卸责；**销售 Deck** 若口头过强仍会被 CFO 记一笔 — 训练 IR。 |

### 2.8 怀疑型投资人（综合）

| 攻击点 | 材料弱点 |
|--------|----------|
| 「**旅游 + 链** 两个最难赛道 **相乘**？」 | 材料用「分阶段、四轨」缓解，**未**给出「先做哪条垂直证明 PMF」的**强记忆锚**（可定性）。 |
| 「**演示即产品**？」 | `SCREEN-RECORDING-BRIEF` 仍写 **Replace … with a real capture** — **P0 级可信度**：zip 内若仍是占位视频，**当场减分**。 |
| 「你们是不是 **protocol washing**？」 | 02/06 用产品主链 + 分轨回应；需 **Demo 真走一笔** 才封口。 |

## 3. 「为什么不投」— 合并清单（红队投票）

| # | 理由类别 | 典型表述 | 材料侧防御现状 | 修复分（见 §0） |
|---|----------|----------|----------------|-----------------|
| R1 | **采用与冷启动** | 「旅游供给侧太重，你们没证明能批量签」 | 定性 GTM；**无**签约数锚 | 20–25 → **P0**（NDA + 口述；公开层一句「首批供给类型」） |
| R2 | **演示薄弱** | 「MP4 占位 / 环境像玩具」 | brief **明文**可占位 | 25 → **P0** |
| R3 | **TTG 价值捕获弱** | 「治理币不付旅行费 = 对我没增量」 | 分轨清晰；**增值叙事**薄 | 15–20 → **P1** |
| R4 | **智能合约与升级** | 「审计在哪？升级谁按？」 | 11.2 原则有；**证据链**在包外 | 18 → **P1** |
| R5 | **竞争可复制** | 「OTA 加托管外包就完了」 | 矩阵 + 嵌入成本有；**缺**伙伴嵌入案例 | 16 → **P1** |
| R6 | **监管扼杀路径** | 「一国禁令全剧终」 | 11.1 + 分辖区有；**缺**分支图 | 14 → **P2** |
| R7 | **信息不足默认降权** | 「全推 NDA = 隐藏坏消息」 | IR 流程可解；材料需 **「NDA 内有什么目录」** 透明 | 15 → **P1** |
| R8 | **逻辑断层** | 「信誉上链了吗？还是中心化 DB？」 | 06 有边界语；**03 缺一条技术诚实 FAQ** | 12 → **P1** |
| R9 | **叙事与 storyboard 维护** | 「你们 Deck 15 页但文档写到第 18 页？」 | **04 storyboard** 附录页与主 Deck **不同步编号** | 10 → **P2**（维护） |

## 4. 功能覆盖 · 逻辑 · 可信度 · 叙事 — 专项缺口

| 域 | 缺口 | 红队建议（不改 spec 真源前提下） |
|----|------|-----------------------------------|
| **功能** | DID/评级/社区 **链上链下边界** 投资人常猜错 | **03 增 FAQ**：每条用「链上事实 / 链下体验 / 以发布为准」三格一句 |

## 5. 未回答或「公开层故意沉默」的 DD 问题（红队清单）

以下在 IC 上**常被问**，公开包内或为 **NDA**、或仅碎片：

1. **主网 / 测试网**合约地址与验证入口？  
2. **审计报告**出具方、范围、版本覆盖？  
3. **关键参数**（争议窗口、费率上限）谁可改、改的流程？  
4. **团队 Token** 或 **投资人 Token** 与 **45/55 内层** 关系？  
5. **公司实体**与 **协议金库** 的法律关系及 **冲突交易** 政策？  
6. **收入**在公司报表如何体现（若有）？  
7. **已签** OTA/DMC/支付伙伴？（Logo 墙需授权）  
8. **事故响应**与 **保险** 是否考虑？  
9. **用户资金**若合约被黑，**赔付**路径？  
10. **多链**策略还是单链深绑？

**修复策略**：不强行塞入公开 PDF；在 **08 索引** 与 **NDA 目录** 显式列 **「问题 → 文档切片」**，减少「推 NDA」像隐瞒。
