## 一、目标与原则

### 1.1 目标

| 项 | 说明 |
|----|------|
| **单文件行数** | 单文件 **≤500 行**（推荐）；严格可采 **≤400 行**（与前端 43 对标）。**新代码**须继续按 48 模块归属且单文件 ≤500 行；自检可运行 `scripts/check-48-line-count.sh`（STRICT=1 时上限 400，50-O-B2）。 |

### 4.3 移出至 router.rs（或 routes/mod.rs）

| 内容 | 说明 |
|------|------|
| Router 聚合 | 使用 **.merge()** 合并各子 Router，最后**只做一次** `.with_state(meta_state)`。示例：`Router::new().merge(routes::health_meta::router()).merge(routes::auth::router()).merge(routes::me::router())…`，最后 `.with_state(meta_state).layer(...)`。 |
| Layer 顺序 | 与 main 当前顺序一致，避免行为变化：Timeout → RequestBodyLimit → CORS → authority_source → pause_gate → request_id → message_id → idempotency → auth_placeholder → security_headers → metrics（从外到内/从先到后按 main 现有 .layer 顺序）。 |
| 各 handler | handler 本体在 routes/*，router 只引用并 .route(..., get(xxx))；不在此处写 handler 实现。 |

### 4.4 移出至 routes/* 的 handler 与依赖

每个 handler 的**函数体**、所需 **State**、**chain_off::*_impl** 调用、**db::*** 调用，均移入对应 routes 文件；main 仅保留 `use crate::routes` 与 router 聚合。具体：

- **routes/health_meta.rs**：`health()`、`meta(State)`、`metrics()`；需 ApiMetaState。
- **routes/auth.rs**：上述 8 个 auth_* handler；需 ChainOffState、db_pool。
- **routes/me.rs**：get_me、put_me、get_me_stats、put_me_password；需 ChainOffState。
- **routes/guides.rs**：guides_list、guide_create、guide_get、guide_stake、upload_guide_doc、serve_guide_upload；需 State（含 store、pool、上传路径等）。

**State 统一约定**：所有路由**共用一个 State 类型 `ApiMetaState`**（main 内约 1359 行定义）；router 只做一次 `.with_state(meta_state)`。各 handler 签名为 `State<ApiMetaState>`，从 state 中取 `state.chain_off`、`state.indexer_state` 等使用。ApiMetaState 字段见 §十一。

**Handler 签名约定**：迁移到 routes 时保持与 main 一致的提取器顺序，例如：`State(state), Path(id), Json(body)`。常用组合：**Path**（:id/:name）、**Query**（如 GuidesQuery）、**Json**（body）、**State\<ApiMetaState\>**。需登录的 handler 先通过 `extract_user_with_session_check(&state, headers)` 或 state.chain_off 取当前用户。**仅用于某 route 的 DTO**（如 main 内 **GuidesQuery**、**UploadGuideDocBody**）放在对应 routes 文件内定义（如 routes/guides.rs）。

## 七、Schedule Engine 模块规格（80 §4.15）

### 7.1 职责

| 职责 | 说明 |
|------|------|
| **重叠判断** | 给定 start_date/end_date，判断两订单档期是否重叠。 |
| **锁定生效** | deposit 达 finality 后，将 start_date～end_date 标记为已占用；取消/终态后释放。 |
| **payment_window 软占用** | confirm 后、deposit 前软占用（如 30min），超时释放。 |
| **防重复接单** | 向导接单时校验：该向导在目标订单的 start_date～end_date 是否已有已锁定订单。 |

### 7.2 接口建议（供 routes/orders、chain_off/orders 调用）

- `schedule_engine::check_overlap(guide_id, start_date, end_date) -> Result<bool, _>`：是否与已有锁定档期重叠。
- `schedule_engine::lock_slot(order_id, guide_id, start_date, end_date)`：deposit finality 后调用。
- `schedule_engine::release_slot(order_id)`：取消/终态后调用。
- `schedule_engine::hold_soft(order_id, guide_id, start_date, end_date, until)`：confirm 后软占用；超时由定时或下次校验释放。

### 7.3 数据来源

- 订单的 start_date/end_date 来自 itineraries 或 orders 表（80 要求必选）；当前 schema 若有缺，需在 48 或 80 落地时补齐。
- 档期占用可先存于 chain_off 的 `guide_slot` 或独立 `schedule_engine::SlotStore`；与 01/03 档期表设计一致。

### 11.2 ApiMetaState 统一说明与字段

### 12.2 run() 保留块与可选抽取

| 段落 | 建议 | 说明 |
|------|------|------|
| 加载 .env、CLI 解析、SSOT/门禁 | 保留 main | 入口与提前退出 |
| db_pool、migrate、chain_off_store、**hydrate** | 保留 main 或抽 **startup::hydrate** | hydrate 约 150 行，抽出可压 main 行数 |
| seed_test_accounts_if_empty | 保留 main | 依赖 chain_off_store、db_pool |
| indexer_state 加载/回放/持久化（CLI 分支） | 保留 main | 与 chain::indexer 协作 |
| 构建 ApiMetaState（含 indexer_state handle） | 保留 main 或 state.rs 提供 **from_run_context** | 见下条 |
| Router 聚合、.with_state、.layer(...) | 移 **router.rs**；main 只调 router::app(...) | idem_cache 在 main 创建后以闭包传入 layer，不经过 router 入参 |
| Outbox worker spawn | 保留 main 或抽 chain/outbox | 可选 |
| idempotency 缓存 | main 创建 `Arc<RwLock<IdempotencyCache>>`，以 **move** 闭包传入 **idempotency_key_layer** | 与 §4.3 layer 顺序一致 |

**indexer_state 与 ApiMetaState**：若 run() 使用 **load_or_init_indexer_state** 得到的状态，应将其包装为 **IndexerStateHandle**（`Arc<RwLock<IndexerState>>`）后传入 ApiMetaState，以便 **indexer_tick** 与持久化一致；若当前为 **new_indexer_state()**，需核对与 persist 逻辑是否一致。

### 12.3 internal 路由与可变 state

- **indexer_tick**：通过 `state.indexer_state` 取得 handle，在 **chain::indexer::append_event_and_advance_checkpoint** 内对 handle 执行写操作；run() 中若需落盘，应在 tick 后或定时调用 **persist_indexer_state**（当前 main 未在 HTTP 路径持久化，实施时可统一）。
- **process_resolution_outbox**：通过 `state.chain_config` 与 `state.resolution_outbox` 消费一条并执行。
- 两处均只需 **State&lt;ApiMetaState&gt;**，无需单独 State 类型。

### 12.4 Headers 与鉴权

- 需要「当前用户」的 handler 使用 **extract_user_with_session_check(state, headers)**；**HeaderMap** 作为 Axum 提取器与 State 一起放在签名中，例如：`headers: HeaderMap`。
- 迁移时保留该签名与调用方式；**extract_user_with_session_check** 落点见 §11.3（state.rs 或 chain_off::auth）。

### 12.5 响应类型与 chain_off/db 依赖

- **响应类型**：与 main 一致，即 **(StatusCode, Json)** 或 **impl IntoResponse**，不改为 Result 等以免行为变化。
- **chain_off 子模块**：可 **use crate::db**、**use crate::chain**；**order_from_db** 在 chain_off 内（如 orders.rs 或 mod.rs）保留为 pub(crate)。
- **db 与 chain_off 的 Row 名**：§11.7 已说明（DbUserRow 等区分）。
