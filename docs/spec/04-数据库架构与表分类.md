## 一、架构原则（与 01/02 一致）

| 原则 | 说明 |
|------|------|
| **链为准** | 资金终态、订单↔escrow 映射仅由链上事件驱动；DB 为**缓存、检索、投影**，可重建。 |
| **域分离** | 按业务域分表与迁移，便于权限、备份与扩展（账号 / 订单 / 链投影 / 治理与审计 / 证据）。 |
| **分布式友好** | SQL 与 DDL 保持 PostgreSQL/CockroachDB 兼容，无单机专有依赖。 |
| **可追溯** | 链相关表 append-only 或可重放；对账/裁决/执行器留审计表。 |

## 二、域划分与目录建议

### 2.1 五大域（逻辑分类）

| 域 | 英文标识 | 职责 | 链/DB 关系 |
|----|----------|------|------------|
| **账号与身份** | `identity` | 用户、会话、角色、KYC；向导资料与质押字段 | 纯 DB；链上不存用户表 |
| **旅游订单与撮合** | `orders` | 订单、行程、订单聊天、档期占位 | 订单状态由链事件驱动；行程/聊天/档期纯 DB |
| **链与托管投影** | `chain` | 链事件、消费进度、订单投影、对账与纠偏、执行器 | 链为准；表为投影与审计 |
| **治理与运营** | `governance` | 幂等键、运营配置、可选运营后台用户/操作日志 | 多签/治理在链或 Runbook；DB 仅辅助 |
| **审计与证据** | `audit` | 评价、争议、证据回执、对账报告 | 争议与证据与订单强关联；对账报告只追加 |

**说明**：治理币（若有）在 01 中 MVP 不发行、Phase 2 可选；当前**无治理币表**。智能合约侧仅 Escrow/EscrowFactory，链上事件驱动订单资金态；管理员域当前已落地最小基线表（`admin_users`、`admin_sessions`、`admin_audit_logs`、`admin_approval_requests`），用于 70 阶段“最小后台 + 审计 + 审批”能力，完整 Admin 体系仍在增量建设。

**与 UI 的扩展说明**（55 阶段同步）：  
- **DID 排行榜**（13-1、30）：数据可由 orders + reviews 聚合或 stub；可选 did_rank_snapshot 表（55-S12/五附.2）。  
- **TT社区（UGC）**（13-1、31）：发帖/点赞/评论/收藏/关注/私信、**反馈/建议**；社区域表与 API 已实现（community_*、community_feedback；55-S10）。  
- **Governance**（13-1 治理页）：池与奖励记录已建（governance_pool、governance_reward_records）；proposals/votes 待产品定稿。

### 2.2 迁移目录与命名建议

**方案 A（推荐）**：单目录 `crates/api/migrations/`，用**文件名前缀**区分域，便于时间顺序与 SQLx 兼容。

| 前缀 | 域 | 示例 |
|------|-----|------|
| `01_` | 账号与身份 | 已有 `20250228000001_users_sessions.sql`，可视为 01_ |
| `02_` | 旅游订单与撮合 | 已有 `*_guides.sql`、`*_orders.sql`；新增 itineraries、order_messages、guide_slot 可归 02_ |
| `03_` | 链与托管投影 | event_log、checkpoints_sharded、orders_projection（接链索引器时加） |
| `04_` | 治理与运营 | idempotency_keys；可选 reconciliation_reports、correction_log、executor_executions |
| `05_` | 审计与证据 | reviews、disputes、evidence_receipts；对账报告 reconciliation_reports 亦可归 04_ |

**方案 B**：按 schema 分离（如 `identity.users`、`orders.orders`）。CockroachDB/PostgreSQL 均支持；需在连接串或 SQLx 中指定 schema，迁移脚本中写 `CREATE TABLE identity.users ...`。适合多团队、多库物理分离前先做逻辑隔离。

**当前仓库**：已采用单目录 + 时间戳命名（`20250228000001_*` …）；**不强制改文件名**，仅建议**新增迁移时**按域选前缀或至少在本文档「表分类」中标注所属域，便于排查与权限规划。

## 四、与智能合约、治理、旅游订单、账号、管理员的关系

| 项目维度 | 数据库对应 | 说明 |
|----------|------------|------|
| **智能合约** | event_log、checkpoints_sharded、orders_projection、executor_executions、correction_log | 链上 Escrow/EscrowFactory 事件为真源；DB 仅索引器投影与对账/执行器留痕 |
| **治理/多签** | 无专门表；可选 idempotency_keys、运营配置缓存 | 多签/Allowlist/Timelock 在链与 Runbook；08-4 收益流/权限矩阵落 Runbook 或治理文档 |
| **治理币** | MVP 无；Phase 2 若有则新增治理/激励表 | 01 写死 MVP 不发行平台币 |
| **旅游订单** | orders（必选）；itineraries、order_messages、guide_slot（可选） | 订单与 01 状态机一致；行程/聊天/档期为体验与撮合增强 |
| **账号** | users、sessions、guides | 注册/登录/向导申请/质押字段；链上不存用户表 |
| **后端管理员系统** | 70 阶段已落地最小后台基线（账户/会话/审计/审批），完整 Admin 与财务/风控/导出域待扩展 | 当前为 Partial：具备最小读路由与角色变更审批 |

## 七、索引与约束一览（现有迁移 + 建议）

**用途**：便于性能排查与门禁/约束核对；新增迁移时请同步更新本小节。

### 7.1 现有迁移中的索引与约束

| 表 | 主键/唯一 | 外键 | 索引 |
|----|-----------|------|------|
| users | id PK, email UNIQUE | — | idx_users_email (LOWER(email)) |
| sessions | token PK | user_id → users(id) ON DELETE CASCADE | idx_sessions_user (user_id) |
| guides | id PK, user_id UNIQUE | user_id → users(id) ON DELETE CASCADE | idx_guides_user, idx_guides_status |
| orders | id PK | tourist_id → users(id), guide_id → guides(id) | idx_orders_tourist, idx_orders_guide, idx_orders_status |
| reviews | id PK | order_id → orders(id), reviewer_id/reviewee_id → users(id) | idx_reviews_order, idx_reviews_reviewee |
| disputes | id PK, order_id UNIQUE | order_id → orders(id), arbitrator_id → users(id) | idx_disputes_order |
| itineraries | id PK, order_id UNIQUE | order_id → orders(id) ON DELETE CASCADE | idx_itineraries_order, idx_itineraries_draft (WHERE draft_id IS NOT NULL) |
| order_messages | id PK | order_id → orders(id) ON DELETE CASCADE, sender_id → users(id) | idx_order_messages_order, idx_order_messages_created (order_id, created_at) |

### 7.2 复合索引建议（按需在后续迁移中增加）

| 表 | 建议索引 | 用途 |
|----|----------|------|
| orders | (tourist_id, status) | 「我的订单」按旅行者+状态筛选 |
| orders | (guide_id, status) | 向导端订单列表按状态筛选 |
| order_messages | 已有 (order_id, created_at) | 按订单分页拉取聊天 |
| reviews | 已有 order_id、reviewee_id | 订单评价列表、向导主页评价聚合 |

**说明**：若「我的订单」查询已由 idx_orders_tourist + status 过滤满足，可暂不新增复合索引；上线后根据慢查询再补。
