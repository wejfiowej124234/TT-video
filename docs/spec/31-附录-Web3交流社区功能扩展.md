## 2. 目标能力一览（要具备的功能）

| 能力 | 说明 | 参考 |
|------|------|------|
| **视频** | 短视频上传、封面、时长限制（如 60s/3min）；信息流内可播放、进度条、静音/开声 | 抖音 |
| **多照片** | 单条帖子支持多图上传；卡片内轮播或网格展示，可左右滑 | 小红书 / 微信朋友圈 |
| **评论与聊天** | 帖子下评论（一级 + 二级回复）；可点击「回复」展开讨论 | 抖音 / 微信朋友圈 |
| **私信（DM）** | 用户间一对一私聊；会话列表 + 会话详情；支持文字、可选图片/链接 | 微信 |
| **关注** | 关注/取关作者；关注列表、粉丝数、关注数展示；Feed 有「关注」流 | 抖音 / 微博 |
| **加好友** | 双向好友关系（申请→同意）；好友列表；可与好友私聊 | 微信 |
| **交流社区感** | 注册登录后：发帖、评论、私信、关注、好友；身份用钱包/DID/昵称；可选「话题房间」或群聊 | Web3 社区 + 微信 |

**Web3 感**：身份以**钱包 / DID** 或**账号（邮箱登录）** 为根；展示「向导 / 游客」「Escrow 向导」等徽章；不在此页做支付与撮合；可选链上关注图或链下先行的关注/好友。

## 4. 页面应怎么设计：信息架构与布局

### 4.1 社区作为「交流中心」的四个主区

建议将 **TT 社区** 设计为一个**带导航壳的交流中心**，与 31 主规范中的单页 Feed 形成「壳 + 多区」结构：

| 区域 | 路由建议 | 内容 | 未登录 |
|------|----------|------|--------|
| **动态（Feed）** | `/community` 或 `/community/feed` | 推荐/关注流；多图+视频卡片；发帖入口；筛选条 | 可浏览，发帖/互动需登录 |
| **消息（Chat）** | `/community/messages` | 会话列表（DM）；未读红点；点击进入会话详情 | 需登录 |
| **关注/好友** | `/community/friends` 或拆成 `/community/following` + `/community/friends` | 关注列表、粉丝、好友列表；加好友/关注入口 | 需登录 |
| **我的** | `/community/me` 或 `/me` 与现有个人中心统一 | 头像、昵称、关注/粉丝/好友数；我的帖子、我的收藏；设置 | 需登录 |

**导航形式**（二选一或结合）：

- **桌面**：左侧竖栏或顶部 Tab —— 「动态 | 消息 | 关注/好友 | 我的」。
- **移动**：底部 Tab Bar —— 「动态 | 消息 | 好友 | 我」，与 30 §4 赛博风统一（霓虹边框、深色底）。

### 4.2 动态（Feed）页细化

- **顶部**：标题 + 副标题 + 筛选条（推荐/关注、最新/最热、类型、目的地）。
- **列表**：
  - **多图帖子**：卡片内为轮播或网格（如 2x2、横向滑）；指示点或页码。
  - **视频帖子**：卡片内嵌播放器（静音自动播或点击播）、进度条、时长角标。
- **单条卡片**：媒体区 + 文案 + 作者（头像、昵称、游客/向导、Escrow 徽章）+ **评论入口**（点击进帖子详情或抽屉）+ 点赞/收藏/分享。
- **发帖**：悬浮「发布」或顶栏入口；发帖弹窗/页：类型（照片/视频/美食/旅游）、多图上传、视频上传+封面、文案、目的地/标签。

### 4.3 帖子详情与评论（可弹层或独立页）

- **入口**：Feed 卡片点击或「评论」按钮。
- **内容**：完整媒体（多图轮播/视频播放）+ 文案 + 作者 + 互动条。
- **评论区**：一级评论列表（游标分页）；每条可「回复」展开二级；发表评论输入框（需登录）；可选「按热度/按时间」排序。

### 4.4 消息（Chat）页

- **会话列表**：与「我」有过私信的用户列表；展示头像、昵称、最后一条消息预览、时间、未读数。
- **会话详情**：左侧或上方为会话列表（可折叠），主区为与当前用户的对话气泡；底部输入框 + 发送；支持文字，可选图片/链接（与 04 媒体约定一致）。
- **Web3 感**：会话列表/详情可展示对方「游客/向导」「Escrow 向导」标识；不在此做支付。

### 4.5 关注/好友页

- **Tab**：关注 | 粉丝 | 好友（可选「推荐关注」）。
- **关注**：我关注的人列表；可取关；支持跳转其主页/发私信。
- **粉丝**：关注我的人列表；可回关、发私信、加好友。
- **好友**：双向好友列表；加好友入口（搜索昵称/ID 或从粉丝/关注里「加为好友」）；申请列表（我发出的/收到的）。

### 4.6 我的（社区侧）

- 头像、昵称、钱包/DID 简写、游客/向导、Escrow 向导。
- 关注数、粉丝数、好友数（可点进对应列表）。
- 「我的帖子」「我的收藏」入口。
- 与现有 `/me` 个人中心可合并或从社区「我的」跳转。

## 5. Web3 交流社区的感觉（设计原则）

| 原则 | 说明 |
|------|------|
| **身份即钱包/账号** | 登录用现有 04 注册/登录或连接钱包；展示 DID 简写、向导/游客、Escrow 向导，增强可信度。 |
| **链上可选、链下先行** | 关注/好友可先链下存储；后续可选上链（如 Lens 式 follow NFT）做可组合与跨应用。 |
| **不混入支付与撮合** | 社区页不做下单、Escrow 存款/释放；可与 29 自由市场联动（如「约 TA 当向导」跳转市场）。 |
| **内容与消息分离** | Feed/评论是「内容互动」；消息是「私密对话」，列表与详情清晰，符合微信式预期。 |
| **赛博风统一** | 全社区（动态/消息/好友/我的）保持 30 §4 赛博朋克风格，与 DID 一致。 |

## 6. 功能清单与实现优先级

| 优先级 | 功能 | 说明 |
|--------|------|------|
| **P0（体验闭环）** | 多图帖子、视频播放、评论（一级+二级）、评论入口 | 让「内容+讨论」完整可见、可操作。 |
| **P1（交流闭环）** | 私信（会话列表+会话详情）、关注列表/粉丝/关注数、发帖/评论/私信需登录 | 注册登录后能聊、能关注。 |
| **P2（深度社交）** | 加好友（申请/同意/好友列表）、关注 Feed、帖子详情页/抽屉 | 好友关系、关注流、完整帖子详情。 |
| **P3（扩展）** | 话题房间/群聊、推荐关注、消息通知（赞/评/@）、链上关注图 | 增强社区感与 Web3 可组合。 |

## 7. 与 04 后端对接建议（占位）

以下为扩展能力在 API 层的占位，与 31 主规范 §11 及 04 §三 对齐；实现时以 04 正式路由为准。

| 能力 | 建议路由/方式 | 说明 |
|------|----------------|------|
| **评论** | `GET/POST /api/v1/community/posts/:id/comments`（主规范 §11 已有）；二级回复可为 `parent_id` | 游标分页、按热度/时间排序 |
| **私信** | `GET /api/v1/community/conversations`；`GET/POST /api/v1/community/conversations/:id/messages` | 会话列表；会话内消息列表与发送 |
| **关注** | `POST/DELETE /api/v1/community/users/:id/follow`；`GET /api/v1/community/me/following`、`/me/followers` | 关注/取关；我的关注、我的粉丝 |
| **好友** | `POST /api/v1/community/friends/request`、`/friends/accept`、`/friends/list`；可选 `GET /api/v1/community/friends/requests` | 发申请、同意、好友列表；申请列表 |
| **多图** | 发帖 body 已支持 `media_ids[]`（主规范 §11）；列表与详情返回 `media_urls[]` | 前端轮播/网格展示 |
| **视频** | 媒体上传类型含视频；帖子返回 `media_url`、`is_video`、`duration_s`；播放用 URL | 前端内嵌 video 或播放器组件 |

## 8. 小结：页面应怎么设计（一句话 + 结构图）

- **一句话**：TT 社区做成以 **L1**（动态｜发现｜消息｜好友｜我）为主结构的 Web3 交流中心（**31 §5.1**；**发现**为扩展 Tab；**建议与反馈**在 **L2** 帮助与支持下拉）；动态区支持多图、视频播放与评论聊天；登录后可私信、关注、加好友，风格与 DID 赛博风统一，不做支付与撮合。

- **结构示意**：

```
/community (或 /community/feed)   →  动态：Feed + 多图/视频 + 评论入口 + 发帖
/community/explore                →  发现：话题/探索（与 31 §5.1、62-补充-02 一致）
/community/messages               →  消息：会话列表 + 会话详情（DM）；活动中心等子路径见 layout
/community/friends                →  关注/好友：关注、粉丝、好友列表 + 加好友
/community/me（或 /me）           →  我的：资料、关注/粉丝/好友数、我的帖子/收藏
```

- **实现顺序建议**：先做**动态区**的多图、视频播放与评论（含帖子详情/抽屉），再做**消息**（私信）与**关注/好友**，最后补「我的」与扩展（话题房间、推荐关注等）。主规范 31 保持不变，本附录作为「Web3 交流社区功能扩展」的单一扩展说明，与 31 配套使用。
