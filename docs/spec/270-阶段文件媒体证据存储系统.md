## 一、文档定位

本文定义 TravelTrust 在 270 阶段的“文件、媒体与证据存储系统”开发规范。

270 阶段将非结构化数据（图片、附件、证据、快照）统一迁移到对象存储体系，避免 DB 膨胀、IO 抖动与安全风险。

与权威层关系：

- `01`：证据可用性与隐私（P0）约束。
- `02`：对象存储 + pre-signed URL 的基础设施分层。
- `04/14`：上传与证据接口契约单源。
- `70`：后台“文件与证据中心”权限与审计承接。

## 二、必须纳管的数据对象

项目中至少包括：

- 向导资质文件
- 用户头像
- 行程附件
- 聊天图片
- 争议证据
- 审核截图
- AI 输出快照

硬约束：

- 以上对象不得长期存储在业务 DB 字段中。
- DB 仅保存元数据与引用，不保存大文件二进制。

## 三、系统目标

1. 存储可扩展：海量媒体不压垮 DB。
2. 分发可加速：通过 CDN 提升访问性能。
3. 内容可校验：文件 hash 可用于完整性校验。
4. 版本可追溯：关键证据支持版本化。
5. 访问可控：签名 URL 与时效控制。

## 四、核心能力（必须具备）

1. `object storage`
2. `CDN`
3. `hash`
4. `version`
5. `signed url`

缺失风险：

- DB 爆
- IO 爆
- 安全爆

## 五、存储架构建议

- 对象存储：S3 兼容或云厂商对象存储。
- CDN：静态与媒体分发加速，边缘缓存策略分级。
- 证据域隔离：普通媒体与争议证据分桶或分前缀隔离。
- 冷热分层：高频媒体热存储、历史证据冷存储。

## 六、数据模型建议

建议最小实体：

- `media_objects`
- `media_versions`
- `media_access_logs`
- `evidence_files`
- `signed_url_tokens`

命名对齐（与 `09/Runbook/现有实现口径`）：

- `media_objects` 对齐为 `evidence_objects`（可保留别名映射）。
- `evidence_files` 对齐为 `evidence_receipts`（证据回执域）。
- `media_access_logs` 对齐为 `evidence_access_logs`（审计语义更清晰）。

字段级要求：

- `media_objects`：`object_id`、`bucket`、`object_key`、`mime_type`、`size_bytes`、`sha256`。
- `media_versions`：`object_id`、`version_no`、`created_at`、`created_by`。
- `evidence_files`：`case_id`、`object_id`、`evidence_type`、`submitted_by`。
- `signed_url_tokens`：`object_id`、`url_scope`、`expires_at`、`issued_to`。
- `media_access_logs`：`object_id`、`actor_or_ip`、`action`、`occurred_at`（**MVP 已落库**：`GET /api/v1/media/access/:token_id` 在 **200**/**410** 写入；另含 `token_id` 外键可空、`occurred_at` 默认 `now()`；见迁移 **`20260415000044_media_access_logs.sql`**、`crates/api/src/routes/media.rs`）。

## 七、访问与安全约束

1. 私有对象默认不可公网直接访问。
2. 所有受限文件通过短期 `signed url` 下发。
3. 证据文件访问必须带鉴权与审计。
4. 上传必须做 MIME 与大小白名单校验。
5. 恶意文件扫描与隔离策略必须接入。
6. 公开直链仅允许“公开材料白名单”；默认访问路径为签名 URL。

公开白名单口径：向导公开资料等可配置为白名单对象，允许短期直链；争议证据、审核截图、内部附件默认私有。

### 8.2 后台模块要求

后台新增一级模块：`文件与证据中心`

子模块（必须）：

- 对象目录
- 上传记录
- 版本历史
- 证据归档
- 访问日志
- 签名链接管理

## 九、权限模型（最小角色）

建议最小角色：

- `MEDIA_VIEWER`
- `MEDIA_OPERATOR`
- `EVIDENCE_REVIEWER`
- `MEDIA_AUDITOR`

权限约束：

- 争议证据访问需更高权限与审计。
- 批量删除、批量导出需审批。

与 `70` 承接约束：`MEDIA_*` 与 `EVIDENCE_*` 角色需落入后台 RBAC 矩阵，不得仅在阶段文档定义。

## 十二、结论

文件、媒体、证据存储系统是可扩展性与合规性的基础设施。没有 270 阶段，数据增长后会在存储、性能和安全上同时失控。
