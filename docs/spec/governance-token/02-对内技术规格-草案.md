## 1. 范围与非目标

### 1.1 范围

- 治理代币 **若上线** 时的：链上合约边界、索引与 DB 投影、API 与 ABI 对齐、测试与 CI 门禁。  
- 与 **激励池 / 治理页** 相关的现有占位实现（49 §G）的演进路径。

### 1.2 非目标（当前）

- 不替代 [01-总库总览](../01-总库总览.md) 中的 **订单结算代币** 定义。  
- **代币总量、TGE、锁仓与解锁曲线** 的**最终投资条款**仍以 **法务定稿对外白皮书 + 08-4** 为准；本文 **§2.5** 仅为 **工程与文档对齐用、可修订的 100% 分解占位**。

### 1.3 本地链优先与上真实链门槛（工程硬约束）

**顺序不得颠倒**：先在 **本地虚拟链（Anvil 等）** 完成验证与联调，再切换 RPC/密钥部署 **测试网**，最后 **主网**。操作约定与部署入口见仓库 **[contracts/README](../../../contracts/README.md)**（`forge test`、`forge script`、Anvil）；运维换部署与 env 核对另见 **[Runbook §2.56](../../../ops/RUNBOOK.md)**。

**本地阶段须验收（随最终实现勾选，缺一不可再切公链）**：

1. **订单主路径**：与现有 Escrow / FeeRouter / RegionVault 等已落地合约一致的 **createEscrow → deposit →（争议可选）→ release/refund** 等闭环，在本地部署地址与 **API / 前端 / 索引器（若有）** 指向上能 **端到端跑通**。  
2. **治理代币与治理交易流（Target）**：一旦引入 **TTG / ERC20Votes / Governor / Timelock / Snapshot·Claim（83）** 等模块，须在本地链上跑通 **铸造或分配 → 委托 → 投票（或限域治理调用）→ 时间锁执行 → 与 83 文档一致的关键只读 API 或索引投影**；**`/governance` 产品页** 与链上真值边界仍以 **[13-1](../13-1-UI产品级SSOT与页面规范.md) 表 2-续**、**[83](../83-区域治理与收益分配-协议白皮书.md) 附录 I.0** 为准。  
3. **质量门槛**：相关 **Foundry 单测**、约定集成脚本或手工验收清单 **全部通过**，**ABI / 04 §3.4 / 14** 已与本地清单地址同步。

**说明**：**法务书面定稿**、**LEGAL-SIGNOFF** 与对外披露是 **必要条件**，但 **不替代** 上述工程闭环；**禁止**在本地主路径或治理流未验收的情况下，仅因「文档已定稿」就上 **主网** 承接真实资金或真实投票权。

## 2.5 代币供应 100% 分解（对内 SSOT · 占位可修订）

**目的**：闭合 [82-治理币-文档总览](../82-治理币-文档总览.md) **§六 T7** 与 [84-第一阶段10国Country-Pool发行参数总表](../84-第一阶段10国Country-Pool发行参数总表.md) **§1.5**「须在 SSOT 写死」的要求；供 **工程、数据、募资表重算、PPT 摘抄** 使用同一套 **占总量百分比**。**非法务要约**；路演/印刷前须与 [01-对外白皮书-草案](01-对外白皮书-草案.md)、[08-4](../08-4-对外口径包.md)、[LEGAL-SIGNOFF](LEGAL-SIGNOFF-CHECKLIST.md) 一致。

**硬约束**：

- 各行 **占治理代币（TTG，工作名）总供应量** 比例 **之和 = 100.0%**（允许小数位后修订，但须重算合计）。  
- **国家池相关承销桶** 占总量 **≤ 25%**，与 **84 §1.3、§1.5** 一致；**不得**在未改 84 的情况下把本行改为大于 **25%**。  
- **个人/全局承销**（非国家桶）与 **生态 / 团队 / 金库** 等子桶 **互斥**，避免双计。

**占位分解表（草案 · 产品可改数须同步全库）**：

| 分配桶 | 占总量 % | 与 84 / 83 关系（摘要） |
|--------|----------|-------------------------|
| **国家池相关承销**（Country Pool / RegionShare 等路径） | **25.0** | 上限闭合 **84 §1.3**；**84 §四** 各国法币目标须与本行子分配或轮次表一致后重算 |
| **个人 / 全局公募**（非国家桶 TTG） | **20.0** | **84 §1.5** 个人桶；权利边界 **83 §19** |
| **生态与市场** | **15.0** | 增长、空投/活动预算等（实现与披露以对外稿为准） |
| **团队** | **15.0** | cliff/vest 见对外白皮书草案 |
| **顾问** | **5.0** | |
| **协议金库 / DAO 储备 / 流动性与激励预算** | **20.0** | 与 **83** Global/储备叙事对照时须单列子科目，**不**与 Escrow 用户本金混路径（见 §4.1） |
| **合计** | **100.0** | |

**修订流程**：改任意一行 → bump 本文版本 → 同步 [84](../84-第一阶段10国Country-Pool发行参数总表.md)（若影响国家桶或募资表）、[82](../82-治理币-文档总览.md)、[governance-token/03](03-对外材料-PPT与白皮书数据页摘抄索引.md)、[00-文档索引](../00-文档索引.md) 版本说明（若已登记）；并按 [07 §二 2.4](../07-开发流程与顺序.md) 跑 `check-governance-doc-linkage.sh`。

## 3. 当前代码基线（As-Is）

### 3.1 链上

- **身份质押（现行 SSOT）**：**`contracts/src/IdentityStakingPool.sol`**，由 **`GuideIdentityStakingPool.sol`** / **`ProviderIdentityStakingPool.sol`** 继承落地（**[81](../81-经济模型-向导质押与订单押金.md)**、**[14 §1.1](../14-合约-API-ABI-前后端对齐.md)**、**[contracts/README](../../../contracts/README.md)**）。**质押品** 为构造器注入的 **`IERC20`**（示例为 USDC 6 decimals），**不是** 专用治理代币合约。**旧版单体质押实现已从仓库移除**；**`Staked` / `Withdrawn` / `Slashed`、`stakeOf`、`MIN_STAKE()`** 等与旧版 **ABI / topic0** 向后兼容，供索引器与只读 API 消费。  
- 若新增 **ERC20Votes / Governor / Timelock** 等模块：须经 **安全与架构评审**，定稿 **命名空间与部署清单**，并更新 `contracts/abi/` 与 **14**。**默认**与本仓库 **`contracts/src/`** 同仓迭代；若拆 **独立合约 repo**，须在 **[contracts/README](../../../contracts/README.md)** 或 **02 §2 映射**、**[02-架构设计](../02-架构设计.md) §十** 注明路径，避免 ABI/地址双 SSOT。

### 3.2 后端 API（占位）

- 路由：`crates/api/src/routes/governance.rs`  
  - `GET /api/v1/governance/pool`  
  - `GET /api/v1/governance/rewards`  
- DB：`crates/api/src/db/governance.rs`（`governance_pool`、`governance_reward_records`；以迁移为准）

### 3.3 前端

- 页面：`frontend/app/governance/`（与 [13-1](13-1-UI产品级SSOT与页面规范.md) **表 2、表 2-续**（`/governance` vs 83 链上 DAO）一致）  
- 定稿后：任何「领取/委托/投票」动作须走 04 契约 + EIP-712/交易流程（见 06、35）。

## 4. 目标架构（To-Be，条件启用）

### 4.1 链上分层（建议）

1. **代币层**：标准 ERC-20；若需投票快照，采用 **ERC20Votes** 或等价方案。  
2. **治理层**：OpenZeppelin Governor 兼容或自研 **限域治理**（仅允许白名单参数类型变更）。  
3. **时间锁**：所有可执行提案经 **Timelock**；延迟与 01/08-1 一致（如 ≥48h 运营参数类）。  
4. **金库（可选）**：若存在链上金库，须与 Escrow 合约 **资金隔离**，禁止同一 `transfer` 路径混用用户托管余额。  
5. **FeeRouter / RegionVault / GovernanceTreasury / Global Pool 叙事**：**`FeeRouter.sol`**、**`RegionVault.sol`**、**`GovernanceTreasury.sol`** 等已在 `contracts/src/` 落地（**完备度** = **Partial / MVP / Target** 以 **[14](../14-合约-API-ABI-前后端对齐.md) §1.1**、**04 §3.4**、**110**、**Runbook** 为准，**禁止**与「未部署」混读）；与 [83](../83-区域治理与收益分配-协议白皮书.md) **§3**、**[84](../84-第一阶段10国Country-Pool发行参数总表.md)** **Global Pool** 叙事对照时，须保持 **用户 Escrow 本金** 与 **协议金库 / 路由滞留** 路径分轨；**84** 承销侧产品逻辑与订单结算解耦（募资 ≠ 单笔订单结算）。

### 4.2 索引与对账

- 新增事件：`DelegateChanged`、`ProposalCreated`、`VoteCast`、`ProposalExecuted` 等（以最终 ABI 为准）。  
- `crates/api/src/chain/indexer.rs`（或等价）消费最终块确认后事件；**reorg** 处理与 10/110 一致。  
- DB 投影表须可 **仅从链上事件重建**（与 01 不变量一致）。

### 4.3 API 演进

- 在 04 §3.4 登记：  
  - 查询：池余额、提案列表、投票权快照、用户委托关系。  
  - 写操作：原则上 **用户链上自签**；后端仅提供 **元数据与模拟计算**，避免托管私钥。  
- 若必须后端代发（不推荐）：须单独安全评审与 08-1 披露。

## 5. 数据模型（草案表 — 以迁移为最终 SSOT）

在现有占位表之外，若链上治理启用，可扩展（示例）：

| 逻辑实体 | 用途 |
|----------|------|
| `governance_proposals` | 提案 id、链上 proposalId、状态、起止时间 |
| `governance_votes` | 投票记录投影（或仅保留链下缓存，以性能与合规为准） |
| `governance_delegations` | 委托关系快照 |

**原则**：链上为权威；DB 为缓存与报表；对账任务参照 `indexer-reconcile` / 财务对账门禁模式。
