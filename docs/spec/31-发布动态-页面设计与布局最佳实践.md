**适用范围**：TT 社区「发布动态」弹窗（发帖/写笔记）及同类创作类页面的显示与布局设计。

---

## 一、整体布局原则

### 1.1 单列、自上而下流程（F 型 / 纵向扫视）

| 原则 | 说明 |
|------|------|
| **单列主内容** | 表单项垂直排列，避免多列导致视线跳跃；桌面端可限制最大宽度（如 max-w-2xl）居中，保证可读性。 |
| **顺序即流程** | 按用户心智顺序：**先选类型 → 再加媒体 → 再写文案**，与 Instagram / 小红书 / 微博发帖一致。 |
| **一屏一主任务** | 首屏能完成「选类型 + 加图 + 写一句」；高级项（话题、@、定位）可收折或放在次要位置。 |

### 1.2 三区固定结构

```
┌─────────────────────────────────────┐
│  顶栏（固定）· 返回 | 标题 | 关闭     │  ← 始终可见，不随内容滚动
├─────────────────────────────────────┤
│                                     │
│  主内容区（可滚动）                   │
│  · 类型选择                          │
│  · 图片/视频上传                     │
│  · 正文输入 + 字数/话题               │
│                                     │
├─────────────────────────────────────┤
│  底栏（固定）· [ 发布 ]               │  ← 主 CTA 始终可见，拇指可触
└─────────────────────────────────────┘
```

- **顶栏**：返回（左）、标题（中）、关闭（右）；高度建议 ≥ 48px，安全区适配。
- **主内容**：`flex-1 overflow-y-auto`，仅此区域滚动。
- **底栏**：主按钮全宽或 max-width 居中，留足 padding 与 safe-area-inset-b。

## 二、显示与层次

### 2.1 视觉层次

| 层级 | 用途 | 建议 |
|------|------|------|
| **主操作** | 发布按钮 | 唯一强色（如品牌主色/高对比），尺寸突出（py-3.5～4），可带轻微阴影。 |
| **区块标题** | 类型、图片、正文 | 小号字 + 中字重，与正文区分；可配合 section 背景区分区块。 |
| **说明/提示** | 格式说明、字数、选填提示 | 弱色（如 text-slate-500）、小字号，不抢主流程。 |
| **占位与约束** | placeholder、0/9、0/1000 | 明确且简洁，字数接近上限时可用警告色。 |

### 2.2 分区方式

- **同一逻辑一组**：类型选一组、媒体上传一组、正文一组，组内间距小于组间间距（如 gap-2 组内，space-y-6 组间）。
- **轻量容器**：用圆角卡片（rounded-xl）+ 细边框 + 浅底（如 bg-slate-800/40）区分区块，避免全屏白/全屏灰。
- **留白**：区块间留白 ≥ 区块内留白，避免拥挤。

### 2.3 移动端拇指区

- **易触**：返回（左上）、发布（底部中/全宽）在拇指自然范围内；避免把「发布」放在顶部右侧。
- **触控尺寸**：主要按钮与可点击区域建议 ≥ 44×44px（min-h/min-w 或 padding 保证）。

## 三、表单与控件

### 3.1 类型选择

- 展示为**横向一排 pill/chip**，选中态明显（背景 + 边框 + 可选阴影）。
- 类型不宜过多（4～6 个为佳），过多时可「更多」收折或第二行。

### 3.2 媒体上传

- **首图/首帧优先**：多图时第一张大一些或与添加框同尺寸，形成清晰「封面」感。
- **添加入口**：虚线框 + 「+」+ 数量（0/9），点击即选文件；可支持多选与拖拽（若技术可行）。
- **预览**：缩略图可带顺序调整（左右箭头）、删除（×），避免与发布按钮误触。

### 3.3 正文

- **多行输入**：textarea，rows 约 4～6，min-height 保证一定高度（如 120px）。
- **字数**：右下角或输入框下方固定展示「当前/上限」，接近上限时高亮。
- **话题/标签**：作为辅助说明或第二行提示即可，不必首屏占大面积。

### 3.4 主 CTA（发布）

- **唯一主按钮**：一屏一个主操作（发布），其余为次要（返回、关闭）。
- **状态**：未填正文时禁用并给出说明（如「填写正文后即可发布」）；提交中显示「发布中…」并禁用防连点。
- **位置**：底栏固定，全宽或 max-width 居中，与内容区有明确分隔（边框或阴影）。

## 四、无障碍与语义

| 项 | 建议 |
|----|------|
| **区域** | 顶栏用 `<header>`，主内容用可滚动容器并设 `aria-label` 或 role，底栏可为 `<footer>` 或 div。 |
| **标题** | 弹窗标题与 `aria-labelledby` 关联；区块用 `<section>` + `<label>` 或 `aria-labelledby`。 |
| **说明** | 字数、格式说明用 `aria-describedby` 关联到对应输入。 |
| **焦点** | 打开时焦点到返回或标题；提交后焦点离开按钮；Esc 关闭并还原焦点。 |

---

## 五、与当前实现的对应

TT 社区 `PublishDrawer` 已按本标准优化并保持对齐：

- **三区**：`<header>` 顶栏（返回 + 标题 + 关闭，min-h 48px）、`role="main"` 可滚动主内容、`<footer>` 底栏发布。
- **顺序**：类型 → 图片上传 → 正文（+ 话题提示 + 字数）；单列 max-w-2xl 居中。
- **分区**：类型 / 图片 / 正文 各为独立 `<section>`，圆角卡片 + 组内 gap-2、组间 space-y-6。
- **首图优先**：多图时第一张 28×28（112px），其余与添加框 24×24 一致，形成封面感。
- **触控**：类型按钮与关闭、发布均为 min-h/min-w ≥ 44px。
- **字数**：接近上限（≥90%）即用警告色，达上限高亮；`aria-live="polite"`。
- **主 CTA**：底栏固定、全宽发布按钮 + min-h-48px，禁用态与「填写正文后即可发布」提示。
- **无障碍**：顶栏/主区/底栏语义化，`aria-labelledby`、`aria-describedby`、`aria-busy`、footer `aria-label`；发布失败条 `role="alert"` + `aria-live="assertive"`。
- **企业级**：弹窗打开时 `document.body.style.overflow = "hidden"` 锁定背景滚动，关闭时恢复；焦点陷阱（Tab 在弹窗内循环）、关闭后焦点还原到触发元素（见 31-TT社区-企业级检查报告-页面与发帖弹窗）。

后续若增加「位置」「@提及」「可见范围」等，建议仍按**单列、分组、主次分明**排列，高级项可收折或放在正文下方、发布按钮上方。
