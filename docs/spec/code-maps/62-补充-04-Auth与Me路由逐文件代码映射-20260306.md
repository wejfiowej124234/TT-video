## 4. 关键约束核对

### 4.1 33 页面实现顺序与职责边界

1. Auth 负责账号生命周期，不承载交易/链上动作。
2. Me 负责个人资料、统计、设置，不承载订单协议流程。
3. `returnUrl` 机制保障业务页跳登录后可回跳，链路可用。

### 4.2 37 i18n/a11y 约束

1. Auth+Me 范围翻译键覆盖：
   - 抽取范围：`app/auth`, `app/me`, `components/me`
   - 结果：`total_keys=139`, `missing_zh=0`, `missing_en=0`
2. a11y 证据：
   - 错误提示使用 `role="alert"`
   - 加载态使用 `role="status"`
   - 关键输入包含 `aria-invalid` / `aria-describedby`
   - 关键按钮保留 focus-visible ring 样式

### 4.3 与 API 契约一致性（04）

1. Auth 页面调用 `postLogin/postRegister/postForgotPassword/postResetPassword/postVerifyEmail`。
2. Me 页面调用 `getMe/putMe/getMeStats/putMePassword/postLogout`。
3. 改密页与 `PUT /api/v1/me/password` 契约保持一致。
