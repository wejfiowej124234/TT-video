## 2. 逐条宪法对齐（代码证据）

### 宪法 1: 资金区必须像银行

规范要求（13）:
- 禁止资金区渐变、炫光、重玻璃。

代码现状:
- `frontend/components/escrow/EscrowDetail/index.tsx`: `panelClass` 使用 `bg-slate-900/70 backdrop-blur-md shadow-[0_0_20px...]`
- `frontend/components/escrow/OrderFlowSteps.tsx`: DID 变体使用 `border-cyan-500/30` + `backdrop-blur-md` + 青色 glow 阴影
- `frontend/components/escrow/EscrowDetail/BilateralConfirmBlock.tsx`: DID 变体同样是玻璃+青色边框
- `frontend/components/escrow/EscrowDetail/OrderMessageLink.tsx`: DID 变体同样为玻璃态

结论:
- 部分冲突。实现偏向 30-DID 赛博视觉，而 13 对 Escrow 的“银行级克制”更严格。

### 宪法 2: 3D 只存在于情绪层

规范要求（13）:
- 3D 不进入 Escrow/Dispute/Governance。

代码现状:
- 3D主组件: `frontend/components/did-rank/Web3SciFiBackground.tsx`（R3F + Three）**仍存在**，供 **`MePageBackground`** 等复用。
- **2026-03 真值**：**`/did-rank`**、**`community/layout` 壳层**已**不挂载**该组件（页身 CSS 叠层见 **[88](../88-五主路由页身实现快照与UX缺口审计-20260330.md)**）。**`/community/me`** **不**挂载 **`MePageBackground`**（**88 §二**）；**`/me`**、**`/guide`** 工作台仍可能使用 **`MePageBackground`**。
- 其它：`frontend/app/community/tt/page.tsx` 等以代码为准。
- Escrow 页面: `frontend/app/escrow/[id]/page.tsx` 为纯内容壳，无 3D 注入

结论:
- 符合“资金区不进3D”。
- **情绪层 3D/R3F** 当前在 **`/traveltrust`**（**cinematic 3D + layout lock**；**L1** portal + **CSS** 公告跑马灯；legacy 页内树 **未**挂载 — **contract**）、**`MePageBackground`** 等路径；**`/`** 为 **Ken Burns + 1 预览卡数据链 + 冷灰页脚**（**非** R3F · **[`(home)/README`](../../frontend/app/(home)/README.md)** · **FIVE-MAIN-ROUTES**）。与 21 中「Landing Hero 必须 3D」存在执行偏差（见 **21-补充** 2026-03 修订段）。

### 宪法 3: 旅游层与金融层分层融合

代码现状:
- Landing: `frontend/app/(home)/page.tsx`（**`/`**）**Ken Burns** + **`TT_MARKETING_HOME_*`** + 玻璃表单 + **`TT_MARKETING_HOME_SECTION_BRIDGE`** + **`ITINERARY_CARD_COUNT=1`** 预览卡 + **`UnlockModal`→`getOrder`** + **`TT_MARKETING_HOME_FOOTER_TOP_FADE`** + 冷灰 **`LandingFooter`**（**`useLandingPage`** · **`landingItinerarySession`**（**`localStorage`** · 跨 tab · **`marketFavoritesStorage.ts`**）— **[(home)/README](../../frontend/app/(home)/README.md)** · **[LANDING-MARKET-PAGES-CODE-SSOT](../../frontend/evidence/GO_local_web3_pages_closure/LANDING-MARKET-PAGES-CODE-SSOT.md)** §2 · **88 §一** · **86 §6.1**）
- Market: `frontend/app/market/page.tsx` 为情绪层玻璃容器，Web3 信息轻量露出；**`useMarketPage`**（**300ms debounce** · **`getDiscoverOrders`** · 收藏 **`localStorage` only** · **F-020 best-effort 已接线（①）· ② SLA**）— **[LANDING-MARKET-PAGES-CODE-SSOT](../../frontend/evidence/GO_local_web3_pages_closure/LANDING-MARKET-PAGES-CODE-SSOT.md)** §3
- Escrow: 独立路由与流程容器 `frontend/app/escrow/[id]/page.tsx`

结论:
- 分层架构成立，边界清晰；但 Escrow 内部视觉克制仍有收敛空间。

## 4. 建议闭环动作（代码驱动）

1. 在 `13` 增加“例外条款或禁止条款清单”:
- 明确 Escrow 是否允许 `backdrop-blur`、`cyan glow`、`bg-slate-900/70`。

2. 增加资金区样式守卫（建议）:
- 约束 `frontend/components/escrow/**` 禁用 `backdrop-blur-*` 与 glow 阴影（或仅允许白名单组件）。

3. 统一规范优先级表（13 vs 28 vs 30）:
- 由 13 锁“资金区硬约束”，28 锁“情绪层美术”，30 锁“DID/社区赛博风”。

4. 在验收清单加入自动化检查:
- grep 规则：`escrow/**` 中出现 `backdrop-blur|shadow-\[0_0` 标记为需人工复核。
