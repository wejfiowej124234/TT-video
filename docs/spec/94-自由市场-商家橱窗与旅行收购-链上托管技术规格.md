## 1. 背景与目标

### 1.1 背景

自由市场当前包含「旅行预约 / 商家 / 旅行收购」子站入口。需在**不与主 `/market` 订单列表混用业务状态**的前提下，提供：

1. **商家橱窗**：酒店、餐饮、景区等门店以图文视频展示「可成交的旅游相关供给」，并进入与旅游一致的托管支付闭环。  
2. **旅行收购**：收购方发布「悬赏式」跨境带货需求（多媒体 + **自填验货与交割标准**），承接方接单履约，同样进入托管支付闭环。

### 1.2 支付与结算原则（硬约束）

- **结算代币**：**USDT、USDC**（及治理配置的其它 **ERC-20 稳定币**）；以链上 `settlement token` 与订单元数据为准。  
- **资金路径**：与现网一致——用户仅在**订单绑定的 Escrow 合约**上执行 **Approve / Deposit**；**不向平台或对私地址「直接打款」**完成订单（前端文案与 CTA 须与 `frontend/app/pay`、`frontend/locales` 中既有 `pay_*` / `escrow_*` 叙事一致）。  
- **真相源**：链上状态 + 后端投影；UI 以 **`/escrow/:orderId`** 为阶段主引导，**`/pay`** 为枢纽页（与现产品一致）。

### 1.3 写路径门闸（商家 vs 收购 · **① 实现对读**）

- **商家（① 已实现 · 2026-05-27）**：**`POST /api/v1/market/provider/listings`** 及 **`…/listings/drafts`** → **`market_merchant_gate.rs`** **三门闸** — **PG **`users.role=provider`** + **`onboarding_entitlements.status=paid`**（**`role_target=provider`**）+ **approved 商家申请**（PG **`role_applications`** 或 **chain_off 内存** **`provider_applications_by_user`**）；**403** **`merchant_role_required`** / **`provider_application_not_approved`**，**400** **`onboarding_entitlement_required`**。  
- **旅行收购（① 已对齐 · PD-009 · 2026-05-27）**：**`POST …/market/acquisition/*`** 写路径 → **`market_merchant_gate.rs`** 内 **`ensure_acquisition_market_write_allowed`**（**`acquisition_publish_gate.rs`**）— **旅行者侧** + **`users.default_wallet_address`** + **发布保证金（`staking_positions.kind=acquisition_publish_bond`）或信用 ≥700 免押** + **24h 频控（≤5）** + **`GET /me.trust`** 收购向无阻塞（**`identity_status=restricted`** / **`risk_level=high`** → **`acquisition_trust_restricted`**；**`acquisition_publish_suspended_until`** → **`acquisition_publish_suspended`**）；**POST publish** 另须 body **`agree_escrow_copy: true`**。**勿** 要求 **`region_steward`** / **96-18 准入费** / **商家 KYB**。HTTP 错误码 **[acquisition-publish-trust-rules v1 §3](artifacts/acquisition-publish-trust-rules.v1.md#aq-rules-http-34)** · **§8.1 CLOSED**。  
- **②③** Stripe/生产 PSP 与 staging 矩阵 **另闸**；**不**以本文冒充 **②③ GO**。

### 1.4 旅行收购 · 发布 / 履约 / 风控分层（**PD-009 · LOCKED**）

**产品 SSOT：** **[acquisition-publish-trust-rules v1](artifacts/acquisition-publish-trust-rules.v1.md)**（与 **87 §1.4**、**identity-unified-model PD-009** 同源）。

| 层 | 用户动作 | 门闸摘要 |
|----|----------|----------|
| **L0 浏览** | 看收购目录/详情 | 匿名 **`GET …/acquisition/listings*`** |
| **L1 发布** | Studio 发布 listing | 登录 + **主钱包** + 勾选 Escrow/风险 + **（发布押金 ∨ 信用≥阈）** + 日频控 |
| **L2 接单** | 详情页创单 | 登录 + **trust 门禁** + 大额 **履约押金** |
| **L3 成交** | Escrow 托管 | **94 §6.3** 里程碑 + **`/escrow/:id`** |
| **L4 信用** | 评价 / 争议 / 榜 | **03 §1.2.2** · **`acquisition_trust_score`** · **160** 举报 |

**与商家差异（硬约束）：** 收购 **不** 走 **`/provider/register`** 资质链；**Hub `/me/identities`** 收购卡片 **「进入子站」** 正确，**首次发布引导在子站内**（绑钱包 + 押金说明）。

### 1.5 非目标（本期可不实现）
- 法币支付通道、信用卡收单。  
- 平台中央资金池「代持」用户充值余额（与协议定位冲突）。  
- 完全自动化的海关 / 税务 / 跨境合规裁决（仅提供规则入口与人工争议接口）。

### 2.2 全局 UI 要素

- **钱包连接状态**：子站常驻（与 DApp 分区一致，见 **92**）。  
- **筛选条**：见 **§2.3**（定稿）；与主 `/market` 的 `StickyFilterBar` 心智一致；数据源 **`GET …/market/{provider|acquisition}/listings?country&category&sort=`** — **`meta.source=postgres_catalog`** 时 PG 真源，API 失败且 demo gate 开时 **demo masonry** + degraded 提示（**非** demo-only）。  
- **合规提示条**：一行链到帮助中心 / 对外口径包（**08-4**）；收购页强调禁限带与自负责任。  
- **跳转既有能力**：「我的订单」「支付与托管」链到全站已有路由（见 04 前端路由表）。

### 2.3 子站列表顶栏：国家 / 分类 / 排序（定稿 · 与十国产品期对齐）

**目标**：用户在**不离开首屏认知**的前提下完成「选国 → 选类 → 看结果摘要 → 浏览卡片」；国家列表**仅十国**（与 `frontend/lib/productCountries.ts` → `GET /meta.product_countries` 同源），不出现未开放地区。

#### 2.3.1 垂直顺序（上 → 下）

1. 子站 **Tab**（旅行预约 / 商家 / 旅行收购）— 保持现状。  
2. **筛选主带（建议 Sticky）**：滚动瀑布流时仍可见；高度控制为**一行主控 + 一行 chips**，避免占半屏。  
3. **结果摘要行**（`text-meta`、低对比）：例：`日本 · 餐饮 · 共 1 条`；演示阶段须含「演示数据」提示，与 `market_subsite_filter_summary_line` 叙事一致。  
4. 瀑布流 / 空态（无结果时主带保留，空态区提供 **「重置筛选」**）。  
5. **列表底部收口（1.0.2）**：有结果时，瀑布流下方保留**一行说明 + 次级 CTA**（返回主 `/market`、再进入 DID 榜、条款/争议），避免滚到底「无引导」；实现见 `MarketSubsiteListFooterStrip`。

#### 2.3.2 国家

- **选项集**：十国 ISO（`CN JP KR SG TH AE US AU FR ES`）+ **`all`（全部十国）**。  
- **控件**：桌面端 **横向可滚 pill**（与 Tab 选中态区分：国家略小一号、未选中为半透明白边）；移动端国家过多时同一容器横向滑动。  
- **默认值策略（推荐 B）**：首次进入若 URL **无** `country` 参数，可从 **`localStorage`**（按子站分 key，如 `tt_market_subsite_country_pref_provider`）恢复用户上次选择；若需可分享深链，用户点选后**写回 URL** `?country=JP`。实现上允许「无参 = all」以避免首屏强制跳转闪动。  
- **详情页**：列表进入详情时 **Query 可透传**（`?country=JP&category=dining`）便于返回列表恢复上下文；详情元数据不必依赖 `country`。

#### 2.3.3 分类（两页差异）

| 子站 | 一级分类（chips） | 收入「更多」/ 二期的项 |
|------|-------------------|------------------------|
| 商家橱窗 | `hotel` / `dining` / `attraction` / `experience` | 价格区间（USDC）、标签（亲子/海景等） |
| 旅行收购 | `luxury` / `sneakers` / `electronics` / `health` / `accessories` | 路线方向、悬赏区间、紧急度、是否要求当面验货 |

- **单选 vs 多选（定稿）**：主带 **单选**（含 `all`），降低与分页 API 的组合复杂度；多选留二期或「更多」抽屉。

#### 2.3.4 排序

| 子站 | 选项 |
|------|------|
| 商家 | `recent`（默认，按发布时间或 `sort_key` 降序）、`price_asc`、`price_desc` |
| 收购 | `recent`、`bounty_desc`（按悬赏区间上界或托管意向高价降序） |

#### 2.3.5 URL 与 API 对齐

- **查询键（建议）**：`country`（`all` \| ISO）、`category`（`all` \| slug）、`sort`（上表枚举）。  
- **列表 GET（Target）**：`GET .../listings?country=JP&category=dining&sort=recent&cursor=` — 与 UI 同键，减少映射层。  
- **防抖**：子站与主 **`/market`** 列表 refetch 均为 **300ms** 防抖（**`useMarketStandaloneBusinessPage`** · **`useMarketPage`**）；子站 PG 行仍经 **`marketCatalogAdapter`** 成卡片形（① 维护项）。

#### 2.3.6 视觉（86 / 92）

- 容器：与 `MarketHubSubNav` 同级的 **玻璃横条** — `backdrop-blur`、细边框、`ring-ref-cyan` 轻光；**禁止**在金额/悬赏数字上使用强 glow（**92** 金融态）。

## 4. 链上用户旅程（与旅游对齐的 7 步）

以下适用于**商家成交单**与**收购履约单**：

1. **浏览**子站列表。  
2. **打开详情**：阅读多媒体、价格或悬赏、**协议摘要**（收购含验货标准）。  
3. **发起订单**：创建 `Order`，进入协议草稿。  
4. **双边确认协议**：双方签名 / 确认；生成协议版本与哈希展示。  
5. **绑定 Escrow**：部署或绑定合约地址；**仅在本订单 Escrow 详情页提示可充值**。  
6. **钱包 Approve + Deposit（USDC/USDT）**：遵循现有 tx 状态机（见 **35**）。  
7. **履约与里程碑举证 → Release / Dispute**：与旅游一致，争议走现有仲裁链路（**100**、**03**）。

**前端硬规则**：

- 列表页、详情页 **不得** 内嵌「向任意地址转账」；仅 **「打开托管详情」「去支付枢纽」** 等跳转到 **`/escrow/*`** 与 **`/pay`**。  
- **金额展示**：使用等宽数字；明确 **token 符号与链**；与 `pay_pageSubtitle_*` 类文案一致，防止用户提前充值。

## 8. 安全、合规与风控

- **禁限带与跨境**：收购详情固定展示**规则入口**；发布前勾选「已阅读风险提示」（审计日志 **120**）。

- **反欺诈（通用）**：与 **160** 社区治理衔接；商家 KYB **不** 替代收购发布风控。  
- **资金区 UI**：遵循 **92**：金额、合约地址、网络切换、交易状态为 **F 区（金融态）**，禁用强装饰动效误导。  
- **链下奢侈品真伪**：平台可插入「验货指引模板」，**不**构成鉴定结论；争议结果以协议 + 仲裁为准。
