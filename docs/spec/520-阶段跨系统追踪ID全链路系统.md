## 一、文档定位

本文定义 TravelTrust 在 520 阶段的“跨系统追踪 ID 全链路系统”开发规范。

520 阶段用于建立统一链路标识体系，打通前端到后端、异步任务、链上与运维后台的追踪关系。

## 二、建设背景

企业级排错与审计必须具备全链路追踪字段：

- `trace_id`
- `request_id`
- `order_id`
- `tx_hash`
- `job_id`

需要串联链路：

- 前端 -> 后端 -> queue -> indexer -> chain -> db -> admin

缺失统一追踪体系时，问题定位会变成手工拼日志，效率极低。

## 三、核心能力（必须具备）

必须具备：

- 全链路 ID 生成与传递规范
- 多系统日志统一关联
- 链上与链下事件关联查询
- 管理后台一键链路追踪

## 四、系统目标

1. 请求可串联：同一业务动作可完整追踪。
2. 故障可定位：快速定位失败节点与责任域。
3. 审计可复核：关键链路可导出追踪证据。
4. 观测可统一：日志、指标、事件共享追踪主键。

## 五、数据模型建议

建议最小实体：

- `trace_spans`
- `trace_links`
- `trace_contexts`
- `trace_errors`
- `trace_artifacts`

字段级要求：

- `trace_spans`：`trace_id`、`span_id`、`system_name`、`status`、`started_at`、`ended_at`。
- `trace_links`：`trace_id`、`request_id`、`order_id`、`tx_hash`、`job_id`。
- `trace_contexts`：`trace_id`、`context_type`、`context_value`、`captured_at`。
- `trace_errors`：`trace_id`、`system_name`、`error_code`、`error_message`。
- `trace_artifacts`：`trace_id`、`artifact_type`、`artifact_ref`。

## 六、后台模块要求

后台新增一级模块：`全链路追踪中心`

子模块（必须）：

- Trace 检索
- 链路拓扑
- 错误定位
- 证据导出
- 追踪统计

## 七、实施计划（520 阶段）

### 7.1 P0（必须）

- 统一 trace_id/request_id 传递规范。
- 接入后端、队列、索引器与管理后台。
- 打通 order_id/tx_hash/job_id 关联查询。

### 7.2 P1（增强）

- 前端到链上端到端拓扑可视化。
- 异常链路自动聚类与告警。

### 7.3 P2（规模化）

- 多区域/多集群统一追踪查询。
- 追踪数据与审计系统自动关联。

## 八、发布门禁

1. 核心业务链路可一键追踪。
2. 关键 ID 字段跨系统传递完整。
3. 异常定位时延满足运维目标。

## 九、结论

跨系统追踪 ID 是企业级可观测与排障基础设施。没有 520 阶段，复杂链路故障将持续高成本排查。
