## §1 `report.json` 作为发布准入输入（固定步骤 · **非**仅模板）

**问题收口**：若 **没有**固定流程把 **`evidence/GO_YYYYMMDD/report.json`** 接进发布前步骤，则 R-001 仍是「人工可填」，**不是放行系统**。

### 1.1 强制约定

| 步骤 | 动作 | 产出 / 门禁 |
|------|------|-------------|
| **S1** | 按 **93 §7** 跑回归，填 **§0.9** 环境四元组 | 单条用例目录 + 脱敏 HTTP |
| **S2** | 汇总 **`report.json`**（**R-001** 结构） | **`evidence/GO_YYYYMMDD/report.json`** |
| **S3** | **机读校验** | **`python scripts/validate-regression-report.py …/report.json`**（**通过才允许进入「已汇总」状态**） |
| **S4** | **Release Gate 判定** | 填 **`release_gate`** / **`release_gate_reason`**（**93 §7.1**） |
| **S5** | **发布决策会签** | **Release Owner**（产品与工程）在工单/PR **引用该 `report.json` 路径 + SHA256**（可选 `sha256sum` 侧车） |
| **S6** | **并入发版清单** | **`docs/go-live-checklist.md`** 对应勾选（见 **§1.2**） |

**硬规则**：**staging / prod 发布口径**须至少存在一份 **`report.json`**，其 **`environment.name`** 与目标部署一致或显式记 **PARTIAL_GO** 原因；**禁止**用 **local-only** 报告冒充 **staging 放行**。

### 1.2 与 `go-live-checklist.md` 的挂载点

在 **[go-live-checklist.md](../go-live-checklist.md)** **「冻结与范围」或发版并联段**增加勾选（由执行团队复制到清单正文）：

- [ ] **R-002** 本轮 **`evidence/GO_YYYYMMDD/report.json`** 已生成且 **`validate-regression-report.py`** **exit 0**。
- [ ] **`release_gate`** 与 **93 §7.1** 一致；**NO_GO** 已阻止合并/部署。
- [ ] （可选）**`sha256`** 已记入发布记录或 **evidence manifest**。

## §2 测试环境矩阵（Environment SSOT · **减少争论**）

**本表裁决**（与 **93 §0.9** 同字段）：*staging 是否必须 DB*、*chain_off 何时合法*、*缺失依赖记 BLOCKED 还是 N/A*、*何种结果可进发布口径*。

| `environment.name` | `database` | `chain_mode` | **是否允许作为发布口径主证据** | **说明** |
|----------------------|------------|--------------|----------------------------------|----------|
| **local** | disabled / enabled | chain_off / testnet | **否**（仅开发闭环）；可产 **report.json** 作 **PR 辅助** | 无 DB 时大量 **N/A** 正常 |
| **local** | enabled | testnet | **否**（预发前联调） | 可与 staging 交叉，**不**替代 staging |
| **staging** | **enabled** | testnet（或团队约定） | **是**（**主发布前 Gate 推荐环境**） | **DATABASE_URL** 与目标 schema **必须**一致意图 |
| **staging** | disabled | * | **否** | 不应用于宣称「可上线」 |
| **prod** | enabled | mainnet | **仅只读 / 影子验证** | **禁止**用种子账号写生产；结果 **BLOCKED/N_A** 为主 |

| 依赖缺失 | 建议五态 | **能否计入 GO** |
|----------|----------|-------------------|
| 邮件（验证/通知） | **BLOCKED** 或 **N/A** | **PARTIAL_GO** 须写明；**核心链路不依赖邮件**则可 **GO** |
| RPC / 钱包 | **BLOCKED** | **PARTIAL_GO**（**93 §7.1**） |
| Indexer / internal | **N/A**（用户域不测）或运维单跑 | **不**阻塞 **93 用户域 GO**（与 **93 §8.1** 一致） |

**chain_off**：**仅**在 **local/staging 工程约定**下用于 **mock-pay / 双写**验证；**生产**须 **`P3_CHAIN_OFF` 未误开**（见 **go-live-checklist §3.6**）。

### §2.1 R-003 实战铁律（防假 PASS · 与 **[R-003](R-003-Staging首次完整回归-A-B域-执行Runbook.md)** 互指）

**`validate-regression-report.py` 仅校验 JSON 结构与 Gate 枚举**；**不**能发现「HTTP 200 + 半配置 staging + 无 DB 持久化」类问题。执行 **staging 首次 A+B** 时 **必须**同时遵守：

| # | 铁律 | 摘要 |
|---|------|------|
| **1** | **无 DB 持久化佐证 → 无 PASS** | 至少一条写路径须能 **二次验证**（服务端再读 DB/审计与响应一致）；否则相关条 **BLOCKED/FAIL**，整轮 **最高 PARTIAL_GO**（见 **R-003 铁律 ①**） |
| **2** | **A 域先于 B 域** | **会话 / `/me` / 鉴权** 未 **100% PASS** → **禁止**同一 `run_id` 下继续 **B** 域（见 **R-003 铁律 ②**） |
| **3** | **首份 `report.json` 可审计** | **`environment`** 四元组与进程一致（**禁止**实际 `chain_off`、报告写 `testnet`）；**FAIL/BLOCKED** 须有 **`notes`**（见 **R-003 铁律 ③**） |

## §5 社区富媒体 / 对象存储 / 签名 URL（业务未知点 · **非硬闭环**）

**现状**：**D-COM-*** 覆盖 Feed/帖/评/私信主路径；**视频 / 大附件 / 对象存储 / 签名 URL 长链回读 / 账户归属** 仍可能「看起来能用、实际半通」。

## §6 机读校验命令（放行闸）

