## §0 全局约定（所有域共用）

### 0.1 执行顺序（固定）

1. **ENV**：健康检查、元数据、构建号、`DATABASE_URL` / `chain_off` 等环境真值。  
2. **正向主链**：按产品主路径打通（先读后写、先创建再流转）。  
3. **负例**：鉴权、权限、非法参数、幂等冲突。  
4. **扩展项**：性能、观测、跨浏览器 — 记 **N/A** 或 **NOT RUN**，勿与主链 **PASS** 混算。

### 0.2 结果五态（汇总口径 · 固定）

| 状态 | 含义 |
|------|------|
| **PASS** | 判据全部满足；**HTTP + 持久化**（若该用例声明 DB）证据齐全。 |
| **FAIL** | 任一硬判据不满足（含证据缺失视为 FAIL）。 |
| **BLOCKED** | 环境或外部依赖不可用（RPC、邮件、第三方、只读生产策略等），**已记录原因**。 |
| **N/A** | 本环境**不适用**（例如本域未部署某功能、角色未开通）；**不是**失败。 |
| **NOT RUN** | 本轮**未执行**（排期或裁剪）；总表统计时**单独计数**，勿记入 PASS。 |

### 0.3 认证载体（本轮必记 · 禁止混算）

执行时**必须**在「运行记录」中写明本环境实际采用的会话载体，至少一项：

- **Cookie（HttpOnly 会话）**
- **Bearer（Authorization 头）**
- **混合**（例如登录接口返回 body token、后续请求走 Cookie — **按实际**）

**规则**：若 **staging** 为 Cookie、**dev** 为 Bearer，**分别**记 PASS/FAIL，**禁止**合并为一条跨环境 PASS。

### 0.4 自动化优先级（每条用例一列）

| 标记 | 含义 |
|------|------|
| **AUTO-P0** | 优先做成 **API / E2E** 自动化（稳定、可门禁）。 |
| **MANUAL-P1** | 先人工执行或半自动（需业务判断、多步 UI）。 |
| **MANUAL-BLOCKED** | 依赖 **外部邮件 / 只读生产 / 不可控第三方**，默认不纳入 CI 硬门禁。 |

### 0.5 最小证据集（「够硬」标准）

每条用例至少保留：

1. **HTTP**：方法 + 路径 + **状态码**；响应体保留 **脱敏** 副本（抹去 token、邮箱、手机号等）。  
2. **持久化**（若适用）：**一条**可复核的 DB 查询或 API 再读（`GET` 回读）证明写入生效。  
3. **留痕路径**：`evidence/GO_YYYYMMDD/<域>-<用例ID>/` 下 `request-response.redacted.json`、`notes.md`；DB 则 `query.txt` + 结果摘要。  
4. **汇总索引**：同目录 **`report.json`**（**§0.10**、**[R-001](R-001-全站回归报告模板与汇总JSON结构.md)**）。

### 0.6 多维度深度检查（发版抽检用 · 与用例正交）

执行单条用例时，**至少**勾选下列维度中与本条相关的项；**全站轮次**建议在 **§6** 做横切抽检。

**优先级（与 Release Gate 对齐）**：**P0 必检** — **①②③**（契约 HTTP、持久化/投影、RBAC）；**P1 建议** — **④⑤⑥**（UI/i18n、F/X/G、可观测）。**NO GO（§7.1）** 主要由 **①②③** + **A/B 核心链路** 失败驱动。

| 维度 | 优先级 | 检查什么 | 不合格典型 |
|------|--------|----------|------------|
| **① 契约 HTTP** | **P0** | 方法/路径/状态码/**`error` 码**与 **04 §3.4**、`/meta` 规则一致 | 未文档化 500、错误体无 `error` |
| **② 持久化 / 投影** | **P0** | 写后 **GET 再读** 或 **DB** 或 **链上 read** 与 API 一致 | 内存-only 冒充落库 |
| **③ RBAC / 参与方** | **P0** | 旅行者/向导/Admin/**未登录** 行为符合 **13-1 表 2**、**87** | 跨用户读订单、Admin 无审计 |
| **④ UI / i18n** | P1 | 关键文案 **`locales`** 键存在；**loading / empty / error** 三态可辨 | 白屏、键名外露 |
| **⑤ 分区 F/X/G** | P1 | 页面动效/粒子/银行级克制符合 **[92](92-P0-全站UI分区控制表-金融体验灰区与动效裁决.md) §四** | 资金页强 glow、Experience 页误用银行密度 |
| **⑥ 可观测** | P1 | 响应含 **`x-request-id`**（若部署启用）；争议/支付有留痕 | 无法关联日志与请求 |

### 0.9 环境标识（每轮 **必须**记录 · **禁止**跨环境合并统计）

**规则**：**不同 `environment` 下同一用例的结果不得合并为一条 PASS/FAIL**；总表、**PASS 比例**、**Release Gate（§7.1）** 均 **按单次运行、单一环境** 判定。

| 字段 | 取值 | 说明 |
|------|------|------|
| **`environment`** | `local` / `staging` / `prod` | 本轮主测环境 |
| **`database`** | `enabled` / `disabled` | **`DATABASE_URL` 可用且写路径生效** → `enabled`；纯内存/无 PG → `disabled` |
| **`chain_mode`** | `chain_off` / `testnet` / `mainnet` | 与 **`GET /meta.chain`**、部署一致 |
| **`auth_mode`** | `cookie` / `bearer` / `mixed` | 与 **§0.3** 一致；**须与本轮请求真值一致** |

**典型误判**：**local**（无 DB）某用例 **PASS**，**staging**（有 DB）同用例 **FAIL** —— 结论为 **staging 真问题**，**不得**用 local PASS 抵消；应分别写入两份 **`report.json`**（**R-001**）。
