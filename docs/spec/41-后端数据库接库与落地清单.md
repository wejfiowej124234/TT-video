# 41 - 后端数据库接库与落地清单

**用途**：自文档 41 阶段起，将**后端数据库接库、迁移、表完整性与分布式 DB 兼容**整理为可执行、可勾选清单；与 [数据库表与UI功能对照检查](../数据库表与UI功能对照检查.md)、[04-附录-DDL草案](04-附录-DDL草案.md) 一致，支撑接库后 UI 全部功能（除可选行程/聊天持久化外）落库。

**迁移单源**：**仅** `crates/api/migrations/` 下 SQLx 时间戳 `.sql` 文件。历史文档与 [27-archived](27-archived/README.md)、[archive](archive/README.md) 中出现的 `migrations/001_initial.sql` 等路径已废弃，勿再作为执行依据。

**受众与用法**：后端、运维；接库时按 §二～§四 逐项执行并勾选；可与 [41-后端数据库接库与落地清单](41-后端数据库接库与落地清单.md)、27-P41 阶段说明一并使用。

### 与开发进度的关系（是否该这一步了）

| 条件 | 说明 |
|------|------|
| **文档序列** | 32 中 33～40 为前端/运营九项（页面→组件→DApp→测试→i18n→性能→上线前 UI→内容）；**41 为 40 之后的后端接库阶段**，与 34～40 无强依赖，可与 40 并行或 40 闭环后执行。 |
| **后端现状** | 迁移（5 支）、`db.rs` 双写与 hydrate、chain_off 已就绪；**仅缺**配置 `DATABASE_URL` 与执行迁移，无前置代码缺口，**符合「该这一步了」**。 |
| **何时做 41** | ① 40 已就绪或进行中、准备接库/上线前持久化；② 或 34～39 已基本完成，后端可单独推进 41（与 40 并行）。发版前若需数据落库，41 应在 P14 发版前勾选前或同期完成。 |

**结论**：当前项目具备做 41 的条件（迁移与 db 层已有、UI 与 API 已跑在内存）；若你处于 40 或 39/40 阶段，或准备上线/持久化，**现在做 41 符合开发进度，可以执行**。

## 三、后端数据库接库与落地勾选总表

接库时按下列块逐项执行并勾选；§三.1～三.3 通过即 41 核心闭环；§三.4 为可选。

### 3.1 环境与迁移

| □ | 验收项 | 完成标准 |
|---|--------|----------|
| ☐ | 配置 DATABASE_URL（PostgreSQL 或 CockroachDB） | .env 或环境变量已设；API 启动可连库 |
| ☐ | 执行全部迁移（含 users_sessions、guides、orders、reviews_disputes、itineraries、order_messages、community_*、community_feedback、idempotency_keys、governance、evidence_receipts、orders_guide_id_nullable 等） | API 启动时自动执行（`migrator.run`）；或 `cd crates/api && sqlx migrate run`；无报错；55-S14 与 04 同步 |
| ☐ | 启动 API 后 hydrate 正常（list_users/list_orders 等无错、内存与 DB 一致） | 日志出现 `database: connected and migrations applied` 及 `database: hydrated N users, ... itineraries, ... order_messages into chain_off`；无 db 报错；可选：重启后数据仍在 |

**执行备注**：迁移文件见 `crates/api/migrations/`（**以目录内实际 `.sql` 文件为准**，含 users_sessions、社区、治理、admin、schema_evolution 等；数量随迭代增加，不必与旧文「16 支」硬对齐）。与 [55-阶段-数据同步与数据库功能同步](55-阶段-数据同步与数据库功能同步.md) §1.2 对照时，以**本目录清单**为最新。API 启动时若已设置 `DATABASE_URL`，会先建池再自动执行 `migrator.run`，无需单独跑 `sqlx migrate run`。接库步骤见 [测试账号与本地联调 §五、数据库接库（阶段 41）](../测试账号与本地联调.md#五数据库接库阶段-41)。
