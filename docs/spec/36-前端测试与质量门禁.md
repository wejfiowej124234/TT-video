## 二、测试范围与层级（01 三项）

以下对应「单测、集成、E2E」三层；前端侧以 34 组件、35 DApp 行为、33 页面为对象。

### 2.1 单测（Unit）

| 对象 | 验收要点 | 参考 |
|------|----------|------|
| **34 组件** | 关键组件能渲染、必要 props 与 children 正确；无崩溃、无禁止类名（可选：快照或类名断言） | 34 §3 组件清单 |
| **DApp hooks** | `dapp/hooks`（如 useEscrowActions）在 mock 环境下行为正确：参数校验、状态迁移、错误处理 | 35、06 |
| **工具/格式化** | 金额、地址、链 ID 等格式化函数；小数位、最小单位与 22/05 一致 | 22、05 |
| **禁止类名** | 可选：脚本或单测断言「指定目录下不出现 text-gray-*、text-blue-*、裸 bg-white（例外除外）、rounded-md 等」 | 34 §2.1、§5.3 |

### 2.2 集成（Integration）

| 对象 | 验收要点 | 参考 |
|------|----------|------|
| **页面 + API** | 关键页（Landing、Market、Escrow Detail）在 mock API 下能加载、展示订单/托管状态、不报错 | 04、33 |
| **路由与布局** | 33 所列路由可访问；Header、布局与 13-1 表 1 一致 | 33、13-1 |
| **钱包态与链操作入口** | 未连接/错链时 Escrow Detail、付款步等不展示敏感按钮；连接后操作入口可见（可 mock 钱包） | 35、13-1 §四 |

### 2.3 E2E（端到端）

| 场景 | 验收要点 | 参考 |
|------|----------|------|
| **01 核心流程** | 游客下单 → 向导接单 → 游客 deposit 进 Escrow → 双签/超时 release → Completed；可选：争议路径至终态 | 01 §1、07 |
| **关键路径** | Landing 可进、Market 可切换订单/向导、Escrow Detail 可打开并展示状态与操作区 | 33、13-1 |
| **53 阶段扩展路径** | 53 阶段：订单/双边确认/评分路径（抢单、确认接单、双边确认、评分页、orders/messages）须有 E2E 或集成覆盖；详见 [53-阶段开发技术文档](53-阶段开发技术文档.md) §六附续。 | 53 §六附续、U4 |
| **13-1 异常态覆盖** | 见 §三；未连接、错链、allowance 不足、disputeWindow 过期、reorg 提示等有明确表现并可验证 | 13-1 §四、35 §2.4 |

## 三、13-1 异常态用例清单（必须覆盖）

以下异常态在 13-1 §四、35 §2.4 中规定；36 须确保**有测试或走查用例**能验证其表现。

| 异常态 | 表现要求 | 测试/走查方式 |
|--------|----------|----------------|
| 钱包未连接 | 明确提示 + 连接入口，不展示敏感操作 | E2E 或集成：未连接下进入 Escrow Detail/付款步，断言无「支付/确认/争议」主按钮或为禁用态 |
| 链不对 | 提示切换网络、显示当前 chainId | E2E 或集成：切到非目标链，断言有切换网络提示、链操作禁用或隐藏 |
| USDC allowance 不足 | 提示授权、引导 approve | E2E 或集成：mock allowance 不足，断言有授权引导与不直接发起 deposit |
| OFAC/冻结命中 | 风控提示、不执行交易 | 与后端/合约一致；前端可做 mock 或文档化验收 |
| disputeWindow 过期 | 明确「已过争议窗口」、不可再发起争议 | 集成或 E2E：过期订单 Escrow Detail 上争议按钮禁用或文案为「已过争议窗口」 |
| reorg/replay 回滚 | 提示「链已回滚，状态已更新」、引导刷新或重试 | 有 reorg 策略时，前端展示提示与刷新入口；可走查或 mock 事件回退用例 |

## 四、验收勾选表与门禁标准

实现或回归时按下列项勾选；**全部通过**视为 36 质量门禁满足，可作为 P8/P10 输入。

### 4.1 单测

| □ | 验收项 | 核对方式 |
|---|--------|----------|
| ✓ | 34 关键组件（如 TrustBadgesRow、StatusBadge、EscrowDetail、WalletStatusMini）有单测或渲染测试 | 查看 `**/*.test.{ts,tsx}` 或等价 |
| ✓ | DApp 相关 hooks（如 useEscrowActions）在 mock 下有单测 | 覆盖正常/异常分支 |
| ✓ | （可选）禁止类名脚本或断言存在且通过 | 34 §2.1、§5.3 |

### 4.2 集成

| □ | 验收项 | 核对方式 |
|---|--------|----------|
| ✓ | 关键页（Landing、Market、Escrow Detail）在 mock API 下可加载、无报错 | 集成测试或手工 + 清单 |
| ✓ | 未连接/错链态下，链操作入口不展示或禁用 | E2E：core-path 中「Escrow 页未连接钱包时不展示 Deposit/Release 主按钮」；错链走查 |

### 4.3 E2E

| □ | 验收项 | 核对方式 |
|---|--------|----------|
| ✓ | 至少一条核心路径 E2E 可跑通（如 Landing → Market → Escrow Detail 打开） | e2e/core-path.spec.ts |
| ✓ | （发版前）01 核心流程：下单→接单→deposit→release→Completed 或争议路径有 E2E/演练 | e2e/release-flow.spec.ts 页面结构可跑通；真实 deposit/release 需测试网或 mock 后端 |

### 4.4 异常态

| □ | 验收项 | 核对方式 |
|---|--------|----------|
| ✓ | 13-1 §四 六类异常态均有对应用例或走查项（未连接、错链、allowance、OFAC、disputeWindow、reorg） | §三 清单逐项有测试或走查记录 |

### 4.5 门禁标准（P8/P10）

| 门禁 | 36 贡献 |
|------|----------|
| **P8 Phase 4 门禁（一）** | 34 组件与 Tokens + **36 前端测试**：单测/集成覆盖关键组件与页面，禁止类名与异常态有清单或用例。 |
| **P10 Phase 4 门禁（二）与 E2E** | **36 E2E 与异常态**：至少一条 E2E 路径通过；13-1 异常态覆盖有用例或走查；可与 38 性能一并作为 P10 输入。 |

### 4.6 53 与 36 交叉确认（收口时勾选）

| □ | 验收项 | 核对方式 |
|---|--------|----------|
| □ | **53 订单/双边/评分路径**在 36 门禁或用例中已覆盖或已引用 53 | 53 阶段：抢单、确认接单、双边确认、评分页、orders/messages 在 §2.2 集成、§2.3 E2E 中有对应用例或已引用 [53-阶段开发技术文档](53-阶段开发技术文档.md) §六附续；**frontend/__tests__/integration/** 下 53-bilateral-accept、53-rating-messages、**53-orders-messages**、及 components/escrow **OrderFlowSteps.integration** 已实现。收口时**与 36 维护人确认**上述路径在门禁或用例中已覆盖或已引用 53，后在 [53-收口验收清单](53-收口验收清单.md) §六附续 §4「36 门禁」行勾选。 |
