## 1. 为何单独成篇

**R-003** 刻意 **收窄**为 **A+B** 与 **首轮真环境证据**，避免第一次就把 **社区富媒体、对象存储、Admin 全量** 绑进同一跑道导致 **假 PASS** 或范围失控。**R-004** 把「R-003 完成之后自然展开的第二段」写成 **单一入口**，便于排期、互指与 **R-002 §4** 持续补齐。

## 2. 推荐顺序（第二阶段流水线）

| 顺序 | 主题 | 说明 |
|:----:|------|------|
| **1** | **C 域（社区）** | 按 **93 §3** 跑 **社区主路径**（Feed / 帖 / 评 / 私信等）；与 **31 / 04 §3.4 `/community/*`** 对齐；产出 **`cases[]`** 与证据目录。 |
| **2** | **富媒体专项** | **视频 / 大附件 / 对象存储 / 签名 URL / 刷新后回读 / 账户归属 / 删除与编辑权限**；业务风险与 **Gate 口径**见 **R-002 §5**、规格 **[270](270-阶段文件媒体证据存储系统.md)**；可单独 **`report.json` 附录** 或 **下一轮 `run_id`**，避免与 **R-003** 报告混写。 |
| **3** | **Admin 深度验证** | 按 **93** Admin 抽检与 **[70](70-管理员系统开发文档.md)** 路由/审批/审计要求做 **深度**（非 R-003 的「不纳入必达」级别）；高危写路径须有 **双人/审计** 留痕意识。 |
| **4** | **自动化补齐** | 回填 **[R-002 §4](R-002-回归执行闭环与发布准入.md)**：**用例 ID ↔ `crates/api` / E2E**；**AUTO-P0** 与真实资产对齐，防「文档写了无人维护」。 |

## 3. Gate 与报告策略

- **C / 富媒体 / Admin** 的 **`release_gate`** 仍服从 **[93 §7.1](93-全站功能验证矩阵-域别回归清单.md)**；富媒体未闭环时 **不得**单独把整轮打成 **NO_GO** 若核心交易链路已绿 —— 与 **R-002 §5** 一致，**必须**在 **`release_gate_reason`** / **`cases[].notes`** 写清 **已知风险**。  
- **D 域**（若本轮纳入）仍建议 **只读/影子** 口径，与 **93**、**R-002 §2** 一致。

## 4. R-004 阶段性完成条件（硬门槛 · 四项 + 自动化阈值）

满足 **全部**下列项后，**才允许**将 **R-004** 标记为 **「阶段性完成」**（仍可在 **[R-002 §4](R-002-回归执行闭环与发布准入.md)** 继续迭代 **AUTO-P1** 等）。

| # | 条件 | 合格标准 |
|---|------|----------|
| **C1** | **C 域核心链路** | **发帖 → 评论 → 私信** 三条串联在 **staging**（或与发布口径一致的环境）上 **全部为 `PASS`**（**93** 对应用例 **`cases[]`** + 证据目录）。 |
| **C2** | **富媒体最小闭环** | **至少一条**端到端：**上传 → 存储 → 回读 → 权限校验**（与 **R-002 §5**、**[270](270-阶段文件媒体证据存储系统.md)** 对齐；**`notes`** 写清对象存储/签名 URL 等事实）。 |
| **C3** | **Admin 核心子域深度验证** | **L2 / L4**（与 **[70](70-管理员系统开发文档.md)** 分层一致）各完成 **至少一次**「深测」（非浅层 200）：审批/审计/高危写路径按团队 Runbook 留痕。 |
| **C4** | **AUTO-P0 覆盖率** | **[R-002 §4](R-002-回归执行闭环与发布准入.md)** 中 **AUTO-P0** 用例，**已自动化覆盖**比例 **≥ X%** —— **`X`** 由团队书面定义（建议记入 **`release_gate_reason`** 或 **`evidence/…/r004_completion_notes.md`**），**未定义 X 则本项不闭合**。 |

**报告策略**：可 **单独** **`report.json`**（**`run_id`** 建议含 **`R004`**）或在 **`cases[]`** 中显式区分 **R-003** 与 **R-004** 轮次；**`validate-regression-report.py`** 仍须对 **汇总报告** 通过（若团队拆多文件，**至少**有一份 **汇总** 机读闸通过）。
