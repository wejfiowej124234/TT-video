# Spec Conflict Resolution · 规范冲突处理

**Version:** 1.0.0  
**Status:** `Target`  
**上位 SSOT**：[00-Spec-Constitution-规范宪法.md](00-Spec-Constitution-规范宪法.md)  

## 1. 总则

- **任何冲突**先查 **宪法** 的 **P0 / P1 / P2** 表与 **冲突规则**。  
- **不得**用 **86** 单篇覆盖 **04 / 13 / 13-1** 已定义的路由、资金模型或页面契约。  
- **灰区**（例如 **`/market`**、**`/traveltrust`** 上 Experience vs Business 边界）：以 **[92](92-P0-全站UI分区控制表-金融体验灰区与动效裁决.md)** 与 **[86 §0.3](86-UI-双系统未来风-风格与动效技术规格.md)** 为准；仍不清 → **升级** 到 **13 产品/协议宪法** 修订议程（同批改 **13-1 / 86**）。

## 2. Case：86 vs 13（资金区 / 动效）

| 情形 | 处理 |
|------|------|
| 动效或视觉出现在 **13 §一** 定义的 **资金区**（及 **86 §0.3** Protocol/资金行、**92** F 区） | **以 13 + 92 为准**；**拒绝** **86** 中与之矛盾的装饰/粒子/强动画条款。 |
| 需求在 **营销 / 非资金叙事壳**（**86** 允许的 Experience 分区，且 **92** 为 X 或明确允许的 G） | **可用 86**；仍 **不得**改 **04** 路由与 **13-1** 信息架构。 |
| **86 某条** 与 **04 §3.4** 路由表冲突 | **以 04 为准**；改 **86** 或删误写。 |
| **86 某条** 与 **13-1** 页面/状态机冲突 | **以 13-1 为准**；改 **86** 或走 **13-1** 变更流程。 |

## 3. Case：86 vs 13-1（页面与交互）

- **页面是否存在、路径、RBAC、异常态** → **13-1** 为 **P0** 产品级 SSOT。  
- **外观、动效、Token 外观映射** → **86（P1）** 在 **92** 允许范围内补充。  
- **冲突** → **13-1** 胜；**86** 修订 **Scope** 或分区表述。

## 4. Case：体验增强 vs Tokenomics / 83·84

- **分配比例、Region、FeeRouter、金库叙事** → **83 / 84** 等与 **08** 相关契约为准（**P0 域**）。  
- **86** 仅可定义 **展示层**（图表样式、排版）；**不得**定义新比例或「覆盖」链上参数。  
- **冲突** → **回退 86**；若需改经济真源 → **走经济规格与 07 发版链**。

## 5. 升级路径（必须记录）

1. 在 PR / 工单中 **点名冲突文档与条款**（文件名 + 章节）。  
2. 标明 **拟采信层级**（P0 / P1）及 **是否需同批改多篇**。  
3. 若动 **04 / 13 / 13-1 / 07** → 遵守 **[CONTRIBUTING.md](../../CONTRIBUTING.md)** 与 **07 §二 2.4** 等流程。
