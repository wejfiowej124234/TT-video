## 一、总目标

治理 UI 须**同时**满足：

1. **普通持币人**能读懂「在决定什么、与旅游业务的关系」  
2. **区域运营 / 服务商 / 向导 / 旅行者** 等业务关切与 **治理代币（TTG）持有人** 能进入**适合自己视角**的治理界面，且只看到**有权看、有权做**的内容（见 **§五**；**注册与多身份**见 **§5.0**）  
3. **链上真实提案**可**发起**（在阈值与权限允许时）、可投票、可追踪 **queue → Timelock → execute**（与 B-417 证据语义一致）  
4. **每条提案**在详情页提供 **「通过后影响分析」**（国家/区域、资金池、角色、下单/结算/信用），从「能看」升级到「真能理解」（见 **§六**）  
5. **移动端**具备可执行的折叠与主路径，旅游场景下仍可完成「看提案—投票—看结果」（见 **§七**）  

一句话：**全球旅游网络的链上治理中枢**（全链路：发起—审议—投票—执行—影响可解释），而非论坛型「投票列表页」。

| 路径 | 职责 |
|------|------|

## 三、整体视觉风格

与项目 **旅游 + Web3 + 高端科技 + 全球市场** 一致，并与 **86 / 22** 可共存：

- **主色**：深蓝 / 紫蓝，**点缀**金色（强调状态、CTA）  
- **背景**：深色科技风；可轻量粒子或流光线条（**须**符合 **13** 资金区隔离：投票/签名区保持银行级清晰，不动效干扰确认）  
- **卡片**：半透明玻璃拟态 + 细发光边框（与 **28** 叙事组件可复用变体）  
- **气质**：**国际治理指挥台** — 数据密度高、层级清晰，避免论坛贴列表  
- **移动端**：同一套 Token；**密度降级**见 **§七**，**不**单独搞一套「简化品牌」  

图标语义建议：**提案**卷轴/文件、**区域**地图/地球、**金库**金库/资金池、**投票**权杖/印章、**DID**徽章/身份牌。

## 四、提案创建器（满分必备）

**定位**：从「只读治理」升级为**完整治理闭环**；**须**与链上 **`propose` 门槛**（持币量、阈值）与 **Timelock 目标合约 ACL** 一致，**禁止** UI 绕过链上 revert 条件。

### 4.1 路由与入口

- 主入口：**`/governance/proposals/new`**  
- 列表页顶栏 **「发起治理提案」**、首页 Hero 次要 CTA（若用户满足门槛）  

### 4.2 创建流程（推荐分步向导）

| 步骤 | 内容 | 说明 |
|------|------|------|
| 1. 选择模板 | 平台参数 / 区域 / Treasury / DID / 紧急 | 与 **§九** 模板一致；模板决定表单字段与默认 **target** 范围 |
| 2. 填写人话信息 | 标题、摘要、业务标签 | 用于列表展示与 **影响分析** 初稿；可落链 **description** |
| 3. 链上动作配置 | 目标合约、方法、参数 | **高级模式**可切换为 **十六进制 calldata**；普通模式用 **方法选择器 + 表单** 生成 **calldata** |
| 4. Calldata 可视化 | 解码展示 + 原始 hex 折叠 | `ProposalActionTable` 的「编辑态」；与详情页「链上动作」同源组件 |
| 5. 风险预览 | 影响范围、权限、资金量级 | 调用 **§六** 规则引擎或静态规则：是否动金库、是否改费率、是否影响多区域 |
| 6. 模拟与提交 | `eth_call` 模拟（若适用）、钱包 **`propose`** | 失败时展示 **revert 原因**（可读化） |

### 4.3 权限与降级

- 未达 **proposalThreshold**：页面仍可达，但 **提交** 置灰并解释 **链上要求**  
- **多操作提案**：若 Governor 限制单操作，UI **须**与合约一致（与 **contracts** 实现同步）  
- **仅运维/多签** 的合约：**禁止**在创建器里选为 target（或标红 + 强制二次确认）

## 五、角色视图分层（满分必备）

**问题**：单一控制台难以同时服务 **治理代币（TTG）持有人、区域运营方、服务商、向导、旅行者** 以及 **地区代理商（区域服务商准入）** 与 **金库/分账只读关切** 等不同读者。  
**方案**：在 **统一 IA** 之上增加 **「视角（Persona）」层** —— 同一套页面，**默认模块排序、默认筛选、可操作项** 随视角变化。

### 5.0 注册身份与治理视角（与本系统模式对齐）

- **推荐结论**：**产品上「分身份」**（注册与业务权限清晰），**链上治理数学「不分身份」**（投票权仍由 Governor / Votes 合约决定，见 **§5.2**）；治理 UI 在二者之间加一层 **可读视角**，而不是再做一套平行账户体系。  
- **注册与多身份**：**注册列表 / 首登首屏** 以 **旅行者** 为唯一默认入口；**右上角用户头像** 提供 **追加身份申请**（服务商、向导等），**同一用户**可叠加 **旅行者 + 服务商 + 向导** 等。**治理页** 可将 **`getMe()` 已开通身份** 与 **「与我相关」**、默认筛选联动（例：已认证向导则向导类提案可优先展示，可开关）。  
- **「投资人」在产品语言中的含义 = 地区代理商**：指 **个人或公司** 在 **已注册旅行者** 之后，通过 **多重身份申请** 争取 **某地区的区域服务商 / 地区运营席位**。**申请条件**（产品规则，与 **83/84**、运营配置一致落地）包括：**所连接钱包** 在该产品上满足 **该区域规定的治理代币（TTG）持有量（或等效门槛）**；名额可采用 **先到先得**。**对外文案** 统一使用 **地区代理商** / **区域服务商（准入）**，**不**对用户称「投资人」，避免与泛金融募资混淆。  
- **与后端路由名的关系**：**04** 中仍可能存在 **`investor-*`** 等 **链上经济/分账** 路径名（如应计分录、份额对账），**实现与审计**沿用仓库命名；**前端展示** 与 **本规格** 用语以 **地区代理商、金库、分配** 为准，二者不必逐字相同。  

### 5.1 视角与默认首页模块（含地区代理商）

| 视角 | 核心诉求 | 默认强调模块 | 操作边界（示例） |
|------|----------|----------------|------------------|
| **治理代币（TTG）持有人** | 投票权、收益相关提案 | 待投票、Active、金库/费率类 | 投票、发起（达阈值） |
| **区域运营 / Region Steward 叙事** | 本区域规则与收益 | 区域页、`与我相关`=区域 | 只读 + 投票（若持币） |
| **服务商** | 准入、抽成、处罚规则 | DID/服务商类提案、影响分析 | 只读为主 |
| **向导** | 评级与订单规则 | DID、review window、争议窗口 | 只读为主 |
| **旅行者** | 是否影响下单/退款 | 低打扰：仅「影响旅行者主路径」类提案高亮 | **未持治理代币（TTG）时**无链上投票权；可看公开提案、影响说明与教育内容 |
| **地区代理商（区域服务商准入）** | 本区域规则、名额、金库与分润叙事 | 区域、Treasury、与 **该地区** 相关的提案与 **影响面板** | **先旅行者**→**申请该地区身份**；**钱包**满足 **该区域治理代币（TTG）门槛**；**先到先得**；详见 **§5.0** |
| **金库·分账只读（财务/合规关切）** | 应计/分配、链上数据对拍 | **`GET …/governance/*`** 中与 **04 §3.4** 一致的只读页（如 **distribution** 叙事） | **非**独立注册身份；与 **地区代理商** 业务流程可交叉展示，**职责**分开 |

### 5.2 与治理代币 TTG（链上投票权）的关系

- **链上真值**：投票权重、法定人数、提案门槛等，**以 Governor / VotesToken（或等价）合约为准**；**UI 角色不改变**地址在快照点的 **`getPastVotes` / 委托** 等计算（**除非**未来合约层单独实现「角色系数」——本文 **Target** **不**预设该能力）。  
- **同一地址多角色**：若某钱包**既**是 **旅行者** **又**持有治理代币（TTG），链上仍按**持币规则**享有 **propose / vote**；**旅行者视角**只做 **信息优先级**（例如先突出影响下单/退款的提案），**不削减**链上权利。  
- **同一账号多身份（旅行者+服务商+向导）**：链上投票仍只看 **钱包地址** 与 **快照权重**；UI 可将 **已开通身份** 用于 **「与我相关」** 标签与默认排序，**不**引入第二套投票计数。  
- **地区代理商申请门槛与投票权**：某区域要求的 **治理代币（TTG）持有量** 用于 **准入/名额**（产品规则），**不**自动等同于「另一套票数」；若与 **Governor** 使用 **同一 TTG**，用户可能 **同时**满足 **申请门槛** 与 **投票快照**，但 **计票** 仍 **只**按 **Governor / `getPastVotes`**（及委托规则），**不在 UI 层按身份加倍或扣减**。  
- **无币的旅行者 / 向导 / 服务商**：可进入治理区阅读与 **影响面板** 理解风险；**投票 / 发起** CTA **须**与链上可读条件一致（未连接、无权重、非 Active 等**分因展示**）。  
- **产品好处**：降低误操作与客服解释成本；让持币人更快看到与**收益/区域**相关的票；让非持币参与者理解「治理改什么」而不误以为「点一下就算投票」。
