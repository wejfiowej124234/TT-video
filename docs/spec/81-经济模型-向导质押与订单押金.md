## 1. 原始设想与结构模型分析

### 1.1 原始设想

- **向导身份押金**：1000U（长期锁仓）
- **每笔订单再质押**：订单金额的 **30%**

### 1.2 结构模型分析（锁仓量）

| 订单金额 | 身份押金 | 订单质押（30%） | 总锁仓 |
|----------|----------|-----------------|--------|
| 2000U    | 1000U    | 600U            | 1600U  |
| 5000U    | 1000U    | 1500U           | 2500U  |
| 10000U   | 1000U    | 3000U           | 4000U  |

**多单叠加**：向导同时接 3 单、每单 3000U 时，单单押金 = 900U × 3 = 2700U，加身份押金 1000U，**总锁仓 = 3700U**，对中等向导已非常重。

---

## 2. 五维度评估（安全性、流动性、激励、可扩展性、现实落地性）

### 2.1 30% 比例过高

- **现实世界**：Airbnb / Uber / Freelancer 等**不需要**押金。
- **Web3**：多数 escrow 项目押金在 **5%～15%**；**30% 属于高风险行业级别**。
- **后果**：向导难以承接大额订单；高端向导流动性被锁死；**规模上不去**。

### 2.2 身份押金 + 单单押金叠加

- **双层锁仓**：1000U 长期 + 每单 30% 短期。
- 多单并行时总锁仓快速上升，供给侧（向导）压力大，接单率与可接单规模受限。

### 2.3 安全性是否真的提升？

- 例：订单 2000U，向导押 600U；若向导爽约，平台可罚 600U，但游客损失可能包含**时间、预订酒店、机票变更**等，**600U 未必覆盖真实损失**。
- **结论**：押金比例高 ≠ 风险完全可控；需结合争议裁决、风险池等综合设计。

---

## 3. 问题总结

| 问题 | 说明 |
|------|------|
| **30% 过高** | 限制供给、降低接单率、压缩高端市场；与行业惯例（5%～15%）不符。 |
| **双层锁仓过重** | 身份 + 多单单笔押金叠加，中等向导总锁仓压力大。 |
| **押金≠覆盖全部损失** | 单单押金主要起约束与部分赔偿作用，真实损失需争议规则与风险池等补充。 |

## 4. 推荐模型（可规模化）

以下为**更合理、可规模化**的设计建议，供产品与风控定稿。

**实现注记**：链上 `Staking.sol` **现状**（`MIN_STAKE`、`slasher`、无按单 bps）以 [08-3-参数与门禁表](08-3-参数与门禁表.md)、[14-合约-API-ABI-前后端对齐](14-合约-API-ABI-前后端对齐.md) §1.1 为准；**§4.2～§4.4** 比例/Cap/信誉档位为**设计先行**，落实须改合约或后端 enforcement 并回填 **08-3 / 14**。**`slash` 罚没归宿**与 FeeRouter **正交**，见 [84 §1.1.1](84-第一阶段10国Country-Pool发行参数总表.md) 与 [Runbook §7.1](../../ops/RUNBOOK.md)。

### 4.1 向导身份押金：1000U（维持）

- **作用**：防止垃圾注册、基础安全保证、提升平台信用。
- **建议**：
  - 可部分解锁（规则与冷却期由 08-3/合约定）；
  - **解押冷却期 7～30 天**（与 01 一致）；
  - 严重违约可扣罚身份押金。

### 4.2 订单质押：10%～15% 更合理

| 类型         | 建议比例     | 说明                     |
|--------------|--------------|--------------------------|
| 普通订单     | **10%**      | 与行业 5%～15% 对齐      |
| 高风险订单   | **15%**      | 可按金额/目的地/新向导等 |
| **上限**     | **不超过 20%** | 30% 过于激进，不推荐     |

### 4.3 押金上限 Cap（重要）

- **公式**：订单质押 = **min(订单金额 × 比例, Cap)**  
- **示例**：`min(订单金额 × 15%, 2000U)`  
- **效果**：大单不会锁死向导；平台风险可控；具体 Cap 数值由 08-3 与合约定。

### 4.4 信誉减免机制（高级）

| 向导类型   | 建议订单质押比例 | 说明         |
|------------|------------------|--------------|
| 新向导     | 15%              | 默认         |
| 信誉高     | 8%               | 按评分/完成率 |
| 星级高     | 5%               | 可配置档位   |

- **效果**：正向激励，不单纯靠锁仓；与 01/03 评价与信誉联动。

## 5. 极端场景与规则（必须写清）

以下规则须在**业务流程与争议规则**中明确，避免上线后歧义。

| 场景         | 规则要点（须定稿） |
|--------------|--------------------|
| **向导违约** | 扣单单押金；严重可扣身份押金；与争议裁决、slash 规则一致。 |
| **游客违约** | **MVP 定稿**（见 [03-业务流程与风控](03-业务流程与风控.md) **§一 1.2.1**、[08-3-参数与门禁表](08-3-参数与门禁表.md) **「向导订单质押与 81 对齐」**）：**不要求**游客另行订单质押；依靠 **Escrow 内已付资金** + **取消/No-show 阶梯** + **争议裁决**。**若未来**启用游客押，须修订 01/03/04/08-3/合约与本文。 |
| **争议裁决** | 押金如何分配：自动按比例、全扣、部分扣、退还向导等；须与 executeResolution / 仲裁结果一一对应，写进 03 与合约。 |

## 6. 经济模型优化建议（高级）：三层结构

可考虑**三层结构**，而非完全依赖单单押金：

| 层         | 说明 |
|------------|------|
| **身份押金** | 固定（如 1000U），长期锁仓，可罚扣、可部分解押+冷却。 |
| **单单押金** | 比例制（10%～15%）+ Cap + 信誉减免；订单终态后按规则退还或扣罚。 |
| **风险池**   | 平台抽成的一部分进入**保险/风险池**，用于争议赔偿、不可抗力等，减轻对单单押金的依赖。 |

## 8. 结论与一句话建议

- **1000U + 30% 能不能做？**  
  **可以**，但会**限制供给、降低接单率、压缩高端市场**。

- **推荐**：  
  **1000U 身份押金 + 10%～15% 订单质押（最高不超过 20%）+ Cap（如 min(订单×15%, 2000U)）+ 信誉减免**；并明确**向导违约 / 游客违约 / 争议裁决**时押金处理规则，可选引入**风险池**形成三层结构。
