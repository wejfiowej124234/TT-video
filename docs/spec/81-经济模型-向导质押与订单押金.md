## 1. 边界锁死（先不混）

### 1.1 本文系统只管两类事

1. **身份准入质押**：获得/维持 **供给侧角色** 链上资格所需的**长期**稳定币锁定。  
2. **履约风险质押**：与**单笔订单**或**可计量风险敞口**绑定的**锁定/解锁/扣罚**稳定币。

**服务对象（供给侧两类）**：

| 角色 | 协议 SSOT | 说明 |
|------|-----------|------|
| **向导** | Guide | 接单、履约、争议当事人之一；见 **附录 A** 数值建议。 |
| **商家 / 服务提供方** | Shop（UI）·`provider`（API/DB） | 独立身份押金与订单/退款/欺诈等风险押金；与向导 **分池**，见 **§2**。 |

### 1.2 本文系统明确不管（不得与身份质押混账）

| 对象 | 说明 |
|------|------|
| **区域代理 / 区域运营资金池（认购、换 TTG、融资稳定币）** | 已归 **协议金库（Treasury）** 及 **[84 §1.2.1](84-第一阶段10国Country-Pool发行参数总表.md)**、**[governance-token/02 §4.7](governance-token/02-对内技术规格-草案.md)**、**[85](85-TravelTrust网络落地页-融资级设计与开发规格.md)** 分轨；**不进入** 身份质押池。 |
| **订单托管本金** | **Escrow** 独立；用户本金路径 **不得** 与身份质押池 `transfer` 混用（**[01](01-总库总览.md)**、**[governance-token/02 §4.6](governance-token/02-对内技术规格-草案.md)**）。 |
| **FeeRouter 第一层 45/55 与 Global 内 65/20/15** | **可分配平台手续费** 叙事；与 **身份质押罚没去向** **正交**，见 **[84 §1.1.1](84-第一阶段10国Country-Pool发行参数总表.md)**、**Runbook §7.1**。 |
| **TTG 治理质押 / 激励分配** | **[83](83-区域治理与收益分配-协议白皮书.md)** / **[84](84-第一阶段10国Country-Pool发行参数总表.md)** / **[governance-token/02](governance-token/02-对内技术规格-草案.md)**；**不得**与 **USDC 等身份质押品** 混读为同一合约池。 |

**强制**：**身份质押稳定币路径** 与 **FeeRouter / TTG 治理叙事** **分路径**——延续 **附录 B.1** 与历史 **v1.x** 表述，工程与对外披露须分标签展示。

## 2. 企业级结构：两池三账本（不要单一大 Staking 池）

### 2.1 池 1：`GuideIdentityStakingPool`（Target 命名）

服务 **向导** 身份与向导侧订单风险。

**存放**：向导 **身份押金**；向导 **订单风险押金**（按单锁定/解锁）。

### 2.2 池 2：`ProviderIdentityStakingPool`（Target 命名）

服务 **商家 / provider** 身份与商家侧风险。

**存放**：商家 **身份押金**；**履约 / 退款 / 欺诈** 等 **订单级风险押金**（产品规则与 **03/08-3** 定稿）。

### 2.3 每池内部三套账本（会计分层）

同一合约域内可核算，**用途不得混**：

| 账本 | 英文参考名 | 记录内容 | 用途摘要 |
|------|------------|----------|----------|
| **A. 身份押金账** | Identity Stake Ledger | 身份级锁定余额 | 准入门槛、基础信用担保、严重违规可罚没 |
| **B. 订单风险押金账** | Order Risk Stake Ledger | 订单级锁定余额 | 单笔履约风控；按订单锁定/解锁；争议时可部分扣罚 |
| **C. 罚没准备金账** | Slash Reserve Ledger | **罚没已归集**后的池内准备金 | 赔付、履约补偿、系统性风险覆盖；**与 A/B 分账** |

**强制（企业级）**：**Slash Reserve Ledger** 与 **`ReserveVault`**（或等价模块）在 **Target 架构中必须存在**——**禁止**通过治理或配置 **关闭** 准备金归集路径、**禁止**将「进入 Slash Reserve 的一路」在部署上设计为 **0%**（见 **§3.5**）。

> **实现注记**：当前仓库已落地 **`GuideIdentityStakingPool`** / **`ProviderIdentityStakingPool`**（**`IdentityStakingPool`**；旧单文件 **`Staking.sol` 已移除**）；ABI 真值为 **`contracts/abi/GuideIdentityStakingPool.json`** / **`ProviderIdentityStakingPool.json`**（见 **14**、**contracts/README**）。**两池三账本** 为强制会计边界，参数与部署以 **08-3 / 14** 为工程真值。

## 3. 罚没（Slash）分流：企业级（替代「三选一口径」）

### 3.1 原则

- **[01](01-总库总览.md)** 中 **「StakingInsurancePool | PlatformTreasury | Burn 三选一」** 适合**早期概念门禁**（**单出口**择一）；**「StakingInsurancePool」** 为**占位名**，链上实现载体为 **`GuideIdentityStakingPool`/`ProviderIdentityStakingPool`**（**`IdentityStakingPool` 系**），见 **14**、**contracts/README**。  
- **企业级长期运行**采用 **每次 slash 后按固定比例自动分流** 至多个接收方，与 **FeeRouter 手续费分母** **正交**（**slash 与仲裁/slash 是否计入平台费** 仍遵 **84 §1.1.1**）。

### 3.2 建议第一版比例（部署默认；运行期见 **§3.4**）

**方案 S1（含 Sink）**：

| 去向 | 比例 | 对应账本/模块 |
|------|------|----------------|
| **Slash Reserve Ledger**（本池内风险准备金） | **60%** | **§2.3-C** / `ReserveVault` |
| **Protocol Treasury**（协议金库，非 FeeRouter 分轨叙事） | **30%** | 与 **84 §1.2.1 分轨 B** 区分记账；**罚没转入** 为独立分录 |
| **Burn / Null bucket / 治理可控 sink** | **10%** | 可选；若不启用 Burn，将 10% 并入 Reserve 或 Treasury 须 **同批披露** |

**方案 S2（无 Burn）**：**70%** → Slash Reserve；**30%** → Protocol Treasury。

### 3.3 工程落点

- **`SlashRouter`**（**§8**）执行分账；**禁止**将本分流误解为 **§1.2** 之 **45/55** 或 **Global 65/20/15** 的一部分。

### 3.4 分流比例：部署默认 vs 治理可调（有界）

| 层级 | 规则 |
|------|------|
| **部署默认** | **§3.2** 之 **S1 / S2** 比例作为 **genesis 默认**写进合约或配置（与审计包一致）。 |
| **治理调整** | 允许 **`Governor` / `Timelock`** 修改 **`slash_to_*_bps`** 三组参数（或等价路由配置），**仅改参数、不直接改用户余额**（与 **§4** 一致）。 |
| **上下限（强制）** | 合约须 **硬编码** 每组 bps 的 **MIN/MAX**，且 **`slash_to_reserve_bps` 的下限 > 0**（与 **§3.5** 一致）；三组 **之和恒为 10000**（或固定两项、第三项用补数，须 **单一 SSOT 公式**，避免溢出与舍入争议）。 |
| **禁止** | **禁止**治理将 **Reserve 支路** 调至 **0 bps** 或通过「开关」绕过 **`ReserveVault`/`SlashRouter`** 的准备金入账——若需极端参数，须 **新版本部署 + 披露 + 法务**，**不得** silent 关闭风险准备金语义。 |

**结论**：**默认比例写死于部署**；**运行期可调**，但 **永远在合约边界内**，避免「太死不灵活 / 太活乱改」两种极端。

### 3.5 Slash Reserve / ReserveVault：必须存在（不可关闭）

- **`Slash Reserve Ledger`（§2.3-C）** 与 **`ReserveVault`（§8）** 为 **身份罚没风控** 的 **强制组成部分**：用于归集 **罚没后的风险准备金**，供赔付与系统性缓冲。  
- **支出路径（企业级强制）**：**`ReserveVault` 对外划出**须 **仅**经 **`Governor → Timelock`** 授权的受控接口（如 **`GovernanceTreasury` 模式、Timelock 目标调用、或带角色上限的受控 `withdraw`**）；**禁止**将 **运维热钱包随意 `transfer`、单点 `onlyOwner` EOA 日常提款** 作为**常态**支出路径（**Break-glass** 若有，须 **Runbook + 事后审计** 写死，与 **01** 执行器/多签纪律一致）。  
- **禁止**：配置层或治理 **关闭** Reserve 模块、**100% 罚没直转 Treasury 且无准备金留存**（除非 **全新产品决策** 与 **84/08-4/LEGAL-SIGNOFF** 同批，并 bump 本文版本）。  
- **与订单侧无关**：本节 **不** 讨论 **Escrow 完成后平台服务费**；该费用见 **附录 C** 与 **[01 §十](01-总库总览.md)**。

## 4. 核心参数与治理方式

### 4.1 建议上链参数（每角色池一套或映射到统一 Registry）

| 参数 | 含义 |
|------|------|
| `min_identity_stake` | 身份最低质押（**Guide**） |
| `min_identity_stake_provider` | **Provider / 商家** 身份最低质押（**Target 默认示例：与 Guide 同锚 — 1000 USDC 累计下限**，与链上 **`IdentityStakingPool.MIN_STAKE()`**（**`GuideIdentityStakingPool` / `ProviderIdentityStakingPool` 部署**）及 **08-3** 叙事对齐；旧 **`Staking.sol`** 已移除；独立池部署后可经治理与 Guide **分参**） |

| `order_stake_cap` | 单笔上限（Cap） |
| `cooldown_seconds` | 解押冷却 |
| `max_concurrent_orders` | 并行订单与锁仓上限（可选） |
| `slash_to_reserve_bps` | 罚没→准备金比例 |

## 5. 身份状态机与订单风险状态

### 5.1 向导 / 商家身份状态（建议枚举）

| 状态 | 说明 |
|------|------|
| **Pending** | 申请/审核中 |
| **Active** | 可接单或可按规则服务 |
| **Restricted** | 限制接单或限额 |
| **Suspended** | 暂停；常与风控/争议联动 |
| **Exited** | 退出；解押按冷却与罚没规则 |

**企业级要求**：**不要**仅「余额 ≥ 阈值」即视为有效，须 **显式状态 + 余额** 联合判定。

### 5.2 订单风险质押状态（建议枚举）

| 状态 | 说明 |
|------|------|
| **Unlocked** | 未占用 |
| **LockedForOrder** | 绑定订单锁定 |
| **FrozenForDispute** | 争议冻结 |
| **Slashed** | 已扣罚（可部分） |
| **Released** | 订单终态后释放 |

**价值**：身份与单笔订单 dispute **解耦**；后续 **DeFi 化** 时需区分 **可提取 / 冻结**（见 **§6**）。

## 6. DeFi 预留接口（未来可生息，今日先留边界）

**前提**：**Phase 1** 静态池、不生息（**§7**）。以下为 **Target 接口能力**，第一阶段可实现 **NoOp**。

1. **质押资产抽象**：`underlyingAsset()`、`depositUnderlying`、`withdrawUnderlying`（不锁死「仅原生 USDC 余额」）。  
2. **份额制记账**：`shares` / `assets`（**ERC-4626 思路**；早期可 1 share = 1 USDC）。  
3. **余额视图**：`availableAssetsOf`、`lockedAssetsOf`、`slashableAssetsOf`（或可合并为策略可读视图）。  
4. **策略适配器**：`IStrategyAdapter` — `deployIdleAssets`、`redeemToPool`、`totalManagedAssets`；默认 **`IdleStrategyAdapter`**。  
5. **风险熔断**：`pauseStrategy`、`unwindStrategy`、`setStrategyCap`。  
6. **收益归属参数**：`yield_to_staker_bps`、`yield_to_reserve_bps`、`yield_to_treasury_bps`（第一阶段可全 0）。

## 7. 分阶段路线（企业级顺序）

| 阶段 | 内容 |
|------|------|
| **Phase 1：静态池** | 存 USDC（或单 underlying）；锁定/冻结/slash/cooldown；**不生息**；**跑通会计与风控** |
| **Phase 2：保守生息** | 仅 **未冻结、未被订单占用** 余额可进 **低风险策略**；**策略 cap**；**争议/slash 资金不外放至策略** |
| **Phase 3：治理化收益** | 收益分配、策略切换、cap 调整走 **Governor/Timelock** |

**禁止**：将 **身份担保资产** 在 Phase 1 即包装为 **面向公众的「收益产品」**，避免合规与风险外溢。

## 9. 推荐口径（可直接对外/对内评审）

**身份质押稳定币系统**采用 **角色分池、账本分层、罚没分流、参数治理、策略可插拔** 的企业级结构：**向导**与**商家**分别进入 **独立身份质押池**；池内区分 **身份押金、订单风险押金与罚没准备金**；**Escrow、FeeRouter、Treasury（承销/换币）、TTG 治理激励** 各自独立、**不交叉混账**；未来若引入 DeFi，**仅允许未冻结、未占用资产** 通过 **策略适配器** 进入 **低风险收益层**。

| 问题 | 单源 |
|------|------|
| **基数是什么** | 单笔 Escrow 实例的 **`totalAmount`**（托管总额，单币）；链上释放时 **`platformFeeBps`** 按 **[14](14-合约-API-ABI-前后端对齐.md)** 与 **[01 §十](01-总库总览.md)** 公式计提（**万分比**；**dust** 归平台费腿）。 |
| **是否为「总价 5%」** | 若产品将 **标价** 等同于 **托管总额**，则 **5% = `platformFeeBps = 500`**；若标价 **含/不含** 平台费，须在 **产品定价与 08-4** 披露，**避免** 与链上 `totalAmount` 语义冲突。 |
| **5% 最终怎么收（单句真值）** | 从 **该笔 Escrow 托管总额 `totalAmount`** 中，在 **`release` / `releasePartialRefund` / `releaseSlashed`** 等 **链上结算**时按 **`platformFeeBps`** 计提 **`platformFeeAmount`**，**与向导应收 `guideAmount` 同一笔交易**完成分配；**资金先入 `platformFeeRecipient`**（默认接 **FeeRouter**），再 **`distribute`** 到 **83/84** 各桶 — **不是**用户另付一笔 5%，也 **不是** Paid 当下即从 Escrow **预划**至 Router。取消/全额退款路径 **0** 平台费腿。详见 **[01 §十](01-总库总览.md)**。 |
| **与 81 的边界** | **平台服务费** 进入 **`platformFeeRecipient`（常接 FeeRouter）** → **83/84 第一层 45/55** 等；**身份质押罚没** 走 **§3 `SlashRouter`** → **Reserve/Treasury/sink**；二者 **正交**（**84 §1.1.1**）。 |

**缺省目标示例（产品/部署，非法律承诺）**：**`platformFeeBps = 500`（5%）** 见 **[01 §十](01-总库总览.md)**（基数为 **`totalAmount`**）；**市场参照**与定价披露见 **01** 同段；**谁可改 `platformFeeBps`** 见 **01 §十** **治理归属**段（**Governor / Timelock**）。

## 附录 A：向导专项——原始方案评估与可规模化比例

本节保留 **v1.x** 经济测算，供 Guide 池参数参考；**商家**比例由产品与风控另表定稿并写入 **08-3**。

### A.1 原始「1000U + 30%」与锁仓测算

- **向导身份押金**：1000U（长期锁仓）  
- **每笔订单再质押**：订单金额的 **30%**

| 订单金额 | 身份押金 | 订单质押（30%） | 总锁仓 |
|----------|----------|-----------------|--------|
| 2000U    | 1000U    | 600U            | 1600U  |
| 5000U    | 1000U    | 1500U           | 2500U  |
| 10000U   | 1000U    | 3000U           | 4000U  |

**多单叠加**：向导同时接 3 单、每单 3000U 时，单单押金 = 900U × 3 = 2700U，加身份押金 1000U，**总锁仓 = 3700U**。

### A.2 五维度评估（摘要）

- **30%** 相对行业 **5%～15%** 偏高，限制供给。  
- **身份 + 多单叠加** 锁仓过重。  
- **押金高 ≠** 覆盖旅行者全部机会成本；须 **争议 + Slash Reserve（§2.3-C）** 等组合。

### A.3 问题总结

| 问题 | 说明 |
|------|------|
| **30% 过高** | 压缩高端市场与接单率 |
| **双层锁仓过重** | 身份 + 多订单 |
| **押金≠全部损失** | 须规则与准备金 |

### A.4 推荐模型（可规模化）——向导

**实现注记**：链上 **Guide/Provider 池** **现状**以 [08-3](08-3-参数与门禁表.md)、[14](14-合约-API-ABI-前后端对齐.md) §1.1 为准；下列比例为 **设计先行**。

- **身份押金**：1000U（可治理调整）；解押冷却 **7～30 天**（与 **01** 一致）。  
- **订单质押**：**10%～15%** 为主，**不超过 20%**；**Cap**：`min(订单金额 × 比例, Cap)`。  
- **信誉减免**：新向导 15% → 高信誉 8%～5% 等（**08-3** 定稿）。

### A.5 向导侧极端场景（须与 03/合约一致）

| 场景 | 规则要点 |
|------|----------|
| **向导违约** | 扣订单风险押金；严重可扣身份押金；与 **SlashRouter（§3）** 一致 |
| **旅行者违约** | **MVP**：不要求旅行者另押；**Escrow + 03 阶梯 + 裁决**（见 **03 §一 1.2.1**、**08-3**） |
| **争议裁决** | 与 `executeResolution` 一一对应 |

### A.6 三层结构（经济补充）

| 层 | 说明 |
|----|------|
| **身份押金** | 长期准入 |
| **订单风险押金** | 按单 |
| **Slash Reserve / 平台抽成风险池** | 与 **§2.3-C**、**§3** 对齐；**非** FeeRouter 叙事 |
