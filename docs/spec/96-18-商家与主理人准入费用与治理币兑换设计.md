## §1 目标与非目标

### §1.1 目标（产品意图，可评审）

1. **商家（`provider`）** 与 **区域主理人（`region_steward`）** 在 **获得角色或开通关键能力前**，为平台承担 **可审计的开发 / 基础设施成本**，支付 **明确标价** 的费用。  
2. 费用可与 **治理币（TTG）持有或兑换** 挂钩（例如：**最低持币门槛**、**经官方承销的换币路径**），但 **须** 与 **旅行订单 Escrow 计价币种** 解耦（对齐 **82 §三**、**01**）。  
3. **费率示例（如 2%）** 仅作 **设计占位**；定稿须经 **经济 + 法务 + 工程** 三方书面（见 **§9**）。

### §1.2 非目标（本文不写死）

- **不**替代 **向导** **`guides`** 资质审核链（**04**、**Admin PATCH …/admin/guides/:id**）；商家 / 主理人 **当前主路径** 仍为 **注册规则校验写 `users.role`**，若引入 **付费准入**，属 **新增产品状态机**，须另开 **95 F 行 / 04 §3.4** 登记。  
- **不**在本文内定稿 **证券属性** 结论；任何 **向公众售 TTG** 或 **捆绑投票权销售** 的表述，**须** 走 **governance-token/LEGAL-SIGNOFF** 与 **08-4**。

## §3 收费模型比选（推荐决策树）

> **占位示例**：「兑换治理币时收 **2%** 开发费」在工程上可映射为下列 **之一或组合**；**组合**须显式拆分展示（B2）。

| 模型 | 用户感知 | 链上复杂度 | 合规敏感度 | 适用场景 |
|------|----------|------------|------------|----------|
| **M1 · 固定申请费**（稳定币或法币计价） | 清晰 | **低**（可链下支付 + 链上仅记 `role` 解锁） | 中（支付服务 KYC） | MVP、强控「先付费后开号」 |
| **M2 · TTG 最低持仓门槛** | 「要买币」 | **中**（快照或 Oracle / 自持余额校验） | 高（持币门槛 ≈ 投资门槛叙事） | 强治理绑定、已有流通市场 |
| **M3 · 官方承销 / 固定汇率兑换 + 点差** | 接近「2%」叙事 | **高**（库存、Rug、oracle、暂停开关） | **最高** | 仅建议在 **法务签核 + 多签金库** 后做 |
| **M4 · 路由抽成（FeeRouter / UniswapV3 类）** | DEX 用户熟悉 | **高**（路由白名单、防夹、回调税） | 中高 | 与 **83 FeeRouter** 叙事统一时优先 |
| **M5 · 年续费 / 席位费** | SaaS 化 | 中 | 中 | 主理人 **Seat** 叙事与 **83** 附录一致时 |

**推荐（工程可迭代顺序）**：**M1 或 M2（只门槛不承销）** 作 **Phase A**；**M3/M4** 仅在 **82/83/84/governance-token** 同批扩写且 **96-07** 终验通过后 **Phase B**。

## §5 技术实现路径（与「2%」的落点）

### §5.1 路径 A — **链下收款 + 链上仅解锁角色**（最低耦合）

1. 用户在 **托管支付页**（Stripe / 合规稳定币结算等）支付 **M1**。  
2. **`payments` / `entitlements`** 表记 **`paid_at` / `sku` / `user_id` / `fee_schedule_version`**。  
3. **`POST /auth/register` 或独立 `POST /api/v1/onboarding/...`** 在 **校验 entitlement** 后写 **`users.role`**。  
4. **优点**：不动 **Country Pool / TTG 流动性**。**缺点**：TTG 叙事弱；须防 **伪造支付回调**（签名校验 + 幂等）。

### §5.2 路径 B — **链上：用户 → Treasury 的明确 `transfer` / `permit` + 事件**

1. 用户在申请流中 **向 `Treasury` 或 `FeeReceiver` 合约地址** 转 **USDC / TTG**（金额 = 报价）。  
2. **Indexer / 后端** 读 **`Transfer` 或自定义事件`**，与 **`user_id` + `nonce`** 绑定后解锁角色。  
3. **优点**：可审计、与 **96-07** 终验对齐。**缺点**：Gas、失败重试、合约升级须 **Timelock**（**83**）。

### §5.3 路径 C — **在 TTG 兑换中嵌入「平台开发费」**（对应「2%」）

1. **若** 兑换经 **自有 Router 或白名单池**：在 **swap 输出** 或 **输入** 上扣 **bps**（与 **B3** 分母一致）。  
2. **须** 与 **84 / 83 FeeRouter** 百分数 **同批变更**（见 **82 §三** 文档联动门禁：`check-governance-doc-linkage.sh`）。  
3. **须** 评估 **池子是否需单独 `application_fee` LP 段** 或 **直接从输出扣减至 Treasury**（避免 LP 被动承担损失）。  

### §5.4 路径 D — **仅持币门槛（M2）+ 无承销**

1. **`GET /me` 或注册前检** 读 **链上 TTG 余额**（或快照合约）。  
2. **不满足** 则拦截注册 / 展示换币 **外链（DEX）** 而不做 **官方承兑**。  
3. **优点**：合规面相对 **M3** 小。**缺点**：**2%** 不落在平台口袋，除非另加 **M1/M4**。

## §6 池子与链上变更清单（评审用）

> **原则**：凡动 **流动性池参数、Router 费率、Treasury 归属**，**须** 走 **83/84/14** 变更流程 + **96-07** 冻结地址/字节码 + **审计**。

|----------|----------------|------|
| **Country Pool / Global Pool（84）** | **视模型而定** | **M3 官方售币** 可能涉及 **库存与价格**；**仅 M4 路由抽成** 未必改 **84** 募资参数，但须防 **叙事冲突**。 |

## §9 风险登记（摘要）

- **合规**：公开 **承销 TTG**、**固定价兑换** 可能触发 **当地证券 / 支付牌照** 问题 — **须法务书面**。  
- **技术**：Router **税** 与 **夹子上游** 交互 — **须** 安全审计与 **滑点上限**。  
- **叙事**：**2%** 与 **LP 费 / 协议费** 叠加 — **须** UI **总成本** 披露（**B7**）。
