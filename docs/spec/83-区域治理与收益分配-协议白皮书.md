# TravelTrust Whitepaper（节选规格）

## 区域治理、收益分配与席位机制（Final Specification）

### 1. 总体设计目标

TravelTrust 采用**分层治理**与**区域收益池**模型，以支持全球多国家市场的独立发展，同时保持协议整体一致性与资金安全。

**系统目标**：

- 支持多国家市场扩展；
- 支持区域投资与收益分配；
- 防止区域绑架协议；
- 防止收益套利；
- 防止治理攻击；
- 保持链上资金真相；
- 支持长期 DAO 运行。

**核心原则**：

- 所有资金分配以链上为准；
- 所有收益资格按快照确定；
- 所有治理变更需 DAO 批准；
- 所有席位必须承担运营义务。

---

### 2. 核心概念

#### 2.1 Region（区域）

**定义**：Region 是协议中的国家或地区运营单元。

**组成**（每个 Region）：

- RegionShare  
- RegionSeat  
- RegionVault  
- RegionDAO  

**约束**：Region **不是**独立协议，仅是收益与治理子单元。

#### 2.2 RegionShare（区域份额代币）

**定义**：RegionShare 是某区域收益参与代币。

**代表**：

- 区域收益参与权；
- 区域治理投票权；
- Seat 竞逐资格。

**不代表**：

- 公司股权；
- 品牌所有权；
- 协议控制权。

#### 2.3 RegionSeat（区域席位）

**定义**：RegionSeat 是区域控制席位。

**代表**：

- 区域运营责任；
- SeatBonus 资格；
- RegionDAO 提案权；
- 区域品牌授权资格（须协议批准）。

**约束**：Seat **不是**永久权利；可被替换或收购。

#### 2.4 RegionVault（区域金库）

**定义**：RegionVault 用于存储该区域收益。

**来源**（示例）：

- FeeRouter 分配；
- Escrow 费用；
- 协议分成。

**机制**：RegionVault 资金**只能**按规则分配；**不得**直接随意转出（由合约逻辑约束）。

#### 2.5 ProtocolVault（协议金库）

**定义**：ProtocolVault 用于：

- TTG 奖励；
- Treasury；
- 安全基金；
- 协议开发。

**治理**：ProtocolVault 由 **GlobalDAO** 控制。

---

### 3. 收益分配模型

**机制**：所有订单费用必须经过 **FeeRouter**。**第一层拆分**与 [84-第一阶段10国Country-Pool发行参数总表](84-第一阶段10国Country-Pool发行参数总表.md) **§一** 一致，作为 **Target** 链上路由的**协议单源**（实现前以合约为准；对外披露仍受 [08-4](08-4-对外口径包.md) 收益与证券隔离约束）。

**费用基数（闭合）**：下文 **45% / 55%** 所相对的 **「可分配平台费用 100%」** 的分子定义，以及 **L1/L2 gas、争议仲裁费、向导 `Staking.slash` 罚没（如 USDC）** 与该基数的**正交**关系，以 **84 §1.1.1**、[Runbook](../../ops/RUNBOOK.md) **§7.1** 为准；本 **§3** 流程图仅刻画 **进入 FeeRouter 的可分配手续费** 路径。

**流程（Target）**：

```text
Escrow → FeeRouter →┬→ 国家可分配费用桶（45%）→ 各 RegionVault（按国/区）→ Snapshot → RegionShare / SeatBonus → Claim
                     └→ Global Pool（55%）→ TTG 质押激励（65%×55%）/ 储备（20%×55%）/ 运营（15%×55%）
```

**第一层**（可经 GlobalDAO 在参数范围内调整，**不得**由 RegionDAO 或 Seat 单方修改）：

| 去向 | 比例 | 说明 |
|------|------|------|
| **国家可分配费用桶** | **45%** | 进入 **各 Region** 的链上归集与分配逻辑（**RegionVault** 从此桶按规则拆分，**不是**在整笔费用上再占独立 35%） |
| **Global Pool** | **55%** | 协议级池；对应下文 **ProtocolVault / Treasury / 安全与开发** 等合并叙事 |

**Global Pool 内部分配**（占 **Global Pool 自身** 100%）：

| 去向 | 比例 |
|------|------|
| TTG Staking（激励） | **65%** |
| 储备（Reserve） | **20%** |
| 运营（Operations） | **15%** |

**与 2.5 ProtocolVault 的对应关系**：**ProtocolVault** 在实现上可映射为 **Global Pool** 及其子账；**TTG 奖励**主要来自 Global 内 **65%**  slice；**Treasury / 安全基金 / 协议开发**由 **20% + 15%** 按治理细则切分（具体科目在 Runbook 或 08-4 收益流图中写死）。

**RegionVault 分配**（均在 **45% 国家桶** 之内）：

- 按 **Snapshot** → RegionShare；
- **SeatBonus** 单独计算。

#### 3.1 历史草案（v1.0.1 及以前文档中的第一层比例）

以下比例已被 **v1.1.0** 上表替代，**不得**作为新对外材料或新合约的默认依据；仅作审计与 diff 参照：

| 去向（旧第一层） | 比例 |
|------------------|------|
| RegionVault（旧叙述） | 35% |
| ProtocolVault（旧叙述） | 65% |

| 去向（旧 ProtocolVault 内） | 比例 |
|-----------------------------|------|
| TTG Staking | 70% |
| Treasury | 30% |

### 4. Snapshot 规则

**定义**：收益资格按周期快照确定。

**默认参数**：

- `SnapshotPeriod` = 30 天；
- `minLockForSnapshot` = 7 天（防止快进快出套利）。

**规则**：

- 持仓必须满足最低比例；
- 必须满足锁仓时间；
- 快照后确定资格；
- 当前周期收益按快照分配。

---

### 5. 最低持有资格

**定义**：每个 Region 设置 `minHoldRatio`。

**建议梯度**：

| 市场类型 | minHoldRatio |
|----------|----------------|
| 小市场 | 1% |
| 中市场 | 2% |
| 大市场 | 3% |
| 核心市场 | 3%～5% |

**机制**：低于比例进入**宽限（Grace）**状态（见第 6 节）。

---

### 6. 持仓状态机（Share 资格）

**状态**：

| 状态 | 含义 |
|------|------|
| Eligible | 具备当期收益资格 |
| Grace | 低于 minHold，宽限期 |
| Inactive | 未恢复，停止未来收益 |

**规则**：

- 低于 `minHold` → **Grace**；
- Grace 持续 30 天未恢复 → **Inactive**。

**Inactive 后果**：

- 停止未来收益；
- 历史已确定收益可按规定 **Claim**（与合约具体实现一致）。

---

### 7. Seat 权限与限制

**Seat 拥有**：

- 运营权；
- SeatBonus 资格；
- RegionDAO 提案；
- RegionDAO 投票增强（若参数启用）。

**Seat 不得**：

- 修改 Fee 比例；
- 修改 Vault 比例；
- 修改 Snapshot 规则；
- 修改 Buyout 规则；
- 修改 Global 参数。

**治理**：**GlobalDAO** 拥有最终否决权；冲突可上送仲裁与 Global 层（见附录 E）。

---

### 8. SeatBonus 规则

**前提**：SeatBonus 须同时满足：

- Seat 状态为 **Active**；
- KPI 达标；
- 未处于处罚状态。

**计算**：

```text
SeatBonus = min(RegionProfit × bonusRate, bonusCap)
```

**建议上限**：

- `bonusRate` ≤ 10%；
- `bonusCap` ≤ RegionVault 的 10%。

否则 **SeatBonus = 0**。

---

### 9. Seat 状态机

**状态**：

| 状态 | 含义 |
|------|------|
| Active | 正常运营 |
| Watch | 轻度未达标 |
| Probation | 连续未达标 |
| Inactive | 运营失效 |
| Replaceable | 可被收购 |

**转移规则**：

- 1 次 KPI 不达标 → **Watch**；
- 2 次 → **Probation**；
- 3 次 → **Inactive**；
- 4 次 → **Replaceable**。

**Bonus 系数**：

| 状态 | Bonus |
|------|--------|
| Active | 100% |
| Watch | 70% |
| Probation | 0 |
| Inactive | 0 |
| Replaceable | 0 |

---

### 10. KPI 模型

**原则**：KPI 必须可量化。

**推荐权重**：

| 维度 | 权重 |
|------|------|
| GMV | 40% |
| 订单数 | 20% |
| 商家数 | 20% |
| 评分 | 20% |

**职责划分**：

- **KPI 计算**：后端（链下统计与抗刷治理）；
- **KPI 结果上链**：合约记录结果摘要或哈希（防篡改），具体字段在实现规格中定稿。

---

### 11. Seat 收购机制（Buyout）

**权利**：允许收购 Seat。

**条件（摘要）**：

- 持有 ≥ `2 × minSeat`；
- 锁仓 ≥ 90 天；
- 提交报价；
- 登记主体（RegisteredSubject = true）。

**定价优先级（须写死顺序）**：

1. TWAP  
2. 最近融资价格  
3. DAO 估值  
4. 拍卖  

---

### 12. 收购流程与冷却

**流程摘要**：

1. BuyoutProposal  
2. 锁仓 / 保证金（Bond）  
3. 通知 Seat  
4. Seat 接受 → 交割；否则 **RegionDAO 投票**  
5. 冲突 → **GlobalDAO** 裁决路径（见附录 E）  
6. 通过 → **下周期生效**

**冷却**：`Cooldown = 180` 天（防骚扰性提案）。

---

### 13. Seat 失效与 PendingVault

**机制**：Seat 失效时，**RegionVault → PendingVault**（或等价托管合约状态）。

**规则**：

- 普通 Share 继续按规则参与分配（与实现一致）；
- **SeatBonus 暂停**；
- 长期无 Seat → 按规则回流 **ProtocolVault**（防资金与治理悬空）。

---

### 14. Claim 机制

**能力**：

- `minClaim`；
- `batchClaim`；
- `autoMerge`（小额合并，降 Gas）；
- `delegateClaim`（若启用）。

**原则**：可领取余额与执行须在链上可验证；后端仅协调 UI 与批处理策略，**不得**伪造领取结果。

---

### 15. RegionShare 流动性

**三层**：

| 层级 | 说明 |
|------|------|
| OTC | 场外协商 |
| Whitelist | 白名单转让 |
| DEX | 去中心化交易 |

**阶段建议**：

| 阶段 | 允许 |
|------|------|
| 初期 | OTC + 白名单 |
| 成熟期 | 可引入 DEX |

**目标**：降低操纵与闪崩风险。

---

### 16. DAO 权限边界（摘要）

**RegionDAO 不得修改**：Fee 比例、Vault 比例、Snapshot、Buyout 规则、Global 参数。

**GlobalDAO**：可否决、可设定参数范围；具体列表见附录 E。

---

### 17. 团队约束

**必须**：

## A.2 状态转移条件

| 当前 | 条件 | 下一状态 |
|------|------|----------|
| Active | KPI 未达标一次 | Watch |
| Watch | KPI 未达标第二次 | Probation |
| Probation | KPI 未达标第三次 | Inactive |
| Inactive | 未恢复 | Replaceable |
| Replaceable | Buyout 成功 | 新 Seat |

| 状态 | Bonus |
|------|--------|

| Watch | 70% |
| Probation | 0 |
| Inactive | 0 |
| Replaceable | 0 |

## A.4 Seat 控制条件

Seat 须持续满足：

- `SeatBalance ≥ minSeatRatio`；
- `KPI ≥ threshold`；
- 未在处罚状态。

否则触发失效路径。

# 附录 J — 全系统状态机总图

## J.1 Order 状态机

| 状态 | 含义 |
|------|------|
| Created | 创建 |
| Confirmed | 双方确认 |
| Escrowed | 已托管 |
| InProgress | 进行中 |
| Completed | 完成 |
| Disputed | 争议 |
| Resolved | 裁决完成 |
| Released | 已放款 |
| Refunded | 已退款 |
| Cancelled | 取消 |

**主路径**：Created → Confirmed → Escrowed → InProgress → Completed → Released。  
**争议路径**：InProgress → Disputed → Resolved → Released / Refunded。

## J.2 Escrow 状态机

| 状态 | 含义 |
|------|------|
| Empty | 未存款 |
| Funded | 已存 |
| Locked | 锁定 |
| Released | 放款 |
| Refunded | 退款 |
| Slashed | 扣罚 |

**约束**：资金只能沿允许边转移；**不得**随意回退（与 [10-系统级不变量](10-系统级不变量白皮书-v1.0.md) 对齐）。

## J.3 Seat 状态机

与附录 A 一致；增加终端态 **Replaced**（收购完成后）。

## J.4 Share 资格状态机

Eligible → Grace → Inactive；Grace 可恢复 Eligible；Inactive 在满足规则下可恢复 Eligible（实现须明确条件）。

## J.5 Vault 状态机

| 状态 | 含义 |
|------|------|
| Accumulating | 累积 |
| SnapshotReady | 可快照 |
| Distributing | 分配中 |
| Claimable | 可领取 |
| Empty | 清空 |

Seat 失效：Accumulating → PendingVault（或等价状态）。

## J.6 Buyout 状态机

None → Proposed → Locked → Voting → Approved → Executed；失败：Rejected → Cooldown。

## J.7 DAO 状态机

Draft → Proposed → Voting → Passed → Timelock → Executed（或 Failed）。

## J.8 Snapshot 状态机

Waiting → Triggered → Calculating → Stored → **Final**（仅 Final 后可进入可 Claim 分配阶段）。

## J.9 Claim 状态机

None → Claimable → Claimed / Merged / Expired。

## J.10 Region 生命周期

Init → Active →（NoSeat / PendingSeat）→ Active；严重：Active → Suspended → Closed（Closed 收益回 Protocol）。

## J.11 全系统一致性规则（摘要）

- Order 结束 → Escrow 结束；
- Escrow 结束 → FeeRouter 执行；
- FeeRouter → Vault 增加；
- Vault → Snapshot；
- Snapshot → Claimable；
- Seat 状态影响 Bonus；
- Share 状态影响分配资格；
- Buyout 影响 Seat；
- DAO 影响参数。

**不得跳步**。

## J.12 不允许的状态（摘要）

- Escrow 未结束即分配 Vault；
- Seat 无效仍领取 SeatBonus；
- Snapshot 未 Final 即 Claim；
- Buyout 未执行即更换 Seat；
- DAO 未通过即改参数；
- 后端直接改余额。
