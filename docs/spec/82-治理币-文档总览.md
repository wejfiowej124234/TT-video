## 三、与总库及合规的硬约束对齐

- **[01-总库总览](01-总库总览.md)**：**MVP 不发行平台支付币**；结算以 allowlist 稳定币（如 USDC）为准；治理代币若引入，**不得**替代旅行订单计价与 Escrow 结算币种，除非单独产品决策并全量更新 01/04/14/08-4。
- **[08-1-战略与合规风险检查清单](08-1-战略与合规风险检查清单.md)**：治理升级、Timelock、多签与「治理币与升级安全模型」等条款优先。
- **[08-4-对外口径包](08-4-对外口径包.md)**：收益流、**是否分红/是否与治理币价值绑定**、证券隔离等 **必须与对外白皮书一致**；对外白皮书定稿前以 08-4 为上限约束。
- **[81-经济模型-向导质押与订单押金](81-经济模型-向导质押与订单押金.md)**：当前链上质押示例为 **ERC-20 质押品（如 USDC）**，与「治理代币」分属不同设计对象；对内规格中须区分 **质押资产** vs **治理/激励代币**。
- **[49-阶段建议-下一阶段方向与优先级](49-阶段建议-下一阶段方向与优先级.md) §G**：治理与激励产品步骤与占位接口；细化规则时以本文档分册为补充 SSOT。
- **[83-区域治理与收益分配-协议白皮书](83-区域治理与收益分配-协议白皮书.md)**：多区域 **Region/Seat/Share**、Vault 与分配、DAO 权限边界、Buyout/Snapshot/Claim 及 **附录 I/J**（职责矩阵与状态机总图）；与治理币叙事、Fee/Treasury 口径交叉时须三方（83/82/08-4）一致。
- **[84-第一阶段10国Country-Pool发行参数总表](84-第一阶段10国Country-Pool发行参数总表.md)**：第一阶段 **Country Pool** 国家表与 **45%/55%**、承销 vs 费用分母；**§1.1.1** 可分配费用基数（**不含**用户自付 gas；**仲裁费 / `Staking.slash` 与 45/55 正交**）与 **[Runbook](../../ops/RUNBOOK.md) §7.1** 闭合；**§1.5** 写死 **100% 总量**内 **国家承销桶（≤25%）** vs **个人/全局承销桶**、**统一估值锚** 与 **对外禁用「分红」** 推荐替代表述；**已与 83 v1.1.0+ §3 合并为同一套 FeeRouter 叙事**，对外数字以 **83 §3 + 84 §一** 为双锚、**08-4 附录图** 为展示单页；后续**任一侧**改百分数须按 [07 §二 2.4](07-开发流程与顺序.md) **同批**改对侧、附录图与 **governance-token/03**，并跑 `check-governance-doc-linkage.sh`。

## 三附、链上交付顺序（工程硬约束）

**原则**：任何将 **真实资金**、**真实投票权** 或 **真实主网 state** 置于风险下的部署，须在 **本地虚拟链** 上先完成「**整套业务流程** + **治理币（TTG）及相关链上使用流程**（委托、投票、领取/Snapshot·Claim 等，以最终合约为准）」的联调与验收，**再**进入 **测试网** 复验，**最后** 按 Runbook/多签流程上 **主网**。

| 阶段 | 要做什么 | 权威入口 |
|------|----------|----------|
| **本地（Anvil）** | `forge test`、部署脚本、订单主路径与治理模块（若已开发）端到端；ABI/04/14 与本地清单地址一致 | **[contracts/README](../../contracts/README.md)**、[governance-token/02 §1.3](governance-token/02-对内技术规格-草案.md)、**[Runbook §2.56](../../ops/RUNBOOK.md)** |
| **测试网** | 同脚本切换 RPC；监控、索引与对账演练；不代替本地已闭项 | **[Runbook](../../ops/RUNBOOK.md)**（**§2.56**、**§7.1**）、**14** |
| **主网** | 多签、变更窗口、对外披露与 **LEGAL-SIGNOFF** 已满足 **且** 前两阶段工程验收已完成 | **08-4**、**LEGAL-SIGNOFF**、**07 §五 5.2A** |

**法务定稿**与**对外白皮书**是合规与叙事的必要条件，**不替代**上述工程验收顺序。

## 四、企业级发布门禁（摘要）

0. **链上交付顺序**：须符合上文 **§三附**；未经本地+测试网闭环，不得仅以文档定稿上主网承接真实用户资产或治理权。  
1. 对外白皮书：**法务书面定稿** + 版本号/日期 + 与 08-4 交叉审阅无冲突。  
2. 对内规格：任何链上代币/新增表/路由变更须同步 **04 §3.4**、**14**、ABI 单源与 CI 门禁。  
3. **禁止**：对外稿出现「保证收益」「等同于股权/分红」等表述；详见对外白皮书「合规与表述边界」节。  
4. **文档联动**：新增或重大修订 `82` / `83` / `84` / `governance-token/*` 时，须按 [07-开发流程与顺序 §二 2.4](07-开发流程与顺序.md) 更新 [00-文档索引](00-文档索引.md)、[00-最终版架构图对应模块清单总表](00-最终版架构图对应模块清单总表.md) §二点五、**[07](07-开发流程与顺序.md) §零 0.3**（及 [00-文档体系与阅读串联](00-文档体系与阅读串联.md) 兼容壳关键词；若索引已含可核对，不得长期漂移）；合并前须通过 `scripts/check-governance-doc-linkage.sh`（见 [.github/workflows/governance-doc-linkage-gate.yml](../../.github/workflows/governance-doc-linkage-gate.yml)）。  
5. **法务签核**：对外白皮书（中/英）及 PPT/PDF 定稿前须完成 [governance-token/LEGAL-SIGNOFF-CHECKLIST](governance-token/LEGAL-SIGNOFF-CHECKLIST.md)（含 **可分配费用分母与正交**、**收益流图示脚注** 等逐项勾选）。

### 6.3 总评（通畅性 · 合理性）

- **经济模型纵向**：**81（质押）→ 83（协议分配与治理对象）→ 84（Phase1 十国承销与费用百分点）→ 08-4（对外边界 + 附录图）** 链条清楚；**84** 对 **25% 承销分母 vs 28.5 费用百分点** 的防呆（§1.3、§3.2）**合理**，避免投资人误加总。
- **架构横向**：**订单主链（80→42→53、18 主图）** 与 **经济扩展（82～84、FeeRouter Target）** 及 **融资卫星页（85）** 分离明确，**权限**（多签 / DAO / Admin / 产品治理页）在 **08-4、13-1、83 附录 I** 可交叉核对，**整体逻辑成立**。
- **残留风险**：**文档一致 ≠ 监管定性**；任何募资、白皮书、**85** 上线前仍须 **LEGAL-SIGNOFF** 与 **08-4** 定稿交叉。
