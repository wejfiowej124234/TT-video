## 使用说明

- **勾选**：每项前的 `- [ ]` 完成则改为 `- [x]`；建议在分支或 PR 中按 P 粒度提交，便于追溯。
- **门禁**：每个「门禁」小节内的**子项须全部通过**再进入下一 P。
- **每阶段完成是否有检查**：有。每个 P 的表格**右侧**即检查依据——**实现类**（P1/P3/P5/P7/P9/P11）右侧列为**「验收」**，按验收逐项达标后勾选本节末尾「实现完成 → 进入下一 P」；**门禁类**（P0/P2/P4/P6/P8/P10/P12/P13/P14）右侧列为**「要求」**（P0 另有「参考」列），按要求逐项通过后勾选「全部通过 → 进入下一 P」。
- **测试**：单元测试、集成测试在对应门禁中执行；E2E 在 P10/P14 发版前必过。
- **编译与单测**：每个实现阶段（P1/P3/P5/…）完成或门禁前，须对应包 `cargo check` 与 `cargo test` 通过（如 `cargo check -p traveltrust-api`、`cargo test -p traveltrust-api`）；修正类型/借位等实现问题后建议同步更新该阶段实现记录。
- **缺口/遗漏**：对照 01 §10、02 §十三、04 §五、06 §6.3、17 六区检查是否有未实现或文档未覆盖项。
