# P0～P50 开发流程勾选清单（综合执行版）

**用途**：按「开发一块 → 测试 → 审计 → 检查缺口与遗漏」执行，完成一项勾选一项，按此清单可把项目从开工到发版走完。**阶段数量以项目为准**：清单给出 P0～P14 必做项，P15～P50 为扩展位（可按 [17-MVP 产品与模块清单](17-TravelTrust-MVP-产品与模块清单.md) 六区或 [04 §五](04-后端与API.md) 子阶段拆分）。

**受众与用法**：开发与项目管理；实现时与 [07-开发流程与顺序](07-开发流程与顺序.md) 配套使用，按 P 逐项打勾。**文档维护责任**：项目或技术负责人；07 Phase 或 01 §10/04 §五 变更时建议同步本文 P 与门禁项。文档版本与最后更新见 [00-文档索引](00-文档索引.md)。

**配套文档**：[07-开发流程与顺序](07-开发流程与顺序.md)（Phase 0～5）、[01-总库总览](01-总库总览.md)（§10 审计前检查、17 条、12 缝）、[11-开发前准备清单](11-开发前准备清单.md)、[15 附录〇 发版前勾选总表](15-多维度文档与技术检查报告.md#发版前勾选总表)。

---

## 使用说明

- **勾选**：每项前的 `- [ ]` 完成则改为 `- [x]`；建议在分支或 PR 中按 P 粒度提交，便于追溯。
- **门禁**：每个「门禁」小节内的**子项须全部通过**再进入下一 P。
- **测试**：单元测试、集成测试在对应门禁中执行；E2E 在 P10/P14 发版前必过。
- **缺口/遗漏**：对照 01 §10、02 §十三、04 §五、06 §6.3、17 六区检查是否有未实现或文档未覆盖项。

## P15～P50：扩展位（按项目需要拆分）

以下为**可选扩展**，用于把「一大块」拆成更细的 P，便于按模块或区域逐块开发与门禁。**不要求全部使用**；若项目规模大，可按下面方式分配编号。

| 区间 | 建议用途 | 参考 |
|------|----------|------|
| **P15～P19** | 按 [17](17-TravelTrust-MVP-产品与模块清单.md) 六区拆分：AI 行程生成层 / Marketplace 撮合层 / 协议控制台 / Escrow 托管层 / 风控与仲裁层 / 用户与身份系统；每区「实现 + 门禁」各占一 P | 17 一～二 |
| **P20～P29** | 按 [04 §五](04-后端与API.md) 后端落地子阶段或 05/06 前端子模块拆分；每块「实现 + 门禁」 | 04 §五、05、06 |
| **P30～P39** | 专项：安全加固、性能与压测、多链/多环境、可观测与告警、文档与 Runbook 闭环等 | 01 §9、10、08、ops/RUNBOOK |
| **P40～P50** | 预留：新功能迭代、合规扩展、第三方对接、运营后台等 | 项目自定 |

**使用方式**：在「P15～P50 分配表」中写下本项目实际使用的 P 编号与对应内容，例如：
