## 二、按模块说明

### 2.1 前端负责（符合企业级）

- **页面与交互设计**：路由、组件、布局、样式（含 31 TT社区、29 自由市场、30 DID、个人中心等）均在 `frontend/`，由前端代码与设计规范（如 30 §4 赛博风）决定。
- **展示逻辑**：如何渲染列表、表单、抽屉、空态、错误态等，由前端实现；**不包含**「谁可以发帖」「订单状态如何流转」等业务规则，后者应在后端。

### 2.2 后端 + 数据库负责（符合企业级）

以下**业务数据与规则**以 **04 §三 API** 与 **crates/api + migrations** 为**唯一来源**，前端通过 `frontend/lib/apiClient.ts` 调用，**不**在前端存储或伪造：

| 能力 | API / 路由 | 数据库表（migrations） |
|------|------------|------------------------|
| 用户与账号 | /auth/*, /api/v1/me, /api/v1/me/password | users, sessions |
| 向导 | /api/v1/guides, upload-doc, stake | guides, 证件存储 |
| 订单与行程 | /api/v1/orders, /api/v1/itineraries, discover/orders | orders, itineraries |
| 订单消息 | /api/v1/orders/:id/messages | order_messages |
| 评价 | /api/v1/orders/:id/reviews | reviews |
| 争议与证据 | disputes, order/evidence | disputes, 证据存储 |
| DID 排行榜 | /api/v1/did-rank/travelers|guides|itineraries | 已实现（DB 优先 + chain_off 回退） |

- **业务逻辑**：注册/登录、向导注册与质押、下单/接单/取消、**链下**确认行程完成（`confirm-completion`）、**链上释放前置与规则**、争议与裁决、评价规则（仅终态可评）等均在**后端**实现（crates/api、core）；前端只发请求、展示结果与错误。`confirm-completion` **≠** 单笔放款（04 §3.4）。
- **数据持久化**：上述表通过 **PostgreSQL migrations** 建表；环境变量 `DATABASE_URL` 配置后为真实持久化，符合企业级「业务数据落库、可审计」要求。

### 2.3 TT 社区：后端 + DB 已挂载（生产级强化仍待 160 / 31）

| 能力 | 当前实现（有 `DATABASE_URL`） | 说明 |
|------|------------------------------|------|
| Feed / 发帖 / 详情 / 我的帖子 | `GET/POST /api/v1/community/*` + `community_posts` 等 | 路由与表见 **04 §3.4**、`crates/api/src/routes/community.rs` |
| 评论 / 点赞 / 收藏 | 对应 community 子路由 + 关联表 | 同上 |
| 关注 / 粉丝 / 好友 / 私信 | 对应路由 + follows / friends / conversations 等 | 同上 |
| 反馈 | `GET|POST /api/v1/community/feedback` + `community_feedback` | 见 55 / 04 |
| 无 DB 或降级 | 部分读接口可返回空/占位；前端可保留 mock 兜底（按实现） | 部署须配置 `DATABASE_URL` 方可持久化 |

- **展示与交互**仍在前端（31）；**业务数据与写操作鉴权**以服务端为准。
- **尚未等同「完整生产级社区」**：举报/审核工单、推荐快照审计、大规模反刷与媒体对象存储等仍以 **160** Target 与 **270** 等为 SSOT，见下文 §四。

## 三、企业级标准对照（简要）

| 标准项 | 核心业务（订单/用户/向导/争议） | TT 社区（当前） |
|--------|--------------------------------|------------------|
| 业务数据单一来源 | ✅ 以 04 API 为唯一来源 | **①** Feed/互动/社交/子页以社区 API 为准；dev 空库 **showcase** 须披露（**[COMMUNITY-PHASE1-FREEZE](../../frontend/evidence/GO_local_marketing_front_closure/COMMUNITY-PHASE1-FREEZE.md)**），**非** 生产 mock 主路径 |
| 持久化 | ✅ 数据库 + migrations | ⚠ 有 DB 时落 `community_*` 等表；无 DB 时不持久化 |
| 鉴权与权限 | ✅ 需登录接口带鉴权 | ⚠ 写操作需登录；读操作按 04/31 定稿 |
| 可审计 / 可追溯 | ✅ 订单、争议、证据有审计要求 | ⚠ 基础落库已有；举报/处置全链路见 160 Target |
| 风控与限流 | ✅ 04 §四 有反刷/限流 | ⚠ 按产品与 160 继续加强 |
| 前后端契约 | ✅ 04 §三、14 前后端对齐 | ✅ 核心社区路由已入 04 §3.4；扩展见 31、160 |

## 五、小结

- **设计、排版、前端交互**：存于**前端**，符合企业级「展示层在前端」的划分。  
- **核心业务逻辑与数据**（用户、向导、订单、争议、证据、评价）：存于**后端 + 数据库**，业务数据同源、持久化、鉴权与审计按 04/01 落实，**符合企业级**。  
- **TT 社区**：**有 `DATABASE_URL` 时**核心数据走后端 API + DB，**部分符合**企业级；无 DB 或未配置时仍可能降级。**完整生产级**（审核、媒体、风控规模）以 **160**、**31** 为 SSOT 继续迭代。
