# 顶级 UI 标准：Landing / Discover / Itinerary（Awwwards / Stripe / Apple / 高端旅行）

**Version:** 1.2  
**用途**：在 [13-协议级UI设计宪法](13-协议级UI设计宪法.md)、[21-UI-3D-旅游Web3融合规范](21-UI-3D-旅游Web3融合规范-v1.0.md)、[22-Design-Tokens](22-Design-Tokens-旅游Web3融合体系-v1.0.md)、[23-UI交付物](23-UI交付物-Figma-Landing-Escrow模板.md) 基础上，将 **Landing / Discover / Itinerary** 提升至 Awwwards / Stripe / Apple / 顶级旅行品牌级别的高级感；**Escrow 保持银行级克制，不按本规范加花哨**。本文含 **§十～§二十一**：导演级方案（叙事脚本、滚动分镜、3D、动效时间轴、焦点图）、**§十六 Moodboard 三方向**、**§十七 五幕动画原型**、**§十八 Figma 层级**、**§十九 情绪色彩**、**§二十 Escrow 银行级基准**、**§二十一 仍缺的关键**。文档版本与最后更新见 [00-文档索引](00-文档索引.md)。

---

## 一、目标与对标

| 对标 | 要求 |
|------|------|
| **Awwwards / Stripe / Apple** | 视觉叙事清晰、动效统一克制、留白与焦点控制、高端感来自克制 |
| **顶级旅行品牌** | 沉浸 → 参与 → 信任 → 行动；情绪入口优先于功能罗列 |

**核心结论**：缺的不是「动画」，而是**视觉叙事逻辑**。顶级旅游首页是「情绪入口」，不是「漂亮图片 + 动效」或「产品化 Hero」。

---

## 二、六维度专业拆解

### 1. 视觉叙事层级

| 要求 | 说明 |
|------|------|
| **沉浸 → 参与 → 信任 → 行动** | 全站节奏按此四步；Hero 只做沉浸与一句主张，不讲功能/技术/USDC/snapshot |
| **单屏单焦点** | 每一屏只有一个视觉中心；多元素抢焦点即降级 |
| **留白** | 高端感约 50% 来自留白；页面过满则再多动效也显廉价 |

### 2. 动效哲学

| 要求 | 说明 |
|------|------|
| **统一节奏** | 全站主动效 **600ms**，次级 **200–300ms**；禁止有的快有的慢 |
| **统一缓动** | 建议 `cubic-bezier(0.22, 1, 0.36, 1)`，高级缓慢感；0.6～0.8 区间 |
| **少而准** | 动效贵在统一与克制，非数量 |

与 [21](21-UI-3D-旅游Web3融合规范-v1.0.md) 动效等级、[22](22-Design-Tokens-旅游Web3融合体系-v1.0.md) 动效 Token 一致；实现时全站采用同一组 duration + easing。

### 3. 旅行品牌质感

| 要求 | 避免 |
|------|------|
| 全宽分段、大图、轻微视差、柔和叠层、空间留白 | 卡片网格堆满、多列挤在一起 |
| 每段只讲一个目的地，图 + 叙事文本左右交替 | 信息密度过高、OTA 式列表 |

### 4. Web3 信任表达

| 要求 | 避免 |
|------|------|
| **不吵闹地表达可信**：Hero 下极简「On-chain secured」徽章，或行程单底部一句「Funds locked on Polygon.» | 大图标、多处 badge、强调 USDC/snapshot/技术术语 |

### 5. 页面节奏与空间控制

| 要求 | 说明 |
|------|------|
| **统一边距** | 上下边距、左右 padding、标题与内容距离全站一致；不一致即显不高级 |
| **单屏一焦点** | 见 §二.1 |
| **留白** | 见 §二.1 |

### 6. 高端感缺失点（须补齐）

- 微交互层（按钮 hover 轻微位移 2px、阴影变化、状态反馈）
- 页面转场（淡入、内容 stagger、旧页 fade out）
- 滚动叙事（scroll-based：图缓动、文案渐显、背景微动）
- 光影层次（subtle gradient overlay、background blur、远近层叠，且克制）

## 三、Landing 顶级标准

### 3.1 第一屏：沉浸式叙事（情绪入口）

**必须**：

- 视觉叙事优先：旅程在流动（如 3D 地球弧线/轻粒子），**不是**产品功能说明。
- 一句极简品牌主张 + 一句次级解释 + **单一 CTA**。
- 示例结构（可替换文案）：
  - `[沉浸式场景/3D 地球弧线]`
  - `Plan journeys. Lock trust on-chain.`
  - `AI-crafted itineraries secured by escrow.`
  - `[Start your journey]`

**禁止**：在第一屏讲功能、技术、USDC、snapshot、多 CTA 并列。

### 3.2 第二屏：旅行内容质感

- 全宽分段式展示；每段只讲一个目的地。
- 大图 + 轻微视差 + 柔和叠层 + 留白；图与叙事文本左右交替。
- 避免卡片网格堆满。

### 3.3 第三屏及以后

- 「How it works」等可保留，但视觉权重低于第一、二屏的叙事。
- 信任表达：极简徽章或一句「On-chain secured」/「Funds locked on Polygon.»，不喧宾夺主。

### 3.4 Landing 当前缺失模块（须补齐）

- 沉浸式叙事段（第一屏按 §3.1 重做）
- 滚动故事段（scroll-based storytelling）
- 高端视觉分段（全宽、大图、左右交替）
- 页面转场动画（进入/离开统一淡入、stagger）

## 四、Discover 顶级标准

| 要求 | 避免 |
|------|------|
| 目的地**故事化**呈现 | 纯卡片网格、OTA 式列表 |
| 视觉叙事分块、大图 + 叙事文本 | 多列小卡片堆叠 |
| 非卡片化布局为主 | 满屏小卡片 |

**当前缺失模块**：目的地故事化、视觉叙事分块、非卡片化布局。

---

## 五、Itinerary 顶级标准

| 要求 | 避免 |
|------|------|
| **杂志级排版** | 订单详情页式信息堆砌 |
| 按 Day 分段：Day 1 — Arrival in Tokyo + 大图 + 细节说明 + 小型费用卡片 | 表格式、密集列表 |
| 轻滚动动画、分段浮现 | 整页一次性展示 |

**结构示例**：

- Day 1 — Arrival in Tokyo  
  - 大图  
  - 细节说明  
  - 小型费用卡片  
  - 轻滚动动画  

**当前缺失模块**：杂志级排版、分段滚动动画、情绪转场。

## 六、动效与微交互规范（可落地）

### 6.1 全站统一

| 类型 | 数值 | 说明 |
|------|------|------|
| 主动效 | 600ms | 页面级、区块级 |
| 次级 | 200–300ms | 按钮、标签、小元素 |
| easing | `cubic-bezier(0.22, 1, 0.36, 1)` | 全站一致，高级缓慢感 |

与 [22](22-Design-Tokens-旅游Web3融合体系-v1.0.md) 动效 Token 对齐；若 22 未写死，以本文为准并回写 22。

### 6.2 微交互

- 按钮 hover：除颜色外，**轻微位移 2px**、阴影变化、明确状态反馈。
- 禁止仅颜色变化。

### 6.3 页面转场

- 新页：淡入 + 内容 stagger 出现。
- 旧页：轻微 fade out。
- 禁止无过渡的硬切。

### 6.4 滚动叙事

- 滚动时：图片缓慢移动、文本逐渐浮现、背景轻微运动。
- 节奏与 §6.1 一致，避免突兀。

### 6.5 光影层次

- 可选用：subtle gradient overlay、background blur、远近层叠。
- **必须克制**；不与 13「温和科技感」冲突。

## 七、3D 优化原则

| 要求 | 避免 |
|------|------|
| 3D 作**背景**：低对比、慢速呼吸、轻粒子 | 3D 当主角、高对比、强动效 |
| 不抢主视觉 | 太直接、太明显、太科技感 |

与 [21](21-UI-3D-旅游Web3融合规范-v1.0.md)「3D 只情绪层、不入侵资金区」一致；Landing/Discover 的 3D 仅服务沉浸，不喧宾夺主。

---

## 八、Escrow：不按本规范改动

- **Escrow 已对**：银行级、信息优先、克制动效。
- **高级不是花哨**：Escrow 保持当前规范，不增加 Landing/Discover 式叙事与动效。
- 以 [13](13-协议级UI设计宪法.md)、[21](21-UI-3D-旅游Web3融合规范-v1.0.md)、[23](23-UI交付物-Figma-Landing-Escrow模板.md) 中 Escrow 约定为准。

## 十、首页完整叙事脚本（Director Script）

**目标**：让用户经历一段**心理旅程**，而非仅看到功能说明。以下五幕按顺序落地，时间与节奏须严格执行。

### 第一幕：沉浸（0–6 秒）

| 维度 | 内容 |
|------|------|
| **视觉** | 深色柔和渐变背景；抽象地球弧线缓慢流动；轻粒子沿弧线移动 |
| **文案** | **H1**：`Plan journeys. Lock trust on-chain.` **副标题**：`AI-crafted travel itineraries secured by escrow.` **CTA**：`Start your journey` |
| **节奏** | H1 0.6s 淡入 → 副标题 0.8s 淡入 → CTA 1.0s 淡入 |
| **目标** | 建立「高端 + 安全」第一印象 |

**禁止**：在第一幕出现功能点、技术词、多 CTA。

### 第二幕：旅行叙事（Scroll 1）

| 维度 | 内容 |
|------|------|
| **视觉** | 大图全宽：如 Tokyo skyline at dusk；左侧或叠加文字区 |
| **文案** | `Day 1 — Arrival in Tokyo`；`A private transfer, curated dining, local exploration.` |
| **滚动时** | 图片轻微视差（约 5px）；文本缓慢出现；背景光线微移动 |
| **目标** | 营造真实旅行质感 |

### 第三幕：AI 智能生成

| 维度 | 内容 |
|------|------|
| **布局** | 左图右文 / 右图左文交替结构 |
| **文案** | `Designed by AI. Confirmed by humans.`；展示每日安排、预算分解、版本号、snapshotHash（小字） |
| **动效** | 数字**渐变出现**（opacity/translate），**禁止**数字跳动 |
| **目标** | 建立科技可信，不喧哗 |

### 第四幕：Escrow 可信展示

| 维度 | 内容 |
|------|------|
| **视觉** | 极简；背景从蓝过渡到浅灰；**抽象锁定动画**（非常克制） |
| **文案** | `Funds are locked on Polygon. Released only when completed.` |
| **目标** | 理性收束，为行动做铺垫 |

### 第五幕：行动召唤

| 维度 | 内容 |
|------|------|
| **视觉** | 大留白；CTA 居中 |
| **文案** | `Publish your itinerary. Travel secured.` + 主按钮 |
| **目标** | 转化 |

## 十一、滚动动画分镜脚本

全站滚动动效分为三类，实现时不得混用或随意加减速。

### A. 视差层（Hero & 旅行大图）

| 元素 | 参数 |
|------|------|
| 背景 | 移动约 **6px**（随 scroll） |
| 文字 | 移动约 **2px** |
| 粒子 | 延迟约 **100ms**（相对背景） |

### B. 内容 reveal（区块进入视口）

| 属性 | 数值 |
|------|------|
| opacity | 0 → 1 |
| translateY | 12px → 0 |
| duration | **600ms** |
| easing | **cubic-bezier(0.22, 1, 0.36, 1)** |

### C. 分段过渡（旅行段 → Escrow 段）

| 变化 | 说明 |
|------|------|
| 背景渐变 | 减弱 |
| 色温 | 暖 → 冷 |
| 视觉噪声 | 减少 |

即：从「旅行叙事」进入「可信 Escrow」时，整体氛围由情绪转向理性，动效与对比度同步收敛。

## 十二、3D 场景概念设计（Travel Network Visualization）

Landing Hero 的 3D 须统一为以下概念，与 [21](21-UI-3D-旅游Web3融合规范-v1.0.md) 一致并细化。

### 概念

| 项 | 要求 |
|------|------|
| **主体** | 半透明地球；细弧线连接城市；弧线尾部有光点流动 |
| **运动** | 轻微旋转（**3° 以内**）；粒子透明度 **20%–40%** |
| **材质** | Matte surface；**无金属高光**；**无镜面反射** |
| **光照** | 柔和 rim light；**无强对比** |

### 绝对禁止

- Neon glow  
- 大幅旋转  
- 用户拖拽交互（3D 仅作背景，不提供交互焦点）  

实现时以「Travel Network Visualization」命名该场景，便于与 21/22 Token 对齐。

## 十三、全站动效时间轴系统

与 §六 一致并**锁死**为下表，全站共用；Escrow 单独降速。

### 通用（Landing / Discover / Itinerary）

| 场景 | 参数 |
|------|------|
| **主节奏** | **600ms** |
| **次级** | **250ms** |
| **easing** | **cubic-bezier(0.22, 1, 0.36, 1)** |
| **页面进入** | 内容 stagger **80ms**；最大延迟 **400ms** |
| **按钮 hover** | scale **1.02**；shadow **+5%**；**150ms** |

### Escrow 页面（单独规则）

| 场景 | 参数 |
|------|------|
| **所有动画** | **≤ 200ms** |
| **类型** | 仅 **opacity** / **collapse**，无 scale/复杂位移 |

与 [21](21-UI-3D-旅游Web3融合规范-v1.0.md)、[22](22-Design-Tokens-旅游Web3融合体系-v1.0.md) 动效 Token 对齐；若 22 未写死，以本表为准并回写 22。

## 十四、视觉层级与焦点控制图

**规则**：**每一屏只有一个视觉中心**；焦点顺序明确，其余元素不抢戏。

### Landing 第一屏

| 顺序 | 元素 |
|------|------|
| 1 | **H1**（主标题） |
| 2 | **CTA**（主按钮） |
| 3 | **3D 背景**（最后注意，不先于文案） |

**不是** 3D 第一；文案优先。

### 旅行叙事段（第二幕、第三幕及 Discover/Itinerary 同类区块）

| 顺序 | 元素 |
|------|------|
| 1 | **图片**（大图/全宽） |
| 2 | **文字**（标题 + 说明） |
| 3 | 按钮永远在**第二层**，不压过图片与主文案 |

### Escrow 页面

| 顺序 | 元素 |
|------|------|
| 1 | **状态**（如 Funded / Completed） |
| 2 | **金额** |
| 3 | **操作按钮**（单一主操作 + 次操作） |

**无其他干扰**：无装饰动画、无叙事大图、无 3D。

## 十五、高端旅游站仍缺的关键项

以下五项须在实现中逐项闭合，验收时可对照 §九 与本节。

| 项 | 说明 |
|------|------|
| **情绪渐变过渡** | 从 Hero 到 Escrow 段，整体情绪由沉浸 → 信任 → 行动，视觉与动效须有渐变（见 §十一 C） |
| **分段叙事结构** | 五幕清晰分段，每段单焦点、留白充足，不挤在一屏 |
| **空间节奏控制** | 统一边距、统一 padding、标题与内容距离全站一致（见 §二.5） |
| **光影层次** | Subtle gradient overlay、background blur、远近层叠，且克制（见 §二.6、§六.5） |
| **统一缓动曲线** | 全站仅使用 **cubic-bezier(0.22, 1, 0.36, 1)**，无例外（见 §六.1、§十三） |

## 十六、视觉 Moodboard（三套高端方向）

**原则**：不做「炫酷」，做「高级感控制」。三方向可选，**建议以方向 B 为主 + 方向 A 的排版质感**。

### 方向 A：Minimal Luxury Travel（高端杂志风）

| 维度 | 内容 |
|------|------|
| **关键词** | 大留白、超大图、柔光、高端杂志排版、低对比渐变 |
| **视觉特征** | 图片占约 **70%**；文本极少；**Serif + Sans** 组合；灰白 + 柔蓝点缀；3D 极淡 |
| **适合定位** | 高端私人旅行 / 轻奢品牌 |
| **优点** | 高级、克制 |
| **缺点** | 科技感偏弱 |

### 方向 B：Gentle Tech Travel（科技 × 旅行融合）★ 主方向

| 维度 | 内容 |
|------|------|
| **关键词** | 冷蓝空间、光轨、地球弧线、空间渐变、低饱和 |
| **视觉特征** | 深蓝 + 柔光粒子；AI 行程分段叙事；细线图标；轻微视差 |
| **适合定位** | 本产品（TravelTrust） |
| **优点** | 科技与旅行平衡 |
| **缺点** | 需严格动效控制（见 §六、§十三） |

### 方向 C：Calm Earth Modern（自然极简）

| 维度 | 内容 |
|------|------|
| **关键词** | 大地色、米色、极简、真实摄影、减科技 |
| **视觉特征** | 温暖背景；旅行摄影主导；Web3 仅在底部表达；3D 几乎无 |
| **优点** | 极易让普通人接受 |
| **缺点** | Web3 属性弱 |

**落地方案**：**方向 B 为主 + 方向 A 的排版质感**（大留白、Serif+Sans、高端杂志式分段）。

## 十七、Landing 五幕动画原型分镜（导演级）

与 §十 叙事脚本对应，本节约定**动画与转场**的视觉与节奏，实现时按秒与场景执行。

| 场景 | 时间/触发 | 视觉与动效 |
|------|-----------|------------|
| **Scene 1 – Hero** | 0–5 秒 | 黑蓝渐变背景；半透明地球；光点缓慢移动；文案淡入 `Plan journeys. Lock trust on-chain.`；粒子 **3° 轻旋**；CTA **轻浮动** |
| **Scene 2 – Scroll 转场** | 随滚动 | 背景由**深蓝 → 浅灰**；地球渐渐淡出；旅行图片浮现 |
| **Scene 3 – Itinerary 杂志段** | 随滚动 | 大图；标题渐显；文本 **stagger 出现**；预算卡片滑入 |
| **Scene 4 – Escrow 可信段** | 随滚动 | **视觉收缩**；背景极简；文案 `Funds secured. Released only when completed.`；**轻微锁定动画**（极克制） |
| **Scene 5 – Final CTA** | 随滚动 | 大留白；按钮居中；**轻呼吸动画**（非常弱） |

与 §十一 滚动分镜、§十三 时间轴一致；Escrow 段无粒子/无 3D/无强动效。

## 十九、情绪色彩控制图

全站按**三阶段情绪**控制色调、明度与对比；与 §十一 C、§十七 分段过渡一致。

| 阶段 | 页面/区块 | 色调 | 明度 | 对比 | 感觉 |
|------|------------|------|------|------|------|
| **情绪 1：探索** | Landing Hero、Discover 入口 | **冷蓝 + 光点** | 中 | **低** | 空间感 |
| **情绪 2：沉浸** | Itinerary、旅行叙事段 | **摄影主导**（真实大图） | **高** | **柔和** | 旅行真实 |
| **情绪 3：可信** | Escrow、Dispute、协议控制台 | **深灰蓝** | **低** | **高** | 严肃、银行级 |

实现时：Landing → Itinerary 段可带渐变与柔光；进入 Escrow 段须收束为 §二十 的极简与单色。

## 二十、Escrow 银行级视觉基准样板

Escrow 必须达到以下比例与规则，**无例外**；参考风格：Stripe Dashboard、银行 App、Coinbase 交易确认页。

### 页面结构比例

| 区域 | 占比 | 内容 |
|------|------|------|
| 顶部状态区 | **20%** | 订单/托管状态、链信息 |
| 主金额区 | **20%** | 金额、币种、释放条件 |
| 事件区 | **40%** | 时间线/事件列表（创建、入金、释放、争议等） |
| 操作区 | **20%** | 主按钮 + 次按钮、风险提示 |

### 视觉规则（必须做到）

| 规则 | 说明 |
|------|------|
| **无渐变** | 背景与面板均为单色或极简分割 |
| **无 3D** | 禁止任何 3D、地球、粒子 |
| **无粒子** | 禁止光点、光轨、动态粒子 |
| **无图像背景** | 禁止大图、摄影背景 |
| **单色主按钮** | 主操作使用 Trust 轴单色，不发光、不渐变 |
| **明确边界线** | 区块之间用清晰分割线或留白，不依赖阴影堆叠 |

与 [13](13-协议级UI设计宪法.md)、[21](21-UI-3D-旅游Web3融合规范-v1.0.md)、[23](23-UI交付物-Figma-Landing-Escrow模板.md) 中 Escrow 约定一致；验收时逐条核对。

## 二十一、仍缺的关键（本质）

**缺的不是动画，而是以下三项**；实现与验收时优先闭合。

| 项 | 说明 |
|------|------|
| **情绪节奏控制** | 全站从「探索 → 沉浸 → 可信」须有清晰情绪曲线；Landing 到 Escrow 的视觉与动效须**收放有度**（见 §十九、§十一 C、§十七） |
| **视觉层级收放** | 旅行段可「放」（大图、留白、叙事）；Escrow 须「收」（比例固定、无装饰、单焦点）；层级切换处不得突兀（见 §十四、§二十） |
| **3D 与真实摄影融合** | Hero 用 3D（Travel Network Visualization）；叙事段用**真实摄影**大图；二者之间过渡须自然（色温、饱和度、节奏一致），不出现「3D 与照片各说各话」 |
