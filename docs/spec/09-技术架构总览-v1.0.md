# 1. 项目技术定位

TravelTrust 是一个：

- 基于 EVM 的去中心化托管协议（Escrow）
- Rust 驱动的企业级后端
- 分布式 SQL 能力（**当前接库：PostgreSQL**；**目标拓扑：CockroachDB**，见 [41-后端数据库接库与落地清单](41-后端数据库接库与落地清单.md) §1.0）支撑的全球可扩展系统
- Web3 DApp + 3D 展示型前端

核心原则：

> **链为资金真相**  
> **DB 为业务检索与可重建投影**  
> **所有链状态必须可回放**  
> **所有资金终态必须可审计**

# 3. 分布式数据库设计（CockroachDB）

## 3.1 设计原则

- 强一致事务
- 避免单行热点
- Append-only 优先
- 投影可重建
- 纠偏只追加不覆盖

## 3.2 核心表分组

### 业务真相（DB 为准）

- users
- guides
- orders
- disputes
- evidence_objects
- audit_log

### 链事件真相（链为准）

- event_log（append-only）
- checkpoints_sharded（分片 checkpoint）
- escrow_mapping

# 4. 数据流闭环

## 4.1 支付流程

用户点击支付 → wagmi 写链 deposit → Polygon 打包 → 12 confirmations → Indexer 写 event_log → Projector 更新 orders_projection → API 返回最新状态 → 前端刷新。

**资金状态永远来源于链事件。**

## 4.2 争议执行流程

仲裁员裁决 → 后端审批 → Executor 发 executeResolution → 链上事件 → Indexer → Projection → 状态更新。

`resolutionId = keccak256(chainId, orderId, resolutionSeq, decisionHash)`

# 5. Finality 与 Reorg 策略

- **finalityN = 12**
- event_log 记录 blockHash + logIndex
- 检测 txHash 不同 blockHash → 触发 reorg
- 回退安全高度 → 重放事件 → 投影重建
- 副作用幂等

# 12. 关键主链路（最高优先级）

TravelTrust 最核心业务链路如下，属于跨层一致性的第一优先级检查项：

`旅行者创建需求 -> AI/自定义行程生成 -> 向导接单与沟通 -> 双方确认最终行程 -> confirm-final-plan -> 创建/绑定 Escrow -> 钱包支付托管 -> 旅游服务履约 -> 链下确认行程完成（confirm-completion，非放款）-> 完成或争议 -> （Happy）行程评分（若适用）→ 智能合约 release；（争议等）仲裁执行/退款处罚 → 结算/对账/审计归档`

该主链路与 **[07-开发流程与顺序](07-开发流程与顺序.md) §五 5.1 / 5.2**（订单与撮合、行程与报价）保持一致（**Happy：链下行程完成确认 → 评分 → 链上 release**，**confirm-completion** 与 **release** 解耦见 [04](04-后端与API.md) §3.4、[14](14-合约-API-ABI-前后端对齐.md)；与 [02-架构设计](02-架构设计.md) §14.3、[18-TravelTrust-全系统架构图](18-TravelTrust-全系统架构图.md) §七、[53-阶段开发技术文档](53-阶段开发技术文档.md) 一致）。

# 13. 五个真正中心（系统重心）

从企业级治理视角，全系统围绕以下五个中心运转：

1. 订单中心：`itinerary / order / schedule / review`
2. 协议中心：`escrow / events / tx / finality / dispute`
3. 风控仲裁中心：`risk / blacklist / dispute / evidence / ruling`

5. 运营治理中心：`admin / audit / moderation / config / settlement`

任何新增模块应先映射到上述中心之一，再决定其归属层与依赖边界。

# 14. 最终分层结论（五层混合平台）

TravelTrust 的最终形态不是单一 Web 站点，也不是纯 DApp，而是五层混合平台：

- 体验层：Web + DApp + 社区 + 3D 展示
- 业务层：行程 / 订单 / 聊天 / 评论 / 仲裁
- 协议层：Escrow 合约 / 链上事件 / Finality / 对账
- 平台层：AI / 规则 / 配置 / 任务 / 搜索 / 推荐 / 审批
- 运行层：云部署 / 观测 / 安全 / 审计 / 发布 / 灾备

该五层结论与本文件 `2.x` 技术栈定稿、`11.x` 九层工程分层并行成立：

- `11.x` 用于工程拆层与组件落位。
- `14` 用于业务与治理视角的高层沟通与决策。
