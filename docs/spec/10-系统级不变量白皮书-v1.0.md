# 1. 定位与范围

本白皮书给出**系统级不变量**：在任意实现、升级与运维下**不得被违反**的硬约束。违反任一条且未走显式例外流程（留痕+复盘+补救）视为门禁失效。

- **资金类**：余额、释放、幂等、终态来源  
- **状态机类**：订单与争议状态迁移合法性  
- **数据类**：append-only、投影可重建、纠偏只追加  
- **分布式与 Reorg**：finality、回退、重放、checkpoint  
- **执行器类**：原子性、双人、限额、不可篡改  
- **叙事与产品步骤（非新不变量，防漂移）**：对外与实现描述中 **Happy 路径**须与 [01](01-总库总览.md) §〇、[03](03-业务流程与风控.md)、[53](53-阶段开发技术文档.md)、[04](04-后端与API.md) §3.4 一致：**链下确认行程完成（`confirm-completion`）→ 行后评分（若适用）与双方确认 → 再链上 `release`**；**不得**将 `POST confirm-completion` 与单笔放款等同；不得与「仅 DB/接口即视为已放款」混谈（资金终态仍以链上事件为准，见 F4、01）。

# 2. 资金类不变量

| # | 不变量 | 含义 | 可验证方式 |
|---|--------|------|------------|
| **F1** | Escrow 合约内余额 ≥ 所有未释放订单金额 | 链上余额不得小于应付未付总和 | 合约只读 + 投影汇总校验 |
| **F2** | resolutionSeq 必须严格递增 | 同一 orderId 下裁决序号单调递增，不允许回退或重复 | 事件与 DB 约束 |
| **F3** | 同一 resolutionId 不可执行两次 | resolutionId 全局唯一，重复执行必须拒绝 | 链上检查 + 幂等键 |
| **F4** | DB 不得直接修改资金终态 | 资金终态（已支付/已退款/已扣罚等）仅来自链事件；DB 仅缓存与索引 | 01 链为准、17 条 #2/#12、对账设计 |

---

# 3. 状态机不变量

| # | 不变量 | 含义 | 可验证方式 |
|---|--------|------|------------|
| **S1** | Order 状态仅允许合法迁移 | CREATED → PAID → COMPLETED；CREATED → PAID → DISPUTE → RESOLVED；不允许跳跃或回退 | 01 状态机、03、投影与 API 校验 |
| **S2** | 非法转移必须拒绝 | 未在 01/03 定义的转移不得被投影或 API 接受 | 投影与 API 实现、E2E |

---

# 4. 数据不变量

| # | 不变量 | 含义 | 可验证方式 |
|---|--------|------|------------|
| **D1** | event_log 永远 append-only | 链事件表只追加，不覆盖、不删除 | 表约束、迁移策略 |
| **D2** | correction_log 只能追加 | 纠偏与对账修正只追加记录，不覆盖历史 | 表约束、Runbook |
| **D3** | 投影可随时重建且结果一致 | 从 event_log + checkpoint 重放得到的投影与当前 orders_projection 一致（在无并发纠偏窗口内） | 重放脚本、对账报告 |

---

# 5. 分布式一致性与 Reorg 不变量

| # | 不变量 | 含义 | 可验证方式 |
|---|--------|------|------------|
| **R1** | 任意 Reorg 后最终状态与链一致 | 回退到安全高度并重放后，DB 状态与链上终态一致 | Reorg Runbook、重放测试 |
| **R2** | Indexer 不得依赖非 Final 区块产生不可逆副作用 | 仅 finalityN 确认后的区块驱动资金/投影变更 | 01 §5、02 §七 |
| **R3** | Checkpoint 永远小于安全高度 | checkpoint 不超过 (currentBlock - finalityN) | 实现与监控 |
| **R4** | finalityN 小于该值的状态不得作为可执行终态 | 未达 finality 的区块不驱动「可执行」终态（如放款） | 01 §5、执行器逻辑 |

# 6. 执行器不变量

| # | 不变量 | 含义 | 可验证方式 |
|---|--------|------|------------|
| **E1** | executeResolution 原子性 | 单次调用要么全成功要么全失败，无部分执行 | 合约与执行器实现 |
| **E2** | Executor 无法单人执行 | 双人审批或多签，无单点可触发资金终态变更 | 01 §7、Runbook §7 |
| **E3** | 审批记录不可篡改 | 审批链 append-only，可审计 | 表约束、08-4 |

# 7. Reorg / Idempotency 硬规则（SSOT 必含）

与 [07 开发流程](07-开发流程与顺序.md)、[01 §5/§9](01-总库总览.md) 一致；SSOT 与状态机设计须显式包含以下规则：

| # | 规则 | 说明 |
|---|------|------|
| **IR1** | 允许的失败/撤销语义 | Draft 能否取消、Confirmed 能否过期、Funded 能否超时自动 dispute 等写死 |
| **IR2** | Reorg 影响 | 哪些状态仅在 finality 后生效；reorg 后 disputeWindow 是否重算写死 |
| **IR3** | 幂等策略 | 同一 tx 重复上报/重复消费事件的处理（拒绝/去重/结果复用）写死 |
| **IR4** | event 主键与唯一性 | (chain_id, tx_hash, log_index) 主键；block hash 变化触发回滚策略 |
| **IR5** | 可执行终态门禁 | finalityN 以下的状态不参与「可执行」决策 |

# 8. 与 01 §10、08-1 宪法五条的对应

**与 01 §10 系统级不可违反不变量（最终版）**：01 资金类→F1/F3/F4；映射类（orderId↔escrow 唯一）→17 条 #4、合约约束；状态类→S1/S2；事件驱动类→F4、D3、R2/R4；治理类→08-3 变更留痕；执行器类→E1/E2/E3。本白皮书为 01 系统级不变量的**可验证化展开**，与 01 §10 无冲突。

**与 08-1 宪法五条**：[08-1 系统级不变量（宪法级条款）](08-1-战略与合规风险检查清单.md#系统级不变量宪法级条款—绝对不允许被破坏) 五条与本白皮书对应关系：

| 08-1 宪法条 | 本白皮书 |
|-------------|----------|
| 用户资金最终状态只能来自链事件 | F4、D3、R1 |
| 任意人工操作必须可追溯 | E3、Runbook、08-3 变更记录 |
| 任意参数修改必须留痕 | 08-3、W-PARAM-ABUSE |
| 任意裁决必须可回放 | E1、E3、D2、证据链 |
| 任意发布必须可验证 | Q6、07、W-Q6-FE、W-BOMB-10 |
