## 1. 页面定位（一句话）

**TT社区采用与 DID 排行榜相同的 Web3 赛博朋克风格（深色底、霓虹青/品红、网格与光晕），以信息流形式承载旅行者与向导发布的照片、旅游分享、美食、旅游视频等 UGC；支持发帖、点赞、收藏、评论与按主题/作者筛选；不在此页做支付与撮合，Web3 以 DID/向导标识、可选内容上链或 NFT 铸造等克制露出。**

---

## 2. UI 设计风格：与 DID 排行榜同一类（赛博朋克）

**明确**：TT社区与 DID 排行榜属于**同一类视觉语言**（**卡片/Feed 霓虹 cyan + fuchsia**），与 28/29 的 Cinematic 玻璃态不同；**页身基座**与 **自由市场 / DID 排行榜** 对齐 **TravelTrust 暖场**（见下表与 **[88](88-五主路由页身实现快照与UX缺口审计-20260330.md)**）。

| 维度 | 要求 | 依据 |
|------|------|------|
| **风格类型** | **Web3 赛博朋克**：动感、科技、霓虹（**内容区**） | 30-DID排行榜 §4.2～4.4 |
| **背景（壳层真值）** | **`#14100d` + `WarmRouteFieldBackdrop`** + **`bg-web3-podium-spotlight`** + **静态 `bg-scifi-gradient-static`** + 径向柔光；**壳层不挂载** `Web3SciFiBackground`、**不用** `bg-scifi-grid`、**不用** `animate-did-gradient` / `animate-did-bg` 驱动整屏背景 | **88 §一**；`app/community/layout.tsx` |
| **主色** | **cyan**（旅行/发现侧）+ **fuchsia**（创作者/互动侧）；标题可用渐变字 `from-cyan-300 via-cyan-400 to-fuchsia-400` | 30 §4.2 |
| **卡片/面板** | `bg-slate-900/70`、`backdrop-blur-md`、霓虹边框（`border-cyan-500/30` / `border-fuchsia-500/30`）、`shadow-[0_0_20px_...]`；hover 加强 | 30 §4.2 |
| **动效** | 卡片 hover 光晕、`motion-sub`、支持 `prefer-reduced-motion` 减弱 | 30 §4.3 |
| **圆角** | `rounded-lg`（与赛博感一致，可略大于 28 的 radius-sm） | 30 §4.4 |

实现时**复用 30 §4.2～4.4 的色值与类名**；**页身背景**以 **`WarmRouteFieldBackdrop` + 静态赛博叠层** 与 **`/did-rank`** 一致，**勿**在壳层恢复整屏 `animate-did-gradient` 或 Three 粒子，除非产品变更并更新 **88**。

## 3. 功能定位：小红书式 UGC（旅行者 + 向导）

### 3.1 谁可以发帖

| 角色 | 说明 |
|------|------|
| **旅行者** | 发布旅行见闻、照片、美食、短视频；可带目的地/标签。 |
| **向导** | 发布行程花絮、接待故事、目的地推荐、美食与视频；可带「Escrow 向导」等标识。 |

### 3.2 内容类型（与小红书对齐）

| 类型 | 说明 |
|------|------|
| **照片** | 单图/多图；支持上传、裁剪与简单标签。 |
| **旅游分享** | 图文/纯文字；目的地、行程心得、攻略片段。 |
| **美食** | 图片+文案；餐厅、小吃、当地特色。 |
| **旅游视频** | 短视频；上传、封面、时长限制（如 60s/3min）。 |

### 3.3 互动能力

- **点赞、收藏、分享**（图标+数字）
- **评论**（一级或二级）
- **关注作者**（旅行者/向导）
- **筛选与排序**：按「最新 / 最热」、按目的地、按作者（向导/旅行者）、按内容类型（照片/视频/美食等）

### 3.4 与业务边界

- **不在此页做**：下单、支付、撮合、Escrow 存款/释放（这些在 29 自由市场与 Escrow 详情页）。
- **可做**：内容上链存证、帖子可选铸造为 NFT（需单独产品与后端设计）；作者身份展示「DID / Escrow 向导」徽章。
- **订单相关聊天（53 阶段）**：**订单相关聊天的唯一入口**为 04 `GET|POST /api/v1/orders/:id/messages`；向导抢单后可在 TT 社区关注旅行者，双方在**消息**中沟通并修改行程，订单关联会话以该 API 为准，详见 [53-阶段开发技术文档](53-阶段开发技术文档.md) §3.1、§3.3。禁止在 31 或前端另建一套「订单聊天」接口。
- **与个人中心互通（2026-06-03 代码）**：**裸 `/community/me` → redirect `/me/settings/profile`**；UGC 在 **`/community/me/posts|collects|likes|reports`**。**订单/行程主入口**在 **`/me`** / **`/me/orders`**（个人中心）；L1「我」或顶栏资料链走 redirect/子页 — 见 [13-1 互通表](13-1-UI产品级SSOT与页面规范.md) · [`app/community/me/README`](../../frontend/app/community/me/README.md)。

## 4. 主流与最前沿 Web3 社区页面设计参考

以下为当前主流 Web3 社交/社区产品的设计共性，供 TT社区 实现时对齐或选型参考。

### 4.1 协议与产品

| 产品/协议 | 特点 | 对 TT社区的参考价值 |
|-----------|------|----------------------|
| **Lens Protocol** | 用户档案即 NFT、可组合社交图、Lens Chain 低成本；Feeds / Groups 模块化 | 信息流与关注关系可抽象为「图」；创作者身份可链上可验证。 |
| **Farcaster** | 链上身份 + 链下内容；Frames 让帖子内嵌互动（如 NFT 铸造、投票） | 帖子可扩展为「带行动」的卡片（如一键预约向导、收藏为 NFT）。 |
| **Xora Social** | 三栏布局：左导航、中 Feed（For You/Following）、右 Trending + 建议；**帖子可选 mint 为 NFT** | 布局可参考：主 Feed + 侧边「热门/推荐」；发帖入口明显；可选「铸造为 NFT」。 |
| **Phaver** | 跨 Lens/Farcaster；游戏化积分与信誉（Phaver Cred）；低门槛登录 | 信誉/等级可视化（向导 vs 旅行者、DID 认证）增强信任；可考虑积分/激励与防机器人。 |
| **Orb Club** | 基于 Lens；用「可收集贴纸包」替代传统点赞，创作者可变现 | 互动形式可扩展：不止点赞，可为打赏、收藏为 NFT、贴纸等。 |

### 4.2 信息流与布局

| 设计点 | 主流做法 | 建议 TT社区 |
|--------|----------|-------------|
| **Feed 切换** | 「For You / Following」或「推荐 / 关注」双 Tab | 支持「推荐 / 关注」；可选「最新 / 最热」排序。 |
| **发帖入口** | 顶部或侧边醒目「发布」按钮；支持文字+图片+视频 | 顶部或悬浮「发布」；上传照片/视频、选择类型（旅游/美食/视频）、带话题/目的地。 |
| **卡片内容** | 媒体（图/视频）+ 文案 + 作者头像/昵称 + 互动条（点赞/评论/分享/收藏） | 与 §5 卡片结构一致；媒体优先，文案折叠/展开。 |
| **媒体渲染** | 图片/视频/音频统一组件（如 thirdweb MediaRenderer）；支持 IPFS/HTTP | 照片与视频首帧或播放器；考虑 IPFS/Arweave 存图与链上存证。 |
| **侧栏** | 热门话题、推荐关注、通知入口 | 可选右侧「热门目的地 / 推荐作者」；与赛博风面板统一。 |

### 4.3 创作者与 Web3 身份

| 设计点 | 主流做法 | 建议 TT社区 |
|--------|----------|-------------|
| **身份展示** | 头像、昵称、链上 ID 或 DID 简写；认证/徽章 | 作者区：头像 + 昵称 + 「向导」/「旅行者」+ 可选「DID」「Escrow 向导」pill。 |
| **内容权属** | 帖子可 mint 为 NFT，权属上链 | 可选「存证/铸造」入口，不强制；与产品与合约设计同步。 |
| **激励** | 积分、代币打赏、收藏即 mint | 先做点赞/收藏/评论；打赏或 NFT 后续按产品与合规设计。 |

### 4.4 小结：TT社区可采纳的前沿点

- **布局**：主 Feed（单列或瀑布流）+ 可选侧栏（热门/推荐）；发帖入口固定可见。
- **内容形态**：照片/视频/图文统一卡片；媒体优先、文案可折叠；支持多图与短视频。
- **身份**：旅行者/向导双角色发帖；DID、Escrow 向导等徽章克制露出。
- **互动**：点赞、收藏、评论、分享；后续可扩展打赏、NFT 铸造、Frames 式轻应用。
- **技术**：信息流 API（分页/游标）、媒体上传与存储（含可选 IPFS/链上存证）。

## 11. API 与数据契约（建议，待 04 落点）

以下为**推荐**的社区 API 设计，便于与 04 对接；实现时以 04 §三 正式路由为准。**最佳实践**：信息流采用**游标分页**（cursor），避免 offset 在实时数据下重复/遗漏；限流与幂等与 01/04 一致。

### 11.1 Feed 列表

| 项 | 建议 |
|----|------|
| **路由** | `GET /api/v1/community/posts` 或 `GET /api/v1/community/feed` |
| **分页** | `cursor`（不透明）+ `limit`（默认 20）；响应含 `next_cursor`、`has_more` |
| **排序** | `sort=latest | hottest`；可选 `destination`、`content_type`（photo/video/food/travel） |
| **筛选** | `feed=recommended | following`；`destination`、`content_type` 为可选过滤 |
| **限流** | 与 04 风控一致；建议读多写少场景下列表限流放宽、发帖/互动限流收紧 |

### 11.2 发帖与媒体

| 项 | 建议 |
|----|------|
| **发帖** | `POST /api/v1/community/posts`：body 含 type（photo/video/food/travel）、content（文案）、media_ids[]（先上传后关联）、destination、tags[] |
| **媒体上传** | `POST /api/v1/community/media`：multipart；返回 media_id、url；**文件类型与大小**白名单（如 JPG/PNG/WebP/MP4，单文件 ≤10MB/视频 ≤50MB）；存储与 CDN 由后端/运维定稿 |
| **幂等** | 发帖建议支持 `idempotency_key` 或 `request_id`，与 04 §四 一致 |

### 11.3 互动

| 项 | 建议 |
|----|------|
| **点赞/收藏** | `POST /api/v1/community/posts/:id/like`、`POST /api/v1/community/posts/:id/collect`（或 toggle）；鉴权必选 |
| **评论** | `GET /api/v1/community/posts/:id/comments`（游标分页）；`POST /api/v1/community/posts/:id/comments` |
| **关注** | `POST /api/v1/community/authors/:id/follow`（或用户体系已有 follow 接口复用） |

### 11.4 帖子与作者最小字段（前端展示）

| 实体 | 建议最小字段 |
|------|--------------|
| **Post** | id, author_id, author_nickname, author_avatar, author_role(tourist/guide), author_badges[]（DID/Escrow）, type, content, media_urls[], destination, tags[], like_count, collect_count, comment_count, created_at, status(visible/pending/rejected) |
| **Comment** | id, author_id, author_nickname, author_avatar, content, created_at |

## 12. 内容审核与合规（企业级最佳实践）

UGC 平台须在**品牌一致性、合规与用户体验**之间平衡；以下为业界通用做法，实现时与法务/运营定稿。

| 维度 | 最佳实践 | TT社区建议 |
|------|----------|------------|
| **策略** | 先发后审（发布即可见，违规下架）或先审后发（待审期间仅作者可见）；结合 AI + 人工复核 | 先发后审可缩短体验；敏感词/图片策略与 04 风控一致；违规内容不展示详情、可展示「已隐藏」 |
| **举报** | 用户可举报单条；后端记录并进入审核队列；对重复举报/恶意举报限流 | 卡片提供「举报」入口；举报后 toast「已提交，我们会尽快处理」 |
| **违规处理** | 明确社区规范（链接至 terms/community-guidelines）；违规可删帖、限流、封禁 | 规范文档待法务；前端仅展示「内容违规已隐藏」或移除，不暴露审核细节 |
| **规模** | 高并发时 AI 预筛 + 人工抽检；品牌/旅行场景可加强涉黄涉暴与违禁词过滤 | 与 04 反刷/限流、01 §4 风控一致；P2 可先人工抽检，P3 接入 AI 与策略配置 |
