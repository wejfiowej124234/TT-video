**结论（与产品阶段一致）：** **不能**用 **86**「统一全站」替代 **04 / 13 / 13-1**。**86** 是 **P1 体验层 SSOT**，且受 **92 + 13** 约束。

## 3. 冲突规则（摘要）

1. **P1 不得改变**：路由结构（**04 §3.4**、**13-1**）、资金交互模型、Token 分配与链上/协议叙事真源（**83/84** 等）、API 契约。  
2. **P1 可增强（在允许区内）**：非资金决策 UI 的动效、视觉层级、引导与叙事外壳（须符合 **86** 篇内分区表 + **92**）。  
3. **P1 与 P0 冲突**：**以 P0 为准**；**须改 P1（86）或改分区表（92）时**，**不得**单文件绕过 **13**/**13-1**/**04** 已定条款。  
4. **若需「加严」现行 13/86 已放行的路由（例如讨论稿要求 `/traveltrust`、`/market` 完全禁止一切 86 增强）**：属于 **宪法级产品决策**，**须** **13 / 13-1 / 86 §0.3 / 92** **同批修订** 并走 **[07-开发流程与顺序.md](07-开发流程与顺序.md)** 与 **[CONTRIBUTING.md](../../CONTRIBUTING.md)** 约定；**单改本篇无效**。

## 4. 资金区 · 风控级动效纪律（操作摘要）

**真源对读（勿在本篇单写新路由表）：**

- **哪些算资金区、哪些动效绝对禁止**：**[13](13-协议级UI设计宪法.md) §一**（尤其 **1️⃣** 补充款）。  
- **逐路由分区与 86 应用级别**：**[86](86-UI-双系统未来风-风格与动效技术规格.md) §0.3**、**§6**。  
- **F/X/G 一页纸裁决**：**[92](92-P0-全站UI分区控制表-金融体验灰区与动效裁决.md)**。

**原则级复述（与上列冲突时以上列为准）：**

- **Escrow、支付/签名主路径、争议金额与裁决主操作区**：**银行级克制**；**禁止**粒子、强装饰动效、3D 入侵主任务。  
- **通常允许**：**skeleton**、**fade**、**步骤过渡** 等低风险反馈（见 **86** 对 Protocol/资金分区的细则）。
