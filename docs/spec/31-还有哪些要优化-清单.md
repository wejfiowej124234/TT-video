## 一、TT 社区 · 前端可做（不依赖后端）

| 项 | 说明 | 优先级 |
|----|------|--------|
| **下拉刷新** | 对标清单 P2：移动端 Feed 下拉刷新（Pull-to-refresh），接 API 后在此触发 refetch。 | P2 |
| **长列表虚拟滚动** | 若 Feed/评论列表很长，可引入虚拟列表（如 react-window）减轻 DOM 与滚动卡顿。 | P2（按数据量） |

## 四、其他模块 · 可选优化

| 项 | 说明 |
|----|------|
| **CustomItineraryModal** | 组件体量较大（约 2300 行），可考虑：拆分为子组件（步骤/表单/预览等）、非首屏区块懒加载（dynamic）、对纯展示子组件使用 `React.memo`，以利维护与首屏/切换性能。 |
| **全站性能** | 已有图片 lazy、路由 loading；可选：bundle 分析（如 `@next/bundle-analyzer`）、关键路由 LCP 测量、大依赖按需引入。 |
| **市场/托管/其他页** | 若有类似「页面切换卡顿」或复杂弹窗，可复用社区经验：条件渲染重背景（如 Three）、Tab 组件 memo、rAF 延后 scrollTo。 |
