## 一、文档定位与范围

| 维度 | 说明 |
|------|------|
| **弹窗入口** | 发现页/市场页「写行程」「发行程」等入口，打开同一弹窗，通过 `creatorType` 切换游客/向导两种模式。 |
| **游客端** | 用户填写目的地国家、按天城市、景区/餐饮/酒店、城市交通与跨城交通、向导等级、人数、预算等；系统给出报价清单与费用估算。 |
| **向导端** | 向导按天填写城市、景区/餐饮、选择平台酒店与城市交通、跨城方式；填写景区/餐饮每人费用；系统计算酒店/交通/向导费并展示报价清单。 |
| **计费统一** | 游客与向导两套逻辑在「按人/按车」、交通明细展示、报价清单结构上保持一致，便于前后端与产品对齐。 |

## 二、常量与配置

以下常量在组件顶部定义，所有计费与校验均依赖它们。

### 2.1 行程与人数

| 常量 | 值 | 说明 |
|------|-----|------|
| `TOTAL_DAYS_OPTIONS` | [1, 2, 3, 5, 7, 10, 14] | 可选行程天数；提交时天数限制 1～30。 |
| 人数范围 | 1～20 | 表单 `headcount` 的合法范围。 |

### 2.2 费用单价（按国家取价）

**单价来源**：所有费用单价均来自 **[44-阶段-国家独立定价模块](44-阶段-国家独立定价模块.md)** 的 `getPricingForCountry(form.country)`，各国独立配置，实现见 `frontend/lib/countries/`。下文为**计费口径说明**（数值以默认国家为例，实际按所选国家变化）。

| 配置字段 | 含义 | 计费规则 |
|----------|------|----------|
| perAttraction | 景区每人每处单价 | 游客端：项数 × 单价 × 人数。 |
| perFood | 餐饮每人每处单价 | 游客端：项数 × 单价 × 人数。 |
| hotelPerNightPerPerson | 酒店每晚每人单价 | 总价 = 晚数 × 单价 × 人数；游客与向导一致。 |
| cityTransportPrice | 城市交通每车每天（sedan/suv/van） | 按天汇总，不乘人数。 |
| intercityPricePerPerson | 跨城飞机/高铁每人每段 | 总价 = 段数 × 对应单价 × 人数。 |
| guideLevelsSuggestedPerDay | 向导等级建议日薪（初级/中级/高级/专家） | 向导费 = 建议日费 × 天数。 |

### 2.3 业务规则

| 常量/规则 | 值/说明 |
|-----------|--------|
| `SEDAN_CAPACITY` | 4；当人数 > 4 且当日选「轿车」时，展示提示：建议选 SUV/商务。 |
| `MAX_AMOUNT` | 999999；单笔金额上限（USDC）。 |
| `TITLE_MAX_LENGTH` | 50；行程标题最大字符数。 |
| `DESCRIPTION_MAX_LENGTH` | 500；描述最大字符数。 |
| 跨城交通方式 | 仅「飞机」「高铁」两种；无汽车选项。 |

## 三、计费标准统一约定

产品与实现统一遵守以下约定，游客端与向导端一致。

| 计费类型 | 规则 | 说明 |
|----------|------|------|
| **按人数计费** | 单价 × 人数，人数变化则总价变化 | 景区（游客：项数×单价×人数；向导：每人价×人数）、餐饮、酒店（晚数×每人每晚×人数）、跨城交通（每人每段×人数）。 |
| **按车计费** | 按天 × 车型单价，不乘人数 | 城市交通（轿车/SUV/商务）；一车可坐多人。 |
| **固定/只读** | 用户不可修改金额 | 服务费（向导等级×天数）、城市交通、跨城交通由系统按规则计算并只读展示。 |
| **酒店** | 平台预设列表选择 | 游客与向导均从平台酒店列表选；费用 = 晚数 × 每人每晚单价 × 人数，向导不填「酒店费用」输入框。 |

## 四、游客端 UI 与算法

### 4.1 表单结构（游客）

- **国家**：必填；选项来自 **`lib/geoOptions`** 的 **COUNTRY_OPTIONS**（根 **`frontend/lib/productCountries.ts`**，顺序与 **`GET /meta.product_countries`** 一致）；决定可选城市列表（**`CITIES_BY_COUNTRY`**）。提交 **POST /api/v1/itineraries/custom** 的 **`country`** 必须为十国**中文名**，否则后端 **400** **`invalid_destination_country`**（与 **POST /api/v1/itineraries** 的 **`destination`** 不限十国不同，见 **04 §3.4**）。
- **按天行程**：`dayPlans[]`，长度 = 所选天数；每天包含：
  - 城市（必填）
  - 景区（多选，来自 `getAttractionDetails(country, city)`）
  - 餐饮（多选，来自 `getFoodDetails(country, city)`）
  - 酒店（单选，来自 `getHotels(country, city)`）
  - 城市交通：轿车 / SUV / 商务（可选；与向导端三选一一致）
  - 跨城交通：仅当「当日城市 ≠ 前一日城市」时显示，飞机/高铁二选一
- **向导等级**：不需要 / 初级 / 中级 / 高级 / 特级；决定建议向导费。
- **人数**：1～20。
- **预算（金额）**：必填；可与「报价清单总价」联动（见下）。

### 4.2 报价清单（游客）— `budgetBreakdown`

- **景区约**：`attractionsTotal = round(Σ(每天景区项数 × PER_ATTRACTION) × headcount)`；展示项数。  
- **餐饮约**：`foodTotal = round(Σ(每天餐饮项数 × PER_FOOD) × headcount)`；展示项数。  
- **酒店约**：`hotelTotal = round(hotelNights × HOTEL_PER_NIGHT_PER_PERSON × headcount)`；展示晚数。  
- **城市交通费用**：`suggestedCityTransportFee`，按每天所选车型单价相加（不乘人数）。  
- **跨城市交通费用**：`suggestedInterCityFee`，仅当存在相邻两天不同城时；每段 = `INTERCITY_PRICE_PER_PERSON[mode] × headcount`。  
- **向导费**：`guideTotal = 所选等级建议日费 × days`。  
- **总价**：`total = attractionsTotal + foodTotal + hotelTotal + transportTotal + guideTotal`；`perDay = round(total / days)`。  

**预算与报价联动**：若用户未手动改过预算，则 `amount` 自动跟随 `budgetBreakdown.total` 更新；用户一旦修改预算，则不再自动覆盖。

### 4.3 交通费用明细展示（游客）

- **城市交通**：按天合并连续同车型为一行。  
  - 算法：遍历 `dayPlans`，若连续多天为同一 `cityTransport`，合并为「第 X–Y 天」+ 车型 + 费用；单天为「第 X 天」。  
  - 费用：`dayCount × CITY_TRANSPORT_PRICE[vehicle]`。  
- **跨城交通**：仅当 `hasTouristInterCity` 为 true 时展示；每段一行：「第 X 天→第 Y 天：飞机/高铁，费用 USDC（单价 USDC/人×人数 人）」。

### 4.4 校验与提交（游客）

- 必填：国家、每天城市、预算金额。  
- 天数：1～30；人数：1～20；金额：0 &lt; amount ≤ MAX_AMOUNT。  
- 若预算 &lt; 报价清单总价，可展示「低于报价」提示；若预算 ≥ 总价，可展示「不低于报价」提示。  
- 提交 payload：国家、城市列表、天数、人数、金额、标题、描述、封面、highlights、交通段（from/to/type）等，用于生成订单卡片或调用后端。

## 五、向导端 UI 与算法

### 5.1 表单结构（向导）

- **国家 / 目的地**：必填；有手动目的地与按天城市。  
- **按天行程**：`guideDayPlans[]`，与 `dayPlans` 长度一致（按 `totalDays` 标准化）；每天包含：  
  - 城市（必填）  
  - 景区、餐饮：向导自由填写文案（及图片等）；另有「景区费用」「餐饮费用」为每人 USDC，仅两个总输入框。  
  - 酒店：从平台预设列表选择（与游客端同源 `getHotels(country, city)`），不填「酒店费用」输入框。  
  - 城市交通：轿车/SUV/商务三选一，与游客端一致。  
  - 跨城交通：仅当当日城市 ≠ 前一日城市时显示，飞机/高铁。  
- **行程费用明细**：仅两个可填项——景区费用（USDC/人）、餐饮费用（USDC/人）；酒店由系统按「晚数×每人每晚×人数」计算并只在报价清单中展示。  
- **行程报价（总价）**：必填；可与「报价清单总价」联动（见下）。

### 5.2 报价清单（向导）— `guideQuoteBreakdown`

- **景区**：`attractionTotal = round(guideAttractionFee × headcount)`。  
- **餐饮**：`foodTotal = round(guideFoodFee × headcount)`。  
- **酒店**：`hotelTotal = round(days × HOTEL_PER_NIGHT_PER_PERSON × headcount)`（平台固定单价，不填输入框）。  
- **向导费**：与游客端相同规则，`guideTotal = 所选等级建议日费 × days`。  
- **城市交通**：`suggestedGuideCityTransportFee`，按天按车型汇总。  
- **跨城交通**：仅当 `hasGuideInterCity` 为 true 时，`suggestedGuideInterCityFee`；每段 = 每人单价 × 人数。  
- **总价**：`total = attractionTotal + foodTotal + hotelTotal + guideTotal + cityTransportFee + interCityFee`；`perDay = round(total / days)`。  

**报价与清单联动**：若向导未手动改过「行程报价」，则 `amount` 自动跟随 `guideQuoteBreakdown.total`；一旦手动修改，不再自动覆盖。

### 5.3 交通费用明细展示（向导）

- **城市交通**：与游客端相同合并逻辑，连续同车型为「第 X–Y 天」+ 车型 + 费用。  
- **跨城交通**：每段「第 X 天→第 Y 天：飞机/高铁，费用 USDC（单价 USDC/人×人数 人）」。

### 5.4 校验与提交（向导）

- 必填：行程报价金额、人数等。  
- 金额：0 &lt; amount ≤ MAX_AMOUNT；天数 1～30；人数 1～20。  
- 若报价 &lt; 向导费+交通费之和，可展示「低于成本」类提示。  
- 提交 payload：目的地、国家、城市、天数、人数、金额、封面、highlights 等，用于生成向导侧订单卡片或后端。

## 六、UI 行为与交互细节

| 项目 | 说明 |
|------|------|
| **轿车人数提示** | 当 `headcount > SEDAN_CAPACITY` 且当日选择「轿车」时，在该日城市交通区块下展示提示文案（如建议选 SUV/商务）。游客端与向导端均展示。 |
| **跨城区块显隐** | 仅当存在「相邻两天不同城」时展示跨城交通选项与跨城费用明细；无跨城时隐藏。 |
| **报价清单显隐** | 游客端：有国家且 `budgetBreakdown.total > 0` 时展示。向导端：有国家且 `guideQuoteBreakdown` 计算完成时展示。 |
| **错误滚动** | 提交校验失败时，通过 `scrollToSubmitError()` 将错误信息滚动到视区内（smooth、block: nearest）。 |
| **键盘与焦点** | Esc 关闭弹窗或关闭景区浮层；Tab 在弹窗内循环焦点；打开时焦点置于首个可聚焦元素。 |

## 七、兼容与废弃字段（GuideDayPlan）

向导端按天结构中，以下字段已标 `@deprecated`，仅为兼容历史或持久化数据保留，新逻辑不使用：

- `vehicleImage`、`vehicleDescription`：城市交通已改为平台三选一（轿车/SUV/商务），不再使用自定义车辆图文。  
- `hotelImage`、`hotelDescription`：酒店已改为平台预设列表选择，不再使用自定义酒店图文。  
- `image`：当日照片已从产品中移除，保留字段避免旧数据解析报错。  

实现上保留上述字段的默认空值，不删除类型定义，以免破坏已有存储或 API 契约。
