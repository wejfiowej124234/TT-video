## 二、i18n 落地（国际化）

### 2.1 单源与约定

| 项 | 约定 | 代码落点 |
|----|------|----------|
| **语言** | 中文（zh）、英文（en）；默认与存储见 `lib/i18n` | `frontend/lib/i18n.ts`、`frontend/locales/zh.ts`、`frontend/locales/en.ts` |
| **取值** | 组件内通过 `useTranslation()` 或 `LocaleProvider` 的 `t(key)` 取文案 | `components/LocaleProvider.tsx`、各页面/组件 |
| **key 命名** | 按模块：`common_*`（通用）、`escrow_*`（托管）、`empty_*`（空态）、`market_*`、`error_*` 等 | 与 30 §5 建议一致 |
| **html lang** | 随当前 locale 同步，便于读屏与 SEO | LocaleProvider 内 `document.documentElement.lang`（30 §8 已勾） |

### 2.2 必须走 i18n 的范围（30 §5、§8）

| 范围 | 说明 | 建议 key 或已用 |
|------|------|------------------|
| **根 error / loading** | 根级 error.tsx、loading.tsx | common_errorTitle、common_errorMessage、common_retry、common_backToHome、common_loading |
| **路由 error 页** | market/error、escrow/error、community/error、did-rank/error | 各模块 errorTitle + common_* |
| **EmptyState** | 暂无订单/向导/匹配、CTA 按钮 | empty_* |
| **EscrowDetail** | 确认最终行程、接单/取消/确认完成（链下）/争议、Deposit/**Release**/Refund、加载中/返回列表等 | escrow_*、common_cancel、common_submitting |
| **LoadingText / 骨架** | 全站「加载中」统一 | common_loading；MarketSkeleton 等 sr-only 文案 i18n |
| **Header / 导航** | 导航项、Wallet、登录/注册、语言切换 | 已有或 nav_* |
| **Signature Modal / 链上提示** | 签名前说明、交易已提交等 | escrow_* 或 dapp_* |

### 2.3 i18n 验收勾选表

| □ | 验收项 | 核对方式 |
|---|--------|----------|
| ✓ | 根 error.tsx、loading.tsx 使用 t(key)，无硬编码中文/英文 | 查看 app/error.tsx、app/loading.tsx |
| ✓ | 各路由 error 页（market、escrow、community、did-rank）使用 t(key) + role="alert" | 30 §8 |
| ✓ | EmptyState 全文案走 empty_* | 30 §8 |
| ✓ | EscrowDetail 关键操作与提示走 escrow_* / common_* | 30 §5、§8 |
| ✓ | 全站加载态统一 LoadingText（common_loading）或等价 i18n | 30 §8 |
| ✓ | html lang 随 locale 切换（zh-CN / en） | LocaleProvider 已实现 |
| ✓ | 语言包 zh.ts、en.ts 同 key 覆盖一致，无漏 key | 对比 locales 文件 |

### 2.4 53 阶段订单/步骤条/错误文案 key 预留（P1）

[53-阶段开发技术文档](53-阶段开发技术文档.md) 订单/Escrow 详情页、步骤条、错误提示须走 i18n；与 53 附录 D i18n 清单衔接。**53 相关 key 预留或登记**（53-S22 验收时 37 与附录 D 清单一致）：

| 类别 | 建议 key 前缀或示例 | 说明 |
|------|---------------------|------|
| **订单状态文案** | **`order_status_*`**（**`orderStateToStatusLabelKey`**：`order_status_draft`、`order_status_pending_guide_confirm`、`order_status_bilateral_pending`、`order_status_confirmed_awaiting_payment`、`order_status_escrowed`、`order_status_completed`、`order_status_rating_pending`、`order_status_rating_confirmed`、终态 **`order_status_cancelled`** 等）；与 **53 §4.6.1**、附录 B 子状态一致 |
| **步骤条** | order.steps.*（如 step_draft、step_guide_confirm、step_bilateral、step_confirm、step_pay、step_done、step_rating、step_release） | 与 53 §3.2 步骤条 8 步一致 |
| **操作与确认** | order.actions.*（如 confirm_bilateral、confirm_rating、go_pay、upload_rating、dispute） | 主按钮与次级操作 |
| **错误与提示** | 社区只读 **`getFeed` / `getPostById` / 会话与好友等 GET** 经 **`communityReadOk`**（**`parseResponse`** + **`throwUnlessApiOk`**）；写操作仍用 **`communityJsonBody`** + **`interpretCommunityWriteError`** / **`messageForCommunityActionResponse`**，勿对写响应强行 **`throwUnlessApiOk`** 以免丢失字段映射。**`fetchJsonWithApiStatusLog`**（治理 **`/governance/*`**、`/meta` 辅助读、**`adminFetchJson`**）：HTTP **2xx** 时对 body 执行 **`throwUnlessApiOk`**；**非 2xx** 不抛 envelope，保留解析体供错误分支。**`order_error_*`**：用户可见 REST/读路径统一经 **`mapApiReadError`**（合规原文 + 与订单 **`mapOrderWriteError`** 码表一致）；兜底示例：建单 **`orders_createFailed`**、列表 **`orders_requestFailed`**、**`evidence_db_persist_failed` / `dispute_resolve_db_persist_failed`→`dispute_*`**、行程 **`escrow_saveItineraryFailed`**、最终行程 **`escrow_confirmFailed`**、**`itinerary_db_persist_failed` / `version_conflict` / `message_db_persist_failed`**、**`dispute_open_db_persist_failed`→`escrow_disputeOpenDbUnavailable`** 等；**`mapReviewSubmitError`**：`review_db` / `review_rate_limit` 特判后委托 **`mapApiReadError`**；**`OrderActionsBlock`** REST→**`mapApiReadError`**，EIP-712→**`mapIntentError`**；HTTP 200 且 JSON 根级**自有属性** **`status` 存在且不为 `ok`** 时 **`throwUnlessApiOk`** 抛 **`Error`**（优先根级 **`error`** 字符串，其次 **`message`**，否则兜底码）以便进入上述映射；根级无 **`status`**（如部分 auth 仅 **`user_id`/`token`**）时不抛；**例外**：EIP-712 **Intent** 三路由（confirm-completion-intent、open-dispute-intent、execute-resolution-intent）**成功**为 **`status: "accepted"`**（202），**勿**对成功体使用 **`throwUnlessApiOk`**（与 **`ok`** 信封区分） | 与 53 附录 C、**`parseResponse`** / **`throwUnlessApiOk`** 衔接 |
| **复制摘要（剪贴板）** | **`order_copySummary_*`**（订单号、出行日期、天数、合计、分项行、行程标题与日行；分项标签复用 **`order_hotel`** 等） | **53-S15**、**EscrowDetail** `handleCopySummary` |

**8 步步骤条 key**：与 53 §4.6.1 一致；语言包为扁平键 **`order_steps_step_draft`**、**`order_steps_step_guide_confirm`**、**`order_steps_step_bilateral`**、**`order_steps_step_confirm`**、**`order_steps_step_pay`**、**`order_steps_step_done`**、**`order_steps_step_rating`**、**`order_steps_step_release`**（**`OrderFlowSteps`** 使用）；文档中的 `order.steps.*` 点号写法与此一一对应。

实现时在 `locales/zh.ts`、`locales/en.ts` 中补全或引用 53 附录 D 清单；新增 53 文案须同步更新本表与 53 附录 D。

## 三、a11y 落地（可访问性）

### 3.1 键盘与焦点

| 项 | 约定 | 代码落点 |
|----|------|----------|
| **焦点可见** | 交互元素获得焦点时可见 2px outline（22/28） | `globals.css` 中 `:focus-visible` |
| **跳过主内容** | 键盘用户可跳过导航直达主内容 | `ClientSkipLink` + `#main-content`；layout 包裹 main |
| **Tab 顺序** | 逻辑顺序与视觉一致；模态打开时焦点 trap（可选） | 按 DOM 顺序与 tabIndex |

### 3.2 ARIA 与语义

| 项 | 约定 | 核对方式 |
|----|------|----------|
| **按钮/图标** | 无可见文案的按钮需 `aria-label`（如收藏、关闭、语言切换） | OrderCard/GuideCard 收藏、Header 语言下拉等 |
| **列表与选项** | 语言下拉等用 `aria-expanded`、`aria-haspopup`、`role="listbox"`/`option"`、`aria-selected` | 30 §4.1 |
| **错误与动态区** | 错误页或关键提示可 `role="alert"` 或 `aria-live` | 30 §4.2、§8 |
| **主内容区** | 主内容容器 `id="main-content"` 供 SkipLink 跳转 | layout.tsx |

### 3.3 动效与对比度

| 项 | 约定 | 代码落点 |
|----|------|----------|
| **prefer-reduced-motion** | 用户开启「减少动效」时，全站动效减弱或关闭 | globals.css `@media (prefers-reduced-motion: reduce)`；30 §8 已含 motion-main/motion-sub/btn-console、DID 动效 |
| **对比度** | 正文与背景、按钮文字与背景符合 WCAG 2.1 AA（建议 4.5:1 正文、3:1 大字/UI） | 22 颜色与 ink/travel 使用；设计阶段已考虑 |

### 3.4 a11y 验收勾选表

| □ | 验收项 | 核对方式 |
|---|--------|----------|
| | ClientSkipLink 存在且可聚焦跳转至 #main-content | 30 §4.1 |
| | 根 layout 或主布局含 `<div id="main-content">` 或等效 | 检查 layout |
| | :focus-visible 全局样式生效（2px outline） | globals.css |
| | 无文案按钮/图标有 aria-label | 收藏、关闭、语言等 |
| | 错误页关键信息有 role="alert" 或 aria-live | 30 §8 |
| | prefers-reduced-motion 下动效已减弱 | 30 §8 |

### 3.5 53 阶段订单/步骤条/评分页 a11y 验收用例（X2）

[53-阶段开发技术文档](53-阶段开发技术文档.md) 订单/Escrow 详情页、八步步骤条、评分页须满足 a11y；以下为**键盘与屏幕阅读器**具体验收用例，实现时与 37 §3.4 一并勾选，53-S22 验收可含本表。

| □ | 验收项 | 核对方式 |
|---|--------|----------|
| | **订单/ Escrow 步骤条** | 步骤条各步可**键盘 Tab 聚焦**；当前步骤与已完成步骤有 **aria-current="step"** 或 **aria-selected**；步骤名对读屏可见（非仅图标）；与 53 §3.2 八步一致 |
| | **步骤条焦点顺序** | 焦点顺序与信息层级一致：状态→金额→时间→操作→风险提示（53 §4.4.5、13-1 表 4） |
| | **评分页上传区** | 上传照片/视频控件可键盘聚焦、有 **aria-label** 或可见文案；审核中/待对方确认/已确认态有 **role="status"** 或 **aria-live** 更新；与 53 §5.3、§4.5 一致 |
| | **评分页按钮** | 提交、确认评分等主按钮可键盘触发、焦点可见；禁用态 **aria-disabled** 或 **disabled** + 文案说明 |
| | **订单操作区** | 抢单、双边确认、前往付款等按钮可键盘操作、有明确 **aria-label** 或可见文案；与 53 附录 D i18n 一致 |

**使用方式**：53-S22 企业级 UI/UX 验收时可引用本表；与 36 E2E/集成测试结合，确保键盘与读屏可完成关键路径。

## 四、开发步骤与执行顺序

| 步骤 | 工作内容 | 产出/完成标准 |
|------|----------|----------------|
| **1. 前置** | 34 组件、36 测试已闭环或本批范围已定；确认 LocaleProvider、locales 与 30 §8 现状 | 30 §8 表与当前实现对照 |
| **2. i18n 查漏** | 按 §2.2 逐范围检查：根/路由 error、loading、EmptyState、EscrowDetail、Header、Modal 等是否全部 t(key)；缺 key 的补 locales | §2.3 勾选通过 |
| **3. 语言包一致** | 检查 zh.ts 与 en.ts 同 key 覆盖，缺译的补全 | 无漏 key、无空白展示 |
| **4. a11y 查漏** | 按 §3.1～§3.3 检查 SkipLink、main-content、focus-visible、aria-label、role="alert"、prefer-reduced-motion | §3.4 勾选通过 |
| **5. 验收与门禁** | §2.3、§3.4 全勾后，作为发版前 i18n/a11y 门禁输入；可与 39 一并验收 | 与 39、30-UX 衔接 |

**小结**：先 i18n 查漏与语言包一致 → 再 a11y 查漏与勾选 → 与 39 发版前验收结合。

## 五、验收与门禁

### 5.1 37 自身验收标准

- **i18n**：§2.3 七项勾选通过；全站用户可见文案无硬编码中文/英文，均通过 t(key) 与语言包。
- **a11y**：§3.4 六项勾选通过；SkipLink、焦点、ARIA、减少动效已落实。

### 5.2 与 30-UX §8 的关系

30 §8「本次已完成的优化」表中已列多项 i18n/a11y（根 error/loading、各 error 页、EmptyState、EscrowDetail、html lang、LoadingText、prefer-reduced-motion 等）。37 执行时在**同一口径**下做查漏与勾选；若 30 §8 已全部打勾，则 37 §2.3、§3.4 多数项可直接勾选，仅做新增页面/组件的延伸检查。

### 5.3 与 39 的衔接

39 上线前 UI/UX 总验收可含「i18n 与 a11y」子项，直接引用 37 §2.3、§3.4 勾选结果，避免重复清单。
