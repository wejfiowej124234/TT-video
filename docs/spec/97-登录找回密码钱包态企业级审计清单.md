- **出站邮件**：**`TRAVELTRUST_EMAIL_TRANSPORT=off|log|resend`**。**`log`** = 将含重置/验证链接的一行 JSON 打到 **API 进程 stderr**（可观测、本地联调取链）；**`resend`** = [Resend](https://resend.com) **HTTPS** `POST /emails`（**`email_transport_resend.rs`**；须 **`TRAVELTRUST_RESEND_API_KEY`** + **`TRAVELTRUST_RESEND_FROM`** — **HTTP `from` 仅此变量**，**不**读取 **`TRAVELTRUST_EMAIL_FROM`**，见 **`.env.example`**；生产预检 **`bash scripts/gates/check-auth-email-resend-gate.sh`**，**`transport≠resend`** 时 **skip**）。**`resend` + 域验证发件人** 视为 **生产可用** 的真实投递路径；**应用内仍无** SMTP 自建队列 / DLQ / 出站重试队列（失败 **503** + **回滚令牌行**，见下 §2.2）。**`off`（默认）** 时忘记密码返回 **`503` `email_transport_not_configured`**。**`auth_email_tokens`** 仍仅存 **HMAC** 哈希，**raw** 仅出站经 HTTPS。
- **密码重置成功后**：PostgreSQL 单事务内消费令牌、更新 **`users.password_hash`**、**`revoke_all_sessions_for_user`**（与 **`put_me_password`** 同源「吊销全部会话」语义）；内存 **`ChainOffStore.sessions`** 同步剔除该用户会话（见 **`crates/api/src/chain_off/auth.rs`** **`auth_reset_password`**）。
- **多重身份与钱包列（审计时勿混读）**：本会话绑定的是**一个账号**（`user_id` / 邮箱）。**`users.default_wallet_address`**（个人中心 **`PUT /api/v1/me`** 可换绑）与 **`guides.wallet_address`**（向导申请时写入的链上 DID，接单/托管签名语义以之为准）是**两条可能不同的地址**；当前**不支持**一账号多默认钱包或一向导多 DID，向导 DID **无**页内换绑 API（全文见 **[64 §五](./64-申请向导-行业标准与DID检查清单.md#五钱包与账号体系多钱包--换绑--向导-vs-旅行者)**）。**`GET /api/v1/me`** 响应若含 **`identity_slots`**（**`id`****/**`state`****/**`stake_display`**；五槽含 **`region_steward`**），与顶栏展示、**`state`** 键名（**非** `status`）及 **DID 四脊签** 之关系见 **[96-17](./96-17-多重身份与钱包真值.md#identity-multi-wallet-ssot)** **§0.3.2～§0.3.5**、**[04 §三 3.2](./04-后端与API.md)**。**找回密码 / 改密 / 重置** 仅影响凭据与会话，**不**自动修改上述两列；矩阵抽检见 **[93 §1](./93-全站功能验证矩阵-域别回归清单.md#1-a-域--账号--注册--登录--me--密码--邮箱)**，编排互指见 **96-17** 同锚。**准入费支付意图 / 角色解锁**（**96-18 Target**）**须** 在 **已认证会话** 下完成，**禁止** 仅凭 **邮件令牌** 绕过 **Session** 写 **`entitlements.paid`**；闭环见 **[96-18 §12.4](./96-18-商家与主理人准入费用与治理币兑换设计.md)**。

## 2. 审计矩阵（可打勾执行）

状态定义：`[ ] 未开始` `[/] 进行中` `[x] 完成`

<a id="spec97-s21-login"></a>

### 2.1 登录（Login）

- [ ] 密码仅以强哈希存储（Argon2/bcrypt），无明文、无可逆加密。
- [ ] 登录错误返回统一语义，避免用户名/邮箱枚举。
- [ ] 限流覆盖账号 + IP + 设备三维，且有突刺保护。
- [ ] 会话具备过期、刷新、吊销、并发上限与主动登出失效。
- [ ] 高风险登录触发二次验证（MFA/挑战）。
- [ ] 登录成功/失败/锁定均写审计日志（脱敏后可追踪）。
- [ ] 登录关键写操作具备幂等键与重放保护。

<a id="spec97-s22-forgot"></a>

### 2.2 找回密码（Forgot Password）

- [ ] 找回 token 一次性、短 TTL、单用途，使用后立即失效。（**本仓库**：**`auth_email_tokens`** 行 **`consumed_at`** + **`consume_password_reset_token_and_rotate_password`** 单事务；**`find_valid_token`** 拒绝过期/已消费；**DB 回归**：**`forgot_reset_password_token_cannot_be_reused_pg`**。）
- [ ] token 在数据库仅存哈希值，不落明文。（**本仓库**：**`TRAVELTRUST_AUTH_TOKEN_PEPPER`** HMAC-SHA256(hex) 存表；迁移 **`20260420160000_auth_email_tokens.sql`**；**.env.example** 说明。）
- [ ] 发送找回邮件存在邮箱/IP/设备多维限频。（**本仓库**：**`auth_forgot_per_email_limit`**（邮箱桶 **`forgot:`**）、**`auth_forgot_risk_limits`**（全局 + IP 等键，与 **`auth_per_email_send_window`** 同源哈希键策略）；**非**独立「设备指纹」维度。）
- [ ] 请求找回与校验 token 返回文案防枚举。（**本仓库**：未命中用户仍 **`200` `if_account_exists_email_sent`**；限流等亦倾向统一成功文案；详见 **`auth_forgot_password`**。）
- [ ] 重置成功后吊销历史会话与 refresh token。（**本仓库**：**无 refresh token 模式**；**PG** 下 **`revoke_all_sessions_for_user`** + 内存 **`sessions.retain`**；**`forgot_reset_password_revokes_pre_reset_session_token_pg`**。）
- [ ] 邮件发送失败有重试、死信与告警链路。（**`resend` 生产可用**：同步 HTTPS 真实投递；失败时 **503** 并**回滚删除**刚插入之 **`auth_email_tokens`** 行。**仍为增强项 / 非本仓库承诺**：应用内重试队列、DLQ、投递状态 webhook、与 Resend 控制台的告警联动。）
- [ ] 全链路有风控特征（设备指纹、异常地理位置、速率异常）。（**部分**：速率/桶限流已落地；**指纹/geo 评分**未作为本文件 SSOT 承诺。）

**用户路径（产品）**

1. 前端 **`/auth/forgot-password`** → **`POST /auth/forgot-password`**（**`postForgotPassword`**）。  
2. 若 **`TRAVELTRUST_EMAIL_TRANSPORT=log`** 或 **`resend`**，且 **`DATABASE_URL`**、**pepper**、**`TRAVELTRUST_PUBLIC_APP_BASE_URL`**（命中 **allowlist**）就绪（**`resend`** 另须 **`TRAVELTRUST_RESEND_*`**）：后端签发重置令牌；**`log`** 在 **stderr** 输出 **`traveltrust_email_outbound`** JSON（含 **`url`**）；**`resend`** 经 Resend 投递 HTML/文本邮件（链接同源）。  
3. 用户打开 **`{PUBLIC_APP_BASE}/auth/reset-password?token=…`**（前端 **`/auth/reset-password`**）→ **`POST /auth/reset-password`**。  
4. 成功后使用新密码 **`POST /auth/login`**。

<a id="spec97-s23-wallet"></a>

### 2.3 钱包态（Wallet State）

> **注**：**「钱包绑定 / 挑战-应答」**与 **`wallet_verify_challenges`** 表、**`me` 钱包验证路由**及审计事件 **`wallet_verify_confirm_*`** 相关；**本文件 §2.3 仍以「链上投影 / escrow 状态机」广义钱包态为主**；细化验收请与 **04**、**93** 矩阵中钱包/Me 相关用例交叉。

- [ ] 链上读取与链下投影存在定时对账（余额、nonce、关键状态）。
- [ ] reorg 回滚机制可自动回放，避免错误状态固化。
- [ ] 签名校验包含 chainId、domain、nonce 重放防护。
- [ ] 状态机迁移合法（冻结/解冻/仲裁/完成不可越级跳转）。
- [ ] 链上失败/超时具备补偿路径（重试 + 人工介入）。
- [ ] 大额/高频/异常地址变更有实时告警。
- [ ] 关键钱包态变更可追溯到 request_id 与 user_id。

## 3. 缺口清单（优先核查）

### 3.1 P0（阻断上线）

- [ ] 找回密码 token 可重复使用或未单次失效。
- [ ] 重置密码后旧会话未全量吊销。
- [ ] 钱包态 reorg 后投影未回滚/未重放。
- [ ] ABI 升级后服务端解析器未锁版本且无回归验证。

### 3.2 P1（高优修复）

- [ ] 登录/找回错误语义不一致，存在账号枚举窗口。
- [ ] 限流仅覆盖 IP，未覆盖账号与设备维度。
- [ ] 审计日志字段未脱敏或缺关键关联键（trace_id/request_id）。
- [ ] token/session 过期清理任务无失败告警。

### 3.3 P2（优化提升）

- [ ] 缺少统一风控评分与挑战策略。
- [ ] 钱包态漂移监控仅有离线报表，缺实时信号。
- [ ] 缺少灰度验证与回滚演练脚本。

<a id="spec97-s4-apiabi"></a>

## 4. API/ABI 审计要点

### 4.1 API（HTTP/内部接口）

- 契约稳定：字段新增向后兼容，错误码字典固定，版本策略明确。
- 鉴权边界：公共、用户、管理接口权限隔离。
- 输入校验：长度、格式、枚举、跨字段一致性验证。
- 幂等保障：重置密码、状态流转、写接口使用 idempotency key。
- 观测能力：trace_id、耗时、失败分类、SLO 指标可导出。

### 4.2 ABI（链上契约交互）

- ABI 版本锁定：后端运行时 ABI 与部署版本可追溯绑定。
- 事件解析健壮：未知事件隔离、解码失败告警、可重放补偿。
- 编解码一致：地址规范、数值精度、decimal 换算统一。
- 升级回归：代理升级后覆盖读写路径与事件路径回归测试。

## 5. 数据持久化 / 数据库审计要点

- 模型完整：用户、凭据、会话、token、钱包快照、事件投影关系闭环。
- 约束完整：邮箱唯一、token 唯一、单次使用标记约束生效。
- 索引有效：高频查询字段（email/user_id/status/created_at/nonce）有索引。
- 生命周期：token/session 有 TTL 与清理任务，具备重试与告警。
- 事务边界：状态变更 + 审计日志 + outbox 同事务提交。
- 安全治理：PII 加密、日志脱敏、备份加密与最小权限访问。
- 对账机制：链上事件表、业务表、财务聚合表可日常对账。

**本地验收最小集（无自建 SMTP）**

1. **`.env`**：`DATABASE_URL`、`TRAVELTRUST_AUTH_TOKEN_PEPPER`，**`TRAVELTRUST_EMAIL_TRANSPORT=log`**（或 **`resend`** + **`TRAVELTRUST_RESEND_*`**），并配置 **`TRAVELTRUST_PUBLIC_APP_BASE_URL`** 命中 allowlist。  
2. **`log`**：启动 API，完成注册后走忘记密码；在 **运行 API 的终端** 检索 **`traveltrust_email_outbound`** JSON，复制 **`url`** 完成重置。**`resend`**：查 Resend Dashboard 收件箱或邮件客户端；出站失败应 **503** 且 DB **无**残留未消费令牌行（回滚删除）。  
3. 跑 **`cargo test -p traveltrust-api`** 中带 **`forgot` / `reset_password` / `PWD`** 的用例（上表 DB 测试）作为回归证据。

**真实投递抽检（`resend`，上线 / 预发前手检）**

1. **配置门禁**（密钥勿写入仓库；可与根 `.env` 并存，**前缀赋值优先**于 `.env` 中同键）：

   ```bash
   TRAVELTRUST_EMAIL_TRANSPORT=resend \
   TRAVELTRUST_RESEND_API_KEY='re_…' \
   TRAVELTRUST_RESEND_FROM='TravelTrust <no-reply@yourdomain.com>' \
   bash scripts/gates/check-auth-email-resend-gate.sh
   ```

   期望终端输出 **`OK: check-auth-email-resend-gate (resend + key + from present)`**，退出码 **0**。

2. **启动 API**：进程环境须含 **`TRAVELTRUST_EMAIL_TRANSPORT=resend`**、**`TRAVELTRUST_RESEND_*`**、**`DATABASE_URL`**、**`TRAVELTRUST_AUTH_TOKEN_PEPPER`**、**`TRAVELTRUST_PUBLIC_APP_BASE_URL`**（须命中 **`TRAVELTRUST_PUBLIC_APP_BASE_URL_ALLOWLIST`**）。  
3. **忘记密码**：**`POST /auth/forgot-password`**，body **`{"email":"<已注册邮箱>"}`**；期望 **200** **`if_account_exists_email_sent`**；收件箱收到重置链接 → 打开后走 **`POST /auth/reset-password`** 完成闭环（与 **04** 契约一致）。  
4. **邮箱验证**：**`POST /auth/register`** 新邮箱（或触发重发路径若产品提供）；期望注册响应中 **`email_verification_link_sent`** 为 **`true`**（在 **`resend`** 出站成功时）；邮件内链接之 **`token`** 与 **`POST /auth/verify-email`** body 同源，成功 **200** **`email_verified`**。  
5. **结论**：上述 **2–4** 通过后，可将本链路在运维台账中记为 **生产可用（Resend）**；**队列 / DLQ** 仍列为后续增强，不记为「无投递能力」类缺口。
