## 一、告警与 Runbook §1 对应关系验收表

与 [Runbook §1 触发表](../../ops/RUNBOOK.md) 及 [27-P28 §四](27-P28-实现记录.md) 告警通道定稿说明衔接；用于验收「告警触发条件 ↔ Runbook 场景 ↔ 指标/日志来源」无缺口。

| Runbook 场景 | 触发阈值（与 Runbook 一致） | 指标/日志来源（可观测落点） | 告警通道落点 |
|--------------|----------------------------|-----------------------------|--------------|
| ① RPC 大面积不可用 | 连续 5 分钟错误率 > 10% 或健康检查失败 | /health 失败率、CHAIN_RPC 调用错误率或依赖健康指标 | Prometheus Alertmanager / Webhook；P28 §四 推荐通道 |
| ② Indexer 落后 | 落后 block 数 > 100 或延迟 > 60s | Indexer 落后 block 数、延迟指标或对账 checkpoint 时间戳 | 同上 |
| ③ reorg | 链重组超过 finalityN（08-3） | 链 reorg 检测或 finality 校验失败事件 | 同上 |
| ④ 执行器卡单 | 卡单时长 > 30min 或队列积压 > 50 | 执行器队列长度、最老任务时长；可选 GET /metrics 扩展 | 同上 |
| ⑤ token 冻结/黑名单 | 监管/合约级冻结或 allowlist 移除 | 合约事件 TokenAllowlistUpdated、配置变更日志 | 同上 |
| ⑥ 配置误发布 | allowlist/feePolicy 等误配 | 配置变更审计日志、可选配置校验接口 | 同上 |
| ⑦ 权限误配 | Pause 白名单/仲裁角色误配 | RBAC/权限变更审计日志 | 同上 |

**说明**：上表为验收用对应关系；实际告警规则与阈值由运维在 Prometheus/Webhook/日志告警中配置，与 Runbook §1 定稿一致即视为 P35 告警落地验收通过。P28 §四 已写死触发条件与推荐通道，本表与之无冲突。

## 二、GET /metrics 可用性验收

与 [27-P31 §一](27-P31-实现记录.md) 指标端点一致；验收「GET /metrics 返回 200 且含 Prometheus 格式及 traveltrust_api_info」。

| 项 | 要求 | 验收方式 |
|----|------|----------|
| HTTP 状态 | 200 | curl -s -o /dev/null -w "%{http_code}" BASE_URL/metrics |
| 内容 | 含 `# HELP traveltrust_api_info` 与 `traveltrust_api_info{version="…"} 1` | curl -s BASE_URL/metrics \| grep -q traveltrust_api_info |
| 可选脚本 | scripts/p35_metrics_ok.sh [BASE_URL] | 执行后 exit 0 即通过 |

**BASE_URL**：默认 `http://localhost:8080`；脚本可接受第一个参数覆盖。

## 三、可选：告警触达测试或演练留痕

| 项 | 说明 |
|----|------|
| **目的** | 验收告警通道（Prometheus/Webhook/日志告警）能触达值班；非 P35 门禁必项。 |
| **步骤** | 1）运维确定告警通道并写死至 Runbook §1 或内部文档（P28 §四 闭合标准）；2）在测试环境触发一次模拟条件（如 /health 不可用或指标超阈值）；3）确认告警推送至值班/群；4）将演练日期与结果记入 evidence 或 Runbook §4 演练历史。 |
| **留痕** | Runbook §3 演练记录模板填写；产物入 evidence/GO_YYYYMMDD/ 或 evidence/DR-YYYYQX-0N/。 |

**说明**：本条为可选；完成即视为告警触达验收闭合，不阻塞 P35 门禁。
