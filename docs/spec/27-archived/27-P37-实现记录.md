## 一、安全加固验收清单表

与 [27-P30 §三](27-P30-实现记录.md) 八类安全项对应；发版前或回归时逐项验收。

| 安全项（P30 §三） | 可执行验收方式 | 通过标准 |
|-------------------|----------------|----------|
| 重入与调用顺序 | 合约单测/E2E；无自动化脚本时人工核对 | 合约 Escrow 先改状态再 transfer；P30 §三 已标注 |
| 权限与最小特权 | chain_off extract_user、执行器 RBAC；人工核对 01 §7 | P30 §三 已标注 |
| 签名与重放 | DApp EIP-712 与 nonce；人工或 E2E | P30 §三 已标注 |
| 前端/代付 | 后端不持私钥；API 鉴权 401（未带身份返回 401） | 04 鉴权占位/chain_off 已实现；可 curl 未带 X-User-Id 得 401 |
| 资金边界 | 链下/链上事件驱动；人工核对 04 §七 | P30 §三 已标注 |
| Token 与 Allowlist | 合约与 08-3 治理 key；人工核对 | P30 §三 已标注 |
| Pause 与自救 | 合约与 Runbook §1；人工核对 | P30 §三 已标注 |
| 证据与隐私 | 证据大小/类型、限流；08-3 evidence 相关 key；audit-deps | content_hash≤128/hex；EVIDENCE_MAX_REQUESTS_PER_MINUTE 在 08-3；API 已实现 |
| **不变量/安全头/锁策略** | **check-invariants.sh** | exit 0；含 rust-toolchain、frontend 锚点、安全头、Node 锁策略 |
| **依赖安全审计** | **audit-deps.sh**（可选） | 发版前或 CI 执行；已知漏洞处理或留痕 |

**说明**：上表与 P30 §一§三 一致；可执行项以 check-invariants、audit-deps 及鉴权 401、08-3 证据限流核对为主，其余为人工或 E2E 核对。

## 二、可执行验收步骤

| 步骤 | 说明 | 通过标准 |
|------|------|----------|
| 1 | 执行 `./scripts/check-invariants.sh` | exit 0 |
| 2 | 可选执行 `./scripts/audit-deps.sh` | 执行并处理已知漏洞或留痕；CI 中可为 continue-on-error |
| 3 | 核对 08-3 证据限流 key（EVIDENCE_MAX_REQUESTS_PER_MINUTE 等）与 API 实现一致 | 08-3 变更记录与 crates/api 一致 |
| 4 | 验收鉴权：未带身份请求受保护 API 返回 401 | 如 GET /api/v1/orders 无 X-User-Id 或无效 token 得 401 |

**说明**：步骤 1 为必选；2～4 可按发版前清单或回归需要执行。与 P30 安全项、02 §十三 13.1、08-5 CI 一致。
