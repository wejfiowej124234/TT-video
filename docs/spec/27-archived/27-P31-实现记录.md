## 一、可观测落地（GET /metrics）

| 项 | 说明 | 落点 |
|----|------|------|
| **路由** | GET /metrics | crates/api/src/main.rs：.route("/metrics", get(metrics)) |
| **格式** | Prometheus 文本格式：traveltrust_api_info{version="…"} 1 + **http_requests_total** 计数器；QPS = rate(http_requests_total[1m])；延迟/错误率可后续接 metrics 库 | main.rs：metrics_request_count_layer、metrics() |
| **与 P28 衔接** | P28 §一 指标行「可选：QPS、延迟、错误率、依赖健康」→ 本端点为落地占位；告警仍按 P28 §四 与 Runbook §1 | 27-P28-实现记录 §一、§四 |

**验证**：`curl -s http://localhost:8080/metrics` 应返回 `# HELP traveltrust_api_info` 与 `traveltrust_api_info{version="…"} 1`。

## 二、性能基线（文档化）

关键路径的**预期响应时间或 QPS 基线**（写死为占位；实际压测后可由运维/开发更新本表或 08-3）。

| 路径 | 方法 | 基线（占位） | 说明 |
|------|------|--------------|------|
| /health | GET | &lt; 10 ms | 健康检查，无 DB/链依赖 |
| /meta | GET | &lt; 50 ms | 读 env 与状态，无重 IO |
| /api/v1/orders | GET | &lt; 200 ms（链下） | 依赖 store/DB；链上依赖 RPC |
| /api/v1/orders/:id | GET | &lt; 150 ms（链下） | 同上 |
| /api/v1/guides | GET | &lt; 100 ms（链下） | 列表 |

**说明**：上述数值为占位基线，非 SLA；实际压测后更新本表或迁至 08-3/运维文档。与 04 §四 请求超时（REQUEST_TIMEOUT_SECS）、01 §9 可观测无冲突。

**实测填表说明**：在目标环境启动 API 后执行 `./scripts/p31_load_baseline.sh [BASE_URL]`（可选 `P31_BASELINE_N=20`）；将输出中各路径的 **ok/N** 与 **elapsed** 填入下表，即可将占位基线替换为实测基线（或迁至 08-3/运维文档）。

| 路径 | N | ok | elapsed（秒） | 备注（可选） |
|------|---|-----|---------------|--------------|
| /health | 20 | 20 | 0.18 | 示例：本地链下；实际以目标环境执行结果为准 |
| /meta | 20 | 20 | 0.42 |  |
| /api/v1/guides | 20 | 20 | 1.25 |  |
| /api/v1/discover/orders | 20 | 20 | 1.85 |  |

**说明**：上表已按最佳实践填选示例值（N=20 全成功、elapsed 满足 §二 与 P36 §二 阈值）；**实际发版前须在目标环境执行 `p31_load_baseline.sh` 后以真实输出替换**。填表后可将 §二 上表「基线（占位）」列改为「实测：N=20，elapsed Xs」等，或保留占位、仅在 08-3 记录实测值。
