### P5-5 策略定稿（索引/投影/对账/Reorg）

与 01 §9、04 §四 一致，以下口径固化便于实现与审计：

| 策略项 | 定稿口径 |
|--------|----------|
| **事件消费** | EscrowCreated、Deposited、Released、Refunded、DisputeOpened、ResolutionExecuted；单源为链上 logs，按 blockNumber+logIndex 有序消费 |
| **投影** | 事件→orders 表资金状态、escrow_address、block/logIndex；幂等键 (chainId, blockNumber, logIndex)；重复事件只应用一次 |
| **checkpoint** | 消费位点持久化（如 blockNumber+logIndex 或 lastProcessedEventId）；重启从 checkpoint 继续；不跳过未确认块 |
| **对账** | 链上终态 vs DB 投影；三段式：自动修（可逆差异）、半自动（需人工确认）、人工（争议/异常）；与 01 §9 资损 runbook 衔接 |
| **Reorg** | finalityN=12（Polygon）；event 表存 blockHash+blockNumber+logIndex；reorg 深度≤finalityN 时重扫/回退 checkpoint；超过则暂停+人工 |

## 实施顺序（建议）

1. **P5-1 合约**：Foundry 项目 → EscrowFactory + Escrow（clone）→ Staking、Registry 最小可用 → 单测 → 本地 Anvil 部署 → ABI 产出至 contracts/abi/。
2. **P5-2 chain 模块**：api/src/chain 配置与 alloy 客户端 → 读 Escrow/Staking/Registry 状态 → 提交 executeResolution/createEscrow 占位。
3. **P5-5 策略文档**：在 27-P5 或 04 §四 中固化索引/投影/checkpoint/对账/Reorg 口径。
4. **P5-3 打通**：订单创建→createEscrow→deposit（前端或后端）→Released 由后端/向导调→索引写 DB。
5. **P5-4 执行器**：裁决 API 写 DB → 执行器消费 outbox 或队列 → chain.executeResolution → 链上执行。
