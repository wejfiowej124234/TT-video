## P17 目标

**功能目标**（17 ③）：协议控制台为「最严肃模块」；Escrow Detail 必须展示状态、金额、币种、snapshotHash、交易记录、finality 状态、操作按钮；所有链操作必须经 Signature Modal，展示 chainId、contract、function、amount、gas，tx 状态机可见（idle→signing→pending→confirmed→final/failed）。

| 维度 | 内容 |
|------|------|
| 链上/链下 | 链下 UI + 链上交互 |
| 页面/模块 | Escrow Detail（OrderFlow 可与 Escrow 合并或独立步骤条） |
| 规范 | 13-1 表 4 EscrowDetail 字段级信息结构、§三 交易交互规范；09 §2.7 txMachine |

| Signature Modal：chainId、contract、amount | 签名前确认弹窗：链 ID、合约、金额 | **已有** |
| Modal：function、gas、token、finalityN（13-1 §三） | Modal 内展示 function、gas、**token**（币种/USDC）、**finalityN**（确认块数 12） | **已实现**（企业级补） |
| tx 状态机：idle→signing→pending→confirmed→final/failed | Modal 与操作区展示 交易状态：空闲/等待签名/确认中/已确认/失败；成功或失败后 Modal 显示「关闭」 | **已实现** |
| 信息层级：状态→金额→finality→操作→风险提示 | 状态→金额与币种→snapshotHash→finality→交易记录→操作→风险提示 | **已实现** |

**结论**：P17 **已实现**；Escrow Detail 完整展示、Signature Modal 含 function/gas、tx 状态机显式展示；门禁 1（useEscrowActions 单测含 tx 状态）通过，门禁 2 可调通（链下/测试网手动验证）。

## P17 实现时落点建议

| 落点 | 建议 |
|------|------|
| **前端 EscrowDetail** | 增加「交易记录」区块（链上事件列表或「待索引」占位）；增加「finality」区块（块高或「等待 N 块确认」）；Signature Modal 内增加 function、gas estimate（wagmi/viem 可读） |
| **DApp / 09 §2.7** | tx 状态机：用 isIdle/isSigning/isPending/isConfirmed/isFinal/isFailed 等显式展示在 Modal 或操作区下方；与 useEscrowActions.test 已有「tx 状态」用例对齐 |
| **04 API** | 若需「交易记录」来自后端：可增 GET /api/v1/orders/:id/events 或由 indexer 写入 DB 后查询；P17 阶段可用占位 |
| **13-1 表 4** | 信息层级固定：状态（不可折叠）→ 金额与币种 → 时间与 finality → 事件列表 → 允许动作 → 风险提示 |
