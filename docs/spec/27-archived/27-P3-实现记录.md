## P3-1：用户/向导 CRUD、档期

**验收**：API 与 04 §二一致。

| 项 | 落点 | 状态 |
|----|------|------|
| 认证 | POST /auth/register、POST /auth/login；返回 token（P3 链下为 bearer_&lt;user_id&gt;） | ✓ |
| 当前用户 | GET /api/v1/me（需 Authorization 或 X-User-Id，含按角色统计）；PUT /api/v1/me 可更新 nickname/avatar_url/default_wallet_address | ✓ |
| 向导列表 | GET /api/v1/guides（Query: city, language, service_type）；仅 status=active | ✓ |
| 向导详情 | GET /api/v1/guides/:id | ✓ |
| 向导注册 | POST /api/v1/guides（需登录）；创建 guide，status=pending | ✓ |
| 质押 | POST /api/v1/guides/:id/stake（body: amount）；MVP 记内存，stake_amount≠0 时 status→active | ✓ |
| 档期 | chain_off guide_slot：创建订单时若向导已有 Accepted/Escrowed 订单则 409 guide_has_active_order；接单/支付/完成/取消/裁决时占档与解档 | ✓ |

**结论**：P3-1 通过；用户/向导 CRUD 与 04 §二一致；档期已用 chain_off guide_slot 实现占档/解档。

## P3-2：订单状态机

**验收**：Created→Accepted→Escrowed→Completed 及取消/争议分支，与 01/03 一致。

| 项 | 落点 | 状态 |
|----|------|------|
| 创建订单 | POST /api/v1/orders（guide_id, amount, currency）；状态 Created | ✓ |
| 接单 | POST /api/v1/orders/:id/accept（向导）；Created→Accepted | ✓ |
| 取消 | POST /api/v1/orders/:id/cancel（游客或向导）；Created/Accepted→Cancelled | ✓ |
| Mock 支付 | POST /api/v1/orders/:id/mock-pay（游客）；Accepted→Escrowed；P3 链下占位 | ✓ |
| 确认完成 | POST /api/v1/orders/:id/confirm-completion；Escrowed→Completed | ✓ |
| 发起争议 | POST /api/v1/orders/:id/dispute；Escrowed→Disputed，创建 dispute 记录 | ✓ |
| 状态校验 | 使用 traveltrust_core::OrderState::can_transition_to；与 01 §1 一致 | ✓ |

**结论**：P3-2 通过；订单状态机与 01/03 一致。

## P3-4：争议表与人工裁决流程

**验收**：仅 DB，与 03 争议窗口、disputeDeadline≥autoCompleteAt 一致。

| 项 | 落点 | 状态 |
|----|------|------|
| 争议表 | chain_off::DisputeRow；order_id, status, evidence_hashes, arbitrator_id, refund_ratio, slash_guide, resolved_at | ✓ |
| 发起争议 | POST /api/v1/orders/:id/dispute；仅 Escrowed 可发起（DefaultEscrow::can_dispute） | ✓ |
| 争议列表 | GET /api/v1/disputes | ✓ |
| 争议详情 | GET /api/v1/disputes/:id | ✓ |
| 裁决 | POST /api/v1/disputes/:id/resolve（body: refund_ratio, slash_guide）；Disputed→Refunded/PartiallyRefunded/Slashed/Completed；裁决后解档 guide_slot | ✓ |

| 证据（链下） | P3_CHAIN_OFF=1 时 GET/POST /api/v1/orders/:id/evidence 走 chain_off：evidence_list_impl、evidence_post_impl（EvidenceReceiptRow：content_hash、created_at、uploader_id） | ✓ |

**结论**：P3-4 通过；争议表与人工裁决仅 DB，与 03 一致；执行器上链在 P5；证据链下占位已实现。

## P3-5：超时与争议窗口

**验收**：与 01/03 定稿一致。

| 项 | 落点 | 状态 |
|----|------|------|
| 配置 | ChainOffConfig::from_env()：P3_ACCEPT_TTL_SECS、P3_PAYMENT_TTL_SECS、P3_AUTO_COMPLETE_DAYS、P3_DISPUTE_WINDOW_DAYS | ✓ |
| 约束 | dispute_window_days ≥ auto_complete_days（from_env 中 max） | ✓ |

| 超时校验 | 接单：created_at + accept_ttl_secs 内未接单则 410 accept_window_expired 并置 Cancelled；支付：accepted_at + payment_ttl_secs 内未支付则 410 payment_window_expired 并置 Cancelled、解档 | ✓ |

**结论**：P3-5 通过；超时与争议窗口配置与 01/03 一致；接单/支付超时已在 accept、mock-pay 时校验并自动取消、解档。

### 7. 实现阶段修正与验证（编译与单测）

实现与补齐缺口后，对以下部分做了**类型与借位修正**，保证可编译、可测：

| 修正项 | 落点 |
