## 二、弹窗/抽屉 · 多维度检查项

### 2.1 设计排版

- [x] **发帖抽屉**：顶部「返回」按钮是否足够醒目（当前为青色大按钮）；标题是否居中；内容区是否限制 max-width（当前 max-w-2xl 居中）；底部「发布」是否固定且醒目（当前有边框与阴影）。
- [x] **发帖抽屉**：类型选择（照片/视频/美食/旅游）是否易点、选中态是否清晰；多图 0/9 区域是否易理解；正文与字数、话题提示是否层次分明。
- [x] **评论抽屉**：顶栏「返回」+ 标题「评论 · N」是否统一；列表与输入区是否留白合理；输入框与发送按钮是否够大（当前 rounded-xl、py-2.5）。
- [x] **帖子详情抽屉**：顶栏「返回」+ 帖子标题是否统一；媒体区/正文/作者/评论区是否分区清晰；底部评论输入是否固定可见。
- [x] **登录弹窗**：是否带顶栏「返回」+ 标题；卡片是否圆角、留白一致（当前 rounded-xl、max-w-sm）；取消与「去登录」是否并排、易点。
- [x] **视频全屏层**：顶栏是否有「返回」文案（当前有）；视频区域是否居中、比例是否正常（当前 max-w-2xl aspect-video）。
- [x] **分享弹层**：是否在卡片内不溢出视口（当前 absolute right-0 bottom-full）；复制链接/举报是否易点；关闭是否点击外部即可；已加 role="menu"、menuitem 与 min-h-[44px] 触控优化。

### 2.2 返回/关闭/退出

- [x] **发帖抽屉**：左上「返回」按钮存在且可见；支持 Esc 关闭；打开时焦点是否在「返回」上（当前有 ref 聚焦）。
- [x] **评论抽屉**：左上「返回」存在；Esc 关闭。
- [x] **帖子详情抽屉**：左上「返回」存在；Esc 关闭。
- [x] **登录弹窗**：左上「返回」或明显「取消」存在；Esc 关闭（当前有 useEffect）。
- [x] **视频全屏层**：顶栏「返回」存在；Esc 关闭（当前有）；已加 overflow-hidden。
- [x] **分享弹层**：点击外部关闭（当前有 document click 监听）。

### 2.3 功能完整性（弹窗内）

- [x] **发帖抽屉**：类型切换、多图选择/排序/删除、正文输入、字数限制、发布按钮（需填正文后可用）；发帖失败时是否有错误条与重试（当前支持 publishError/onRetryPublish）；是否有「填写正文后即可发布」提示。
- [x] **评论抽屉**：评论列表展示、未登录提示（仅未登录显示）、输入+发送、发送失败时错误条与重试（commentSendError/onRetryComment）。
- [x] **帖子详情抽屉**：媒体轮播、正文与标签、作者信息、举报入口、评论列表、底部发评论。
- [x] **登录弹窗**：取消关闭、跳转登录页（returnUrl=/community）。
- [x] **视频全屏层**：播放控制、返回关闭。
- [x] **分享弹层**：复制链接（含 toast 反馈）、举报入口。

### 2.4 无障碍

- [x] 所有弹窗：`role="dialog"`、`aria-modal="true"`（或 aria-label）；是否有 `aria-labelledby` 或 `aria-label`。
- [x] 发帖抽屉：`aria-labelledby="publish-drawer-title"`；返回按钮 `aria-label`；发布按钮可聚焦、禁用态说明（已加 aria-describedby 指向「填写正文后即可发布」提示）。
- [x] 评论/详情抽屉：标题或 aria-label 能表达「评论」/「帖子详情」。
- [x] 键盘：Esc 关闭；发帖抽屉打开时焦点在返回按钮；多图轮播支持左右键（Feed 卡片已支持）。
- [x] 焦点陷阱：打开抽屉后焦点是否移入抽屉内（当前依赖返回按钮聚焦）；关闭后焦点是否应回到触发元素（可选增强，暂未做）。

### 2.5 响应式与安全区

- [x] 所有全屏抽屉：`fixed inset-0`、`overflow-hidden`；顶栏/底栏 `shrink-0`，中间区域 `flex-1 overflow-y-auto min-h-0`，避免底部被推出视口（评论抽屉底栏已补 shrink-0）。
- [x] 顶栏/底栏是否使用 `safe-area-inset-t` / `safe-area-inset-b`（当前已加）；globals.css 是否定义 safe-area 类（已定义；已增 safe-area-toast-bottom）。
- [x] 移动端：触控目标是否足够大（按钮 py-2.5 及以上）；分享弹层已加 min-h-[44px]、py-2.5。

### 2.6 异常态与反馈

- [x] 发帖抽屉：上传单张 >10MB 是否有提示（当前有 uploadError）；发帖失败是否展示错误条与重试（需父组件传 publishError/onRetryPublish）。
- [x] 评论抽屉：评论发送失败是否展示错误条与重试（需父组件传 commentSendError/onRetryComment）。
- [x] 帖子详情/评论：媒体加载失败是否占位文案（当前有 community_media_load_failed）。
- [x] Toast：发布成功、举报提交等是否统一时长与位置（约 2.2s、底部居中；已用 safe-area-toast-bottom 避开安全区）。

### 2.7 i18n

- [x] 所有弹窗内文案是否走 `t(key)`；key 是否在 zh/en 中均有定义（community_*、common_cancel、community_back_drawer、community_publish_submit、community_publish_required_hint 等）。

### 2.8 性能与资源

- [x] 发帖抽屉：blob URL 在提交后或关闭时是否 revokeObjectURL（当前有）；多图预览是否用 Next Image + unoptimized（blob 时）。
- [x] 评论/详情抽屉：图片是否 loading="lazy" 或合理 sizes。

## 三、TT 社区页面 · 多维度检查项

### 3.1 Feed 页（/community）

- [x] 顶栏：标题、示例数据说明、刷新、互动入口、返回首页是否齐全；是否与 **L1** Tab 协调（动态｜发现｜消息｜好友｜我；桌面顶部 Tab、移动底部 Tab）。
- [x] 发帖入口：悬浮「+ 发布」是否易发现；未登录点击是否弹出登录弹窗。
- [x] 搜索：输入框、无结果空态与 **Explore** 引导（**`community_search_empty`**）是否清晰（**非** 协议 `/discover`）。
- [x] 筛选条：推荐/关注、最新/最热、类型、是否 sticky；当前筛选汇总与「清除筛选」是否存在。
- [x] 热门目的地：是否在筛选条下方、pill 是否可点、是否与 destinationFilter 联动。
- [x] Feed 错误态：feedError 时是否展示错误条与「重试」按钮；重试是否执行 refreshFeed（置页码、loading、滚动顶部）。
- [x] 列表：骨架 loading、空态（无帖/关注流空/搜索无结果）、加载更多；卡片是否含多图轮播、双击点赞、话题可点、评论数、分享/举报。
- [x] 底部：桌面是否保留「返回首页」等；移动端是否预留底部安全区（列表已加 safe-area-pb，避免被 Tab 遮挡）。

### 3.2 消息页（/community/messages）

- [x] 会话列表：未读角标、头像、昵称、最后一条预览、时间是否展示；空态是否友好（已加「去动态」CTA）。
- [x] 会话详情（/community/messages/[id]）：气泡、输入框、发送；未登录是否禁用发送并提示；顶栏「返回」图标+文案、底栏 shrink-0 + safe-area-inset-b。

### 3.3 好友页（/community/friends）

- [x] Tab：关注、粉丝、好友、好友申请是否齐全；列表与空态（空态已加「去动态」CTA）、取关/加好友/发消息/同意拒绝是否可用（当前 mock）；底部 safe-area-pb。

### 3.4 我的页（/community/me）

- [x] 头像、昵称、角色、DID/钱包占位；关注/粉丝/好友/获赞数是否展示；我的帖子、我的收藏入口是否清晰；底部 safe-area-pb。

### 3.5 作者页（/community/user/[id]）

- [x] 头像、昵称、角色、DID/钱包、简介、链接、Escrow 徽章；发消息入口；帖子网格（3 列、首图 media_urls?.[0] ?? media_url）、点击进详情抽屉；无用户时友好提示（community_user_not_found）与返回；底部 safe-area-pb。

### 3.6 我的帖子（/community/me/posts）

- [x] 3 列网格、点击进详情抽屉；空态与引导；底部 safe-area-pb；网格首图支持多图帖。

### 3.7 我的收藏（/community/me/collects）

- [x] 列表或网格、空态（community_collects_empty + 去动态 CTA）；底部 safe-area-pb。

### 3.8 社区壳（layout）

- [x] **L1** Tab（动态｜发现｜消息｜好友｜我）、未读角标、高亮当前路由；移动端底部 Tab、安全区（safe-area-pb）；离线条是否在离线时展示（isOnline）；路由切换是否滚动置顶。

## 四、统一规范（弹窗与页面）

- **返回/关闭**：所有「点开后」的抽屉/弹窗均在**左上或顶栏左侧**提供「返回」按钮（图标 + 文案），并支持 **Esc** 关闭（除 Toast 外）。
- **发帖抽屉**：底部「发布」固定可见（shrink-0），内容区可滚动；发布按钮需填正文后可用，并有提示「填写正文后即可发布」。
- **安全区**：顶栏使用 safe-area-inset-t，底栏使用 safe-area-inset-b，避免刘海/横条遮挡。
- **风格**：与 30 §4 赛博风一致（深色底、cyan/fuchsia、圆角、边框）；不在此文档引入新视觉。

## 五、与后端/数据相关的缺口（勾选以提醒落点）

- [ ] 帖子/评论/关注/粉丝/好友/私信/点赞/收藏 均未持久化，当前为前端 mock；接 API 后需替换数据源并保留错误态与重试 UI。
- [ ] 发帖多图为本地 blob 预览，未实际上传；接上传 API 后需做文件类型/大小/时长校验与错误提示。
- [ ] 视频为占位 URL，接媒体 API 后需真实播放器与进度条。
- [ ] 举报仅前端 toast，需后端记录与限流。

## 六、建议勾选顺序

1. **先勾选「二、弹窗」**：逐条对照 2.1～2.8，确认每条弹窗的排版、返回、功能、无障碍、安全区、异常态、i18n、性能。
2. **再勾选「三、页面」**：逐条对照 Feed、消息、好友、我的、作者、我的帖子、我的收藏、layout。
3. **最后勾选「五、后端缺口」**：用于与产品/后端对齐排期。

文档维护：实现或设计变更后及时更新本清单状态；与 31 主规范、31 问题与优化清单 保持一致。
