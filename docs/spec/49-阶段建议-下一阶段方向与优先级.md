## A. 协议与数据闭环（80 一级）

**目标**：按 UI 页面区分两种行程来源——（1）Web3旅行页 = AI 生成行程；（2）自由市场 = 自定义行程弹窗，**不使用 AI**，分「游客行程」与「向导设计行程」两种；自定义行程必须走后端创建 Draft 订单，保证 UI 订单 = 系统订单。

### A.1 按 UI 页面的行程入口设计

| 页面 | 路由 | 行程来源 | 是否 AI | 后端接口（现状/目标） |
|------|------|----------|---------|------------------------|
| **Web3旅行** | `/` | 首页 LandingHeroForm 提交 | **AI 生成** | 现有 **POST /api/v1/itineraries**（generate_itinerary_mock），保持不变 |
| **独立行程页** | `/itinerary/new` | 单份行程表单 | **AI 生成** | 同上 **POST /api/v1/itineraries**，保持不变 |
| **自由市场·自定义行程** | `/market` 弹窗 | CustomItineraryModal | **不使用 AI** | 当前仅前端列表；**目标**：**POST /api/v1/itineraries/custom**，后端创建 Draft + 写 itineraries |

**自由市场·自定义行程弹窗** 两个选项（与现有 UI 一致）：

1. **游客写行程**（creatorType: tourist）：按天选城市→景区→美食→酒店、预算、人数、向导等级等；前端已有 TouristForm、validateAndBuildTourist，需改为提交到后端。
2. **向导创作行程**（creatorType: guide）：按天填写/上传、标题、总价等；前端已有 GuideForm、validateAndBuildGuide，需改为提交到后端。

### A.7 API 契约（企业级）

**接口**：`POST /api/v1/itineraries/custom`

| 项 | 约定 |
|----|------|
| 鉴权 | 需登录；Cookie/Session 或 Authorization 头，与现有 /api/v1/orders 一致。 |
| 请求头 | `Content-Type: application/json`；可选 `Idempotency-Key` / `X-Idempotency-Key`（01 §10 #14）。 |
| 请求体 | 见下表 CustomItineraryBody 结构（与 A.2.2 一致）；必填：creator_type、country、total_days、amount、currency。 |
| 成功响应 | HTTP 200；JSON：`{ "status": "ok", "order_id": "<uuid>", "version": 1, "order_status": "draft", "daily_itinerary": [...], "amount_breakdown": { ... } }`，与现有 POST /itineraries 响应结构兼容。 |
| 错误响应 | 400：参数校验失败（invalid_days、destination_and_city_required、invalid_amount 等）；401：未登录；413：body 超限（与 middleware RequestBodyLimit 一致）；500：内部错误时返回通用错误 JSON。 |
| 幂等 | 同一 Idempotency-Key 在有效期内返回相同 order_id（与 48 幂等中间件一致）。 |

**CustomItineraryBody 字段约定（与前端对齐）**：

- `creator_type`: `"tourist"` | `"guide"`
- `country`: string（必填）— 须为 **`GET /meta.product_countries.name_zh`** 之一（中文国家名，与 **`frontend/lib/productCountries.ts`** 一致）；**勿**传 ISO 双字母；否则 **400** **`invalid_destination_country`**。与 **POST /api/v1/itineraries** 的 **`destination`**（不限十国白名单）区分，见 **04 §3.4**、**07** 读前摘要。
- `total_days`: number, 1～30
- `amount`: string 或 number（总预算/总价）
- `currency`: string，默认 "USD"
- `title`?: string
- `description`?: string
- `image`?: string（封面 URL）
- `headcount`?: number，默认 1
- **游客侧**：`day_plans`: Array<{ city, attractions[], food[], hotel?, cityTransport?, transport? }>；`need_guide`?: string（向导等级）；`breakdown`?: { guideFee?, carFee? }；`transport_legs`?: Array<{ from, to, type }>
- **向导侧**：`guide_day_plans`?: Array<{ city, attractions, food, hotel, ... }>；其余与前端 GuideForm 序列化一致
- `travel_date`?: string（YYYY-MM-DD，可选，用于 start_date/end_date）

### A.11 成功响应与双写约定（补充）

- **成功响应**：与现有 `POST /api/v1/itineraries` 一致，便于前端复用类型。示例：`{ "status": "ok", "order_id": "<uuid>", "version": 1, "order_status": "draft", "daily_itinerary": [{ "day_index": 1, "content_text": "...", "content_images": [] }, ...], "amount_breakdown": { "hotel", "catering", "tickets", "guide_fee", "vehicle", "platform_fee", "total_budget" } }`。自定义行程的 content_text 由后端按「第 N 天：城市 + 景区/美食/酒店」等规则从 day_plans 拼出。
- **双写**：若有 db_pool，在 itinerary_custom_create_impl 内与 itinerary_create_impl 相同，调用 `crate::db::itineraries::insert_itinerary(pool, order_id, None, 1, destination, city, &days_json, Some(&amount_breakdown_json), None, now, now)`；destination/city 取请求体 country 与首日城市或 title。

### A.12 day_plans → ItineraryDayRow 映射规则（后端）

- **游客侧**：对 day_plans 每项生成 ItineraryDayRow { day_index: i+1, content_text: 拼接 "第 i+1 天：{city}；景区：{attractions.join(',')}；美食：{food.join(',')}；酒店：{hotel}" 等（长度可截断），content_images: [] }。
- **向导侧**：对 guide_day_plans 每项同理，按 city、attractions、food、hotel 等拼 content_text；无则用 "第 N 天：待填写"。
- amount_breakdown：由请求体 breakdown 换算为 AmountBreakdown（guide_fee、vehicle 等），或前端直接传 total_budget 与各分项，后端组装。

### A.13 前端提交与刷新流程（细化）

- **调用链**：CustomItineraryModal 内 useItineraryForm 的 handleSubmit（现有调用 validateAndBuildTourist/Guide）→ 校验通过后**不再**直接 onSubmit(item)；改为用 buildTouristCustomBody(form) 或 buildGuideCustomBody(form) 得到 body，调用 **postItineraryCustom(body, idempotencyKey)**，成功则从返回中取 order_id，**调用 onSuccess(order_id)** 并 onClose()。
- **父组件**：useMarketPage 提供 onSuccess = (orderId: string) => { setCustomItineraryOpen(false); getDiscoverOrders().then(setOrders); 或 router.push(\`/escrow/${orderId}\`)；setCustomCreatedToast(true) }。Modal 的 props 由 onSubmit(item: OrderCardItem) 改为 **onSuccess(orderId: string)** 或保留 onSubmit 但签名改为 (orderId: string) 以兼容现有 Toast/视图切换。
- **失败**：postItineraryCustom 非 2xx 时，setSubmitError(解析后的错误信息)，不关闭弹窗。
