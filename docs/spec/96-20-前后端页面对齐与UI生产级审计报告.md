## 1. 证据与真源（本册不 bump 04）

| 对象 | 仓库路径 | 用途 |
|------|-----------|------|
| 后端聚合路由 | `crates/api/src/routes/mod.rs` → `api_router()` | **域清单**与 merge 顺序 |
| 前端路径常量 | `frontend/lib/api.ts` → `routes` / `apiUrl` | **前后端路径对齐**首选消费方 |
| 页面真值 | `frontend/app/**/page.tsx` | **L2** 用户路径枚举 |
| UI 维度 | [96-16 §1](96-16-全页面UI-UX优化方案总册.md) | **D1–D12** 生产级分解 |

**已知全局技术债（来自 `api.ts` 注释，非逐页打开）：**

- **`/auth/*` POST**：与同路径 Next 页面并存时 **rewrite 不覆盖**，浏览器 POST 可能落到 **Next HTML**；开发态注释要求 **直连 API BASE**（与 CORS 策略相关）。凡 **认证表单** 须单独验证 **fetch 目标 URL** 是否为 `apiUrl('/auth/...')` 直连。
- **loopback + `/api/*`**：`apiUrl` 对 `/api/*` 在 loopback 基址下 **直连 `BASE`**，与 Playwright/部分 Node 环境行为相关——E2E 稳定性审计应显式记录。

## 7. 横向发现汇总（首轮可写死项）

1. **Admin 面最大（57 L2）**：与 `routes.admin.*` 矩阵 **一一对照** 工作量最大，建议按 **监管子域** 拆 sprint（用户/订单/社区/索引器/合规…）。  
2. **`/auth` POST 与 Next 同路径**：属 **架构级** 对齐点，优先级应高于单纯视觉优化（见 **§1**）。  
3. **订单 vs 社区「消息」**：API 上并存 **`orderMessages`** 与 **`community.conversationMessages`**，**UX 文案与路由**须防用户混淆（本册 **§5.3** 已分列）。  
4. **`discover` 路径名 vs `/market` UI**：注释已说明以 **04** 为准；审计 **D2** 时须检查 **深链、SEO、面包屑** 是否把用户搞混。  
5. **「间接」页**：`/market` 等大量逻辑在 **hooks/components**，本册 **待核验** 不代表无问题，仅代表 **未在首轮打开 L3**。
