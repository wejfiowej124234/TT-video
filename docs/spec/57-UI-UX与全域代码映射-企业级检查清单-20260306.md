## 1. 目标与范围

本文用于解决三件事：

1. 基于真实代码，建立 UI/UX 到后端/数据库/区块链的可追溯映射。
2. 给出可执行的企业级全域检查清单（前端、后端、数据库、合约、运维、测试、文档治理）。
3. 按清单逐项检查并评分，形成发版前闭环依据。

**UI 规范串联**：全域映射表与评分须能与 **13/13-1 → 86/22 → 28 → 29 → …**（**[07 §五 5.3](07-开发流程与顺序.md)**）对照，避免「只核代码、不核 Experience 分区」。

本次核查以仓库当前代码为准（非旧报告结论），重点核查路径：

- 前端：`frontend/app`、`frontend/components`、`frontend/lib/api.ts`、`frontend/lib/apiClient`、`frontend/dapp`
- 后端：`crates/api/src/routes`、`crates/api/src/chain_off`、`crates/api/src/router.rs`、`crates/api/src/startup/mod.rs`
- 数据库：`crates/api/migrations/*.sql`（SQLx 时间戳序，如 `20250228000001_users_sessions.sql`、`20250228000003_orders.sql`、`20250308000013_idempotency_keys.sql` 等；**非** 仓库根下旧式 `migrations/001_initial.sql`）
- 区块链：`contracts/src`、`contracts/abi`、`contracts/test/Escrow.t.sol`
- 运维与质量：`ops/RUNBOOK.md`、`frontend/__tests__`、`frontend/e2e`

## 7. 文档维护规则（防漂移）

后续每次功能变更，按以下规则更新本文：

1. 新增/变更前端页面：同步更新 `2.1 页面与 API 映射`。
2. 新增/变更后端 API：同步更新 `3.2 后端 API 与业务实现`。
3. 变更数据库表/迁移：同步更新 `3.3 数据库与迁移`。
4. 变更链上交互：同步更新 `3.4 区块链与合约`。
5. 每次发版前复跑 `3.5 测试、运维与交付`，写入得分与证据路径。
