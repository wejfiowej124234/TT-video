## 3) 数据与审计链路（企业级必备）

```
Onchain Events
  → Indexer (finalityN + reorg rollback)
  → event_log (append-only)
  → orders_projection (可重建)
  → reconciliation_reports (对账)
  → evidence bundle (SHA256 manifest)
```

**对象存储（强烈建议）**：
- 证据文件（图片/PDF）放 S3 / GCS / R2  
- DB 只存 metadata + hash + pointer  
- 证据包（GO 包）写入对象存储 + manifest  

与 [01](01-总库总览.md) §9、[10](10-系统级不变量白皮书-v1.0.md)、evidence/README 一致。

## 4) 安全边界（必须写清）

| 项 | 要求 |
|----|------|
| **Secrets** | KMS / Secret Manager（绝不进 env 明文） |
| **私钥** | 执行器使用多签 / 硬件签名 / 托管签名服务（MVP 可先多签） |
| **网络** | DB / Redis / NATS 仅私网访问 |
| **访问控制** | RBAC + 审计日志 append-only |

与 [08-3-参数与门禁表](08-3-参数与门禁表.md)、ops/RUNBOOK 一致。

---

## 5) 观测与告警（上线必备）

| 类型 | 方案 |
|------|------|
| **Logs** | 集中式日志（ELK / CloudWatch / Loki） |
| **Metrics** | Prometheus + Grafana |
| **Tracing** | OpenTelemetry（后端已有 tracing 思维） |
| **告警** | indexer 落后区块高度、reorg 发生次数、reconcile 差异、订单失败率/支付失败率 |

---

## 6) 多区域（未来扩展，不强上 MVP）

| 组件 | 策略 |
|------|------|
| **前端** | CDN 多点天然多区域 |
| **API** | 多区域部署 + 全局 LB（基于延迟） |
| **DB** | CockroachDB 天然多 region（成本更高） |
| **Indexer** | 建议单主多备（避免重复消费复杂度），备机可热切换 |

---

## 7) 实现方案与代码结构必须遵守的约束

为 TravelTrust 生成实现方案与代码结构时，**必须遵守**：

1. **链上 Escrow 合约参数**按 [19-Escrow-合约参数结构设计图](19-Escrow-合约参数结构设计图.md) 的 **EscrowParams** 结构，必须包含：orderId、snapshotHash、platformFeeBps、token、totalAmount。  
2. **行程、聊天、报价修改**全部链下。  
3. **Confirm Final Plan** 生成 snapshotHash，链上只存 hash。  
4. **企业级部署**按本文云架构：CDN/WAF → LB → Next + Rust API + WS Chat → CockroachDB/Redis/NATS → Indexer(Projector) → RPC pool → Polygon。  
5. **资金区 UI** 金融级克制，禁止 3D 进入 Escrow/Dispute。（与 [13](13-协议级UI设计宪法.md)、[13-1](13-1-UI产品级SSOT与页面规范.md) 一致。）
