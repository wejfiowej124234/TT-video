## 1. 双轨定义

| 轨道 | 说明 |
|------|------|
| **前端** | 市场/行程表单中的**预算展示、报价计算、amount_breakdown** 可来自前端计算（如 useQuoteCalculation、CustomItineraryModal）或服务端接口。 |
| **后端** | 订单创建、confirm、snapshot 中的 **amount、amount_breakdown** 以**后端持久化**为准；canonical payload 与 snapshotHash 仅使用后端数据。 |

---

## 2. 收敛原则

| 原则 | 说明 |
|------|------|
| **链/合同为准** | 争议、对账、合约 deposit/release 以**后端 snapshot 与链上状态**为准；前端展示可与后端一致或仅作预览。 |
| **同源优先** | 若产品要求「前后端一致」：建议**预算/报价由后端接口计算**（pricing_core 或 04 约定接口），前端仅展示；或前端与后端共用同一计算规则与版本。 |
| **文档化差异** | 若当前为「前端计算 + 后端落库」双轨，须在 04 或本文**文档化**：哪些场景以前端为准、哪些以后端为准，以及差异时的处理（如后端校验前端传入的 amount 是否在允许误差内）。 |
