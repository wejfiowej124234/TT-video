# 29 · 自由市场页 — 撮合控制台规范（定稿）

**Status:** 自由市场页产品与 UI 定稿  
**定位**：自由市场不是「论坛」也不是「列表页」，而是**撮合平台**上的**撮合控制台（Marketplace Console）**：**撮合行程与向导**，让游客订单和向导供给在同一屏完成「发现 → 对比 → 接触 → 发起接单/邀请 → 进入聊天 → 最终确认 → 去 Escrow」。  
**关键约束**：自由市场**只负责撮合与协商**，资金动作不在此页；资金操作移至 OrderFlow / EscrowDetail（银行级 UI）。

## 0. 风格统一（与全站一致、适合撮合平台）

自由市场页**风格必须与全站统一**，且**仅服务于「撮合行程与向导」**，不混入论坛、社交或 DeFi 情绪。

| 维度 | 要求 | 说明 |
|------|------|------|
| **产品调性** | 撮合平台 | 唯一任务 = 发现订单 + 发现向导 + 发起匹配与协商；不做什么 = 不出现支付/链上操作堆叠、不做论坛/动态流、不做 3D/霓虹。 |
| **视觉** | **86 Business 降级** + **22**，结构参考 **28** | 全站 Design Tokens（`text-ink-*`、`text-travel-500`、`bg-bg-main`/`bg-bg-console`/`bg-bg-soft`、`rounded-[var(--radius-sm)]`）；**全页背景**：**`MarketAmbientBackdrop`** → 与 **`/traveltrust`** 同系 **`bg-traveltrust-atmosphere`** + **`bg-traveltrust-dot-grid`**（暖 Tropical 场域 + 金青点阵，**纯 CSS、无摄影全铺**）；卡片可用轻微玻璃态（`bg-bg-console/95 backdrop-blur-sm`）与 **28** 杂志式信息分层一致；**禁止**裸色、`rounded-md`、赛博霓虹；区块内装饰按 **86** 弱化，不抢撮合信息密度。 |
| **情绪** | 杂志感 + 信息结构化 | 订单卡/向导卡：信息分层清晰（目的地→报价→拆分→亮点→动作），像「旅行产品卡」而非「论坛帖」或「简历」；留白与排版克制，不堆字。 |
| **Web3 露出** | 克制、可信 | 仅 Escrow-ready pill、Supported tokens、DID Verified；不出现付款按钮、大段地址/txHash、3D。 |
| **路由** | 单页入口 | 自由市场 = **/market**（撮合控制台）；与 05/Header 一致；若存在 /discover 则与 /market 关系在 §10 明确（合并或重定向）。 |

实现时**先对齐 13 / 22 / 28 / 86 分层**（资金 **13**、Token **22**、叙事 **28**、**`/market` 外观 86 Business 降级**），再按本文 §1～§9 落实布局与组件；**视觉与动效** 冲突以 **86（降级版）+ 22** 为准，**页面职责与撮合交互** 以本文为准。

## 1. 页面定位（一句话）

**自由市场页采用 Split 双栏：左侧展示游客订单卡（含预算拆分与邀请向导动作），右侧展示向导卡与向导详情抽屉；市场页只做撮合与协商，不出现支付；聊天协商必须版本化并在 Confirm Final Plan 生成 snapshotHash；Web3 只以 Escrow-ready / Supported tokens / DID Verified 形式克制嵌入，资金操作移至 EscrowDetail（银行级 UI）。**

## 2. 页面布局

### 2.1 Desktop（强烈推荐：双栏 + 可切换）

| 区域 | 栅格 | 内容 |
|------|------|------|
| 顶部 | 全宽 | 筛选条（Sticky Filter Bar）+ 视图切换（View Switcher） |
| 左栏 | **7 栅** | 订单流（Traveler Orders）：OrderCard[] + OrderDetailDrawer |
| 右栏 | **5 栅** | 向导库（Guides）：GuideCard[] + GuideDetailDrawer（右侧抽屉） |

**视图切换（View Switcher）**：`Split`（默认）/ `Orders` / `Guides`。Split = 左 7 右 5；Orders = 仅订单列；Guides = 仅向导列。用户不跳页即可完成「发现订单 / 发现向导 — 发起动作」。

### 2.2 Mobile

| 区域 | 内容 |
|------|------|
| 顶部 Tab | **订单 \| 向导** 切换 |
| 内容区 | 当前 Tab 对应列表 |
| 详情 | **Bottom Sheet**（订单详情 / 向导详情） |

## 3. 模块 1：游客订单区（杂志感 + 信息结构化）

### 3.1 订单卡片（OrderCard）内容结构（从上到下）

| 行 | 内容 | 说明 |
|----|------|------|
| 第一行 | 目的地 + 状态 | 例：Tokyo · 5天4晚；状态徽章：Open / In negotiation / Confirmed / Funded / Closed；角标（克制）：Escrow-ready（一行小 pill） |
| 第二行 | 核心报价 | **总价：2,300 USDC**（或 USDT/USDC）— 最大视觉权重；「含平台费」小字（可 tooltip） |
| 第三行 | 费用拆分 | 向导费、专车费、酒店、餐饮、门票、其他 — mini chips / mini table（两行以内） |
| 第四行 | 亮点摘要 | 3 个 bullet（例：私密接送 / 米其林 / 小众路线） |
| 第五行 | 动作按钮 | **主**：邀请向导（Invite）；**次**：查看行程（View itinerary）；**弱**：分享 / 收藏 |

**禁止**：订单卡上不出现「连接钱包 / 支付」按钮；否则市场页会变成 DeFi 页，破坏旅行情绪。

### 3.2 订单详情（OrderDetail Drawer/Modal）

展开后展示：

- 封面图（若有）
- **目的地**：国家 · 城市 · 目的地（若有 `country` 则展示）
- 每日行程（缩略）
- 完整预算表（可滚动）
- 版本号 / 更新时间
- **Agreement Summary**（折叠）：token、platformFeeBps、snapshotHash（若已 Confirm）
- **CTA**：去抢单/进入订单页（跳转 Escrow）

---

## 4. 模块 2：向导展示区（可信 + 商业化）

### 4.1 向导卡片（GuideCard）内容结构

| 区域 | 内容 |
|------|------|
| 头像 + 名称 + 城市 | 例：Nicole · Kyoto |
| 语言 | 中/英/日 |
| 信任信息（轻 Web3） | DID Verified（或 KYC verified）徽章；完成单数、评分、响应时间（SLA 感） |
| 专长标签 | 摄影 / 亲子 / 美食 / 徒步 / 自驾 / 奢华 |
| 报价范围 | 向导费：$80–120/天；专车：$150–220/天（若可提供） |
| 动作 | **主**：查看向导；**次**：邀请接单（若当前选中某订单） |

### 4.2 向导详情 Drawer（右侧抽屉）

- 个人介绍（短）
- 服务范围地图/城市（可选）
- **套餐（Package）** 2～4 个：半日 / 一日 / 多日
- 评价（精选 3 条）
- 可用日期（可选）
- **CTA**：邀请接单 / 私聊

## 5. 撮合流程与交互（咸鱼 + 协议）

### 5.1 两种撮合路径（须同时支持）

| 路径 | 主导方 | 流程 |
|------|--------|------|
| **A：从订单出发** | 游客 | 订单卡点击「邀请向导」→ 弹出向导列表（可筛选）→ 选向导 → 发邀请 → 自动创建会话（Chat） |
| **B：从向导出发** | 向导 | 向导卡点击某订单「接单/申请」→ 游客收到申请 → 进入聊天 → 协商版本 |

### 5.2 聊天协商（必须绑定版本系统）

- 聊天区**右侧**固定「报价摘要卡 QuoteSummaryCard」：
  - 当前总价
  - 明细拆分
  - version
  - 改价按钮（生成新版本）
  - **Confirm Final Plan**（双方确认后生成 snapshotHash）
- 聊天不是闲聊，是**版本化合同协商**；Confirm 后进入 Escrow 流程。

## 6. Web3 融合规则（市场页克制）

### 6.1 允许露出的 Web3 元素

- **Escrow-ready** pill（表示该订单可进入托管）
- **Supported: USDC/USDT on Polygon**（在订单详情折叠区）
- **DID Verified**（向导身份层）

### 6.2 禁止在市场页出现

- 付款按钮
- 大段地址 / txHash（除非在折叠的 Agreement Summary）
- 任何「霓虹链路动画」
- 3D 元素（市场页不要 3D，留给 Landing）

**原则**：市场页是「交易撮合 UI」，不是「链上操作 UI」。

## 7. 高级感必备组件

| 组件 | 说明 |
|------|------|
| **Sticky Filter Bar** | 见 §7.1 筛选逻辑（与实现一致）；支持展开「高级筛选」说明 |
| **View Switcher** | Split（默认）/ Orders / Guides |
| **Empty State** | 无订单：引导「去生成行程」+「创建行程草稿」；无向导：引导向导注册/认证；无匹配：引导放宽筛选 + 清除筛选 |

### 7.1 筛选逻辑（与实现一致）

筛选条分为**两块**，与产品逻辑对齐：

| 区块 | 用途 | 行为 |
|------|------|------|
| **筛选可抢订单** | 国家（单选）、城市（单选，依国家联动） | 仅过滤**订单列表**：选国家 → 只显示该国订单；再选城市 → 显示该国该城市的订单。国家可再点一次取消选择。 |
| **筛选向导** | 语言（多选）、服务（多选） | 仅过滤**向导列表**。语言选项**按国家动态**（如选中国→中文/英语，选日本→英语/日语）；服务类型为：向导服务、陪玩服务、摄影服务、司机服务。向导还按**所选国家**过滤：只显示该国城市列表内的向导。 |

- **订单数据策略**：订单列表只请求一次（`GET /api/v1/discover/orders` 无参），前端按国家/城市过滤展示；后端若支持 `country`/`city` 查询参数，可改为传参拉取以减少 payload。
- **向导数据策略**：请求时传 `city`、`language`、`service_type`（多选时前端过滤或后端支持多值）；前端按国家校验：仅展示 `city` 属于所选国家城市列表的向导。
- **国家/城市选项 SSOT**：筛选条可选国家与联动城市与 **`frontend/lib/productCountries.ts`**（派生 **`lib/geoOptions`** 的 **COUNTRY_OPTIONS** / **CITIES_BY_COUNTRY**）一致；运行时契约与 **`GET /api/v1/meta`** 的 **`product_countries`**、**04** 对齐。**勿与 [84](84-第一阶段10国Country-Pool发行参数总表.md)** 治理叙事「十国」混为同一清单（见 **[07](07-开发流程与顺序.md)** 读前摘要专行）。
- **URL 同步**：`view`、`country`、`city`；`language`、`service` 为多值时逗号分隔（如 `language=中文,英语`）。

## 9. 字段级要求（避免开发跑偏）

### 9.1 Order（游客订单）最小字段

| 字段 | 说明 |
|------|------|
| destinationCountry, destinationCity | 目的地 |
| dateStart, dateEnd, days | 日期与天数 |
| budgetTotal, currency | 总预算、币种（USDC/USDT） |
| breakdown | guideFee, carFee, hotel, food, tickets, misc |
| highlights[3] | 亮点摘要（最多 3 条） |
| status | 订单状态 |
| version, updatedAt | 版本与更新时间 |
| escrowReady | bool，是否可进托管 |
| snapshotHash | confirmed 后才有 |

### 9.2 Guide（向导）最小字段

| 字段 | 说明 |
|------|------|
| name, avatar, city, languages[] | 基础信息 |
| tags[] | 专长标签 |
| rating, completedCount, responseSLA | 信任与 SLA |
| verified | didVerified / kycVerified |
| priceRange | guideFeePerDay, carFeePerDay(optional) |
| availability | optional |

## 10. 与 04/05/28 的对接要点

- **路由**：自由市场页 = **/market**（顶栏「自由市场」入口）；数据来源为 04 §三 的 `GET /api/v1/discover/orders`、`GET /api/v1/guides` 等。**`/discover`** 已实现 **客户端重定向至 `/market`**（`frontend/app/discover/page.tsx`，**04 §3.4**），与 **§11**「路由统一」一致，避免两套「发现」入口分流。
- **数据**：订单与向导数据**唯一来源为 API**（01 §9 业务数据同源）；不因是否连接钱包分源。
- **UI**：全站 **86 Business 降级 + 22**（Token 与动效边界），**叙事/信息分层** 参考 **28**；市场页属「旅行首页/Discover」情绪层，可用玻璃与杂志感，禁用 3D、霓虹、大钱包 CTA。风格统一见 §0；**阅读顺序** **[07 §五 5.3](07-开发流程与顺序.md)**。
