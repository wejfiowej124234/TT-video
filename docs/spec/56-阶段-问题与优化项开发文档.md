### §二附、56-S1 行程单框架 SSOT（单源）

**用途**：行程单与 AI 生成、自定义行程弹窗的**单源约定**；56-S2/S3/S4 实现以本节与 [52-阶段开发技术文档](52-阶段开发技术文档.md) §3.1/§3.2、[04-后端与API](04-后端与API.md) §3.4 为准。

**依据**：§一附、52 §3.1/§3.2、04 §3.4。

**框架原则（§一附）**：

| 原则 | 说明 |
|------|------|
| 按天·城市 | 每天一城；景区、美食、城市交通、跨城交通、酒店均需支持；**景区/美食/酒店必配图**（有则展示，生成/录入时尽量提供）。 |
| 多城市 | 用户选 N 天+城市序列（如北京-上海-杭州）时，**仅生成这些城市**及对应景区/美食/交通/酒店。 |

**56 维度 ↔ 52 §3.1 ↔ 04 API 字段对照**：

| 56/§一附 维度 | 52 §3.1 字段（UnifiedDayRow / daily_itinerary[]） | 04 API 约定 |
|----------------|---------------------------------------------------|-------------|
| 按天 | day_index, date, city | daily_itinerary[].day_index/date/city；day_plans[].city |
| 景区 | attractions: { name, intro, image? }[] | daily_itinerary[].attractions；day_plans[].attractions 为 { name, image? }[]；guide_day_plans 每 day 可有 attraction_image |
| 美食 | dining: { name, description?, image? }[] | daily_itinerary[].dining；day_plans[].food 为 { name, image? }[]；guide_day_plans 每 day 可有 food_image |
| 城市交通 | city_transport: string \| { type, desc?, image? } | daily_itinerary[].city_transport |
| 跨城交通 | inter_city_transport: string \| { from, to, type?, note?, image? } | daily_itinerary[].inter_city_transport |
| 酒店 | hotel: string \| { name, area?, intro?, image? } | daily_itinerary[].hotel；day_plans[].hotel 为 string \| { name, image? } |
| 当日描述/图 | description, images[] | daily_itinerary[].description, .images |
| 配图要求 | 景区/美食/酒店单元含 image 或 intro/name 成对 | POST itineraries/custom 请求体支持 name+image；响应 daily_itinerary 与 52 统一表一致（含 name+image） |

**多城市 AI 契约（56-S3 依据）**：

| 项 | 约定 |
|----|------|
| 输入 | N 天 + 城市序列（如 [北京, 上海, 杭州]），与自由市场「创建行程」所选一致。 |
| 输出 | daily_itinerary 仅包含上述 N 天的城市及对应景区/美食/交通/酒店；**不生成未选城市**。 |
| 先 mock 后接 AI | 可先实现 mock：按城市序列生成占位或固定模板日行，再对接真实 AI 时保持同一契约。 |

**使用方式**：S2 实现时保证 UnifiedDayRow/daily_itinerary 与上表及 52 §3.1 一致，API 返回含各维度与 image；S3 实现多城市仅所选城；S4 行程单与 Landing 按本框架与 52 §3.1/§3.4 渲染。新增字段须同步 52 §3.1 与 04 §3.4。
