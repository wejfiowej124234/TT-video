## 二、详细模块交互架构图

以下**订单主链**与 [53-阶段开发技术文档](53-阶段开发技术文档.md)（双边协议：抢单 → 社区聊天修改 → 向导确认接单 → 双边确认 → 付款 → 完成 → 评分释放）**叙事对齐**；具体状态枚举与 API 以 **04 §3.4**、`crates/core` 为准。

### 1️⃣ 需求与草稿阶段（链下）

```
游客：AI 生成 / 自定义行程（**前置规格**见 **80**；UI/表结构衔接 **42、52**）
    │
    ▼
创建订单草稿 → itineraries / orders 落库
    │
    ▼
发布可抢单（Open / 草稿态按产品定义）
```

**模块涉及**：AI 或自定义行程 API、`itineraries`、`orders`、`users` / `guides`。

**列表与发现 API（56 / 04）**：`GET /api/v1/orders`、`GET /api/v1/discover/orders` 的 item 含 **image**（行程 `cover_image` 优先，否则按日行图文推导，与 hydrate 一致）、**escrow_address**（P18 写入后与详情同源）。前端「我的订单」与市场订单卡已消费；契约单源 **04 §3.4**、**14**、**56 §6.2**；开发顺序入口 **07 §二 2.3 第 6 行**、**07 §五 5.6**。

### 2️⃣ 撮合与双边协议阶段（链下，53 主链）

```

    │
    ▼
```

### 3️⃣ Escrow 创建与托管（链上 + 索引）

```

    │
    ▼

    │
    ▼
```

**链上记录**（示例）：EscrowCreated、Paid（具体事件名以 ABI 为准）。

**后端**：**不**假设存在物理表名 `event_log` / `orders_projection`；投影落点以 **110** 与代码为准。

### 5️⃣附、Target：FeeRouter / 区域池（与主链关系）

**定位**：**Escrow → release** 仍为当前仓库**主交易链**；**FeeRouter → RegionVault / Global Pool → TTG** 等为 **Target** 扩展（与 **82 / 83 / 84** 一致），链上未实现前**不**在本图「订单主链」框内展开，避免与 MVP 实现混淆。

## 七、完整逻辑闭环（与 53 对齐的口语链）

```
行程/草稿（AI 或自定义）
→ 发布 / 抢单
→ 聊天修改 + 向导确认接单
→ 双边确认 → confirm-final-plan / snapshotHash
→ Escrow 创建 + 托管存款
```

## 八、真实可落地性分析

本架构具备：

- **不托管用户资金**（资金在合约内）  
- **平台收入路径可解释**（**当前 MVP**：费用与托管逻辑以 **01/03/53** 与合约为准；**Target** 可分配手续费经 **FeeRouter** 路由时以 **83/84 §1.1.1** 为单源，**勿**与 **Escrow 本金**混读）  
- **冷启动可行**（链下撮合与链上托管分离）  
- **技术复杂度可控**（Indexer + projection + 明确边界）  
- **可逐步升级**（治理参数、激励池、`82` 专题等按总表「附」与阶段文档启动）
- **经济扩展单源**：FeeRouter 费用 **100%** 分母与 **仲裁费 / slash** 正交 — **84 §1.1.1** + **Runbook §7.1**；TTG **100%** 供应占位 — **governance-token/02 §2.5**
- **横切能力（非本图主链展开）**：**通知、WebSocket 实时、媒体/证据对象存储** 等是否「已定稿/已落地」见 [00-最终版架构图对应模块清单总表](00-最终版架构图对应模块清单总表.md) **§三**（含 **社区 Partial**、**订单聊天 HTTP vs WS** 表注）；**社区域**阶段规格见 **[160](160-阶段开发内容与社区系统.md)**。观测与异步等阶段落点见 [120-阶段开发观测告警日志与审计链路](120-阶段开发观测告警日志与审计链路.md)、[250-阶段Job-Queue-异步任务系统](250-阶段Job-Queue-异步任务系统.md)、[270-阶段文件媒体证据存储系统](270-阶段文件媒体证据存储系统.md) 等 Wave 文档。**全链路追踪 ID**（request/order/tx/job 串联）规格见 [520-阶段跨系统追踪ID全链路系统](520-阶段跨系统追踪ID全链路系统.md)，与 **120** 可观测体系配套 — **本图仅指订单主链剖面**。
- **Wave 规格全目录（100～550）**：[00-文档索引](00-文档索引.md) 主表逐行收录各 `NNN-阶段` 文入口；**本图不逐模块展开**。**55 ≠ 550**、空号段与「有文档 ≠ Implemented」见 **[07-开发流程与顺序](07-开发流程与顺序.md) §零 0.3.1** 与 **00 总表 §二点五** 末段。
