<a id="hb-00-doc-cleanliness"></a>

### 2.1.0 文档树「干净」验收对象（行业 / 企业级 / 生产级）

在文档工程语境下，**「干净」不是美学上的「全盘中文文件名」或「`docs`/`spec` 已空」**，而是**可导航、可审计、真源不串、主序不乱**。下表给出**分层口径**（由宽到严）；**评审或对外承诺**时应写明落在哪一档，**禁止**用低档成果冒充高档。

| 层级 | 验收对象 | **可称为「干净」的最低条件** | **不得称为「干净」的典型反例** |
|------|-----------|------------------------------|--------------------------------|
| **行业级**（可协作） | 任意技术文档库 | 有**单一入口索引**能回答「我该先读哪」；链接可维护；**不**靠私聊口口相传 | 同主题多份互相打架的「真源」；入口文档长期断链 |
| **企业级**（可治理） | **`docs/handbook/`** 净写树 | **§3 主表** · **各栏 `README` 主序** · **磁盘 `NN-*.md` 文件名** **三处对拍**（见 **§2.1.2**）；**§1** 与 **`../spec/`** 分工清晰；并行目录（如 **`docs/product-manager/`**）在 **README** 中写明**与 handbook / spec 边界** | **§3** 有行无文、或有文无表；**跨栏抢号**；读者无法判断契约应回 **spec** 还是读本手册 |
| **生产级**（可合入） | **PR + CI** 视角下的 handbook 变更 | **`bash scripts/check-handbook-frontmatter.sh`** 通过；**engineering `NN≥10` 域篇**满足 **[06](engineering/06-工程模块技术文档编制契约与验证闭环.md)** 与 **§2.5 T6/T7**；**`engineering-content`** 对 **`EVIDENCE-*-cluster-verified.md`** 机读形态见 **[engineering/22 §2](engineering/22-横切-簇级verified证据模板.md#vtpl-2-naming)**；**不**在 handbook **整表抄写** **04 §3.4** / **93** 表体替代 SSOT | 以散文「宣称已 Implemented」而无 **Reference** 或 **门禁**可对齐；**verified** 口径违反 **§11.3** |

**与 `../spec/`**：**`spec/`** 长期承担 **Reference** 与**版本表 SSOT**（含大量 **编号 + 中英混排文件名**），属**既定资产**；**不以「spec 仍存在英文文件名」**认定 **handbook 治理失败**。删 **`spec/`** 路径须 **[engineering/08 §3](./engineering/08-文档与spec迁移台账.md#mig-2-matrix)** + **[engineering/09 §3](./engineering/09-文档迁移覆盖审计报告.md#audit-coverage)**（**同 PR** 对拍）+ **[engineering/08 §2](./engineering/08-文档与spec迁移台账.md#mig-delete-policy)**、**[corpus/SPEC-MIGRATION-STATUS](corpus/SPEC-MIGRATION-STATUS.md)**、**[98 §2](../spec/98-以代码为真源的文档体系与旧文档替代路线图.md)** 程序同批。

### 2.1.1 中文优先与「保留英文」清单（生产级）

| 层级 | 规则 |
|------|------|
| **文件名（三栏 `NN-*.md`）** | **主题段用中文**（例：**`01-仓库地图与首次克隆.md`**）；**不写**无号段的散文件与 **handbook/** 根目录堆文（**除** 本目录 **`README.md`**）。 |
| **文内一级标题 `#`** | **以中文叙事为主**；行业通行技术词（**HTTP、API、ADR、ABI、CI、SSOT、Next.js** 等）**可保留**或**首次出现中英并陈**，**不**为「纯中文」而造生僻译名导致检索失败。 |
| **以下文件名保留英文/固定前缀**（改名即破坏脚本、**09/08** 证据链或跨仓习惯） | 各栏 **`README.md`**；**`corpus/SPEC-MIGRATION-STATUS.md`**；**`corpus/REG-{NN}-*.md`**（**REG** 为登记前缀）；**`engineering/_TEMPLATE-工程模块篇.md`**（下划线模板）；**`engineering/EVIDENCE-*-cluster-verified.md`**（与 **[09 §2b](engineering/09-文档迁移覆盖审计报告.md#audit-verified-gate)**、**[22](engineering/22-横切-簇级verified证据模板.md)** 同形检索）。 |

<a id="hb-00-naming-latin-tiers"></a>

### 2.1.3 文件名中英混排分级（企业级命名策略）

**目标**：在**中文可读**与**跨工具链可检索、可门禁**之间取平衡；**禁止**为「纯中文文件名」而破坏 **CI / 迁移台账 / 证据簇** 的稳定键。

| 分级 | 典型形态 | 用途与理由 | 变更门槛 |
|------|-----------|------------|----------|
| **L0 冻结键** | 各栏 **`README.md`**；**`corpus/SPEC-MIGRATION-STATUS.md`**；**`corpus/REG-{NN}-*.md`**；**`engineering/_TEMPLATE-…`**；**`engineering/EVIDENCE-*-cluster-verified.md`** | **脚本、08/09/22、跨仓习惯**依赖固定 basename；与 **§2.1.1**「保留英文」表一致 | **Owner** 批准 + **同步改脚本/台账/全仓链接** 的迁移方案；**禁止**随手改名 |
| **L1 域样板代号** | **`10-A` `20-B` `30-C` `40-D` …** 文件名中的 **`-A/-B/-C/-D`** 段 | 与 **§3**、**§10 · R0**「域样板 / 横切」族一致，便于**排序与肉眼扫号** | 改任一代号须 **同批**更新 **§3**、**[engineering/README](engineering/README.md)**、**09/08** 相关行及阅读链 |
| **L2 主题技术词** | **`NN-HTTP与路由…`**、**`…ADR…`**、**`…API…`**、**`…ABI…`** 等主题段中的行业通行缩写 | **glob / `grep` / Code Review** 与业界表述一致；避免生造译名导致检索失败 | 可优化为「中英并陈文件名」须评估 **全仓相对链接** 与 **外部引用**；**默认**小步、可回滚 |
| **L3 禁止项** | 栏内**无 `NN-` 前缀**的散稿；**`handbook/`** 根（**除** **`README.md`**）堆长文；与 **`../spec/00-*.md`** **撞名**且无 **handbook 语义** | 破坏 **§2.1.2** 排序与 **spec/00** 工具链区分 | **一律不得**新增；存量按 **§11** 与 **98** 收口 |

**结论**：读者看到**英文文件名**时，应优先判断其属于 **L0/L1（须保留）** 还是 **L2（行业可读）**；**不应**将 **`../spec/`** 或 **`REG-*` / `EVIDENCE-*`** 中的英文等同于「未治理」。

<a id="hb-00-frontmatter-min"></a>

### 2.2 每篇必备文首（专业最小集）

1. **`#` 标题** — 含栏位语义（工程 / 产品 / 学习）。  
2. **`Version:`** · **`最后更新:`** · **`受众:`** · **`状态:`** — **`草案` | `现行` | `弃用`**。  
3. **`与 spec 关系:`** — 一句话：替代哪类 **spec 叙事** / **不替代**哪张表或矩阵。  
4. **`engineering/`** 与 **`EVIDENCE-*-cluster-verified.md`**：文首须含 **`SSOT（必读）`** blockquote；**须**含 **「不替代」** 与链 **04 §3.4**、**93**、**14**、**`crates/`·`contracts/`·`frontend/`** 及当次 **PR** **脚本门禁**（**机读**见 **`check-handbook-engineering-content`** 对 **`EVIDENCE-*`** 的 **不替代** 提醒）。**`SSOT（必读）` blockquote 内**须在 **「域矩阵 93」** 与 **「实现」** 之间写出 **链上 ABI 与对齐叙述** 分句（显式 **14** + **`contracts/`** + **`check-55-s13`** 等脚本；与 **[08 · 文首 SSOT](engineering/08-文档与spec迁移台账.md)** 同键），**不得**仅在正文它处提 **14** 而 **blockquote** 中省略该分句。**推荐**与 **[engineering/README](engineering/README.md)** 段首**同形**（**engineering 仅为导读，不替代 spec**；真源枚举同句）；**母版** **[22 §2](engineering/22-横切-簇级verified证据模板.md#vtpl-2-naming)**。

### 2.4 与常见文档模型（Diátaxis）的对齐（生产级信息分型）

业界广泛采用的 **Diátaxis** 将技术内容分为四类，**本仓库**对应关系如下（避免把「教程」「参考手册」「解释原理」混在一篇里双写）：

| Diátaxis 类型 | 读者问题 | 在本仓库的主要落点 |
|----------------|----------|---------------------|
| **Tutorial**（跟着做一遍） | 我第一次怎么跑通？ | **[learn/](learn/)**、根 **[README](../../README.md)**、**[TT-9618](../../runbook/TT-9618-onboarding-local-testnet.md)** |
| **How-to**（完成一件具体事） | 我怎么部署 / 怎么对拍路由 / 怎么过某 Gate？ | **[CONTRIBUTING](../../CONTRIBUTING.md)**、**[ops/RUNBOOK](../../ops/RUNBOOK.md)**、**engineering** 中带操作步骤的篇（规划 **05～09**） |
| **Reference**（可查表、可机读） | 字段 / 路由 / 矩阵行真值是什么？ | **[04 §3.4](../spec/04-后端与API.md)**、**[93](../spec/93-全站功能验证矩阵-域别回归清单.md)**、**代码**（`routes/mod.rs`、OpenAPI 若启用）、**本手册不抄表体** |
| **Explanation**（理解为何如此） | 为什么这样设计？业务与架构叙事？ | **`engineering/01～04` 及后续域篇**、**`corpus/REG-*`**（长叙事再生）、**spec** 中与契约无关的论述（过渡期） |

**结论**：**程序员专业读本**以 **engineering = Explanation + 指向 Reference 的导读** 为主；**真值**永远在 **Reference 层 + 门禁脚本**，手册句首须写清「不替代哪条 SSOT」。

## §9 分层模型：新内容落哪（与「加功能」同构）

**先选层，再选号** — 避免把「契约表」「矩阵行」「人读导读」混在一个文件里双写。

| 层 | 路径 / 模式 | 放什么 | 不放什么 |
|----|----------------|--------|----------|
| **L0 总入口** | [README.md](README.md) | 指到 **00**、**corpus**、三栏 **README** 的一句话导航 | 长叙事、接口字段表 |
| **L1 总册** | **本文件 `00-手册总览…`** | 编制规范、**§3** 主序列表、**§5** 区段、**§6** 合入流程 | 具体功能的实现细节（放到 L3） |
| **L2 栏入口** | `engineering/`、`product-manager/`、`learn/` 各自的 **README.md** | 本栏 **当前** NN 列表与阅读顺序；**ADR（`docs/adr/`）**/**07**/**32 §0** 等跨界链见各栏 **README** 与 **[spec/00 读前摘要](../../spec/00-文档索引.md)** | 与另一栏重复的万字背景 |
| **L3 栏内正文** | **`NN-主题.md`**（三栏） | **按角色** 的导读、决策背景、与代码/spec 的**对读说明** | **04 §3.4** 全表、**93** 全矩阵（只外链） |
| **L4 正文再生** | **`corpus/REG-NN-…`** | 从 **spec 主序列 01～15** 级长文**迁出**后的**可独立阅读**再生稿 | 与 **REG** 同主题的重复短文（应合并或互链） |

**与「加功能」对齐**：  
- **新功能**的**日常增量** → 默认落在 **L3**（`engineering` 某区段 **NN**），并按 **§6** 同步 **04 / 93** 等真源。  
- **在迁移 spec 主序列叙事**（例如把「01 总览级」故事整体搬到 handbook）→ 用 **L4 `REG-*`**，并在 **spec** 原文篇首加 **迁出句**（见 **corpus/SPEC-MIGRATION-STATUS** **P-A**）。  
- **不要**为每个小需求新建 **REG**；**REG** 与 **spec 01～15 同号族** 对齐，**域功能**优先用 **engineering 10～89**。

**子目录策略（现阶段）**：三栏内**保持扁平** `NN-*.md`，便于排序与 grep。**仅当**同一栏、同一区段（如 **20～29**）稳定超过 **约 15 篇** 再议是否引入子文件夹（须先改 **§2.1** 与各 **README** 约定，避免半套子目录半套扁平）。

## §11 文档治理总规则（防膨胀与 SSOT）

本节为 **`docs/handbook/`** 侧**最终口径**：与 **[engineering/02](engineering/02-生产级文档约束与合入门禁.md)**、**[engineering/06](engineering/06-工程模块技术文档编制契约与验证闭环.md)**、**[engineering/08 §2a](engineering/08-文档与spec迁移台账.md#mig-verified-gate)**、**[engineering/09 §2a～§2b](engineering/09-文档迁移覆盖审计报告.md#audit-quant-coverage)**、**[engineering/22](engineering/22-横切-簇级verified证据模板.md)** 及根 **[AGENTS.md](../../AGENTS.md)** **同向**；冲突时以 **可执行产物（CI / 门禁脚本）** 与 **代码** 为准，**不以** handbook 散文推翻 **04 §3.4 / 93 / spec/00**。

### 11.1 **必须**写或补 handbook 的情况

| 触发 | 最低要求 | 典型落点 |
|------|----------|----------|
| **新增或显著改变**某业务域的工程叙事（多文件、多入口、易迷路） | 按 **[06](engineering/06-工程模块技术文档编制契约与验证闭环.md)**：**engineering `NN≥10` 域篇** 九节骨架 + **§6** 至少一条**仓库真实**命令；**先** **[§5](#hb-00-number-blocks)** 选号，**再** **[§3](#hb-00-master-table)** 与栏 **README** 增行 | **L3** `engineering/NN-…` |
| **同一 PR** 修改 **HTTP / 路由 / 前端页面表** 与 **`crates/api` / `frontend/app`** | **须**可复核地跑通 **[CONTRIBUTING](../../CONTRIBUTING.md)** 与 **engineering/04 §6** 所列 **`run-check-04-routes`** 族命令；**须**在 **04 §3.4 / 93** 侧完成契约或脚注，**禁止**用手册表体替代 | **spec 机读 + engineering/04** |
| **横切能力**（流程、阶段族、前端宪法、迁移审计等）且 **09 §3** 已登记为簇级缺口 | **优先一篇 Hub**（如 **23 / 24 / 32**），**不**拆成多篇同义短文；合入时 **09 / 08 / 本 §3** 同批闭合（纪律见 **09** 文内「执行纪律」） | **L3** 横切 `engineering/` |
| **corpus 迁出** 已立项（**SPEC-MIGRATION** **P-A** 起） | **须**走 **§8**、**[98 §2](../../spec/98-以代码为真源的文档体系与旧文档替代路线图.md)**，**禁止**仅建 handbook 而不登记真源与脚本依赖 | **L4** `corpus/REG-*` |

### 11.2 **禁止**或默认**不允许**新增文档的情况

| 禁止 / 强烈抑制 | 原因 | 替代动作 |
|-----------------|------|----------|
| **为 `../spec/` 根目录单文件** 各写一篇 **engineering** 镜像（尤其 **~280+** 散文件、审计快照、兼容壳） | 索引爆炸、与 **spec/00** 重复 | 归入 **09 §3「根目录其余」** 口径：**spec 历史材料**；入口靠 **spec/00**、阶段 **Hub（如 32）**、**08 备注** |
| **把 `27-archived/`、`snapshots/`、`code-maps/`** 整树迁入 **handbook 正文** | 考古层 ≠ 现行读本 | **仅在 08 / 98 §2** 说明保留原因；**必要时**一条链到 **spec** 路径即可 |
| **在 handbook 粘贴** **04 §3.4**、**93** 矩阵 **表体** | 双写与漂移 | **只外链**锚点 + 用 **REG-04** 等 **L4** 收叙事；表体留在 **spec** |
| **新建 handbook 文** 但 **无** **[06](engineering/06-工程模块技术文档编制契约与验证闭环.md)** 意义下的 **九节 + §6**（或 **REG-* 等价结构 + 可执行验证段**）却宣称 **migrated / 承接完成** | 违反 **09 §10b C-2** | 先补结构或降格为 **partial** 笔记 |
| **与已有 `REG-*` / 已有域篇** 主题重复的第二套长文 | 膨胀 | **合并**或 **互链**，二选一 |

### 11.3 哪些情况**才允许**进入簇级 **verified**

**verified** 只用于 **[engineering/09 §3](engineering/09-文档迁移覆盖审计报告.md#audit-coverage)** 中**已定义为叙事簇**、且 **Owner 明确**要做**强证闭环**的条目；**不是**「写得长」或「有 frontmatter」即自动升格。

| 条件 | 说明 |
|------|------|
| **须同时满足** | **[08 §2a](engineering/08-文档与spec迁移台账.md#mig-verified-gate)** **V-1 / V-2 / V-3 至少其一**；**[22](engineering/22-横切-簇级verified证据模板.md)** 命名与锚点；**[09 §2b](engineering/09-文档迁移覆盖审计报告.md#audit-verified-gate)** 对应簇登记行；**08 §3** 矩阵备注一致 |
| **须有稳定 §6** | 域篇或 Hub 的 **§6** 命令与 **CI 具名 step** 或 **PR 日志** **字面可对齐**；**禁止**「口头已验」 |
| **永久不对此类簇做 verified** | **93 矩阵本体**（矩阵**永不**迁入 handbook）；**「根目录其余 ~280+」聚合考古簇**；**无单一可执行门禁**能代表的散袋主题 |
| **verified ≠ 删 spec** | **full** 与 **`删除 spec=yes`** 仍须 **[08 §2](engineering/08-文档与spec迁移台账.md#mig-delete-policy)** 五条件 + **SPEC-MIGRATION** + **98 §2** |

### 11.4 **spec** 与 **handbook** 长期分工（真源边界）

| 载体 | 长期职责 | **不得** |
|------|-----------|----------|
| **`spec/04` §3.4、`spec/93`、路由注册代码** | **HTTP 机读**与**域矩阵** SSOT | 被 handbook **整表复制**或宣称替代 |
| **`spec/00`、`spec/07`** | 主索引、**Wave / 版本三线**、发版顺序 **SSOT** | 被 **handbook** 另起一套「第二份主索引」取代 |
| **`spec/` 长文、阶段 `NNN-阶段*.md`、70/94/…** | 产品与阶段深叙事、证据表原文 | **默认**整篇迁入 handbook；**导读**用 **engineering / corpus** **外链** |
| **`docs/handbook/`** | **Diátaxis** 下的 **Explanation + How-to**、**对读顺序**、**PR 侧门禁索引** | 自称 **HTTP 字段全表唯一真源**；在 **与 04/93 矛盾** 时仍以 handbook 为准 |
| **`docs/handbook/corpus/REG-*`** | **从 spec 主序列迁出**后的**可独立阅读**再生正文 | 与 **同号 spec** **双写**不登记；未过 **SPEC-MIGRATION** 即 **`git rm` spec** |

**进度三阶（① 本地 / ② 测试网 / ③ 生产）**：handbook 内 **verified**、**§6**、**CI** 证据**默认**只证明 **①**；**禁止**用 **①②** 的文档合入冒充 **③** 已 **GO**（与根 **README**、**AGENTS.md** 同源）。
