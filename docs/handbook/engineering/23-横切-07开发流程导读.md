<a id="x23-1-scope"></a>

## 1. 模块职责（L1）

- **解决**：工程师在「改契约 / 改手册 / 开 ADR」时降低「不知先跑哪条门禁、何时必须打开 **spec/07**」的查找成本。  
- **在系统中的角色**：横切 **How-to + Explanation**；与 **[07-ADR](./07-架构决策记录ADR规范.md)**（**ADR 形态**；**`ADR-*.md` 唯一落 `docs/adr/`**）**互补不重复**——**流程与版本表**以 **spec/07** 为纲，**ADR 写法与目录约定**以 **engineering/07** 为纲。

---

<a id="x23-2-mechanism"></a>

## 2. 核心机制（L2）

1. **三线一致（07 文首 / 手册 00 / 07 §六 表顶）**：动 **[04](../../spec/04-后端与API.md)** `Version:` 时，**同批**改 **手册 00** 中 **07** 行与 **§六 6.5** 表顶，并跑 **`bash scripts/check-07-version-triple.sh`**（失败即 **PR 不合格**；见 **§6**）。  
2. **合入前**：契约变更 → **04 §3.4** → **`run-check-04-routes`**；全仓流程见 **[02](./02-生产级文档约束与合入门禁.md)**、**[05](./05-本地环境与常用门禁速查.md)** 矩阵。  
3. **发版 / GO**：仍以 **07** 与 **[95](../../spec/95-全链路生产就绪检查清单与完成度矩阵.md)** / **[96-索引](../../spec/96-索引-全链路外生产验收分册.md)**、根 **go-live-checklist** 为序；本文**不**缩短 **③ 生产** 闸口（见根 **README** 工程规划方向）。

<a id="x23-3-model"></a>

## 3. 数据与状态模型（L2～L3）

- **版本号**：**07** 与 **手册 00** 的版本字段为**人类与门禁共同消费**的字符串；**真值**以 **git 默认分支上文件内容**为准，不以聊天口述为准。  
- **PR 状态**：**Open / Merged** 与 **CI green** 独立；**merged** 后若 **07 三线**漂移，下一 PR **仍须**红则修。
