## 1. 模块职责（L1）

- **解决**：把「行程草稿 / 市场可见性 → 旅行者下单 → 向导接单 → 双边与托管前后动作 → 列表与详情一致性」在后端收敛为**可审计的 HTTP 面 + DB/档期副作用**；并与 **chain_off**、**投影读失败** 等运行态门禁对齐。  
- **在系统中的角色**：**B 域**核心子系统之一；上承 **itineraries**（草稿来源）、下接 **Escrow 前端路由与链上步骤**（放款/释放不在本篇展开为逐步教程，入口见 **04** 与 **[14](../../spec/14-合约-API-ABI-前后端对齐.md)**）。**94 子站**（商家橱窗 / 旅行收购 **`/api/v1/market/*`**）见 **[21-B](./21-B-市场与托管机制.md)**。  
- **何时须打开 [53](../../spec/53-阶段开发技术文档.md)**（**T-018**）：改 **产品步骤条 / 53-Sx / TT 社区与订单聊天 / 行程确认 UX**、或核对 **阶段专有窗口** 的 **key 与默认值**（以 **53 §3.5** + **[08-3](../../spec/08-3-参数与门禁表.md)** 为准；**03 §一** 表内「如 24h」仅为示例，**不得**当工程秒数真源。**仅**改 **`/orders`** / **`discover/orders`** 的 **HTTP、错误码、93 B-ORD 矩阵** 且**不**动步序时，**20-B + 04 + 93** 通常足够。**状态机硬约束**（完成 vs 放款、超时、争议窗口）须同时打开 **[01](../../spec/01-总库总览.md)** 与 **[03](../../spec/03-业务流程与风控.md#spec03-section-I)**（**[§一 · 1.1](../../spec/03-业务流程与风控.md#spec03-s1-1)** / **[1.2](../../spec/03-业务流程与风控.md#spec03-s1-2)** / **[1.3](../../spec/03-业务流程与风控.md#spec03-s1-3)**）。

<a id="b20-2-mechanism"></a>

## 2. 核心机制（L2）

**主路径（口语序，非唯一代码调用序）**

1. **市场可读**：向导侧通过 **`GET /api/v1/discover/orders`** 浏览可抢的 **Draft** 订单卡片（筛选、分页、**503 chain_off_unavailable** 等与 **04** 一致；实现入口 **`crates/api/src/routes/discover.rs`**，聚合逻辑见该文件与 **04** 散文窗）。  
2. **下单与「我的订单」**：**`POST /api/v1/orders`** 创建；**`GET /api/v1/orders`** 列出当前用户可见订单（含 **`limit`/`cursor`/`state`** 等 query 语义，以 **04 §3.4** 为准）。  
3. **详情与门禁**：**`GET /api/v1/orders/:id`** 在 **无 `chain_off`** 时按契约返回 **503**（禁止假 **200** 空壳）；有 **`chain_off`** 且为参与方时返回详情体（含 **`itinerary`/`breakdown`** 等与列表卡片同源字段，见 **04** 说明）。  
4. **状态推进写口**：接单、终版计划、双边确认、mock 入账、设置 escrow 地址、取消、完成确认、评分相关 POST 等集中在 **`crates/api/src/routes/orders/`**（**`mutations.rs`** 与 **`mod.rs`** 的路由表）。  
5. **观测与对账**：**`GET /api/v1/orders/:id/chain-sync-status`** 提供链同步/投影可读字段；与 **`GET /meta`** 中机读锚点同源（见 **`orders/mod.rs`** 顶部常量注释）。

**设计取舍（为何这样拆）**

- **Discover 只读、Orders 写**：自由市场列表不承担订单状态机写入，避免「列表接口隐式改库」；与 **93** 中 **B-MKT-\*** 与 **B-ORD-\*** 分工一致。  
- **chain_off 作为业务层闸门**：大量订单读写在无链环境仍要**可失败可观测**，故 **503 + 稳定错误码** 优于静默空数据。  
- **档期与订单原子性**：取消/完成等路径若配置 **`SCHEDULE_SLOTS_PATH`**，失败时须回滚订单行并返回 **503**（**04** 与 **`mutations.rs`** 注释中的 **ORDER-SCHEDULE-ATOMIC-\*** 族）；避免「库已取消但档期仍锁」。

## 3. 数据与状态模型（L2～L3）

- **订单状态**（字符串与语义）：与 **`OrderState`** / **`chain_off::str_to_order_state`** 可解析集合一致（如 **draft、created、accepted、escrowed、completed、cancelled、disputed…**）；**列表筛选 query `state`** 与详情内 **`order.state`** 精确匹配，未知值 **400 invalid_state**（见 **04** 散文说明）。  
- **参与方与 87 双读**：详情与消息体根级 **`tourist_id` / `traveler_id`** 等与 **04**、**87** 对齐；改字段须同步 **OpenAPI/前端 reader**，勿只改一端。  
- **状态机硬约束**：资金相关迁移「谁驱动」以 **[01](../../spec/01-总库总览.md)**、**[03](../../spec/03-业务流程与风控.md)** 为准；**53 §三** 描述产品步序与 UI 期望，**实现以 04 + 本仓库 `orders/` 代码为准**。

**不**在本篇复述 **04 §3.4** 或 **93** 表格行；需要逐字段验收时直接打开上述真源。

<a id="b20-7-debug"></a>

## 7. 调试与排错（强制）

- **`GET …/orders/:id` 503 `chain_off_unavailable`** → 运行态是否挂载 **chain_off**；对比 **`GET /meta`** 与 **04** 对该路径的约定。  
- **`GET …/orders/:id` 503 `orders_projection_read_failed`** → DB **`orders_projection`** 读失败；查 API 日志与 DB 连接；对照 **04** 与 **`orders`** 列表是否同口径降级。  
- **详情 200 但字段与列表卡片不一致** → **04** 要求 **`breakdown`/`itinerary`** 与 **discover/orders**、**GET /orders** 同源；从 **`orders/mod.rs`** 列表/详情组装路径追。  
- **取消/完成返回 `schedule_release_failed` / `order_db_reconcile_failed`** → **`SCHEDULE_SLOTS_PATH`** 与档期文件权限；读 **`mutations.rs`** 回滚分支。  
- **93 矩阵红** → 对应 **`matrix_93_b_*`** 测试文件内注释的 **B-ORD-xxx** 编号；回到 **93 §2.3** 最小证据列。
