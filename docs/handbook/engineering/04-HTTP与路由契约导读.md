## §1 标准对拍顺序（每次改 API）

0. 若本次变更落入 **[02 · §2 附](./02-生产级文档约束与合入门禁.md#hb-prod-adr-triggers)**「**须写 ADR**」——**先**按 **[07-架构决策记录ADR规范](./07-架构决策记录ADR规范.md)** 在 **`docs/adr/*.md`** 落盘 **Why**（入口 **[`docs/adr/README`](../../adr/README.md)**；**不**替代 **04 §3.4** / **93** 表体）。  
1. 改 **`crates/api`** 路由实现。  
2. 更新 **[04 §3.4](../../spec/04-后端与API.md)** 窗内 **`| METHOD | /path |`** 行（与 **CONTRIBUTING** 同口径）。  
3. 运行 **`bash scripts/run-check-04-routes.sh`** 至 **exit 0**。  
4. 更新 **[93](../../spec/93-全站功能验证矩阵-域别回归清单.md)** §8.4 相关脚注 / 用例族（或走 **96-01** 束表 **N/A** 流程）。

**与 REG-04 分工**：**[REG-04 §3](../corpus/REG-04-API叙事.md#reg04-engineering)** 描述同一闭环的**台账语境**；**执行命令以本文 §6 为准**。
