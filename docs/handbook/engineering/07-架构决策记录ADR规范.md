<a id="adr-1-role"></a>

## 1. 与 engineering 域文的分工

| 文档类型 | 回答的问题 | 典型落点 |
|----------|------------|----------|
| **engineering/NN 域篇**（如 **[20-B-订单机制](./20-B-订单机制.md)**） | 当前模块**如何工作**、改哪里、怎么验 | `docs/handbook/engineering/` |
| **ADR** | **为何**在多个可行方案中选当前方案；**弃用**了哪些备选 | 见下文 §2 |

**结论**：ADR **不**承载接口字段表或 **93** 行；ADR 结论若导致 **HTTP/状态机** 变化，仍须走 **04 / 01 / 03** 与 **[02](./02-生产级文档约束与合入门禁.md)** 合入链。

<a id="adr-2-format"></a>

## 2. 建议正文结构（单篇 ADR）

1. **标题**：`ADR-<短号>-<主题>.md`（短号可用日期 **`ADR-20260428-orders-chain-off-gate.md`** 或仓库递增 **`ADR-0007-…`**）。  
2. **状态**：`proposed` · `accepted` · `superseded` · `deprecated`（与实现生命周期独立，仅表决策生命周期）。  
3. **上下文**：问题背景、约束（合规、性能、团队技能）。  
4. **决策**：选定方案一句话 + 关键取舍。  
5. **后果**：正负面影响、需要的跟进（监控、迁移、文档）。  
6. **参考**：PR、issue、spec 锚点（**不**抄 **04/93** 表）。

## 3. 存放位置（**唯一目录**）

| 路径 | 说明 |
|------|------|
| **`docs/adr/`** | **全部** `ADR-*.md` 的**唯一**落盘目录（命名见 **§2**）。 |

**`docs/handbook/engineering/adr/`**：仅 **[README](./adr/README.md)** 互链入口（兼容旧链接）；**禁止**在该目录新增 ADR 正文。

**契约 SSOT**：ADR 只承载 **Why**；**HTTP / 矩阵 / 字段**仍以 **[04 §3.4](../../spec/04-后端与API.md)**、**[93](../../spec/93-全站功能验证矩阵-域别回归清单.md)** 与**仓库代码**为准；**不**引入 **OpenAPI** 或其它平行契约源。

<a id="adr-4-usage"></a>

## 4. 工程使用与回归路径

| 你在本簇做的事 | 落点 / 真源 | 回归时至少跑（见 **§6**） |
|----------------|-------------|---------------------------|
| 判定「要不要写 ADR」 | **[02 · §2 附](./02-生产级文档约束与合入门禁.md#hb-prod-adr-triggers)** | 无单独脚本；满足触发条件则**先**落盘 ADR 再开改码 PR。 |
| 写 **Why**（备选方案、取舍） | **`docs/adr/*.md`**（**§3**） | **`docs/adr`** 在 **`docs/handbook` 外**，`check-handbook-frontmatter` **不**覆盖；文首元数据**建议**与 **§2** 同形（**Version** 等），以 **Review** 与 **Owner** 人工对拍为准。 |
| ADR 导致 **新 HTTP / 改路径** | **[04 §3.4](../../spec/04-后端与API.md)** + **`crates/api/src/routes/*`** + **[engineering/04](./04-HTTP与路由契约导读.md)** | **`bash scripts/run-check-04-routes.sh`**（与 **CI** 同名）。 |
| ADR 要求改 **状态机 / 域叙事** | **[01](../../spec/01-总库总览.md)**、**[03 spec](../../spec/03-业务流程与风控.md)**、**[93](../../spec/93-全站功能验证矩阵-域别回归清单.md)** | 按域补 **93** 脚注 / 用例族 + 相关 **`cargo test`**（默认 **`cargo test -p traveltrust-api`** 见 **§6**）。 |
| ADR 要求 bump **spec/07** 文首 **`Version:`** / **Wave 叙事** | **[spec/07](../../spec/07-开发流程与顺序.md)** + **[23](./23-横切-07开发流程导读.md)** | **`bash scripts/check-07-version-triple.sh`**（与同 PR **spec/07** 文档 bump **同批**）。 |

**影响面**：ADR **不**自动更新 **04/93**；合码 PR 仍须显式改契约与矩阵（或 **N/A** 流程），否则 **run-check-04-routes** / Review 仍会失败。

<a id="adr-5-troubleshoot"></a>

## 5. 调试与排错

| 现象 | 优先检查 |
|------|----------|
| 「写了 ADR 但 CI 仍卡 **02**」 | **§2 附** 是否**同时**要求 **04/93/14/代码与脚本** 更新；ADR **不能**替代契约补丁。 |
| **ADR `accepted` 与实现不一致** | 将 ADR 标为 **`superseded`** 或 **`deprecated`**，并开 PR **对齐代码**；**禁止**用 ADR 正文充当 **04 §3.4** 表体。 |
| **`check-07-version-triple.sh` 失败** | **[23 §6](./23-横切-07开发流程导读.md)** 与 **spec/07** 文首 **`Version:`**、**[spec/00](../../spec/00-文档索引.md#文档版本与最后更新)** **07 行**、**spec/07 §六 6.5** 表顶是否**同号**。 |
| **`run-check-04-routes.sh` 失败** | **[04-HTTP与路由契约导读](./04-HTTP与路由契约导读.md)**；窗内 **`| METHOD | /path |`** 是否与 **`api_router()`** 一致。 |
| **frontmatter / engineering-content 报警** | **[06](./06-工程模块技术文档编制契约与验证闭环.md)**；**本文件（engineering/07）**须在文首保持 **Version / 与 spec 关系**；**`docs/adr` 内 ADR**不在 **frontmatter** 扫描范围（见 **§4**）。 |

<a id="adr-6-verify"></a>

## 6. 工程验证（本簇）

> **以 spec/04 §3.4、93 与代码为准**：本节命令用于证明「**handbook 元数据** + **契约对拍** + **07 三线**」未破坏；**不**证明「ADR 决策内容」本身可被机读验收。

**ADR 无独立 CI job**；下列命令名与仓库 **`scripts/`** 及常见 **CI step** 对齐，按**当次 PR 实际改动**择跑。

```bash
# handbook 文首（改本文件或其它纳入扫描的 handbook MD 时）
bash scripts/check-handbook-frontmatter.sh
```

```bash
# engineering 域篇结构 / 外链卫生（改 NN≥10 域文或与 engineering 互链时）
bash scripts/check-handbook-engineering-content.sh
```

**当本 PR 已改 HTTP 契约或路由挂载**（与 **04 §3.4** / **`routes/*`** 同批）：

```bash
bash scripts/run-check-04-routes.sh
```

**当本 PR bump 了 `spec/07` 文档版本三线**：

```bash
bash scripts/check-07-version-triple.sh
```

**当本 PR 含后端实现改动**（与根 **AGENTS.md** 默认门禁一致）：

```bash
cargo test -p traveltrust-api
```
