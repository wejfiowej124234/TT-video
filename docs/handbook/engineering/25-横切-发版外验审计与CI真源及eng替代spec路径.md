<a id="x25-1-1-replace-without-rm"></a>

### 1.1 你要的「替代」：**不删库也能当家**

这里把话说透：**「用 `engineering/` 替代心里那团乱的 spec」**和**「立刻 `git rm -r docs/spec`」**不是一回事；你要的前者**现在就可以做**，后者必须等 **08 / 98 / STATUS / 盘点** 程序。

| 做法 | 说明 |
|------|------|
| **默认从 `engineering/` 进门** | 日常读 **README 主序表 → 00～25～域篇**；把 **`spec/`** 当成 **需要查表体、改矩阵、签字 GO 时再打开的 Reference** —— 心智上是「**主读 engineering，按需下钻 spec**」，**不要求**磁盘上先删掉 **`spec/`**。 |
| **写代码 / 对拍契约** | **HTTP** 仍 **04 §3.4 + `run-check-04-routes`**；**域**仍 **93**；**链上**仍 **14 + contracts + 门禁脚本** —— 这些**不靠**「先删 spec」才成立；**handbook 只是少让你在长 spec 里迷路**。 |
| **真想减少磁盘上的 spec** | **按簇、按路径**走 **[08 §3](./08-文档与spec迁移台账.md#mig-2-matrix)**：某一行的 **`删除 spec`** 在台账与 **98 / registry / 脚本去硬编码** 同批变为 **yes** 之后，再删**那一簇/那几条路径** —— 是**渐进收口**，不是「TT Runbook 勾完 = 整树可删」。 |

**结论**：你的目的（**新文件夹当家、少在乱 spec 里打滚**）**不必等删库**；仓库拦的是**未经程序的整库删除**，不是拦你把 **`engineering/`** 当**第一阅读面**。
