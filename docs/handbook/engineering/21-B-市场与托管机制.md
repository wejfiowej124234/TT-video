<a id="b21-1-scope"></a>

## 1. 模块职责（L1）

- **解决**：把 **94** 定义的「子站发现 → listing / draft → 与旅游订单一致的 **USDC/USDT Escrow** 资金路径」落到**可读工程面**：路由挂载、与 **discover/orders** 的边界、以及**不**在文档侧复制 **04 §3.4** 的纪律。  
- **与 [20-B](./20-B-订单机制.md) 分工**：**20-B** 主扛 **`/orders`** + **`/discover/orders`** 主链；**本篇**主扛 **`market_subsite`** 路由树及 **94** 所述 **provider / acquisition** 列表与详情（以 **04** 登记路径为准）。  
- **与 [53](../../spec/53-阶段开发技术文档.md)**：状态机、双边协议 UI、**53-Sx** 仍回 **53**；**HTTP 契约** 以 **04** 为准。  
- **何时须打开 [53](../../spec/53-阶段开发技术文档.md)**（**T-018**）：改 **94 子站**与 **主订单链**之间的 **产品步序**、**53-Sx**、或 **market_subsite** 与 **53 §3.5** 窗口 **key** 对齐时，**须**以 **53** 为步序 SSOT，并与 **[08-3](../../spec/08-3-参数与门禁表.md)** 对拍。**仅**改 **`/market/*`** 的 **04 §3.4** 登记与 **93 B-MKT-\*** 时，**21-B + 04 + 93** 常足够。**资金终态 / 取消 / 争议** 仍以 **[01](../../spec/01-总库总览.md)**、**[03](../../spec/03-业务流程与风控.md#spec03-section-I)** 为准。

<a id="b21-2-mechanism"></a>

## 2. 核心机制（L2）

1. **路由挂载**：**`crates/api/src/routes/mod.rs`** **`merge(market_subsite::router())`**；实现入口 **`routes/market_subsite.rs`**（与 **`mod.rs` 域清单** 注释同频）。  
2. **列表 / 详情 / 草稿**：**`GET …/market/provider/listings`**、**`…/acquisition/listings`**、**`GET …/listings/:id`**、**`POST …/listings`**、**`…/drafts*`** 等——**方法/路径/字段** 仅以 **[04 §3.4](../../spec/04-后端与API.md)** 为准；**94 §2** 为 IA 与体验定稿，**冲突时以 04 为准**。  
3. **资金路径**：与 **94 §1.2** 一致——用户只在**订单绑定 Escrow** 上 **Approve/Deposit**；**`/pay`**、**`/escrow/:orderId`** 枢纽语义见 **04** 与 **[14](../../spec/14-合约-API-ABI-前后端对齐.md)**，**不在**本篇复述合约调用表。  
4. **与主 `/market`**：**[29](../../spec/29-自由市场-撮合控制台规范.md)** 主撮合页与子站 **Shell**（**94 §2**）分工；前端演示闸 **94 §0** 所述 env 与 **04** 机读路由独立，合入时须两边对拍。

<a id="b21-3-model"></a>

## 3. 数据与状态模型（L2～L3）

- **`market_listings`** 行（**`variant`**、**`published`/`draft`** 等）为子站目录真值；细节字段以 **04** 散文窗 + **`market_subsite`** handler 为准。  
- **与 `orders` 投影**：列表卡片若与旅行订单混排，**`business_line`** 等机读键以代码 **`chain_off::orders`** 注释与 **04** 为准（见 **20-B §3**）。  
- **不**在本篇展开 **93** 矩阵列；子站相关族名见 **§6** `cargo test` 过滤串与 **93 §2.1** **B-MKT-005～012** 脚注。
