## §1 分层模型（与实现对读）

自上而下（与 **spec/02**「整体分层」一致）：

1. **表现层**：Web / DApp 各端、开放 API 消费方。  
2. **应用层**：用例编排（下单、确认、release、争议、身份质押流程等），**不写**领域硬规则。  
3. **领域层**：订单状态机、托管规则、评分与仲裁规则、质押门槛等 **纯业务**。  
4. **基础设施层**：DB、链客户端、KYC、通知、对象存储等 **可替换适配器**。

**链 / DB 边界**：链上事件驱动资金真值；DB 承担检索、投影与业务数据；**不得**仅凭前端或代付断言已支付。

**须回读 spec/02（≥3 · T-014）**：**[§一 项目共性](../../spec/02-架构设计.md#spec02-yi)** · **[§三 领域切分](../../spec/02-架构设计.md#spec02-san)** · **[§七 事件消费与执行器](../../spec/02-架构设计.md#spec02-qi)**（**§十 / §十三 检查清单** 等仍以 **[spec/02](../../spec/02-架构设计.md)** 全文为准，含 **[架构级检查清单](../../spec/02-架构设计.md#02-sec-13-checklist)**）。

## §2 领域切分（读 spec/02 §三）

典型子域包括：**订单与托管**、**向导与市场**、**争议与证据**、**评价与信誉**、**身份与准入** 等；与 **Rust crate / 路由域** 的对应关系以 **`crates/api/src/routes/mod.rs`** 与 **[14 §2.1](../../spec/14-合约-API-ABI-前后端对齐.md)** 为实装真源。

## §3 事件、对账与执行器（提要）

- **链上事件**为资金状态推进的主信号；消费侧须 **幂等**、**finality** 与 **checkpoint** 口径与 **spec/02 §七** 一致。  
- **执行器**：裁决后的链上执行、多签 / timelock 等仍以 **spec/02** 与 **ops/RUNBOOK** 对读。
