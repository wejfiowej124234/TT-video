## 1. 闭环类型总表

| # | 闭环类型 | 含义 | 状态判断（可对外复述的一句话） |
|---|----------|------|--------------------------------|
| **1** | **启动闭环** | 前端、后端、数据库、环境变量能启动 | **「系统能跑起来」**：API **`/health` 200**；前端 **`npm run dev` / build** 能进首页；DB 连接串在目标环境 **可连通**（或文档声明的 **chain_off-only** 模式一致）。 |
| **2** | **本地门禁闭环** | 本地脚本、测试、文档检查、registry 检查通过 | **「本地 CI 通过」**：本轮 **[CONTRIBUTING](../../CONTRIBUTING.md)** 与 **[solo-dev-rhythm §6.5](../../docs/solo-dev-rhythm.md)** 约定命令集 **exit 0** 留证据；动 **`docs/spec` 路径依赖** 时 **registry + inventory** 已同步（见 **AGENTS**）。 |
| **3** | **文档规范闭环** | engineering / spec / registry / evidence 对齐 | **「规范迁移受控」**：**engineering 主序三处对拍**、**spec 路径 registry**、**证据目录**与台账结论 **不自相矛盾**（删径 **四门** 仍按 **08 / 98 / STATUS / 96-索引**）。 |
| **4** | **用户注册登录闭环** | 注册 → 邮箱/认证 → 登录 → 获取用户态 | **「用户能进系统」**：**`POST /auth/register`→会话→`GET /api/v1/me`**（或等价）在 **①** 可跑通；**须 `chain_off` + DB** 时与 **04** 一致；**②** 再验邮件/Stripe test 等 **见 [TT-9618](TT-9618-onboarding-local-testnet.md)**。 |
| **5** | **市场发现闭环** | 首页/市场 → 筛选/列表数据 → 详情 | **「用户能看到可交易对象」**：**`GET /meta`** 表明 **`chain_off` 与列表数据源一致**；**`GET /api/v1/discover/orders`** + **`GET /api/v1/guides`** 返回 **非「假空」**（无 **chain_off** 时的空列表须按 **[TT-9623](TT-9623-vertical-slice-01-guides-catalog.md)** 口径理解）；详情 **与 04 字段** 对齐。 |
| **6** | **下单托管闭环** | 选服务 → 创单 → 托管/支付/状态机 | **「用户能产生交易」**：**04 §3.4** 订单路径 **可创建/可见状态迁移**；**Escrow/支付** 以当前里程碑声明为准（**①②** 与 **③** 分层）。 |
| **7** | **Web3 治理/收益闭环** | 治理币、区域权益、收益池、分配、claim | **「链上经济模型能跑」**：**②** 起 **合约 + RPC + 索引/投影** 与 **96-07 / 14** 对拍；**claim** 与 **治理页** 行为与 **04** 一致；**不**用 mock 治理数据冒充 **③**。 |
| **8** | **后台运营闭环** | 审核、风控、商户、订单、区域、证据 | **「平台能运营」**：**`admin` 角色** 下关键 **只读/写** 路径 **可复现**；审计/合规表与 **96-04 / 96-08** 范围触发时 **有证据**；**internal** 路由 **不**对公网暴露。 |
