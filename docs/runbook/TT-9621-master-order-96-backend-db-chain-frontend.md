## 1. 你为什么还需要这一页（多维上的「结构性问题」）

仓库里**正确**的入口很多，若**没有一条固定顺序**，容易出现：

1. **入口分散**：同一周内在 **96-18**、**96-15**、**96-20**、**TT-9618**、**go-live-checklist**、**93-matrix** 之间跳读，**P0 被稀释**。  
2. **先 UI 后真值**：后端 **501 / not_impl**、**chain_off** 缺失、**DB 投影未接线** 时做大范围视觉优化 → **高返工**。  
3. **「链上池子通畅」与「能 demo」混句**：索引器 tick、**ChainConfig**、**db::mod** 与迁移表 **未同批可观测** 时，不宜宣称 **②** 已闭（见下方 **§3.2** 与 **96-18** 台账最近行）。  
4. **企业级深度与日常迭代混用**：对外承诺 **Tier C / DPA** 时才强跑 **96-15** 全 Tier；日常见 **[TT — spec→handbook 全量替代清单 · §0](TT-SPEC-TO-HANDBOOK-FULL-REPLACEMENT-CHECKLIST.md)** 与 **[solo-dev-rhythm §0.a](../solo-dev-rhythm.md)**。

**本页职责：** 把 **「先干什么、再打开哪份、怎么算做完」** 压成 **一张表 + 一张多维雷区清单**。

## 3. 多维「仍常见问题 / 雷区」清单（深度扫雷 · 仓库静态 + 台账互证）

### 3.1 契约与后端实现

| 问题 | 说明 | 建议动作 |
|------|------|----------|
| **`chain_off` 与 501** | 无 **`chain_off`** 时，**`POST /api/v1/orders`** 等路径直接 **`not_impl_json`**（见 `crates/api/src/routes/orders/mod.rs` **`order_create`**）。 | 前端与 **E2E** 须按环境矩阵设计；**勿**假定「默认可创单」。 |
