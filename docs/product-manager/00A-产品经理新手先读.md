# 产品经理新手先读

## 这份文档是给谁的

给第一次接手 TravelTrust 的产品经理看。

如果你现在的状态是：

- 对区块链不熟
- 对治理币不熟
- 对项目文档太多有压力
- 不知道该先看哪一份

那就先看这份，不要直接扎进技术规范。

## 先用一句话理解 TravelTrust

TravelTrust 不是一个单纯卖币的网站，而是一套围绕旅游订单、履约争议、平台治理、区域合作和企业级后台运营建立起来的系统。

你可以先把它理解成：

- 前台有交易和用户体验
- 中台有财务、风控、客服、运营、合规
- 更上层还有区域治理、协议治理和可能的治理币机制

所以它不是“一个页面”就能讲完的项目。

## 产品经理在这个项目里到底要负责什么

在这个项目里，产品经理不只是写 PRD，还要把下面几件事讲清楚：

1. 我们第一阶段到底向市场讲什么故事。
2. 治理币是不是现在就讲，讲到什么程度。
3. 谁能看数据，谁能审批，谁能导出，谁能改关键参数。
4. 对外哪些话能说，哪些绝对不能说。
5. 融资、财务、权限、合规这四条线怎么一起闭环。
6. 社区怎么搭、内容怎么发、X / 抖音 / INS 等平台怎么运营。
7. 产品介绍、动画视频解说、平台账号矩阵和增长节奏怎么建立。
8. 一级市场有哪些常见渠道、要准备哪些资料、先接触哪些平台。

如果你想更具体地知道“我每天到底要干什么、什么才算合格”，直接看 [10-区块链产品经理职责与工作标准](10-区块链产品经理职责与工作标准.md)。如果你想知道融资、平台运营、社区建设这些工作具体怎么做，再看 [11-区块链产品经理增长运营与社区标准](11-区块链产品经理增长运营与社区标准.md)。如果你想知道一级市场渠道和要准备哪些融资资料，再看 [12-一级市场与融资渠道清单](12-一级市场与融资渠道清单.md)。

但在进入这些工作之前，第一步不是急着对外表达，而是先把项目学懂。你至少要先搞清楚：

1. 这到底是不是一个旅游平台。
2. 它为什么要用 Escrow、争议和链上可验证。
3. 它为什么同时有前台、后台、治理和合规这些层。
4. 它和普通 Web3 项目到底哪里不一样。

## 先不要搞混的 5 组概念

### 1. 支付和治理不是一回事

- 支付：用户下单、结算、退款时用什么币或什么支付方式。
- 治理：谁参与规则、区域、参数和生态激励的决策。

当前项目总览明确，MVP 不发行平台支付币。所以不能把治理币说成下单支付币。

### 2. 治理币和股权不是一回事

- 治理币是协议治理和某些参与机制的一部分。
- 股权是公司所有权。

这两者不是一个法律概念，不能对外混说。

### 3. 融资叙事和产品落地不是一回事

- 融资叙事解决“外部为什么愿意关注和参与”。
- 产品落地解决“系统到底能不能跑起来、能不能审计、能不能合规”。

只讲融资故事，不讲后台、财务、风控和合规，会被认为不完整。

### 4. 角色权限和数据权限不是一回事

- 角色权限：这个人能做什么动作。
- 数据权限：这个人能看到哪些范围的数据。

举例：同样是财务角色，不一定都能看全部国家的数据。

### 5. 对外口径和内部目标不是一回事

- 内部目标可以写得更激进，比如未来阶段目标、理想模型、远期规划。
- 对外口径必须谨慎，只能说当前合规、可落地、可签核的内容。

## 学到什么程度，算你已经入门了

如果你已经能回答下面 6 个问题，就算真正入门了：

1. TravelTrust 到底是什么，不是什么。
2. 它相比普通旅游平台强在哪里。
3. Escrow、争议、信誉、区域治理分别在解决什么问题。
4. 为什么项目不能把支付币、治理币、股权、分红讲成一回事。
5. 为什么后台权限、财务、合规不是可选项。
6. 第一阶段最该看哪几份文档、最该解决哪些问题。

再往前一步，如果你还能回答“我作为这个项目的产品经理，接下来一周要做什么、输出什么、和谁对齐什么”，那才算开始真正进入工作状态。

再更进一步，如果你还能回答“融资方案怎么写、社区怎么搭、内容怎么发、平台账号怎么运营、视频怎么讲”，那就说明你已经不只是看懂，而是开始具备真正推进项目外部增长的能力了。

如果你还能回答“一级市场有哪些常见渠道、官网是什么、我们还缺哪些投递资料”，那就说明你已经开始具备真正推动融资外联的能力了。

## 你学这套资料时，最重要的是先建立正确理解

你先不要急着背对外话术，先把下面几件事建立起来：

1. 明白这个产品的核心是“信任机制”，不是“代币机制”。
2. 明白这个产品既有用户交易侧，也有企业运营侧。
3. 明白它不是纯中心化平台，也不是纯空心 Web3 概念站。
4. 明白为什么它会同时出现旅游、Escrow、争议、治理、权限、合规这些内容。

## 如果你只准备开第一场入门会

第一场会建议只聊 3 个问题：

1. 项目第一阶段到底卖什么和讲什么。
2. 治理币现在讲到哪一步，不讲到哪一步。
3. 哪些内部能力必须先补齐，才能支撑融资和对外沟通。

## 你暂时可以不深究的内容

第一次接手时，不需要一上来就钻进去：

- 合约实现细节
- 链上脚本执行细节
- 每一个参数的技术来源
- 全部测试与部署步骤

你先把业务边界、对外叙事、权限框架、合规底线吃透，已经足够进入产品经理角色。
