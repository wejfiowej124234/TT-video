# Bug 分级与质量复盘机制

## 这份文档是干什么的

这份文档用于把 Bug、需求、咨询三类问题分开处理，并建立质量复盘机制。

它要解决的是：

1. 所有问题都堆在一个群里。
2. 严重 Bug 和普通建议混在一起。
3. 每周做了很多修复，但没有质量复盘。

## 问题分流规则

| 类型 | 定义 | 去向 |
|------|------|------|
| Bug | 现有能力和预期不一致，流程失效或结果错误 | 本文台账 |
| 需求 | 新增能力或优化项 | [30-产品需求池与优先级总表](30-产品需求池与优先级总表.md) |
| 咨询 | 用户提问、理解不清、链接找不到 | [32-用户反馈与问题闭环台账](32-用户反馈与问题闭环台账.md) |

## Bug 分级标准

| 级别 | 定义 | 例子 | 目标响应 |
|------|------|------|------|
| P0 | 阻断核心链路、对外演示或合规安全风险 | 首页打不开、关键反馈表单无法提交 | 当天处理 |
| P1 | 明显影响主链路体验，但有绕行方式 | `/market` 核心 CTA 异常 | 1 到 2 天内处理 |
| P2 | 一般功能异常或体验问题 | 页面文案错位、次要按钮异常 | 本迭代处理 |
| P3 | 轻微问题或优化类表现 | 排版小问题、非关键体验瑕疵 | 排队处理 |

| Bug ID | 问题摘要 | 页面 / 模块 | 严重级别 | 当前状态 | 负责人 | 发现来源 | 复现方式 | 目标修复时间 | 备注 |
|------|------|------|------|------|------|------|------|------|------|
| BUG-001 | 反馈入口 SLA 未在帮助页体现 | `/help` | P2 | 待处理 | 产品经理 | 深查缺口 | 打开帮助页查看说明 | 本迭代 | 属内容与承接问题 |
| BUG-002 | 开发版与可对外版边界未明 | 发布机制 | P1 | 待处理 | 产品经理 | 深查缺口 | 查看资料和入口定义 | 2 天内 | 属质量与发布风险 |

## 状态定义

| 状态 | 定义 |
|------|------|
| 待确认 | 已收到，待确认是否为 Bug |
| 待修复 | 已确认为 Bug，待进入处理 |
| 修复中 | 已进入开发或修订 |
| 待验证 | 已修复，等待复验 |
| 已关闭 | 验证通过 |
| 挂起 | 暂不处理，但需保留记录 |

## 每周质量复盘要看什么

1. 本周新增 Bug 数量。
2. P0 / P1 是否清零。
3. 重复出现的问题是什么。
4. 哪些问题本质上是需求或内容问题，而不是纯 Bug。
5. 哪些问题需要反向推动发布门禁或 FAQ 更新。
