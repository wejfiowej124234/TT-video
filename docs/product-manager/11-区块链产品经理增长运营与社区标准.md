# 区块链产品经理增长运营与社区标准

## 这份文档解决什么问题

这份文档是专门补给这位产品经理的“增长运营标准”。

也就是说，在 TravelTrust 里，如果你除了做产品理解和融资方案，还要负责：

- 社区搭建
- X 平台运营
- 抖音运营
- INS 运营
- 产品介绍内容
- 动画视频解说
- 各类对外内容排期

那你应该按什么标准做，这份文档就是答案。

如果你还要看“一级市场有哪些常见平台、官网是什么、投递时要准备什么材料”，再配合看 [12-一级市场与融资渠道清单](12-一级市场与融资渠道清单.md)。

## 与技术文档对齐（对外内容必守）

增长侧所有**对外文案、海报、视频口播、社群置顶、活动页**，在发布前须与 **[08-4 对外口径包](../spec/08-4-对外口径包.md)**、**[01-总库总览](../spec/01-总库总览.md)** 对读；凡涉及 **链上、质押、治理、费用、已上线** 等表述，**额外**对照 **[README · 工程对齐快照](README.md)**（**`IdentityStakingPool` 系** vs **`/governance`**、**Partial/MVP** vs **Target**），避免与技术文档及实现真值漂移。

## 先说结论：你不是单纯发帖的人，你是在搭一套项目外部增长系统

低标准做法是：

- 开几个账号
- 发几条内容
- 临时做几张图
- 想到什么发什么

高标准做法是：

- 有清晰的项目叙事主线
- 有平台分工
- 有内容矩阵
- 有社区目标
- 有节奏安排
- 有数据复盘

## 你在增长运营上到底要负责什么

### 1. 融资方案不只是写文件，还要形成对外承接链路

你要负责的不只是把融资方案写出来，还要考虑：

- 谁是目标受众
- 他们先看到什么内容
- 他们从哪里进入项目
- 看到介绍后下一步做什么
- 如何从兴趣走到进一步沟通

也就是说，融资方案必须和内容、平台、社区、承接页连起来。

### 2. 产品介绍不只是讲功能，而是讲价值、结构和差异

产品介绍材料至少要讲清：

- 我们是什么
- 我们解决什么问题
- 我们和别人有什么不同
- 我们为什么值得继续关注

不能把产品介绍做成纯技术文档，也不能做成纯口号海报。

### 3. 动画视频解说不是做炫技，而是做理解转化

动画视频的作用不是炫，而是让别人更快理解：

- 交易怎么发生
- Escrow 为什么重要
- 为什么这个项目不仅是旅游平台
- 为什么它有长期扩展空间

所以视频脚本必须服务理解，不是堆概念词。

### 4. 社区不是群聊工具，而是项目关系网络

社区的目标不是“看起来热闹”，而是建立：

- 关注者
- 理解者
- 传播者
- 潜在合作方
- 潜在投资人或支持者

所以社区要有规则、有内容、有节奏、有互动机制。

### 5. 每个平台都必须有明确分工

不能把 X、抖音、INS、社区群都做成一样的内容镜像。

高标准要求是：不同平台承担不同任务。

## 各平台建议定位

### X 平台

定位：项目叙事、行业观点、进展更新、社区连接。

适合发布：

- 项目定位线程
- 产品能力拆解
- 里程碑更新
- 社区互动贴
- 空间活动预告

高标准要求：

- 有固定语气和叙事风格
- 不乱讲未确认内容
- 不把线程写成空洞口号

### 抖音

定位：快速理解、故事化介绍、短视频传播。

适合发布：

- 30 秒项目介绍
- 动画解说
- 场景化问题拆解
- “普通旅游平台 vs TravelTrust” 对比短视频

高标准要求：

- 视频先讲问题，再讲方案
- 文案口语化，不堆术语
- 每条视频只有一个核心信息点

### INS

定位：品牌感、视觉表达、项目气质、国际化外观。

适合发布：

- 品牌视觉卡片
- 产品结构图
- 短视频切片
- 项目理念与阶段进展

高标准要求：

- 视觉统一
- 文案简洁
- 不做信息过载长图

### 社区群组

定位：沉淀长期关系、解释项目、收集问题、组织活动。

适合推进：

- 新人欢迎机制
- FAQ 固定帖
- 每周项目进展同步
- 主题 AMA 或讨论
- 用户问题收集

高标准要求：

- 有群规则
- 有固定栏目
- 有人负责答疑和沉淀问题

## 你要做的增长运营任务清单

### 一、账号体系搭建

1. 明确要开哪些平台账号。
2. 统一账号名称、头像、简介、链接。
3. 统一平台视觉和品牌口径。
4. 明确每个平台存在的目的。

### 二、内容体系搭建

1. 定义内容主线。
2. 定义内容栏目。
3. 制定周更节奏。
4. 制定月度主题。
5. 建内容素材库。

### 三、融资内容准备

1. 写融资主方案。
2. 写融资摘要版。
3. 准备产品介绍页内容。
4. 准备 FAQ。
5. 准备对外解释版本。
6. 配合整理一级市场投递资料包。

### 四、视频内容准备

1. 写动画视频解说脚本。
2. 定义视频镜头结构。
3. 定义解说顺序。
4. 明确每条视频的唯一目标。

### 五、社区搭建

1. 建社区规则。
2. 建欢迎语和新人引导。
3. 建 FAQ。
4. 建活动节奏。
5. 建问题收集与反馈机制。

## 高标准内容矩阵应该长什么样

至少要有下面 5 类内容：

1. 项目是什么
2. 产品为什么不一样
3. 关键机制怎么工作
4. 当前进展和阶段目标
5. 社区互动和问题答疑

如果只有“我们很牛”“欢迎关注”这类内容，不算高标准运营。

## 动画视频解说的高标准要求

1. 先讲用户问题，再讲产品解决方案。
2. 不上来堆术语和 token 概念。
3. 一条视频只服务一个理解目标。
4. 脚本必须和真实产品边界一致。
5. 未实现内容必须明确是路线图，不是当前事实。

## 社区搭建的高标准要求

1. 有清晰定位，不是什么人都往里拉。
2. 有固定节奏，不是想起来才发。
3. 有欢迎机制，不是新人进来就沉底。
4. 有 FAQ 和基础资料，不是反复人工解释同一个问题。
5. 有活动和反馈机制，不是死群。

## 你每周至少要推动的增长运营动作

1. 更新一次内容排期。
2. 更新一次平台发布计划。
3. 推进至少一条高质量项目介绍内容。
4. 推进至少一条视频或视频脚本。
5. 维护一次社区节奏或互动活动。
6. 做一次平台数据和社区反馈复盘。

## 你最应该交付的增长运营成果

1. 融资方案主文档
2. 融资摘要版材料
3. 平台账号矩阵表
4. 社区搭建方案
5. 内容日历
6. 动画视频解说脚本
7. FAQ 与新人引导文档
8. 月度增长复盘
9. 一级市场承接页与投递资料链接集合

## 和一级市场工作的关系

增长运营不是独立于一级市场工作的。

很多一级市场、Launchpad、投研方、社区型发售平台，在看项目时会同时看：

- 你讲得清不清楚
- 你社区有没有基础
- 你平台内容是不是在持续更新
- 你有没有视频、FAQ、官网承接页

所以平台运营和社区建设，本质上也是一级市场准备的一部分。

## 低标准和高标准的区别

### 低标准

- 开号了，但没人知道为什么开
- 发内容了，但没有主线
- 做视频了，但别人看不懂产品
- 建社区了，但没有规则和节奏
- 写融资方案了，但和外部内容不连通

### 高标准

- 平台各自有明确角色
- 内容围绕同一项目主线展开
- 视频帮助别人更快理解产品
- 社区能持续沉淀关系和问题
- 融资方案、承接页、内容、平台、社区形成一个系统

## 你绝对不能做的 10 件事

1. 想到什么发什么，没有内容主线。
2. 每个平台发一模一样的内容，不做分工。
3. 把未确认信息当进展发出去。
4. 把路线图讲成已上线事实。
5. 只做视觉包装，不讲产品逻辑。
6. 只讲 token，不讲真实产品结构。
7. 开社区不写规则、不做欢迎、不做沉淀。
8. 只追求数量，不追求内容质量和理解度。
9. 只做短期热点，不做长期品牌资产。
10. 觉得运营就是发帖，不需要产品理解。
