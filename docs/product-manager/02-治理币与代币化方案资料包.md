# 治理币与代币化方案资料包

## 这份资料包解决什么问题

用于支持产品经理制定治理币、区域份额、代币化融资和治理机制相关方案，避免把协议治理、收益参与、支付结算和融资叙事混成一个概念。

如果你是第一次接这部分，可以先把它理解成：

这份文档的目标不是让你立刻懂所有 token 机制，而是先帮你避免把最危险的概念讲错。

## 小白先看这个结论

1. 治理币不是支付币。
2. 治理币不是股权。
3. 国家桶、个人桶、区域份额不是一个概念。
4. 对外能讲多少，不取决于想象力，而取决于法务、合规和当前实现阶段。

## 产品经理要先统一的四个边界

### 1. 订单结算币和治理币不是一个东西

白话理解：用户付钱用什么，和协议治理用什么，不一定是同一个东西。

[总库总览](../spec/01-总库总览.md) 已经写明，当前 MVP 不发行平台支付币。治理币如果引入，也不能替代订单结算币种，除非整套产品和合规文档一起重写。

### 2. 治理币不等于股权或分红票据

白话理解：不能让外部理解成“买了就是公司股份”或“固定拿收益”。

对外措辞必须避免：

- 分红
- 股权
- 保本
- 固定收益
- 票面利息

推荐使用协议分配、快照条件下的收益参与、治理参与等表述，具体以 [84](../spec/84-第一阶段10国Country-Pool发行参数总表.md) 和 [08-4](../spec/08-4-对外口径包.md) 为准。

### 3. 国家桶和个人桶必须拆开讲

白话理解：面向国家或区域合作的盘子，和面向个人参与的盘子，不能用一张嘴混过去。

[84](../spec/84-第一阶段10国Country-Pool发行参数总表.md) 已明确国家池 vs 个人/全局承销桶（**84 §1.5**）。**承销桶** 仍须 **FDV/折扣** 可核对；**募资数字** 以 [country-pool-fundraise-governance-v1](../spec/governance-token/country-pool-fundraise-governance-v1.md) 为准（**53,500 万 · 无硬顶**），**禁止** Seat×参考价→募资（历史见 [archive](../spec/governance-token/archive/phase1-fundraise-stake-times-reference-price-formula-historical.md)）。

### 4. 工程顺序不能跳

白话理解：白皮书不是上线，路线图必须服从真实研发和门禁顺序。

治理币不是只靠白皮书定稿就能上线。现有规范已经写死：

- 先本地链联调
- 再测试网
- 最后主网

产品经理做路线图时，必须把技术、法务和运营 gate 一起排进去。

### 5. 向导身份质押（`IdentityStakingPool` 系）≠ 治理币叙事

白话理解：对外讲「向导要锁保证金、有扣罚与信誉」时，走的是 **订单与身份池** 叙事；讲「谁能投票、提案、动金库」时，走的是 **TTG / 治理币与 `/governance`** 叙事。两者在 spec 与合约命名上**刻意分开**，产品经理**不要**合成一个「质押币」故事。

回链核对：[81-经济模型-向导质押与订单押金](../spec/81-经济模型-向导质押与订单押金.md)、[87-角色体系](../spec/87-TravelTrust-角色体系技术文档-融合架构版.md)、[89-治理 UI 规格](../spec/89-治理UI-全球旅游市场治理控制台设计规格.md)；人话表见本资料夹 [07-产品经理术语表](07-产品经理术语表.md)。

## 建议产品经理输出

1. 治理币角色定义：治理、激励、区域参与分别是什么
2. 代币总量分解方案：国家桶、个人桶、生态桶、团队桶等
3. 发行节奏方案：本地验证、测试网、主网、对外发布时间
4. 对外材料框架：官网、PPT、白皮书、FAQ
5. 法务签核路线：谁负责、何时签、什么版本可对外

## 如果你要用一句话给外部解释

更稳妥的思路是：

治理币是治理和生态参与机制的一部分，它不是支付币，也不能直接被表述为股权或保本收益工具。

## 必须追问的决策问题

1. 代币总量 `100%` 分解是否已经在对内 SSOT 定稿。
2. 国家池承销与个人承销的 **FDV/折扣** 是否可核对，且 **未** 与 Seat×参考价→募资混读。
3. RegionShare、Seat、TTG 三者对外如何分层解释。
4. 哪些权利是治理权，哪些是收益参与权，哪些只是产品叙事。
5. 当前阶段哪些内容仍是 `Target`，哪些已经进入可执行实现。
