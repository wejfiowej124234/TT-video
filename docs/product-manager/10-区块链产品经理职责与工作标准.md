# 区块链产品经理职责与工作标准

## 这份文档是给谁的

给第一次做区块链产品、第一次接手 TravelTrust、或者还不清楚自己该干什么的产品经理看。

这份文档的目标非常直接：

让你知道你在这个项目里的职责是什么、任务是什么、每天和每周该做什么、什么才算达到区块链产品经理的高标准。

注意：这份文档重点讲“总职责与总标准”。如果你要看融资方案、社媒平台、社区搭建、内容发布、动画视频解说这些增长运营动作的细标准，再看 [11-区块链产品经理增长运营与社区标准](11-区块链产品经理增长运营与社区标准.md)。

如果你要看一级市场渠道、投递资料、常见平台官网和融资外联准备，再看 [12-一级市场与融资渠道清单](12-一级市场与融资渠道清单.md)。

## 先说结论：你不是写页面文案的人，你是项目的业务和规则翻译器

在 TravelTrust 里，产品经理不是只写功能需求的人。

你更像下面 6 个角色的组合：

1. 业务翻译器：把业务目标翻译成产品结构。
2. 规则翻译器：把复杂规则翻译成用户流程、后台权限、状态机和约束。
3. 协同组织者：把技术、设计、财务、法务、风控拉到一个事实版本上。
4. 风险守门人：防止项目把概念讲错、边界做错、流程漏掉。
5. 融资方案组织者：把项目价值、阶段目标、承接路径整理成融资方案。
6. 增长运营推动者：推动内容、社区、平台账号和外部叙事持续运转。

## 在这个项目里，你的核心职责是什么

### 1. 先把项目学懂，而不是先开始提需求

你必须先搞懂：

- TravelTrust 是什么
- 它解决什么问题
- 它和普通旅游平台、普通 Web3 项目有什么区别
- 它为什么需要 Escrow、争议、治理、权限、合规这些层

如果这些都没搞懂，就不要急着改页面、改文案、改流程。

### 2. 定义清楚业务边界

你要负责把这些边界说清楚：

- 什么是订单交易逻辑
- 什么是治理逻辑
- 什么是融资叙事
- 什么是后台治理逻辑
- 什么是不能越过的合规边界
- **向导身份质押（`IdentityStakingPool` 系）** 与 **`/governance` / 治理币（TTG）** 分路径，**不**混称「同一种质押」（人话见 **[07-产品经理术语表](07-产品经理术语表.md)**、**[README · 工程对齐快照](README.md)**）

区块链产品经理最怕的不是不会写需求，而是把边界混掉。

### 3. 把规则变成产品可执行方案

你要把抽象的规则，变成团队能执行的东西：

- 用户流程
- 状态机
- 页面结构
- 权限矩阵
- 审批链
- 异常处理机制

不能只停留在“这个想法很好”。

### 4. 对齐多方单源，避免每个人理解不一样

这个项目天然跨很多角色：

- 前端
- 后端
- 合约
- 财务
- 法务
- 风控
- 运营

你的职责之一，就是保证大家讨论的是同一个版本，而不是各说各话。

### 5. 发现风险并提前拦住

一个高标准的区块链产品经理，不是等问题出事后再补文档，而是要提前发现：

- 叙事是否讲错
- 权限是否过宽
- 流程是否缺审批
- 状态是否无法追溯
- 对外词汇是否越界

### 6. 推动外部增长与运营落地

在这个项目里，产品经理还不能只停留在内部文档。

你还要推动：

- 融资方案整理
- 产品介绍材料整理
- 动画视频解说脚本
- 社区搭建
- X / 抖音 / INS 等平台矩阵运营

也就是说，你不仅要定义产品，还要帮助这个产品被市场理解、被社区理解、被潜在合作方理解。

## 你在这个项目里的具体任务是什么

下面这些，不是“可以做”，而是“应该做”。

### 一、认知类任务

1. 读懂项目整体结构。
2. 读懂核心卖点和差异化。
3. 读懂核心术语，不混概念。
4. 读懂四条主线：融资、治理币、权限、合规。

### 二、定义类任务

1. 定义产品边界。
2. 定义第一阶段主叙事。
3. 定义治理币讲到哪一步、不讲到哪一步。
4. 定义后台角色、数据权限、审批边界。
5. 定义对外口径白名单和风险红线。
6. 定义内容主线、社区主线和平台主线。

### 三、协同类任务

1. 和技术确认哪些是已实现、哪些是 Target。
2. 和法务确认哪些词能说、哪些词不能说。
3. 和财务确认对账、退款、结算、审计能力是否能闭环。
4. 和风控确认高风险动作、黑天鹅场景、人工干预边界。
5. 和设计确认视觉、动画、视频解说是否讲对产品。
6. 和运营确认社区节奏、内容节奏、平台节奏是否一致。
7. 和外部渠道或潜在合作方确认一级市场资料要求与投递节奏。

### 四、输出类任务

1. 输出清晰的产品说明。
2. 输出专题资料包和决策表。
3. 输出角色矩阵、流程图、状态机说明。
4. 输出会议纪要、动作项和 owner。
5. 输出融资方案和配套材料。
6. 输出平台账号矩阵、内容日历、社区规则和视频脚本。
7. 输出一级市场渠道清单、投递资料包和缺口列表。

## 你每天要干什么

如果你是这个项目的产品经理，日常工作至少应该包括：

1. 看当前在推进的核心问题是什么。
2. 看哪些问题还没有单源结论。
3. 看哪些讨论已经偏离文档事实。
4. 和相关负责人核对当前版本有没有变。
5. 把模糊问题改成清晰问题，把清晰问题变成明确动作。
6. 看当天内容、社区、平台运营是否按节奏推进。
7. 看外部表达有没有偏离项目真实边界。
8. 看融资渠道准备是否缺资料、缺链接、缺联系人、缺承接页。

白话一点说，你每天不是忙着“显得很忙”，而是要持续做三件事：

- 补理解
- 拉对齐
- 推闭环

## 你每周要干什么

每周建议至少完成下面这些动作：

1. 更新一次本周最重要的决策清单。
2. 推进 1 到 3 个真正闭合的关键问题。
3. 开 1 到 2 次有明确主题的专题会。
4. 形成会议纪要、owner、截止日期。
5. 检查是否出现了新的叙事风险、权限风险或合规风险。
6. 更新一次融资与增长相关的关键材料。
7. 复盘一次社区、内容和平台运营表现。
8. 推进一次一级市场渠道研究或资料补齐。

## 你每个阶段要干什么

### 阶段 1：先学懂

目标：看懂项目，不乱说。

你要完成：

- 看完新手先读
- 看完学习路径
- 看完产品优势
- 看完职责文档
- 看完术语表

### 阶段 2：先拉清楚边界

目标：知道什么是项目核心，什么不是。

你要完成：

- 业务边界梳理
- 第一阶段主叙事梳理
- 治理币边界梳理
- 对外口径风险梳理

### 阶段 3：进入专题推进

目标：按主题把关键问题逐步闭合。

你要完成：

- 融资专题推进
- 治理币专题推进
- 权限治理专题推进
- 合规门禁专题推进
- 增长运营专题推进
- 社区与平台矩阵推进

### 阶段 4：形成稳定工作机制

目标：不是靠临时救火，而是有节奏地推进。

你要完成：

- 决策表维护
- 会议机制维护
- owner 与 deadline 维护
- 单源更新同步

## 区块链产品经理的高标准要求是什么

下面这些标准，才是高标准，不是低配版产品工作。

### 1. 不讲自己没核实过的内容

区块链项目很容易出现“听别人说”“感觉是这样”的问题。

高标准要求是：

- 没核对单源，不下结论
- 没确认实现，不说已上线
- 没过法务，不做对外定稿

### 2. 不只懂前台，还要懂规则和系统

你不能只盯页面。

你至少要理解：

- 资金流怎么走
- 状态怎么变化
- 权限怎么分
- 风险怎么控
- 谁有审批权

### 3. 不做模糊产品经理

低标准产品经理会说：

- 这个先做一下
- 这个大概差不多
- 这个以后再补

高标准产品经理要说清：

- 现在到底要定什么
- 为什么现在定
- 依据是什么
- 谁负责
- 什么时候闭合

### 4. 不把 Web3 概念当产品能力

会讲区块链，不等于会做区块链产品。

高标准要求是：

- 知道哪些是真产品能力
- 知道哪些只是叙事层
- 知道哪些是路线图，不是当前事实

### 5. 不回避合规、权限、财务这些难题

这些不是技术和法务自己的事。

对区块链产品经理来说，它们就是产品的一部分。

### 6. 不把增长运营外包成“别人会做”

如果这个岗位被要求承担融资方案、产品介绍、动画视频解说、平台运营、社区建设，那么高标准要求就是：

- 不把这些事情只当执行杂活
- 要有节奏、有标准、有内容主线
- 要知道每个平台存在的目标是什么
- 要知道每一种内容服务于什么增长目标

## 这个项目里，你最应该交付的 12 类成果

1. 项目解释材料
2. 业务边界说明
3. 核心流程和状态说明
4. 角色与权限矩阵
5. 决策总表
6. 专题会议纪要
7. 对外口径边界说明
8. 风险与门禁清单
9. 融资方案主文档
10. 平台账号矩阵与运营节奏表
11. 社区搭建方案与社区规则
12. 产品介绍与动画视频解说脚本

## 你绝对不能做的 13 件事

1. 没读懂项目就开始改方案。
2. 把支付币、治理币、股权、分红混着讲。
3. 把未实现内容讲成已上线。
4. 不确认单源就推动跨团队执行。
5. 只盯前台页面，不管后台规则。
6. 只讲增长，不看合规和财务闭环。
7. 开完会不落纪要、不落 owner、不落截止日期。
8. 让技术、法务、财务各说一套，没有统一版本。
9. 把高风险动作设计成无审批、无审计。
10. 觉得“区块链产品经理只负责讲故事”。
11. 只开账号，不定义内容主线和社区目标。
12. 只做平台发帖，不做长期社区关系和品牌积累。
13. 想做一级市场，却没有整理渠道清单和资料包。

## 最后一句话

在 TravelTrust 里，一个高标准的区块链产品经理，不是最会写漂亮文案的人，而是最能把复杂业务、复杂规则、复杂风险，整理成团队可执行版本的人。

### 2. 产品介绍不只是讲功能，而是讲价值、结构和差异

产品介绍材料至少要讲清：

- 我们是什么
- 我们解决什么问题
- 我们和别人有什么不同
- 我们为什么值得继续关注

不能把产品介绍做成纯技术文档，也不能做成纯口号海报。

### 3. 动画视频解说不是做炫技，而是做理解转化

动画视频的作用不是炫，而是让别人更快理解：

- 交易怎么发生
- Escrow 为什么重要
- 为什么这个项目不仅是旅游平台
- 为什么它有长期扩展空间

所以视频脚本必须服务理解，不是堆概念词。

### 4. 社区不是群聊工具，而是项目关系网络

社区的目标不是“看起来热闹”，而是建立：

- 关注者
- 理解者
- 传播者
- 潜在合作方
- 潜在投资人或支持者

所以社区要有规则、有内容、有节奏、有互动机制。

### 5. 每个平台都必须有明确分工

不能把 X、抖音、INS、社区群都做成一样的内容镜像。

高标准要求是：不同平台承担不同任务。

## 各平台建议定位

### X 平台

定位：项目叙事、行业观点、进展更新、社区连接。

适合发布：

- 项目定位线程
- 产品能力拆解
- 里程碑更新
- 社区互动贴
- 空间活动预告

高标准要求：

- 有固定语气和叙事风格
- 不乱讲未确认内容
- 不把线程写成空洞口号

### 抖音

定位：快速理解、故事化介绍、短视频传播。

适合发布：

- 30 秒项目介绍
- 动画解说
- 场景化问题拆解
- “普通旅游平台 vs TravelTrust” 对比短视频

高标准要求：

- 视频先讲问题，再讲方案
- 文案口语化，不堆术语
- 每条视频只有一个核心信息点

### INS

定位：品牌感、视觉表达、项目气质、国际化外观。

适合发布：

- 品牌视觉卡片
- 产品结构图
- 短视频切片
- 项目理念与阶段进展

高标准要求：

- 视觉统一
- 文案简洁
- 不做信息过载长图

### 社区群组

定位：沉淀长期关系、解释项目、收集问题、组织活动。

适合推进：

- 新人欢迎机制
- FAQ 固定帖
- 每周项目进展同步
- 主题 AMA 或讨论
- 用户问题收集

高标准要求：

- 有群规则
- 有固定栏目
- 有人负责答疑和沉淀问题

## 你要做的增长运营任务清单

### 一、账号体系搭建

1. 明确要开哪些平台账号。
2. 统一账号名称、头像、简介、链接。
3. 统一平台视觉和品牌口径。
4. 明确每个平台存在的目的。

### 二、内容体系搭建

1. 定义内容主线。
2. 定义内容栏目。
3. 制定周更节奏。
4. 制定月度主题。
5. 建内容素材库。

### 三、融资内容准备

1. 写融资主方案。
2. 写融资摘要版。
3. 准备产品介绍页内容。
4. 准备 FAQ。
5. 准备对外解释版本。

### 四、视频内容准备

1. 写动画视频解说脚本。
2. 定义视频镜头结构。
3. 定义解说顺序。
4. 明确每条视频的唯一目标。

### 五、社区搭建

1. 建社区规则。
2. 建欢迎语和新人引导。
3. 建 FAQ。
4. 建活动节奏。
5. 建问题收集与反馈机制。

## 高标准内容矩阵应该长什么样

至少要有下面 5 类内容：

1. 项目是什么
2. 产品为什么不一样
3. 关键机制怎么工作
4. 当前进展和阶段目标
5. 社区互动和问题答疑

如果只有“我们很牛”“欢迎关注”这类内容，不算高标准运营。

## 动画视频解说的高标准要求

1. 先讲用户问题，再讲产品解决方案。
2. 不上来堆术语和 token 概念。
3. 一条视频只服务一个理解目标。
4. 脚本必须和真实产品边界一致。
5. 未实现内容必须明确是路线图，不是当前事实。

## 社区搭建的高标准要求

1. 有清晰定位，不是什么人都往里拉。
2. 有固定节奏，不是想起来才发。
3. 有欢迎机制，不是新人进来就沉底。
4. 有 FAQ 和基础资料，不是反复人工解释同一个问题。
5. 有活动和反馈机制，不是死群。

## 你每周至少要推动的增长运营动作

1. 更新一次内容排期。
2. 更新一次平台发布计划。
3. 推进至少一条高质量项目介绍内容。
4. 推进至少一条视频或视频脚本。
5. 维护一次社区节奏或互动活动。
6. 做一次平台数据和社区反馈复盘。

## 低标准和高标准的区别

### 低标准

- 开号了，但没人知道为什么开
- 发内容了，但没有主线
- 做视频了，但别人看不懂产品
- 建社区了，但没有规则和节奏
- 写融资方案了，但和外部内容不连通

### 高标准

- 平台各自有明确角色
- 内容围绕同一项目主线展开
- 视频帮助别人更快理解产品
- 社区能持续沉淀关系和问题
- 融资方案、承接页、内容、平台、社区形成一个系统

## 你绝对不能做的 10 件事

1. 想到什么发什么，没有内容主线。
2. 每个平台发一模一样的内容，不做分工。
3. 把未确认信息当进展发出去。
4. 把路线图讲成已上线事实。
5. 只做视觉包装，不讲产品逻辑。
6. 只讲 token，不讲真实产品结构。
7. 开社区不写规则、不做欢迎、不做沉淀。
8. 只追求数量，不追求内容质量和理解度。
9. 只做短期热点，不做长期品牌资产。
10. 觉得运营就是发帖，不需要产品理解。
