# 上线验收与发布门禁清单

## 这份文档是干什么的

这份文档用于明确 TravelTrust 当前不同版本状态的定义，以及每次上线、演示或对外发布前应该过哪些门禁。

它的核心作用是防止把“本地开发版能打开”误判成“已经可以对外发布”。

## 版本状态定义

| 状态 | 定义 | 能否对外 |
|------|------|------|
| 开发版 | 本地或联调环境可用，功能仍可能变化 | 否 |
| 可演示版 | 可用于内部或受控场景演示，主链路基本可走通 | 谨慎，默认否 |
| 可对外版 | 文案、截图、口径、关键链路已完成门禁，可用于受控对外沟通 | 是，需注明范围 |
| 正式发布版 | 已完成发布门禁、回归、资料同步和对外入口准备 | 是 |

## 发布门禁总表

| 检查项 | 是否必须 | 验收标准 | 当前负责人 |
|------|------|------|------|
| 主链路可走通 | 必须 | `/traveltrust -> /market -> 订单/帮助/社区` 至少可演示 | 产品经理 + 前端 |
| 关键文案已核对 | 必须 | 不出现项目定位和对外边界错误 | 产品经理 |
| 对外口径已过签核 | 对外发布必须 | 已回链合规与法务口径 | 产品经理 + 法务 |
| 链接与入口已核对 | 必须 | 不出现坏链、假链、错误环境链接 | 产品经理 |
| FAQ / 帮助已同步 | 高优先级 | 新变更有对应说明或承接入口 | 产品经理 |
| 截图 / 演示素材已更新 | 对外发布必须 | 所有对外素材与当前版本一致 | 产品经理 + 设计 |
| 发布后回归检查 | 必须 | 发布后再次核对关键入口 | 产品经理 + 前端 |

## 对外演示、截图与录屏脱敏检查

在**任何**对外会议、媒体报道、投资人材料、社区发帖使用界面截图、录屏或直播演示前，建议逐项自检（**不**替代法务对具体素材的审阅）：

- [ ] **URL / 环境**：地址栏、标题栏、书签栏不出现**内网域名**、**非公开 staging**、**个人书签**或与当前叙事不符的环境标识。
- [ ] **账户与身份**：不出现真实员工/测试用户**全名、邮箱、手机号、钱包地址**；必要时使用专用演示账号或打码。
- [ ] **密钥与配置**：终端、IDE、`.env`、浏览器插件、云控制台截图中无 **API Key、私钥、内网 token、数据库连接串**。
- [ ] **管理后台**：若演示 **`/admin/*`**，确认无**生产真实订单金额、真实用户 PII、未公开财务表**；默认假设「**整屏不可外发**」直至法务书面同意范围。
- [ ] **链上与金库**：**`/governance`** 及链上弹窗中的**合约地址、待执行 calldata、金库余额**等，对外使用前须按 **[89](../spec/89-治理UI-全球旅游市场治理控制台设计规格.md)**、**[08-4](../spec/08-4-对外口径包.md)** 收敛口径，避免误导读成「已主网满仓/已可公众操作」。
- [ ] **叙事边界**：口播与字幕**不**把 **Partial/MVP**、**机读脚本通过** 讲成 **83/84/110 Target** 或 **P0 已全部闭合**（真源 **[缺口官方总表](../spec/缺口与待补-官方总表.md)**）。

详尽的对外措辞红线仍以 **[04-合规与风险门禁资料包](04-合规与风险门禁资料包.md)** 为准。

## UAT 场景清单

### 场景 1：品牌承接

1. 能打开 `/traveltrust`。
2. 关键说明不把项目讲成卖币页。
3. 进入 `/market` 的 CTA 明确可见。

### 场景 2：产品进入

1. 能打开 `/market`。
2. 用户能看懂这是产品入口，不是宣传页。
3. 关键 CTA 可正常点击。

### 场景 3：帮助与反馈

1. 能打开 `/help`。
2. 能打开 `/community/feedback`。
3. FAQ、帮助和反馈逻辑自洽。

### 场景 4：社区承接

1. 能打开 `/community`。
2. 新人能看懂社区入口作用。
3. 如果外部社群未建立，不误写成已建立。

### 场景 5：治理控制台（按需）

1. 能打开 `/governance`（及子路径如提案列表，以当前前端路由为准）。
2. 讲解时**不**与订单 **`/orders`～`/escrow`** 主链、**不**与向导 **身份质押（`IdentityStakingPool` 系）** 混为同一叙事（人话边界见 **[README · 快照](README.md)**、**[07-产品经理术语表](07-产品经理术语表.md)**）。
3. 对外演示前已回读 **[89-治理 UI 规格](../spec/89-治理UI-全球旅游市场治理控制台设计规格.md)** 与 **08-4** 边界。

## 发布前检查清单

- [ ] 当前使用的是正确环境链接
- [ ] 主产品路径可演示
- [ ] 页面无明显阻断性错误
- [ ] 对外文案已回链 SSOT
- [ ] FAQ / 帮助已同步
- [ ] 外部资料室索引已同步
- [ ] 如属对外使用，已完成法务或合规确认

## 发布后回归检查

- [ ] 再次核对 `/traveltrust`
- [ ] 再次核对 `/market`
- [ ] 再次核对 `/help`
- [ ] 再次核对 `/community`
- [ ] 若曾对外演示治理：再次核对 `/governance` 与相关素材是否仍符合 **89 / 08-4** 边界
- [ ] 再次核对对外资料链接

## 证据留存建议

每次重要发布或外部演示前，至少保留：

1. 版本日期。
2. 演示链接。
3. 关键截图。
4. 使用的 Deck / FAQ / One Pager 版本。
5. 签核或确认记录。
