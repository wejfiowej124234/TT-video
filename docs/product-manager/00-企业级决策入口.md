# 企业级决策入口

## 先用白话理解这份文档

这份文档的作用不是给你上技术课，而是告诉你：作为产品经理，现在最该盯住哪几类问题。

如果你刚接手项目，可以先把这 4 类问题理解成：

1. 对外怎么讲项目和融资
2. 治理币到底讲到什么程度
3. 内部谁有权操作、审批、看数据
4. 哪些风险和合规问题必须先挡住

## 这份入口是给谁的

面向当前项目的产品经理、增长负责人、融资负责人，以及需要联合财务、法务、技术负责人做方案决策的人。

如果你是零基础产品经理，也可以直接用，因为每一类问题都只保留“你现在最需要知道的部分”。

## 产品经理现在最需要解决的四类问题

### 1. 融资怎么做

白话理解：第一阶段到底怎么跟外部解释“为什么现在值得关注和参与”。

- 先看 [01-融资方案资料包](01-融资方案资料包.md)
- 原始单源重点看 [84](../spec/84-第一阶段10国Country-Pool发行参数总表.md)、[85](../spec/85-TravelTrust网络落地页-融资级设计与开发规格.md)、[200](../spec/200-阶段财务对账结算与报表.md)

你开会时最少要问清：

- 第一阶段卖点到底是什么
- 融资页面只做展示，还是走到更深参与流程
- 财务和对账能不能支撑尽调

### 2. 治理币和代币化融资怎么做

白话理解：如果要讲治理币，必须先讲清它到底负责什么，不负责什么。

- 先看 [02-治理币与代币化方案资料包](02-治理币与代币化方案资料包.md)
- 原始单源重点看 [82](../spec/82-治理币-文档总览.md)、[83](../spec/83-区域治理与收益分配-协议白皮书.md)、[governance-token/README](../spec/governance-token/README.md)

你开会时最少要问清：

- 治理币和支付币是不是混了
- 治理币和股权是不是被讲混了
- 国家桶和个人桶是不是用一个逻辑解释

### 3. 权限和组织治理怎么做

白话理解：公司内部到底谁能做什么，谁能批什么，谁能看哪些数据。

- 先看 [03-权限与组织治理方案资料包](03-权限与组织治理方案资料包.md)
- 原始单源重点看 [70](../spec/70-管理员系统开发文档.md)、[530](../spec/530-阶段数据权限隔离系统.md)、[500](../spec/500-阶段法律与合规日志系统.md)

你开会时最少要问清：

- 财务、风控、合规是不是已经拆角色
- 高危操作是不是必须审批
- 数据是不是按国家、组织、角色做隔离

### 4. 合规和企业级风险边界怎么管

白话理解：哪些事情可以做，哪些词不能说，出了风险谁来兜底。

- 先看 [04-合规与风险门禁资料包](04-合规与风险门禁资料包.md)
- 原始单源重点看 [08-1](../spec/08-1-战略与合规风险检查清单.md)、[08-3](../spec/08-3-参数与门禁表.md)、[08-4](../spec/08-4-对外口径包.md)

你开会时最少要问清：

- 对外能说什么，不能说什么
- 关键参数谁能改
- 黑天鹅场景有没有写明应对机制

## 如果你只开一场总会

第一场不要铺太大，建议只确认下面 4 个结果：

1. 第一阶段主叙事
2. 治理币边界
3. 组织权限框架
4. 对外口径和发布门禁

## 建议决策输出

产品经理可基于本目录，组织以下 5 份内部方案：

1. 融资主方案
2. 治理币与代币融资方案
3. 组织权限与审批方案
4. 数据权限与合规留痕方案
5. 对外口径与法务签核方案

## 决策时必须守住的底线

- 不得把订单结算币和治理币混为一谈，当前项目总览明确 MVP 不发行平台支付币。
- 不得把治理币或区域份额直接宣传为股权、分红或保本收益产品。
- 不得把后台权限、数据权限、审批权、链上执行权混成一个角色域。
- 不得只做融资叙事，不做财务对账、权限审计、合规留痕和发布门禁。

如果你对上面 4 句还不够熟，先回 [00A-产品经理新手先读](00A-产品经理新手先读.md) 和 [07-产品经理术语表](07-产品经理术语表.md)。

- **ABI、身份质押 vs 治理控制台、Partial/MVP 等易混点**：[README · 与仓库实现对齐的快照](README.md) 表格 + [29 · 与技术文档对齐自检表](29-产品经理多维度深度检查与新增缺口.md)
