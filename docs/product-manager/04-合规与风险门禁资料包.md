# 合规与风险门禁资料包

## 这份资料包解决什么问题

用于支持产品经理从企业级角度锁定项目的合规边界、对外口径、参数门禁、黑天鹅策略和发布前 gate。

如果你以前没接触过这类文档，可以先把它理解成：

这份文档是在告诉你，哪些事情不是“以后再补”，而是现在不定清楚就会直接出事的底线问题。

## 小白先看这个结论

1. 对外说错一句话，可能比页面做错一个按钮更严重。
2. 参数不是谁想改就能改，必须有审批和审计。
3. 黑天鹅场景不是写在脑子里，要写成流程和责任分工。
4. 合规证据不是可选项，是企业级项目的生存底线。

## 与工程门禁互证（知悉）

合规与对外口径仍以本文 **必读原文** 为准。工程侧另有一套 **机读脚本**（如 **`bash scripts/run-check-04-routes.sh`**、**`bash scripts/check-55-s13.sh`**）用于 **API 路由表** 与 **ABI 双目录** 等一致性预检，细则见 **[07-开发流程与顺序 §零 0.6](../spec/07-开发流程与顺序.md)** 与 **[33-上线验收与发布门禁清单](33-上线验收与发布门禁清单.md)**。产品经理只需知道：**文档表、脚本与实现应对齐**，避免对外把 **Partial/MVP** 讲成 **Target 终局已验收**。

## 隐私、跨境与个人信息（产品经理边界）

旅游 + 账户体系天然涉及**个人信息与跨境传输**场景。本资料夹**不**提供可替代法务的法律结论；产品经理应做到：

1. **不自撰**：FAQ、官网、Pitch、社群置顶帖中凡涉及「数据存哪、谁能看、保留多久、用户权利、跨境」等表述，**必须**经法务定稿或与 **[08-4](../spec/08-4-对外口径包.md)**、**[500](../spec/500-阶段法律与合规日志系统.md)** 已收敛段落**逐句对齐**。
2. **对外素材先脱敏**：截图、录屏、直播演示按 **[33 · 对外演示与截图脱敏检查](33-上线验收与发布门禁清单.md)** 自检，再提交法务抽查高风险帧。
3. **与产品路径一致**：收集反馈、帮助中心、社区入口若涉及**数据用途说明**，与 **04**、**70**、**530** 中的产品设计对齐，避免「页面写了、后台没做」的对外风险。

## 产品经理必须锁死的 4 类内容

### 1. 对外能怎么说

白话理解：市场、官网、白皮书、PPT 到底允许用哪些词。

对外口径必须以 [08-4](../spec/08-4-对外口径包.md) 为准，尤其是：

- 我们是谁
- 是否托管资金
- 仲裁能做什么
- 稳定币冻结如何处理
- Pause 如何处理
- OFAC 与政府请求如何响应

### 2. 参数谁能改

白话理解：真正能影响系统规则的开关，绝不能谁方便谁来改。

[08-3](../spec/08-3-参数与门禁表.md) 已经把关键 key 和变更门禁写得很明确。产品经理需要把这套参数体系转成治理流程，而不是只看数值本身。

重点要看：

- 谁能改
- 怎么改
- 谁审批
- 留什么证据

### 3. 黑天鹅时怎么办

白话理解：出大问题的时候，不能靠临场发挥。

[08-1](../spec/08-1-战略与合规风险检查清单.md) 已经把很多企业级问题列出来了，包括：

- 稳定币被冻结
- 证据缺失
- 多签失联
- 争议量暴增
- Pause 与 OFAC 冲突
- 发布不可验证

产品经理要把这些从“检查项”转成“可执行机制”。

### 4. 合规证据怎么留

白话理解：以后真被问责、被审计、被投诉时，系统能不能拿出证据。

[500](../spec/500-阶段法律与合规日志系统.md) 已经给出了法律与合规中心的最小能力：

- 合规日志
- 合规导出
- 数据请求
- 证据保全
- 合规审计

这部分是企业级运营的底线，不是可选项。

## 建议产品经理输出

1. 企业级合规 gate 清单
2. 对外口径定稿表
3. 关键参数审批与变更机制
4. 黑天鹅处置矩阵
5. 合规导出与证据保全流程

## 如果你只先记住 4 件事

1. 对外哪些话能说，哪些不能说。
2. 关键参数谁能改、怎么改。
3. 遇到极端风险怎么暂停、怎么响应。
4. 合规证据怎么保留、怎么导出。

## 必须追问的决策问题

1. 我们当前到底是“混合治理平台”还是“完全去中心化协议”，对外说法是否一致。
2. 多签、Pause、参数修改、人工仲裁这些强控制点，是否已经写清边界。
3. 证据保留、删除、司法协助、GDPR 冲突是否有明确落点。
4. 是否已经有文档化的 Gate-1 到 Gate-5 执行路径。
5. 所有对外话术是否都能在 08-3 关键 key 上找到可追溯的参数依据。
