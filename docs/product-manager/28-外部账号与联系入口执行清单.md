# 外部账号与联系入口执行清单

## 当前真实判断

按当前仓库可见信息，项目已经有内部产品入口和私有代码仓库入口，但还没有形成完整的外部账号与联系入口体系。

当前最需要的不是继续写“建议以后注册哪些平台”，而是把注册顺序、命名规则、简介模板和同步规则一次定清楚。

## 与技术文档对齐（企业级）

简介、链接与「已上线」表述须与 **`docs/spec/`**（**[08-4](../spec/08-4-对外口径包.md)**、**[01](../spec/01-总库总览.md)**）及 **[README 快照](README.md)** 对读；可勾选 **[29 自检表](29-产品经理多维度深度检查与新增缺口.md)**。**P0** 真值 **[缺口官方总表](../spec/缺口与待补-官方总表.md)**。

## 建议注册顺序

### 第一优先级

1. X
2. Telegram 或 Discord 主社区
3. 商务联系邮箱

### 第二优先级

4. YouTube
5. Instagram
6. 抖音

### 第三优先级

7. Medium 或博客阵地
8. Notion / Link 页面或统一链接页

## 所有平台统一要准备的 6 项

1. 统一账号名
2. 统一头像
3. 统一一句话简介
4. 统一官网或主承接链接
5. 统一品牌介绍长文案
6. 统一负责人和登录凭据管理方式

## 命名基线

建议优先尝试以下命名：

1. TravelTrust
2. TravelTrust Network
3. TravelTrust Official

如果核心名称已被占用，所有平台都要统一采用同一套替代名，不要每个平台一个写法。

## 简介模板

中文简介模板：

TravelTrust 是一个围绕旅游交易构建的信任型产品系统，连接市场撮合、托管保障、争议处理、信誉沉淀与社区承接。

英文简介模板：

TravelTrust is building a trust-based travel transaction network combining marketplace matching, escrow, dispute handling, reputation and community onboarding.

## 平台执行清单

### X

1. 注册主账号。
2. 设置统一头像、Banner 和简介。
3. 首页链接优先指向主承接页或统一链接页。
4. 发布第一条项目介绍内容。
5. 在 [19-平台账号矩阵表](19-平台账号矩阵表.md) 中登记。

### Telegram / Discord

1. 建立主社区。
2. 设置欢迎语、群规和固定入口。
3. 放入 FAQ、帮助入口和反馈入口。
4. 在 [20-社区链接与入口总表](20-社区链接与入口总表.md) 中登记。

### 商务邮箱

1. 建立统一商务邮箱。
2. 明确谁负责收件和回复 SLA。
3. 把邮箱同步到平台简介、Deck、One Pager 和资料室索引页。

### Instagram / 抖音 / YouTube

1. 统一名称与视觉。
2. 统一简介和主链接。
3. 至少准备 1 条项目介绍内容再公开。

## 注册完成后的同步要求

1. 同步更新 [19-平台账号矩阵表](19-平台账号矩阵表.md)。
2. 同步更新 [20-社区链接与入口总表](20-社区链接与入口总表.md)。
3. 同步更新 [23-资料室总索引页](23-资料室总索引页.md)。
4. 在 [22-外部内容资产总表](22-外部内容资产总表.md) 中登记版本和可对外状态。

## 最容易漏的点

1. 平台名称不统一。
2. 简介和 One Pager 口径不一致。
3. 平台上写了公开链接，但资料室没有同步。
4. 社区建了群，但没有固定 FAQ 和反馈入口。
5. 注册完成后没人持续维护 owner 和密码管理。
