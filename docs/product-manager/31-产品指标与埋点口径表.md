# 产品指标与埋点口径表

## 这份文档是干什么的

这份文档用于统一 TravelTrust 的产品指标、核心漏斗和埋点事件口径。

目标不是一次把所有数据都做完，而是先把“我们到底看什么、怎么定义、怎么埋点”讲清楚。

## 使用原则

1. 指标必须区分产品指标、运营指标和对外传播指标。
2. 所有事件名称和定义要固定，不要今天一个说法明天一个说法。
3. 开发版没有埋点时，也要先把口径写清楚。
4. 发布后所有复盘都要回到这里，不能临时改定义。

## 当前建议先看 3 类指标

### 1. 产品漏斗指标

用于看用户从理解项目到进入交易主链的转化情况。

### 2. 反馈与帮助指标

用于看帮助中心、反馈入口和 FAQ 是否真的减轻解释成本。

### 3. 社区承接指标

用于看社区入口和帮助入口有没有形成后续留存与互动。

## 核心漏斗定义

| 漏斗阶段 | 目标页面 / 动作 | 指标定义 | 当前意义 |
|------|------|------|------|
| F1 品牌触达 | 打开 `/traveltrust` 或首页 | 进入品牌理解阶段的 UV | 看有多少人进入承接页 |
| F2 产品进入 | 打开 `/market` | 从理解进入产品主入口的 UV | 看承接页到产品页转化 |
| F3 下单意图 | 打开 `/orders/new` 或触发新订单动作 | 明确进入交易意图的 UV | 看产品兴趣是否变成操作意图 |
| F4 订单形成 | 进入 `/orders` 或形成订单记录 | 真实进入订单流程的用户数 | 看核心交易是否启动 |
| F5 托管与履约 | 访问 `/escrow/[id]` 或发生托管状态变化 | 进入信任主链的订单数 | 看核心差异化能力是否被使用 |
| F6 信誉沉淀 | 访问 `/did-rank` 或完成评价动作 | 理解或形成信誉结果的用户数 | 看信任展示层是否被使用 |
| F7 社区承接 | 访问 `/community` 或 `/help` | 进入社区和帮助承接的 UV | 看长期承接面是否有效 |

## 核心指标建议

| 指标名称 | 口径 | 周期 | 优先级 | 备注 |
|------|------|------|------|------|
| 承接页 UV | `/traveltrust` 独立访问用户数 | 周 / 月 | P0 | 品牌理解起点 |
| 产品入口点击率 | 从承接页进入 `/market` 的比例 | 周 / 月 | P0 | 判断承接是否有效 |
| 下单意图率 | 访问 `/orders/new` 用户数 / `/market` UV | 周 / 月 | P0 | 判断市场页是否有效转化 |
| 订单形成率 | 进入订单流程用户数 / 下单意图用户数 | 周 / 月 | P0 | 判断交易链路是否顺畅 |
| 帮助自助解决率 | 帮助页访问后未继续提交反馈的比例 | 周 / 月 | P1 | 判断 FAQ 是否减压 |
| 反馈转需求率 | 反馈中最终进入需求池的比例 | 周 / 月 | P1 | 判断反馈质量 |
| 社区承接率 | 从帮助或产品页进入社区页的比例 | 周 / 月 | P1 | 判断社区承接 |

## 事件埋点表

| 事件名 | 触发动作 | 页面 | 事件说明 | 关键属性 |
|------|------|------|------|------|
| `tt_page_view_traveltrust` | 打开 `/traveltrust` | `/traveltrust` | 品牌承接页曝光 | 来源、设备、语言 |
| `tt_click_enter_market` | 从首页或承接页点击进入市场 | `/`、`/traveltrust` | 进入产品主入口 | 来源页面、CTA 名称 |
| `tt_page_view_market` | 打开 `/market` | `/market` | 市场入口曝光 | 来源页面、设备 |
| `tt_click_create_order` | 点击新建订单或下单 CTA | `/market`、`/orders/new` | 下单意图开始 | 来源模块、服务类型 |
| `tt_page_view_orders_new` | 打开 `/orders/new` | `/orders/new` | 订单创建页曝光 | 来源页面 |
| `tt_order_created` | 订单创建成功 | 订单链路 | 订单正式形成 | 订单类型、国家、城市 |
| `tt_page_view_escrow` | 打开托管详情页 | `/escrow/[id]` | 托管节点被访问 | 订单状态、角色 |
| `tt_submit_feedback` | 提交反馈表单 | `/community/feedback` | 用户主动反馈 | 分类、优先级、来源页面 |
| `tt_page_view_help` | 打开帮助页 | `/help` | FAQ / 帮助曝光 | 来源页面 |
| `tt_page_view_community` | 打开社区页 | `/community` | 社区承接曝光 | 来源页面 |
| `tt_page_view_did_rank` | 打开 DID 排行榜 | `/did-rank` | 信誉展示页曝光 | 来源页面 |

## 事件属性建议

所有关键事件至少统一下面这些属性：

1. `source_page`
2. `device_type`
3. `language`
4. `user_role`，如果可识别
5. `entry_channel`，如 direct / help / community / campaign

## 数据口径边界

1. 没有正式生产环境时，当前埋点定义只作为设计口径，不宣称已有真实线上数据。
2. 本地开发版可用于事件设计和联调，不代表正式对外报表。
3. 对外引用数据前，必须补充统计口径、时间范围和环境说明。

## 第一批必须落地的埋点

1. `/traveltrust` 曝光
2. 进入 `/market` 点击
3. 订单创建起点
4. 反馈提交
5. 帮助页访问
