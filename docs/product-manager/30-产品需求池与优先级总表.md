# 产品需求池与优先级总表

## 这份文档是干什么的

这份文档用于统一管理 TravelTrust 产品经理收到的所有新增事项，避免需求散落在聊天、会议和临时口头安排里。

它解决 4 个问题：

1. 新事项从哪里进来。
2. 什么叫需求，什么叫 Bug，什么叫咨询。
3. 需求优先级怎么排。
4. 需求现在推进到哪一步。

## 与技术文档对齐（企业级）

需求描述中的「已实现 / 路由 / 链上 / 发版」须可指 **`docs/spec/`** 与 **[README 快照](README.md)**；可勾选 **[29 自检表](29-产品经理多维度深度检查与新增缺口.md)**。入口：**[spec/00-文档索引](../spec/00-文档索引.md)**、**[07 §零 0.6](../spec/07-开发流程与顺序.md)**、**[缺口官方总表](../spec/缺口与待补-官方总表.md)**。**`/` + `/market*` 四页 ① FE 数据链**（演示/埋点/漏斗须与代码一致）：**[LANDING-MARKET-PAGES-CODE-SSOT](../../frontend/evidence/GO_local_web3_pages_closure/LANDING-MARKET-PAGES-CODE-SSOT.md)**。

## 使用规则

1. 所有新增事项先进入需求池，再决定是否进任务母表。
2. Bug 不直接进需求池主表，先按 [34-Bug 分级与质量复盘机制](34-Bug 分级与质量复盘机制.md) 处理，再决定是否转成需求。
3. 纯咨询类问题优先进入 [32-用户反馈与问题闭环台账](32-用户反馈与问题闭环台账.md)。
4. 每周至少过一遍需求池，更新优先级、状态和下步动作。

## 需求类型定义

| 类型 | 定义 | 例子 | 默认去向 |
|------|------|------|------|
| 新功能 | 需要新增页面、流程、状态或能力 | 新增正式发布状态标识 | 进入需求池 |
| 优化项 | 已有能力要优化体验、结构或说明 | 优化 `/help` 结构 | 进入需求池 |
| 内容需求 | 需要新增或修改文案、FAQ、素材 | 更新对外 FAQ | 进入需求池 |
| 数据需求 | 需要新增指标、埋点、报表 | 增加 `/market` 点击埋点 | 进入需求池 |
| 合规需求 | 为通过签核或门禁新增的要求 | 对外口径加免责声明 | 进入需求池 |
| Bug | 已有能力不符合预期或失效 | 反馈入口提交失败 | 先进 Bug 台账 |
| 咨询 / 反馈 | 用户提问、建议、投诉 | 新人问主群在哪 | 先进反馈台账 |

## 优先级规则

### 优先级分层

| 优先级 | 定义 | 处理要求 |
|------|------|------|
| P0 | 不处理会影响对外发布、关键履约、合规或核心交易链路 | 当周必须推进 |
| P1 | 明显影响核心体验、转化或管理效率 | 本周期优先推进 |
| P2 | 有价值但可延后一到两个迭代 | 进入排期池 |
| P3 | 记录观察，不立即进入执行 | 保持观察 |

### 判断维度

每个需求至少按下面 5 个维度判断：

1. 是否影响核心交易或信任主链。
2. 是否影响对外发布或合规。
3. 是否影响当前阶段转化或承接。
4. 是否有明确用户价值或业务价值。
5. 是否已有依赖条件未满足。

### 周排期冲突处理规则

当产品、运营、融资、社区、合规任务冲突时，按这个顺序判断：

1. 先做合规和发布门禁类。
2. 再做核心交易链路和反馈闭环类。
3. 再做外部承接与转化类。
4. 最后做非关键优化类。

## 状态定义

| 状态 | 定义 |
|------|------|
| 待分析 | 已进入需求池，但未完成背景与价值判断 |
| 待定级 | 已明确问题，待优先级判断 |
| 待排期 | 已明确优先级，等待进入迭代 |
| 进行中 | 已进入执行 |
| 待验收 | 已完成交付，等待验收 |
| 已关闭 | 已上线、已定稿或确认不做 |
| 挂起 | 有价值，但当前依赖未满足 |

## 需求进入母表的规则

满足下面任一条件，需求应升级到 [17-产品经理企业级任务母表](17-产品经理企业级任务母表.md)：

1. 影响对外发布或法务签核。
2. 影响核心交易或信任主链。
3. 需要跨团队协同。
4. 预计持续超过一周。
