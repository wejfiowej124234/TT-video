# 平台账号矩阵表

**端口说明**：下表 Web 链接示例使用 **`localhost:3012`**；本地开发以 **`.env` 中 `PORT`** 与 **[`frontend/README`](../../frontend/README.md)** 为准。

## 这份文档是干什么的

这份文档用于统一管理 TravelTrust 的外部平台账号。

目标是解决下面几个问题：

1. 我们到底开了哪些平台账号。
2. 每个平台是谁在负责。
3. 当前账号是否已经注册、配置、发布首条内容。
4. 外部看到的名称、简介、链接是否一致。

## 与技术文档对齐（企业级）

矩阵中「产品路由、是否已上线」等事实须与 **`docs/spec/`**（**[04 §3.4](../spec/04-后端与API.md)**、**[07 §零 0.6](../spec/07-开发流程与顺序.md)**）及 **[README 快照](README.md)** 对读；发版边界 **[缺口官方总表](../spec/缺口与待补-官方总表.md)**；对外演示 **[33](33-上线验收与发布门禁清单.md)**。

## 当前真实执行状态说明

基于当前仓库，能被确认的真实入口主要是：

1. 本地开发版 Web 路由。
2. 私有 GitHub 仓库入口。
3. 产品内帮助、社区、市场等页面入口。

当前仓库里没有看到已公开确认的：

1. 正式生产域名。
2. 公开 X 账号。
3. 公开抖音账号。
4. 公开 INS 账号。
5. 公开 Telegram / Discord 主群。
6. 对外商务邮箱。

所以这张表的“真实执行版”不是把缺失项伪装成已完成，而是把当前真实已存在入口、当前缺失项和下一步动作写清楚。

## 使用规则

1. 账号或入口一旦建立，就立刻补到这张表。
2. 名称、头像、简介、链接更新时，同步更新这里。
3. 没有正式链接时，不要写假链接。
4. 平台不存在时，也要把真实状态写成“未建立 / 仓库未见”。
