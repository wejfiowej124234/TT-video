# 融资方案资料包

## 这份资料包解决什么问题

用于支持产品经理制定企业级融资主方案，包括融资叙事、国家池方案、落地页承接、财务对账和对外披露边界。

如果你是第一次接项目，可以先把它理解成一句话：

这份文档是帮你回答“我们第一阶段到底拿什么去讲融资，以及这个故事能不能站得住”。

## 小白先看这个结论

1. 第一阶段不能把所有东西揉成一个故事，要分清国家池、治理币、页面承接、财务闭环。
2. `/traveltrust` 是融资级介绍和承接页，不是直接认购页面。
3. 只讲增长和故事不够，财务、对账、退款、审计能力必须一起准备。
4. 任何涉及收益、份额、回报的表达，都要先过法务和合规边界。

## 产品经理要抓的关键决策

### 1. 融资对象是什么

白话理解：你到底在邀请别人关注什么、参与什么。

- 是 Country Pool 国家池承销
- 是治理币相关代币化融资
- 还是品牌落地页承接的 Early Access / 融资线索收集

这三者不能混成一套话术。

### 2. 融资分母是什么

白话理解：你在解释“比例”和“份额”时，到底是按什么盘子算。

必须区分两套分母：

- 费用分母：`45% / 55%` 的可分配平台费用路径
- 承销分母：国家池或治理币总量的承销盘子

这部分以 [84](../spec/84-第一阶段10国Country-Pool发行参数总表.md) 为单源，不能把 `29` 个费用百分点和 `25%` 国家承销桶直接相加或当成一回事。

### 3. 融资页面承接到什么程度

白话理解：页面到底是用来介绍项目，还是直接做交易动作。

[85](../spec/85-TravelTrust网络落地页-融资级设计与开发规格.md) 已经明确：

- `/traveltrust` 是融资级网络落地页
- 不是 ICO 专页
- 不是完整 DApp
- 不得做隐含证券承诺或收益承诺

### 4. 财务和审计是否跟得上

白话理解：如果对方认真问账、问退款、问凭证，我们拿不拿得出来。

融资方案不是只有募资数字，还必须同时考虑：

- 财务摘要与报表导出
- 对账批次与差异归因
- 结算与退款链路
- 审计导出与证据留痕

这部分以 [200](../spec/200-阶段财务对账结算与报表.md) 为主。

## 建议产品经理输出

1. 融资主叙事：面向投资人和市场
2. 国家池分层方案：S/A/B/C 档与先后节奏
3. 融资承接页方案：`/traveltrust` 信息架构与 CTA
4. 财务闭环要求：对账、报表、导出、审批
5. 对外口径包：需法务签核的最终话术

## 如果你想自测自己有没有看懂这份资料

你至少应该能自己回答这 4 句：

1. 第一阶段融资不能只讲代币，要先明确主叙事。
2. Country Pool 和治理币要拆开说，不然估值和口径会打架。
3. `/traveltrust` 先承担展示和线索转化，不做高风险认购表达。
4. 财务、退款、审计和导出能力是融资可信度的一部分。

## 开会时必须确认的问题

1. 第一阶段到底卖什么，是国家池承销、治理币、还是权益认领资格。
2. 募资目标和硬顶的估值锚，是否已经在代币 SSOT 中锁定。
3. 所有对外数字是否已经过 [LEGAL-SIGNOFF-CHECKLIST](../spec/governance-token/LEGAL-SIGNOFF-CHECKLIST.md) 审核。
4. 融资落地页是否只做展示与转化，不触发证券式认购交互。
5. 财务是否能对外部尽调给出可审计的账务与报表说明。
