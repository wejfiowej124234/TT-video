# Product Manager Decision Pack

本目录是给 TravelTrust 产品经理使用的独立资料夹。

如果你对项目还不熟，这里可以把它当成一套“先学懂项目，再进入决策”的入门包。目标不是让你一次看完所有技术细节，而是先帮你真正看懂这个产品是什么、为什么这样设计、和普通项目有什么不同。

- 这个项目到底是做什么的
- 第一阶段在融资上到底讲什么
- 治理币和支付、股权、分红有什么区别
- 后台权限、财务、合规为什么必须一起设计

## 给零基础产品经理的先结论

先记住下面 6 句话：

1. TravelTrust 不是单一页面，也不是单一代币项目，它是一个围绕旅游交易、争议处理、区域治理和企业级后台运营建立起来的完整系统。
2. 当前项目不能把“支付币”“治理币”“股权”“分红产品”混着讲。
3. 第一阶段除了融资叙事，还必须同时把财务闭环、权限分权、合规门禁一起讲清楚。
4. 产品经理在这里不只是写页面需求，更重要的是先把产品结构、业务边界、角色关系和风险底线学明白。
5. 本目录是给你降低理解门槛的，不是替代原始规范；最终定稿仍然要回到 `docs/spec/`。
6. 如果你只剩 30 分钟，先看“新手先读”“学习路径”“产品优势与项目卖点说明”这 3 份。

## 使用原则

1. 本目录优先讲人话和业务意思，再告诉你回哪份原始规范核对。
2. 本目录只做产品经理入口，不替代 `docs/spec/` 内的 SSOT。
3. 涉及数字、费用分母、收益路径、对外措辞时，必须回到原始规范确认。
4. 对外材料、融资 PPT、白皮书、落地页文案，必须经过法务与合规签核后才能发布。
5. **全仓**（工程 + 产品资料夹）**按序文档审计**见 **[`docs/runbook/TT-DOC-ENTERPRISE-AUDIT-CHECKLIST-001.md`](../runbook/TT-DOC-ENTERPRISE-AUDIT-CHECKLIST-001.md)** **Phase 8**；**本目录**深度结论仍以 **[`15-产品经理资料夹企业级检查与缺口清单`](15-产品经理资料夹企业级检查与缺口清单.md)**、**[`29-产品经理多维度深度检查与新增缺口`](29-产品经理多维度深度检查与新增缺口.md)** 为 **PM 域 SSOT**。

## 产品经理学会后应该能做到什么

- 能用人话解释 TravelTrust 是什么，不会讲成单纯发币项目
- 能说清它和普通旅游平台、普通 Web3 项目的区别
- 能分清支付、治理、股权、分红、区域份额这些概念
- 能理解融资、治理币、权限、合规四条线为什么要一起看
- 能看懂后续决策表和专题资料包，不会一上来被术语卡住
- 能知道自己作为区块链产品经理每天、每周、每阶段该做什么
- 能知道自己不只是做产品定义，还要推进融资、内容、社媒运营和社区建设

## 最后提醒

如果你是第一次接这个项目，不要试图一上来读完所有规范。正确顺序是：

1. 先搞懂项目是什么、解决什么问题、强在哪里。
2. 再搞懂哪些概念最容易混，哪些词不能乱讲。
3. 最后再去拆融资、治理币、权限、合规四条线的细节。

## 文档维护规则

1. 本目录面向“小白产品经理学懂项目并进入执行”，不要再把它改回老板汇报导向材料。
2. 新增文档前，先判断是否能并入现有文档，避免越写越散。
3. 任何对外表达、融资数字、治理边界、收益口径，必须回原始 SSOT 再确认。
4. 每次补新资料后，优先同步 [13-一级市场资料包总表](13-一级市场资料包总表.md)、[15-产品经理资料夹企业级检查与缺口清单](15-产品经理资料夹企业级检查与缺口清单.md) 和 [16-对外成品资料建设路线图](16-对外成品资料建设路线图.md)。
