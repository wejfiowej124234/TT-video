# 一、协议级 UI 设计宪法（6 条，任何 UI 讨论前必须锁死）

## 1️⃣ 资金区必须像银行

- **不允许**：渐变按钮、炫光、跳动数字、3D 元素侵入资金区。
- **资金区设计关键词**：严肃、留白、信息优先、状态清晰、风险提示可见。

## 2️⃣ 3D 只能存在于「情绪层」

- **3D 仅允许存在于**：Landing Hero、品牌演绎、资金流抽象可视化。
- **绝不进入**：EscrowDetail、Dispute、Governance。否则可信度崩塌。
- 与 [09 §2.5](09-技术架构总览-v1.0.md)、[05 §九](05-前端总览.md) 一致：3D 不用于订单操作页。

## 3️⃣ 旅游与 Web3 的融合逻辑

- **旅游** = 情绪 + 图片 + 目的地；**Web3** = 状态 + 余额 + 交易 + 签名。
- **正确融合方式**：旅游内容在「上层」，金融交互在「下层」。
- **视觉上**：上半屏可以温和；下半屏必须克制。

## 4️⃣ 角色必须空间隔离

- 五类角色：游客、导游、仲裁员、治理者、观察者。
- **UI 要求**：不是 Tab 切换，而是「进入不同工作空间」；否则会混乱。

## 5️⃣ 风格优先级排序（必须锁死）

**可信度 > 清晰度 > 一致性 > 美感 > 动效**  
不得颠倒。

## 6️⃣ AI 输出控制规则

与 AI 协作 UI 时：**不要先输出代码**。先输出：**视觉哲学 → 信息层级 → 页面结构 → 风格控制表**。否则易产出 neon dashboard 类结果。

# 二、统一视觉哲学（高级原则）

- **易犯错误**：旅游区做得太感性、金融区做得太冷，导致割裂。
- **正确做法**：整个系统统一为 **温和的科技感**（gentle tech feel）。
- **不是**：旅游风 + Web3 风拼接。**是**：单一、温和的科技感贯穿全站。

# 三、必须准备的 5 项（正式版）

## 1️⃣ 项目定位声明（最终版示例）

TravelTrust 是一个基于 EVM 的去中心化旅游托管协议。所有资金状态以链上事件为真相。前端仅用于签名与状态展示。视觉语言必须表达：**可信、克制、未来科技感与旅行体验的平衡**。

## 2️⃣ 目标用户画像（2 类核心）

| 类型 | 特征 |
|------|------|
| **A. 高净值游客（核心用户）** | 注重安全、注重体验、对链理解有限；希望「安全但不复杂」。 |
| **B. 专业导游 / 服务商** | 关注托管安全、结算透明、争议流程公平。 |

仲裁员与治理者属于功能角色，不属于体验主角。

## 3️⃣ 页面列表（协议级产品结构）

| 页面 | 说明 |
|------|------|
| Landing | 落地页 |
| Discover | 发现/导游列表 |
| Booking | 预订/下单 |
| EscrowDetail | 托管详情（资金区，须遵守 1️⃣） |
| DisputeCenter | 争议中心（资金/证据区，须遵守 1️⃣，无 3D） |
| Governance | 治理（须遵守 1️⃣，无 3D） |
| Profile | 个人中心 |
| Admin | 内部管理 |

## 4️⃣ 视觉关键词（必须锁死 5 个）

**克制 · 信任 · 科技 · 空间感 · 温和旅行**

## 5️⃣ 不允许出现的风格（必须写死）

- Neon Cyberpunk  
- 极重玻璃态叠加  
- 交易区强动效
