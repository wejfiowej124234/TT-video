## 2. 真实代码入口与边界

- 前端真实入口：frontend/（Next.js 应用根；技术栈见 09 §2.6～2.7）。
- In-scope：路由/页面（App Router 或 pages/）、API client（lib/）、MetaGate、wagmi/viem 钱包与签名、EIP-712 与 txMachine。
- Out-of-scope：浏览器与钱包插件本体、RPC/链节点、后端部署形态。

## 4. 模块职责与“最优模块化”建议

### 4.1 app/：路由与入口

- 路由：/、/auth、/me、/orders、/disputes、/pay、/staking、/escrow/:id（见 09 §2.7）。
- 安全/一致性：wagmi 的 chainChanged/accountsChanged 或 useDisconnect 须触发清理存储并 reload（05 §七点十）。

最佳实践约束：

- 不把权限/身份结论持久化在 localStorage（05 §七点九；JWT 不落 localStorage）。
- 任何关键写操作必须依赖 /meta 兼容性门禁与 build-time 写死参数（见下）。

### 4.2 lib/：API client（唯一业务数据源）

- 强规则：业务数据唯一来源=后端 API（与 docs/spec/04 对齐）。
- 统一 header：x-request-id、x-message-id（写请求）、X-Idempotency-Key 与 Idempotency-Key（同值）兼容后端。
- 写超时：写操作必须可超时并进入“查询状态”恢复路径，避免弱网误判。

### 4.3 /meta 版本绑定与 Release 门禁

- 启动调用 GET /meta。
- Release 必须写死：TRAVELTRUST_EXPECTED_API_VERSION、TRAVELTRUST_EXPECTED_SSOT_VERSION（或 NEXT_PUBLIC_* 等价）。
- 不兼容必须 fail-closed：禁止关键写操作。

### 4.4 dapp/ 与 components/Providers：钱包连接与签名

- 钱包：**wagmi + WalletConnect v2**（见 09 §2.7）；Provider 注入与 chainId 由 wagmi 管理。
- 签名：**viem signTypedData** 或 wagmi hooks（EIP-712 typed data v4）。

### 4.5 app/ 页面与 dapp/ 写操作路径

- **app/**：layout、auth、me、tourist、guide、arbitrator、pay、staking、escrow/:id 等页面。
- **components/**：通用 UI（按钮、表单、错误提示、loading、连接钱包）。
- **dapp/**：钱包、EIP-712、自研 tx 状态机、viem watchContractEvent（与 06、09 §2.7 一致）。
- **hooks/**（可选）：useWallet、useApiError 等；typed data 生成与签名与 06 契约对齐。

## 5. 构建/发布门禁与证据（Release & Evidence）

### 5.1 构建可验证（manifest）

- 按 [evidence/README](../../evidence/README.md) 可验证发布段落手工生成 manifest.json + manifest.sha256（原 build-frontend-manifest.sh 已移除）
- 可复现构建验证按 evidence/README 与发版前核对执行（原 verify-frontend-deterministic-build.sh 已移除）

### 5.2 必须写死（build-time）的关键参数

这些参数属于“DApp/签名域”与“版本门禁”的硬约束（05 §七点六）：

- **NEXT_PUBLIC_API_BASE_URL**（前端调用后端 base URL）
- **TRAVELTRUST_EXPECTED_API_VERSION** / **TRAVELTRUST_EXPECTED_SSOT_VERSION**（/meta 绑定）
- **TRAVELTRUST_CHAIN_ID** / **TRAVELTRUST_VERIFYING_CONTRACT**（或 NEXT_PUBLIC_* 等价，EIP-712 domain 关键字段）

最佳实践约束：

- Release 构建缺失上述关键值应当 fail-closed；启动时 /meta 校验与写操作前 chain_id/contract 校验须在 frontend 实现中落地。

## 6. 审计/验收清单（Checklist）

1) 入口清晰：前端真实入口=frontend/（Next.js + React + TS + wagmi + viem + R3F + drei + Framer Motion）。
2) 同源约束：页面展示以 API 为唯一数据源；DApp 仅提供签名/交易触发。
3) /meta 门禁：启动必调；Release expected_* 必填；不兼容 fail-closed。
4) 幂等与 trace：写请求同时带 Idempotency-Key 与 X-Idempotency-Key；每次请求带 x-request-id。
5) 可验证发布：manifest + deterministic build 脚本可运行，产物纳入 evidence bundle。
