## 2. 真实代码入口与边界

- 前端真实入口：crates/web（仓库根 frontend/ 目前为空目录位）。
- In-scope：路由/页面、API client、MetaGate、钱包 provider 监听、签名与意图提交（signed intent）。
- Out-of-scope：浏览器与钱包插件本体、RPC/链节点、后端部署形态。


## 4. 模块职责与“最优模块化”建议

### 4.1 lib.rs：路由与身份失效事件（chainChanged/accountsChanged）

- 路由：/、/auth、/me、/orders、/disputes
- 安全/一致性控制：监听钱包 provider 的 chainChanged/accountsChanged，清理存储并 reload。

最佳实践约束：

- 不把权限/身份结论持久化在 localStorage（lib.rs 已做 best-effort 清理，并明确“避免持久化 JWT”）。
- 任何关键写操作必须依赖 /meta 兼容性门禁与 build-time 写死参数（见下）。

### 4.2 api/mod.rs：API client（唯一业务数据源）

- 强规则：业务数据唯一来源=后端 API（与 docs/04 对齐）。
- 统一 header：
  - x-request-id：每次请求自动生成
  - x-message-id：写请求生成（用于后续 outbox/链上串联）
  - 幂等：写请求同时带 X-Idempotency-Key 与 Idempotency-Key（同值）兼容后端。
- 写超时：写操作必须可超时并进入“查询状态”恢复路径，避免弱网误判。

### 4.3 meta_gate.rs：版本绑定（/meta）与 Release 强制门禁

- 启动调用 GET /meta。
- Release 必须写死：TRAVELTRUST_EXPECTED_API_VERSION、TRAVELTRUST_EXPECTED_SSOT_VERSION。
- 不兼容必须 fail-closed：禁止关键写操作。

### 4.4 wallet.rs：钱包连接与签名

- Provider：window.ethereum（EIP-1193）
- chainId：eth_chainId
- 签名：eth_signTypedData_v4（EIP-712 typed data v4）

### 4.5 pages/mod.rs：页面与关键写操作路径（现状 + 建议拆分）

现状：pages/mod.rs 内集中放置多个 Page_* 组件与写操作示例（占位）。

建议的最优模块化（便于维护与审计）：

- pages/home.rs、pages/auth.rs、pages/me.rs、pages/orders.rs、pages/disputes.rs：每页单文件
- components/：通用组件（按钮、表单、错误提示、loading、空态）
- hooks/：通用 hooks（use_meta_gate、use_wallet、use_api_error 等）
- dapp_intents/：typed data 生成与签名请求（与 06 的契约对齐）

## 5. 构建/发布门禁与证据（Release & Evidence）

### 5.1 构建可验证（manifest）

- scripts/build-frontend-manifest.sh：生成 manifest.json + manifest.sha256
- scripts/verify-frontend-deterministic-build.sh：验证可复现（deterministic build）

### 5.2 必须写死（build-time）的关键参数

这些参数属于“DApp/签名域”与“版本门禁”的硬约束：

- VITE_API_BASE_URL（前端调用后端 base URL）
- TRAVELTRUST_EXPECTED_API_VERSION / TRAVELTRUST_EXPECTED_SSOT_VERSION（/meta 绑定）
- TRAVELTRUST_CHAIN_ID / TRAVELTRUST_VERIFYING_CONTRACT（EIP-712 domain 关键字段）

最佳实践约束：

- Release 构建缺失上述关键值应当 fail-closed（当前 meta_gate.rs 对 expected_* 已严格；pages/mod.rs 对 chain_id/contract 也做拒绝）。

## 6. 审计/验收清单（Checklist）

1) 入口清晰：前端真实入口=crates/web；frontend/ 为空目录位。
2) 同源约束：页面展示以 API 为唯一数据源；DApp 仅提供签名/交易触发。
3) /meta 门禁：启动必调；Release expected_* 必填；不兼容 fail-closed。
4) 幂等与 trace：写请求同时带 Idempotency-Key 与 X-Idempotency-Key；每次请求带 x-request-id。
5) 可验证发布：manifest + deterministic build 脚本可运行，产物纳入 evidence bundle。
