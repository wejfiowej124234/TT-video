# TravelTrust 任务母表（Backlog）

**定位**：**任务来源层（Source of Truth for “要做什么”）**，与 [AI任务卡索引.md](./AI任务卡索引.md)（**执行层 / TT**）分离。

| 层级 | 文档 | 作用 |
|------|------|------|
| 需求与规格 | `docs/spec/*` | 产品/流程 SSOT |
| **任务母表（本文件）** | `docs/任务母表.md` | Backlog：条目、模块、状态、是否已落 TT |
| 执行索引 | `docs/AI任务卡索引.md` | 可执行的 TT：路径、验收、封口 |
| 执行方式 | Low-Latency + 话术文档 | 单卡、≤8 文件、锚点 |
| **单人开发节奏** | `docs/solo-dev-rhythm.md` | 封口、推送、CI、Evidence 命名与入仓约定 |
| **新增只读 API（治理/管理 GET）** | **[runbook/ai-template-read-only-api.md](./runbook/ai-template-read-only-api.md)** | **单一模板入口**：任务卡、Read Contract、契约测试、route guard 清单（先读后写） |

**流程（必须遵守）**

1. **先**在本表登记或更新一行（`B-xxx`）。  
2. **再**将「当前要做」的条目 **派生**为 `TT-xxx`，写入 [AI任务卡索引.md](./AI任务卡索引.md)。  
3. **最后**对 AI 说：**执行任务卡 TT-xxx**（或从母表指定：`B-xxx → 生成 TT 并执行`）。  
4. **若**任务为 **新增 `/api/v1/governance/*` 或 `/api/v1/admin/*` 只读 GET**：开工前必读 **[新增只读接口标准模板](./runbook/ai-template-read-only-api.md)**（与封口实现无关的文档与测试约定；**禁止**擅自改 B-115 / B-116 / P5 已封口代码）。

不做母表 → 易出现重复劳动、遗漏能力、TT 索引与「是否做完项目」脱钩。

## 维护规则（最小）

1. **新增能力或缺陷**：先加母表一行，**状态** = 未做 / 进行中 / 待验。  
2. **准备给 AI 执行**：从母表勾选条目 → 在 `AI任务卡索引.md` 增加或引用 TT → 母表 **是否已转为 TT 卡** 填 ✅ 并写 TT ID。  
3. **合并/重复**：同一能力不要开两个 `B`；旧行标记 **废弃** 并在描述中指向新 `B-xxx`。  
4. **与 spec 对齐**：`来源` 列尽量写 `spec/路径#章节` 或 Issue 链接，避免「只活在聊天里」。  
5. **粒度**：一条 B 对应 **单一行为**、默认 **≤1 页面或 ≤1 组件**；过大则继续拆行。
